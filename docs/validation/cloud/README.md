# 구름·안개가 그 형상으로 읽히게 (D7, 2026-11-23)

지시: `docs/prompts/prototype-v4-build.md` D7, `docs/decisions.md`의 「렌더 시트 3장과 구름 진단의 대조」와 Codex D4 4번(구 대리 메시와 8걸음은 그대로, 밀도장을 둥근 덩어리 여러 개가 겹친 모양으로).
**모든 입력은 합성 자료다**(손으로 고른 합성 spec과 목업 합성 응답의 spec. 참여자 데이터 아님).

## 무엇을 바꿨나

| | 전(X66) | 후(D7) |
| --- | --- | --- |
| 메시·패스 | 구 대리 메시 하나, 한 패스, 레이마칭 8걸음, 그림자 없음 | **그대로** |
| 밀도장 | 노이즈로 흔든 반지름 감쇠 × 문턱 덩이 노이즈 → 흐린 얼룩 하나 | **둥근 덩어리 5개의 합집합**(가운데 큰 덩어리 + 둘레 4개, 번갈아 위·아래) + 중간 주파수 노이즈(겉면을 흔들고 속을 얼룩지게). 덩어리 중심·반지름은 `MistLumps.Build(seed)`(C#, 결정적 난수)가 정해 머티리얼 벡터 `_Lump0…_Lump4`로 넣는다. 배치 규칙 버전 `lumps5/1`, seed 0(형상 프리셋 기본값) |
| 알파 | 중심 광선 누적 알파의 목표 = opacity × 0.5 → 가장 짙은 곳도 약 0.5 × opacity | 덩어리 속은 누적 알파가 opacity 가까이까지 찬다. **최종 알파 = opacity × (덩어리 밀도로 쌓은 알파)** — opacity는 spec 값 그대로이고 그 위로 올리지 않는다(X70) |
| 음영 | 구 전체를 법선으로 감싼 확산 | 덩어리마다(가장 깊이 들어간 덩어리 쪽으로 기운 가중 평균) 감싼 확산 + 덩어리 안에서 빛 쪽으로 남은 두께만큼의 자기 그림자 + 주변광 → **덩이마다 위가 밝고 아래가 어둡다**. 색·밝기 슬롯 값은 그대로 |
| 걸음 구간 | 대리 구 전체 | 덩어리 전체를 감싼 구와 겹치는 구간(같은 8걸음이 덩어리 안에 더 촘촘). 처음에는 덩어리마다 구간을 잘랐는데 그 구의 윤곽에서 걸음 자리가 갑자기 바뀌어 구름 안에 둥근 금이 보였다 → 감싼 구 하나로 바꿈 |

**밀도 프리셋 숫자는 바꾸지 않았다**(`FormRenderPlan.FormPresets["mist"].Density` = 0.5, `OwnershipVariantGenerator.FormDensity["mist"]` = 0.5, `RenderedColor.SurfaceAlpha`). 셰이더에서 `_Density`의 뜻만 "중심 광선 알파 목표의 배율"에서 "광학 두께 배율"(σ = 0.5 × 16 = 물체 좌표 길이당 8)로 바뀌었다. 그래서 소유감 러너의 변형 규칙·lowVisibility 판정·색 ΔE 목표(X33, 알베도 기준)는 그대로이고 관련 테스트도 그대로 통과한다. 다만 C# 쪽 유효 불투명도 `opacity × 0.5`는 이제 화면의 실제 알파(덩어리 속 ≈ opacity, maxAlpha 실측 0.997·0.7·0.5·0.152)보다 **낮게 잡힌 값**이다. 이것이 쓰이는 곳은 (1) 소유감 러너의 lowVisibility(유효 불투명도 < 0.15 → opacity < 0.3인 mist에 경고 — 실제보다 보수적으로 경고), (2) X33의 합성 ΔE00 기록(`magnitude.deltaE00Composited`, 기록만 하고 판정에 쓰지 않음)이다. 형태 변형 mist → blob의 "유효 불투명도 0.5 → 1" 기록도 같은 이유로 실제 화면 차이보다 크게 적힌다. 이 값들을 실측에 맞추려면 숫자를 바꾸고 소유감 러너 테스트를 함께 고쳐야 하므로 이번에는 하지 않았다(⚠ 메인 판정 필요).

## 검증 spec (9개 + 안개 안 1개)

## 눈으로 본 판정(메인 확인 전, 하위 에이전트가 PNG를 직접 봄)

- **흰 구름(C01)**: 구름으로 읽힌다. 몽글한 덩이 여러 개, 위가 밝고 아래가 조금 어둡다. 전에는 흐릿한 흰 얼룩.
- **잿빛 구름(C02)·파란 안개(R01)**: 확대하면 덩이가 겹친 구름 모양으로 읽힌다. 장면 전체(기본 거리 1.2 m, 크기 약 0.4 m)에서는 작고 바닥보다 조금 어두운 뭉치로 보인다 — 구분은 되지만 "회색 구름"인지까지는 확대해야 분명하다.
- **M01 안개(opacity 0.5, 밝기 0.4)**: 전에는 거의 안 보였고, 후에는 반투명한 회색 구름 뭉치로 보인다. 다만 "방을 채울 만큼 퍼진 안개"가 아니라 **작은 구름 덩이**로 보인다. 덩어리 밀도장은 "구름"에는 맞고 "퍼진 안개"에는 덜 맞는다(같은 form.type=mist라 구분할 수 없음).
- **M02 검은 연기**: 짙은 회흑색 덩이로 뚜렷하게 보인다. 연기의 가늘게 풀리는 느낌보다는 "검은 구름 덩이"에 가깝다.
- **R03(opacity 0.15)**: 여전히 거의 안 보인다. 말한 값(거의 투명)을 지킨 결과다(X70, 보정하지 않음).
- 정지 화면이다(움직임은 보이지 않음). **헤드셋에서 구름으로 읽히는지는 확인하지 않았다.**

## 알려진 영향·한계

- **카메라가 덩어리 안에 들어가면 앞이 opacity만큼 가려진다**(C03 maxAlpha 0.577 → 1.0, 화면이 회색으로 막힘). 전에는 반투명했다. 배치 러너에서 참여자가 구름을 자기 쪽으로 끌어오면(직접 배치, `holdMinM` 0.3 m는 컨트롤러 기준) 시야가 막힐 수 있다. 헤드셋에서 확인 필요.
- 소유감 러너(X71): 규칙·기록 형식은 그대로지만 mist 원본과 mist ↔ blob 형태 변형 자극의 화면이 달라졌다(mist가 더 짙고 덩어리져 blob과의 차이가 "윤곽·질감" 쪽으로 옮겨감). 내부 보정 시행 값은 다시 봐야 한다.
- 걸음 수 8이라 덩어리 가장자리에 옅은 층 무늬가 남을 수 있다(이번 캡처에서는 눈에 띄지 않음). Quest 모바일 GPU의 채움 비용은 재지 않았다(표본마다 덩어리 5개 거리 + 자기 그림자 5개 교차 계산이 늘었다).

## 환경 밝기에 대한 제안(바꾸지 않음)

형상 뒤 배경은 하늘 지평선(0.74)보다 **바닥**(알베도 0.46, 조명 받아 L\* 약 56)인 경우가 많다. 중간 회색(l 0.55 안팎)·기본 밝기의 안개는 음영을 넣어도 평균 ΔL\*가 −6~−7에 그친다. 바닥·하늘 밝기를 바꾸면 모든 형상과 후보1 러너의 색 측정(합성 배경 = 하늘 지평선 색, X33)이 함께 바뀌므로 이번에는 손대지 않았다. 바꾼다면 바닥만 조금 어둡게(예: 0.46 → 0.38) 하는 쪽이 하늘 기준 색 측정에 영향이 적다 — 시험해 보지 않은 제안이다.
