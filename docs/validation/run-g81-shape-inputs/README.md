# G81 형태 입력 유형별 생성 점검: 실제 로컬 파이프라인, 합성 대사 (2026-11-28)

연구 책임자 요청: "참여자가 어떤 형태를 입력해도 LLM과 사전 기반 매핑을 바탕으로 잘 생성되는지 확인하고 스크린샷을 찍어 달라."
합성 문장 16개(유형 A–H)와 C1 재실행 1회를 experiment 설정으로 처음부터 끝까지 돌렸다. 제품 코드·사전·프롬프트는 고치지 않았다.

## 무엇을 어떻게 돌렸나

- 서버: `chatbot/config/experiment.toml`을 저장소 밖에 복사하고 `[session] log_dir`만 임시 폴더로 바꿨다(나머지는 같다). `--port 8031`, `--researcher-contact`는 합성 점검용 문구다. 이미 떠 있던 8000번 서버와 Unity 에디터는 건드리지 않았다.
- `run_g81.py`
  1. HTTP로 면담을 진행한다. 세션 `SYN-G81-<ID>-1`을 만들고 첫 답에 합성 문장을 넣는다. 나머지 질문은 [넘어가기]로 넘겨 확인 화면까지 간 뒤, [고칠게요]로 확정 텍스트를 그 합성 문장으로 맞춘다. 면담 LLM과 가드는 실제 모델이다.
  2. 헤드리스 Chrome(1280px)으로 참여자 화면을 열고 단추를 누르며 진행한다. 순서는 [다음으로] → 후보 → [맞는 게 없어요] → 그림 3장 → **맨 앞(가장 작은 seed) 그림**을 기계적으로 고름 → 만든 물체 → 그 물체를 고름 → 조절 → [다 고쳤어요]이다.
  3. 세션마다 spec, `selection.json`, 세션 로그에서 기록을 모아 `results.json`에 넣는다. 로컬 경로는 넣지 않았다.
- `make_summary.py`: `results.json`과 그림·메시 축소판(저장소 밖)으로 `summary_1.png`·`summary_2.png`(폭 1600px)를 만든다.
- 다시 돌리기(chatbot 서버를 위 사본 설정으로 띄운 뒤): `python run_g81.py --logs <log_dir> --gen-out <gen3d-out> --raw <임시 폴더>`, 이어서 `python make_summary.py --raw <임시 폴더>`. 필요한 패키지는 websockets와 Pillow다.

## 찾은 문제 (재현 입력)

1. **후보 순서에 따라 만든 물체가 후보에서 빠진다(WebGL 미리보기).** 재현: 「돌덩이예요.」(세션 `SYN-G81-C1-1`). 확정 spec에 `form.type`이 비어 있으면 후보 축이 `form.type: [blob, mist]`가 된다. 그 세션에서 후보 화면에 마지막으로 그려진 후보가 mist면, 만든 물체 칸을 그릴 때 Unity가 `mist_form`(안개에는 생성 메시를 씌우지 않음)을 돌려준다. 그러면 클라이언트가 그 후보를 빼고(`asset_failed`) 참여자를 바로 조절 화면으로 보낸다. 안내 문구는 나오지 않는다. 같은 문장이라도 새 세션 ID에서는 마지막 후보가 blob이어서 성공했다(C1r2). D2도 마지막 후보가 blob이어서 성공했다. 원인 추정(코드 읽기): `chatbot/ifs_chatbot/web/stage.js` `candidateNode`가 `setAsset(asset)`을 `apply(overrides)`보다 **먼저** 부른다. 그래서 GLB가 직전 후보의 덮어쓰기(mist) 위에 씌워진다. 만든 후보의 덮어쓰기는 0번 후보와 같은 `{}`(blob)다. G77이 형태 낱말을 메워 주는 경우가 바로 `form.type`이 빈 spec이므로, 이 버그는 G77 구제 경로를 확률적으로(이번 표본에서는 2번 중 1번) 깨뜨린다.
2. **과거형 형태가 막히지 않는다.** 재현: 「예전에는 공이었어요.」. 매퍼가 '공'을 `form.type=blob`으로 넣고, `_negated`·`_context`는 비어 있다. 그림 프롬프트가 `a single ball`이 되어 생성·선택까지 갔다. 매퍼의 과거 처리 규칙이 이 꼴을 잡지 못한다.
3. **G77이 사전에 없는 형태 낱말을 거의 메우지 못한다.** 「돌덩이예요.」만 `shape_noun`을 냈다. 「조약돌이 하나 있어요.」, 「판때기예요. …」, 「돌덩이 같은 게 있어요.」는 `shape_noun`이 제안 슬롯에 들어 있었는데도 모델이 형태 낱말을 내지 않아(`{"items": []}` 또는 색·질감만) `no_shape_stated`가 됐다. 온도 0·캐시 때문에 같은 문장은 같은 결과를 낸다. 결국 C형 4문장 가운데 그림 단계까지 간 것은 1문장, 화면에 메시가 나온 것은 재실행 1회다.
4. **보통의 몸 감각 묘사가 가드 '확인' 판정을 받아 G77이 꺼진다.** H1 첫 답과 확정 텍스트를 가드 모델이 `UNSAFE-S6`(`controversial`, soft_check 알림 1)로 판정했다. 설계대로 G77은 `session_flagged`로 건너뛰었다. 이번에는 규칙이 형태를 만들어 생성에는 영향이 없었다.
5. (작음) H1 spec의 `_needsConfirmation`에서 '가끔'이 사전의 '가슴'에 흐린 일치(`fuzzy_lexicon`)로 걸렸다.
6. (작음) '쑥색'은 색 사전에 없다. G77이 `green`으로 채워 선명한 초록(채도 단계도 `llm_quoted`)이 됐다. 인용은 맞지만 쑥색(회녹색)보다 훨씬 진하다. '회색'(A1·H1)은 사전값 h0 s0.05 l0.45로, 화면에서 붉은 기가 도는 회갈색으로 보였다.
7. (점검 도구 쪽) C1에서 물체 생성이 끝난 직후 곧바로 새 세션을 만들면, 모델을 다시 올리는 동안 서버가 409(「물체 생성 중이라 …」)를 낸다. 설계된 동작(CP13)이다. 첫 실행에서 C2·C3가 이 때문에 시작되지 못해서, 도구가 `/api/health`의 `modelsReady`를 기다리게 고친 뒤 다시 돌렸다.

## 한계

- 문장마다 한 번씩만 돌렸고, 그림은 기계적으로 seed 0을 골랐다. 참여자가 다른 그림을 골랐을 때(받침이 붙은 그림 포함)의 메시는 보지 않았다. [이 중에는 없어요]로 가는 2회차도 돌리지 않았다.
- 시간에는 캐시 적중이 섞여 있다(C1r2의 형태 단계 9.7초). A1의 그림 단계(61초)는 첫 SDXL 적재 때문에 길었다. 나머지 그림 단계는 37–41초, 형태 단계는 35–52초였다.
- 헤드셋 러너로 `selection.json`(0.5)을 읽혀 보지 않았다. Unity 에디터가 열려 있어서다.
- 면담 질문은 [넘어가기]로 넘겼으므로, 면담 LLM이 형태를 되묻는 경로는 이 점검의 대상이 아니다.
- 눈으로 본 판단은 점검자 한 사람의 참고 의견이다.
