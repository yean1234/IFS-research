> **합성 자료: 파이프라인 검증용이며 효과의 근거가 아님.** 이 폴더의 세션 24개, 발화 96개, 검증 문장 46개는 모두 코드나 연구자가 만든 가짜 자료입니다. 참여자 자료는 하나도 없습니다(AGENTS.md 원칙 6). 아래 수치는 "분석 코드가 정의대로 계산하는가"를 보여 줄 뿐이고, 사람에게서 나온 효과나 측정의 타당성을 뜻하지 않습니다.

## 무엇을 보여 주고 무엇을 보여 주지 못하나

**보여 주는 것**
- 합성 기록을 생성한 뒤 placement 분석, differentiation 분석, 출력까지 명령 하나로 돕니다. 다시 돌려도 결과가 바이트 단위로 같습니다(폴더 전체 md5를 두 번 비교해 확인함).
- 생성기에 가정해 둔 유형 차이를 분석 코드가 그대로 복원합니다. 2×2 칸, 언어 표지, 사례 규칙 모두 그렇습니다.
- Unity 러너가 실제로 남긴 기록 5개(`docs/validation/placement/records`, 자동 시행 합성)를 같은 분석기에 함께 넣어도 형식 오류 없이 읽힙니다.
- 언어 표지 규칙이 합성 문장에서 어디서 맞고 어디서 틀리는지 보여 줍니다. 정확도와 틀린 사례를 모두 공개합니다.

**보여 주지 못하는 것**
- 측정의 타당성. 유형별 거리, 머리 방향, 평정, 발화를 연구자가 정해 넣었으므로 결과가 유형을 잘 가르는 것은 정의상 당연합니다(순환). 2×2 일치 18/18은 코드 경로가 맞는지에 대한 점검일 뿐입니다.
- 실제 사람의 발화. 실제 발화는 템플릿보다 길고 다양하며, 주어 생략과 "저"의 중의성이 더 자주 나올 것입니다.
- 수렴 상관의 의미. 아래 상관은 생성기가 유형마다 템플릿과 평정 중심값을 정해 둔 결과입니다. 성분 구분이 쓸모 있다는 근거가 아닙니다.
- 0–10 문항의 수집 가능성. 현재 Unity 러너의 평정 입력은 1–7뿐이라 M1p·M2·M3(0–10)은 헤드셋 안에서 받을 수 없습니다. 합성 세션은 기록 형식(ratings.csv 숫자)만 가정했습니다.

이 6개는 `chatbot/tests/test_language_markers.py`에 `xfail(strict=True)`로 남겼습니다. Kiwi나 규칙이 바뀌어 결과가 달라지면 테스트가 알려 줍니다. 세트가 작고 연구자가 만든 문장이라, 이 정확도를 실제 발화에서의 정확도로 옮기면 안 됩니다. 문서 3.3대로 실제 전사는 사람 코더가 전수 확인해야 합니다.

## 문서 3.2·3.3 정의와 다르게(또는 문서가 정하지 않아 새로) 정한 점

- **절 나누기**(문서에 없음): EF·SF 뒤에서 끊고, EC 뒤에서도 끊습니다. 다만 EC 다음이 보조용언 VX이거나 `보이/VV`("~아 보이다")이면 끊지 않습니다. ETM(관형형)에서도 끊지 않습니다. 서술어가 없는 조각은 절로 세지 않습니다(fragment).
- **절 안의 서술어**: 마지막 서술어만이 아니라 절에 든 서술어 전부를 봅니다. 그래서 "있는 것 같아요"는 K3로, "내가 본 게 그 돌이에요"는 K2로 잡힙니다(앞의 것은 의도한 동작이고 뒤의 것은 오탐입니다).
- **K4**: Kiwi가 "그거"를 `그거/NP`로 내므로 `이거`·`그거`·`저거`도 받습니다. NP 지시어에는 자리 조건을 걸지 않고, MM+체언에만 주어 자리 조건을 겁니다. 문서 문장을 글자 그대로 읽은 해석입니다.
- **K6**: EP 중 형태가 었·았·였인 것만 셉니다(겠·시는 제외).
- **비율**: 모든 표지를 개수 ÷ 절 수로 냅니다. 토큰 단위 표지(K1·K4·K5)도 같은 분모를 씁니다.
- **L-B**: 문서의 범주(열림·너그러움·차분 / 밀어냄·두려움·짜증)에 맞는 사전이 저장소에 없어서 새로 만들지 않았습니다. 대신 기존 1층 사전(`shared/lexicon/layer1_lexicon.v0.json`)의 emotion 범주(49개, 하위 범주 없음)와 일치한 말과 그 사전 값을 나열하고, 나머지 용언 원형은 분류하지 않고 나열만 합니다. 부정 판정은 그 사전 모듈의 규칙을 씁니다. 앞의 안·못과 뒤 6토큰 안의 않·없·아니·못하·말을 보며, 문서의 "두 토큰 안"과 다릅니다.
- **문항 키**: 문서의 M1′는 파일 키로 쓸 수 없어 `M1p`로 적었습니다. S5·S6은 옛 문구 파일 키(`want_to_know`·`withdraw_attention`)도 받습니다.
- **탈동일시 묶음**: (norm(M2) + norm(P1)) / 2이고, 둘 다 있을 때만 계산합니다(하나뿐이면 빈칸과 `disid_partial`). norm = (x − 척도 최소) / (최대 − 최소)이며, M2는 0–10이고 P1은 1–7입니다.
- **"높음"**: 1–7 척도에서 5 이상(중간 4 초과)입니다. 양가와 사례 규칙에 씁니다.
- **G_early·G_late**: 조건 단계 첫 표본과 마지막 표본 시각에서 30초 창을 잡습니다. 세션 표(csv)만 받으면 머리 표본이 없어서, 조건 단계 전체의 head_facing_ratio로 대신하고 flags에 표시합니다.
- **ΔD**: manifest `space.startDistanceM`을 씁니다(러너 기록에는 1.5). 없으면 `--start-distance`(기본 1.5)를 쓰고 flags에 표시합니다. ΔD = 0이면 2×2를 정하지 않습니다(`quadrant_undetermined`).
- **중앙값 분할**: 중앙값보다 큰 쪽이 먼 쪽·보는 쪽이고, 중앙값과 같으면 가까운 쪽·안 보는 쪽입니다.
- **다시 잡기**: regrab_count = grabCount − 1이며 첫 잡기는 뺍니다.

## placement 분석기 변경

`ifs_chatbot/eval/placement.py`는 평정 범위 점검 한 곳만 바꿨습니다. 전에는 모든 문항을 1–7로 점검했습니다. 이제 `profile_items.rating_range(item)`을 써서 M1p·M2·M3만 0–10으로 점검하고, 나머지는 그대로 1–7입니다. 이렇게 하지 않으면 0–10 문항이 있는 세션마다 `rating_out_of_range`가 거짓으로 뜹니다. 출력 열과 기존 테스트는 바뀌지 않았습니다.
