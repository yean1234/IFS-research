## 무엇을 어떻게 돌렸나

- `build_set.py` → `cases.json`. 문장 하나는 정적 면담의 답 세 줄이다. 순서대로 찾기 단계(신경 쓰는 일), 머물기 단계(느낌), 구체화 단계(모습)의 답이다. 차단 갈래는 틀 × 낱말 목록으로 찍었다. 갈래마다 **틀 11개**, 100문장이다. 사전 밖 형태(P)는 낱말 48개, 틀 14개다. 낱말마다 허용 번역 목록 `enOk`를 실행 전에 적었다.
- 고정 전에는 `run_eval2.py --probe`로 규칙 경로만 봤다(LLM 없음). 그때 바꾼 것은 하나다. '종'은 조사 '이'가 붙으면 '종이'(규칙 사전의 paper)가 되어 사전 밖 낱말이 아니었다. 그래서 '망원경'으로 바꿨다.
- `run_eval2.py`: `Runtime`(experiment 설정 + 이 프로세스 안에서만 `[gen3d] on_none_llm_shape = true`. 가드 모델 끔, 미리보기 끔, G77 끔, 조건 고정 끔, 기록 파일 안 씀)을 쓴다. static 세션 + `simulate.drive`로 세 줄을 답하고, 확정은 고치지 않는다. 그러면 단계 표지 `lineStages`가 `applied`가 된다. 이어서 `llm_shape.run`을 한 번 부른다. 서버를 새로 띄우지 않았고 모델을 내리지 않았다.
- `summarize2.py`: 결과 파일에 뜻 판정(`results[].meaning`)과 `metrics`를 적고 아래 표를 만든다. 채점(CP19-3)은 허용 목록 안이면 '맞음'이고 채움에 센다. 목록 밖의 넓은 말은 '넓음'으로 따로 세고 채움에 넣지 않는다. 이번에는 채택·후보의 영어 이름이 모두 목록 안이었다.
- 형태 없음·걱정 이야기 갈래의 일부(각 10·9문장)는 셋째 줄('잘 모르겠어요 그냥 …' 등)이 '더 없음' 답으로 처리되어 확정 텍스트에서 빠졌다. 실제 면담과 같은 처리라 그대로 셌다.

**원인(코드로 확인, 고치지 않음):** G77 검증기 `llm_fill._check_item`의 `simile_of_predicate` 판정은 비유 표지 뒤 첫 내용 낱말이 VA·VV·MAG·XR이면 막는다. 그런데 그 앞 줄의 건너뛰기 조건 `t.base_tag.startswith(("E", "J", "X", "S"))`가 XR(어근)까지 건너뛴다. Kiwi는 '단단해요·묵직해요·딱딱해요·싸늘해요·답답해요'를 `XR + XSA + EF`로 낸다. 그래서 XR을 건너뛴 뒤 판정할 낱말이 남지 않아 통과한다. VA로 나오는 '무거워요'·'차가워요'는 막혔다(7건). 고치는 길은 건너뛰기에서 XR을 빼는 것(`startswith(("E", "J", "XS", "S"))`)으로 보인다. 이 함수는 G77과 함께 쓰므로, 고치면 G77 판정도 바뀐다. 지시대로 결과를 본 뒤에는 고치지 않았다. 고친다면 새 문장 세트로 다시 재야 한다.

## 한계

- 한 번만 돌렸다(반복 일치는 1차에서 봤다).
- 문장은 한 사람이 틀로 만든 합성 대사다. 차단 갈래는 틀 11개 × 낱말 20개 안팎에서 100개를 골랐다. 그래서 틀의 성질을 재는 면이 크다. 0/100의 95% 상한(약 3%)은 갈래 안의 틀에 대한 말이다.
- 허용 번역 목록은 같은 사람이 실행 전에 썼다.
- 정적 면담으로 단계 표지를 얻었다. 챗봇 면담(면담 LLM이 묻는 경로)에서 단계와 줄이 어떻게 맞는지는 보지 않았다.
- 그림·메시 생성과 참여자 화면은 대상이 아니다.

## 파일

- `build_set.py`, `cases.json`: 문장 세트(실행 전에 고정)
- `run_eval2.py`: 실행 스크립트(`--probe`는 LLM 없이 규칙 경로만)
- `results.json`: 문장마다 상태·부름·후보·원시 출력·검증 항목·기각 사유·채택·조립된 그림 프롬프트·단계 표지·입력 해시·검증 입력 해시, `metrics`
- `summarize2.py`: 뜻 판정·수치·표
