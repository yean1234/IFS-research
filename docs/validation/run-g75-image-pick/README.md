# G75 참고 그림 고르기: 실제 생성기로 확인 (2026-11-28)

experiment 설정 서버(127.0.0.1, 면담 LLM `gemma4:e4b`·가드 모델 실제, Ollama)를 띄우고, 합성 세션을 HTTP로 면담 → 확정(edit, 대사를 줄바꿈으로 이은 글)까지 진행한 뒤 헤드리스 Chrome(DevTools 프로토콜)으로 참여자 화면에서 [다음으로] → [맞는 게 없어요] → 그림 고르기 → 만든 물체 고르기를 눌렀습니다. 생성기는 저장소 밖 `gen3d-venv`의 `tools/gen3d/generate.py --pipeline sdxl-triposg`(그림 단계 `--image-pick --seeds 0,1,2`, 형태 단계 `--from-image … --seed <고른 그림의 seed>`), RTX 5080 16 GB. 대사는 모두 합성이거나 연구 책임자 시험 대사(`chatbot/scenarios/g70_researcher_finish.json`)입니다.

| 세션 | 확정 글(요지) | 규칙 프롬프트(내용 부분) | 그림 3장(seed 0·1·2) | 고름 | 결과 |
| --- | --- | --- | --- | --- | --- |
| R1 | 가슴이 답답해요 / 큰 돌 같아요 / 울퉁불퉁하고 회색이에요 | a single bumpy stone | 모두 관문 통과(personLike 0.001–0.003) | 자리 1(seed 1, 달걀꼴 돌) | 만든 물체가 맨 앞 → 골라 조절로, `form.asset` 복사 |
| R2 | 연구 책임자 시험 대사(…천이 펄럭이듯이 … 모양은 구체 …) | a single round object('천'은 `mapper_action_simile`로 뺌) | 모두 통과(0.036·0.036·0.120). seed 2는 원기둥 받침이 붙은 구 | 자리 1(seed 1, 구) | 만든 물체(구)가 맨 앞 → 골라 조절로 |

- ※ R1의 형태 단계는 캐시 적중입니다. 같은 프롬프트·같은 그림(sha256)·seed로 구현 중 생성기를 직접 한 번 돌렸습니다(그때 54초: 배경 제거 0.7, TripoSG 19.0, 후처리 6.9, 메시 관문 2.6, 나머지는 모델 적재). SDXL 그림은 프로세스가 달라도 같은 seed에서 바이트까지 같았습니다(R1 그림 sha256이 직접 실행 때와 같음).
- 참여자 화면 기준: [맞는 게 없어요] → 고르기 화면 R1 67.9초·R2 43.8초, [이걸로 할게요] → 만든 물체가 후보에 나옴 R1 18.3초(캐시)·R2 56.0초. G73(한 번에 이미지 → 형태, 캐시 없음) 실측은 57.5–100초였습니다. G75는 생성기를 두 번 띄우고 모델을 두 번 내렸다 올리므로 기다림이 두 번 생기고 합계가 조금 깁니다.
- 각 단계 전 면담·가드 모델을 내렸고(`llmUnload.ok = true`), 끝난 뒤 다시 올렸습니다(고르는 동안 두 모델이 올라가 있음). 콘솔 오류 0. 세 세션 모두 `selection.json`이 `ifs-selection/0.4` 스키마로 유효했고, 고르기 화면에 노출된 R1·R2는 `generation.imagePickExposed = true`, R3은 `false`입니다.

관찰:
1. **무채색 화풍은 지켜졌습니다.** 여섯 장 모두 회색 점토 조형 하나입니다(`sheet.png`, 초록 테두리 = 고른 그림). 다만 배경은 '흰 배경'이 아니라 회색 그러데이션 스튜디오 배경이고, 바닥과 그림자가 있는 장면이 있습니다(R1 seed 1, R2 seed 1). TripoSG 앞의 배경 제거(rembg)가 처리해 형태 단계에는 문제가 없었습니다.
2. **그림 관문 오탐은 없었습니다**(6장 모두 통과, 최대 0.12). 이번 대사에는 사람·동물로 보일 만한 형태가 없어 오탐을 볼 기회가 적었습니다. G73 때 '둥근 천'을 사람으로 막던 오탐은 이번 R2 프롬프트가 'round object'가 되어 다시 나오지 않았습니다.
3. **부정 틀이 받침을 다 막지 못합니다.** R2 seed 2에 원기둥 받침이 붙었습니다(부정 틀에 stand·pedestal이 있는데도). 그림 관문은 사람·동물만 보므로 이 그림은 보였습니다. 골랐다면 메시 단계의 여러 물체 검사가 받침이 붙어 있으면 잡지 못할 수 있습니다. 참여자가 고르지 않을 수 있다는 점이 G75의 이점이기도 합니다.
4. **'돌덩이'는 형태 사전에 없습니다.** 「돌덩이 같아요」는 '돌덩이'가 한 낱말로 분석되어 사전의 '돌'·'덩이'와 맞지 않아 `no_shape_stated`로 막혔습니다(R3). 사전에 넣으면 G62 평가 입력도 바뀌므로 이번에는 손대지 않았습니다.
5. 만든 메시는 고른 그림의 큰 모양(달걀꼴 돌, 구)을 따랐습니다(`R1-stone_5_selecting.png`, `R2-cloth-sphere_5_selecting.png`의 점선 칸). R2는 규칙 후보도 구라서 다섯 후보가 거의 같은 구입니다.

화면: `*_3_picking.png` 고르기 화면, `R2-cloth-sphere_2_waiting_image.png` 그림 대기, `R2-cloth-sphere_4_waiting_mesh.png` 고른 뒤 대기, `*_5_selecting.png` 만든 물체가 맨 앞 점선 칸.
