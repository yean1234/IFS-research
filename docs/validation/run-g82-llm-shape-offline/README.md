# G82 첫 단계 오프라인 평가: LLM 형태 이름, 실제 로컬 모델, 합성 문장 45개 (2026-11-28)

[맞는 게 없어요]를 누른 뒤 규칙 그림 프롬프트에 중심 형태 명사가 없을 때만, 면담 LLM이 확정 텍스트에서 형태 낱말 하나를 인용하고 영어 이름을 낸다(`chatbot/ifs_chatbot/llm_shape.py`). 이 평가는 그 경로가 실험에 들어가기 전의 1차 평가다. 실험 경로(`selection.py`·`none_gen.py`)에는 잇지 않았고 `experiment.toml`에서도 켜지 않았다. 스크립트가 `llm_shape.run`을 직접 부른다.

- 이 1차 평가 뒤 코드는 프롬프트 0.2.0(영어 한 낱말)·검증기 0.4.0으로 바뀌었다(G82 다음 단계·CP19). 그 판의 수치는 2차 평가 `../run-g82-llm-shape-eval2/README.md`에 있다. 아래 표의 "지금 코드"는 1차 평가 당시의 코드를 말한다.
- **정정(CP19-3, 2026-11-28).** 위 표는 '넓음'(P03·P19 '돌덩이'→stone)을 채움에 넣은 수치다. 넓은 말(상위어)을 채움에서 빼는 채점으로 고치면 마지막 판은 **12/19(63.2%)로 기준 미달**이다. 이 1차 결과로는 기준을 넘었다고 말할 수 없다. 2차 평가(`docs/validation/run-g82-llm-shape-eval2/`)는 문장마다 허용 번역 목록을 실행 전에 고정하고, 목록 밖의 넓은 말은 채움에 넣지 않는다.
- 통과 기준(`docs/decisions.md` G82 1차, 결과를 보기 전에 고정): 형태 없음·부정·과거·타인·가정·금지 범주·걱정 이야기 속 사물의 오통과 0건, 사전 밖 형태에서 뜻이 맞는 채움 70% 이상. 회차마다 따로 셌다. 마지막 판은 두 회차 모두 기준을 넘었다.
- 문장과 기대값은 첫 실행 전에 적었고, 결과를 본 뒤 바꾸지 않았다. 판을 고친 것은 프롬프트 한 번(0.1.0 → 0.1.1)과 검증기 두 번(0.1.0 → 0.2.0 → 0.3.0)이다. 판마다 결과 파일을 남겼다.
- **주의 1. 같은 45문장으로 판을 고쳤다.** 0.1.1의 73.7%는 그 문장에 맞춰졌을 수 있다. 처음 판(0.1.0 / 0.1.0)은 31.6%였다. 2차 평가(갈래마다 100건 이상)는 새 문장으로 해야 한다.
- **주의 2. 막아야 할 문장의 다수에서 LLM은 후보를 냈고, 검증기가 막았다.** 마지막 판에서 F 8개 중 6개, B 7개 중 4개, W 4개 중 1개에서 후보가 나왔다. 오통과 0건은 LLM이 지시를 지켜서가 아니라 대부분 규칙 검증기 덕분이다. B02 '다람쥐'(squirrel)는 G82에서 더한 영어 보충 금지 목록에만 걸렸다. 한국어 쪽(G77 목록)에는 '다람쥐'·'참새'가 없다.
- **주의 3. 채택 14개 가운데 8개는 위치 고치기(`repair_span`, 검증기 0.2.0)를 거쳤다.** 모델은 인용 글자는 맞게 내지만 charSpan을 한두 글자 틀리게 센다. 고치기를 하지 않는 G77식 엄격 판정이면 채움은 6/19다. 인용 글자가 텍스트에 두 번 이상 나오면 고치지 않는다.
- **주의 4. 걱정 이야기 속 사물은 검증기가 보지 못한다.** W03 '책상'은 "책상 앞에"라는 장소 자리라서 막혔다. 가짜 LLM으로 '보고서'→report, '휴대폰'→phone, '통장'→bankbook을 넣어 보면 모두 통과한다. 실제 모델은 이번에 이 셋에 null을 냈지만 이를 보장하는 규칙은 없다. 마지막 거름은 그림 고르기(G75)와 [이 중에는 없어요]다.

## 무엇을 어떻게 돌렸나

- `run_g82.py`: `Runtime`(experiment 설정에 다음만 바꿈. 가드 모델 끔, 미리보기 끔, G77 `llm_fill` 끔, 조건 고정 끔, 기록을 파일에 쓰지 않음, 이 프로세스 안에서만 `[gen3d] on_none_llm_shape = true`)에 static 세션을 만든다. `simulate.drive`로 확정 텍스트를 합성 문장으로 넣는다. 그다음 세션이 만든 매퍼 v2 spec과 확정 텍스트로 `llm_shape.run`을 부른다. 문장마다 2회 부르고, 회차마다 세션 캐시를 비운다. 서버를 새로 띄우지 않았고 모델을 내리지 않았다(8000번 서버가 같은 모델을 씀).
- `summarize.py`: 결과 파일에 문장별 뜻 판정(`runs[].meaning`)과 갈래별 수치(`metrics`)를 적고, 아래 표를 만든다.
- 다시 돌리기(저장소 `chatbot` 폴더에서): `.venv\Scripts\python ..\docs\validation\run-g82-llm-shape-offline\run_g82.py [--prompt llm_shape.v0.1.0.json --out <파일>]`. 이어서 이 폴더에서 `python summarize.py results.json`을 돌린다.
- 모델: `gemma4:e4b` `sha256:dc35e8d9c6061baa6f0fa870975ab6932e2542b579b13ea0f199fa4bb7300c9c`(Q4_K_M, Ollama 0.40.17). 온도 0, seed 0, `numPredict` 200, think 끔, 시간 한도 20초. 실행할 때 Ollama에 올라와 있던 모델은 `gemma4:e4b` 하나였다(가드 모델 없음). GPU는 RTX 5080 16 GB.
- 매퍼 `scene-spec-builder-v2/2.9.0`, 규칙 그림 프롬프트 `gen3d-shape-prompt/0.3.0+mapper-v2`.

### 뜻 판정

- 문장마다 "영어 이름이 인용된 한국어 형태와 뜻이 맞는가"를 직접 판정했다. 미리 정한 이름(`run_g82.py` `CASES`의 `enOk`, 결과를 보기 전에 적음)에 있으면 '맞음'이다. 그 밖의 이름은 결과를 본 뒤 판정하고 근거 한 마디를 적었다(표의 '사후', `summarize.py` `POST_HOC`).
- '넓음'은 뜻은 맞지만 덜 구체적인 경우다('돌덩이'→stone, '자갈'→pebble). 맞음으로 셌다.
- 채움률에는 채택되었고 뜻이 맞는 것만 넣었다. 이번에는 채택된 14개가 모두 미리 정한 이름이었다.

## 반복 일치

- 온도 0, seed 0으로도 원시 출력 글자가 회차마다 다른 문장이 있었다. 마지막 판에서는 2/45였다. P08은 charSpan을 [9, 12]와 [9, 13]으로 냈고, F03은 공백 하나가 달랐다. 두 경우 모두 판정(상태·채택값)은 같았다.
- 0.1.0 판에서는 P19가 1회 null, 2회 후보로 판정까지 갈렸다(44/45).
- 그래서 "같은 텍스트 → 같은 결과"는 G77처럼 세션 안 캐시와 기록으로만 보장한다. 이번 실행에서는 다른 모델을 함께 올리지 않았다. 가드 모델을 함께 올린 상태는 재지 않았다.

## 설계 확인이 필요한 것

1. **매퍼가 쓴 구간 규칙(`span_covered`)이 형태 낱말을 막는다.** 지시대로 G77과 같게 두었다. 매퍼 v2가 '유리구슬 같'·'벽돌 같'·'눈덩이 같'을 `form.type = blob`의 근거로 쓰면 그 구간을 인용한 형태 이름이 기각된다(P04·P08·P16). 형태 종류에 쓴 구간이면 오히려 형태 낱말이라는 근거다. `form.*`에 쓴 구간만 G82에서 열면 P08·P16이 채워진다(추정. 그 판으로는 돌리지 않았다). F04·F05에서도 `span_covered`가 함께 걸렸지만, 문장 틀 사유가 따로 있어 막힘은 그대로일 것이다.
2. **금지 범주는 목록에 기대는 정도가 크다.** 한국어 쪽은 G77·규칙 목록을 그대로 썼고 '참새'·'다람쥐'가 없다. 영어 쪽 보충 목록(동물·사람 70여 개)이 B02를 막았지만, 목록 밖 동물(가짜 LLM 시험의 finch)은 통과한다. 그림·메시의 CLIP 관문이 뒤에 있다.
3. **걱정 이야기 속 사물은 막는 규칙이 없다**(결론의 주의 4). D15 설계안의 "떠올린 일 줄 인용 기각"은 넣지 않았다(메인 판정: 입력은 확정 텍스트만, 단계 표지 없음).
4. **규칙 꾸밈말 + LLM 명사**(P12·P13·P17, `ruleRoute.reason = modifier_only`): 규칙이 꾸밈말만 잡은 경우에도 중심 명사 자리를 LLM으로 메운다(D15 5절). "규칙이 형태를 잡았으면 부르지 않음"을 "규칙이 중심 형태 명사를 잡았으면"으로 읽은 것이다.

## 한계

- 문장은 손으로 쓴 45개다. 한 사람이 썼고, 갈래마다 4–19개뿐이다. 0/25의 95% 상한은 약 11%다. 2차 평가(갈래마다 100건 이상, 새 문장)가 필요하다.
- 같은 문장으로 판을 고쳤다(결론의 주의 1).
- 뜻 판정은 점검자 한 사람의 판정이다. 미리 정한 이름 목록도 같은 사람이 썼다.
- 면담 전체를 돌리지 않았다. 확정 텍스트를 [고칠게요]로 바로 넣었고, 가드 모델은 껐다. 실제 세션에서는 가드 '확인' 판정(G81 문제 4) 때문에 이 경로를 잃는 세션이 더 있을 수 있다.
- 그림·메시 생성, 그림 관문, 참여자 화면은 이 평가의 대상이 아니다.
