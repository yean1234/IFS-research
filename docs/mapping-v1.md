# 개선 매핑 v1 — 실패 유형 대응과 dev 수치

작업 3 후반 기록입니다. `docs/mapping-failures.md`(v0 실패 45건·14유형)를 기준으로 화이트박스 개선 매핑(v1)을 만들었습니다. 규칙과 형식은 `docs/scene-spec-mapping.md` 6절에 있고, 이 문서는 "어느 실패를 어느 규칙으로 고쳤나"와 dev 수치를 적습니다.

- 코드: `chatbot/ifs_chatbot/scene_builder_v1.py`(+ `jamo.py`, `clarify.py`), 사전: `shared/lexicon/layer1_lexicon.v1.json`(오버레이 174항목), `shared/lexicon/scene_params.v1.json`, 형식: `shared/schemas/scene-spec.v2.1.json`
- LLM·임베딩·네트워크·난수·시각을 쓰지 않습니다(AGENTS.md 1, `docs/decisions.md` D03). 같은 확정 텍스트는 같은 파일 바이트가 됩니다.
- v0(`scene_builder.py`)와 v0 사전 파일 3개는 한 바이트도 바꾸지 않았습니다. v0 출력 바이트가 개선 전 커밋(d4e3e3a)의 v0 출력과 같은지 EX01·EX02와 dev 30개 확정 텍스트로 확인합니다(`tests/fixtures/scene_spec/v0_output_sha256.json`).
- held-out 코퍼스(`heldout.json`)는 열지도 실행하지도 않았습니다.

## 1. 실행 방법

```powershell
cd chatbot
.venv\Scripts\python.exe -m ifs_chatbot.eval.fidelity --corpus tests\fixtures\imagery_corpus\dev.json --mapper v1 --out <결과 폴더>
.venv\Scripts\python.exe -m ifs_chatbot.eval.fidelity --corpus tests\fixtures\imagery_corpus\dev.json --mapper v0 --compare v1 --out <결과 폴더>   # 쌍 비교
.venv\Scripts\python.exe -m pytest -q tests\test_scene_builder_v1.py
```

`--mapper v1`은 `--mapper ifs_chatbot.scene_builder_v1:factory`와 같습니다. 코퍼스 재생에서는 설정의 `[mapping] mode`와 상관없이 `--mapper`가 매핑을 정합니다.

## 4. 남은 실패와 위험

### 4.1 dev에 남은 것

- **컨트롤러 탈락 13건.** 프로브 생략(범주 낱말 하나로 그 차원을 묻지 않음) 12건, 짧은 '모르겠어요' 답 제외 1건. 매핑으로는 되찾지 못합니다. 프로토콜(`shared/protocol/`) 변경이라 IRB 문구 규칙(AGENTS.md 7)과 팀 결정이 필요합니다.
- 확인 질문 루프를 켜도 탈락분은 돌아오지 않습니다(루프는 확정 텍스트에 있는 말만 다시 묻습니다).

### 4.2 dev 과적합 위험 — held-out에서 떨어질 수 있는 곳

규칙을 dev 실패를 보며 만들었으므로 dev 0.937 / 0.000은 낙관적입니다. 저자가 직접 쓴 새 합성 문장 약 100개(색·크기·높이·부정·정정·오탈자·배경 등 규칙별 변형)로 거짓 양성을 찾아 고쳤지만(예: '자주'(often)가 색 '자주색'으로 읽힘, '새하얀'이 분홍이 됨, '윤기가 흘러요'가 움직임이 됨, '초록빛이 돌아요'가 회전이 됨), 이 문장도 규칙 작성자가 쓴 것이라 일반화의 증거가 아닙니다. 알려진 약한 곳:

| 위험 | 내용 | 결과 방향 |
| --- | --- | --- |
| 배경 명사표 | 표에 없는 배경 사물('선반 위 인형'의 인형이 형상인지 배경인지)은 못 가린다. 위치 명사 앞 자리 표지 규칙이 일부를 덮는다 | 배경 오염·왜곡 |
| 회상 문장 판정 | '-던' + 떠오르다 / 상황 명사 / '장면'에 기댄다. 프로토콜 첫 질문의 답 형태에 맞춘 규칙이다 | 형상 문장을 회상으로 오판하면 손실(값 대신 `_context`) |
| 모름 처리 | 모른다고 한 차원은 다른 곳의 언급도 값으로 쓰지 않는다 | 뒤에서 분명히 말한 값을 버릴 수 있음(손실) |
| '-다가' 앞 상태 | '~하다가 ~해요'에서 뒤를 지금 상태로 본다 | 반복 동작('부풀었다 줄었다')은 정해지지 않음 |
| 참조 사물 크기표 | 표에 없는 사물('강아지만 해요')은 값 없이 보존. 크기 규약(6.8)은 가정 | 손실(왜곡은 아님) |
| 색 표면형 | 어절 첫머리 일치. 표 밖 활용형('노래졌어요' 외)은 놓침. 동음어('노래' 노래)는 일부러 뺐다 | 손실 |
| 퍼지 매칭 | 자모 거리 1. 짧은 말은 쓰지 않음. 동률이 다른 범주면 쓰지 않음 | 드물게 엉뚱한 값(확인 필요 표시) |
| 부분 규칙 | 주제 조사 위치로만 부분을 정한다. '끝이 뾰족하고 빨개요'처럼 절이 나뉘면 전체 값이 된다 | 왜곡 가능 |

### 4.3 기준선과 다른 점(비교 설계에서 알아 둘 것)

- v1은 신체 부위어에서 높이를 값으로 만들지 않습니다(v0는 만듦). 두 매핑을 같은 텍스트로 렌더하면 신체 부위만 말한 시행에서 높이가 다릅니다(v1은 Unity 기본 높이). `_inferred`에 제안이 있으니 Unity `useInferredSuggestions`로 켤 수 있습니다. **팀 결정**.
- v1 크기 규약(6.8)은 v0 크기 형용사 값(0.5 + log2(scale)/4)과 같은 척도 위에 있지만, 말한 물리 크기를 압축해 옮긴 값입니다.
