# D14 독립 설계안 (Claude 하위 에이전트) — 색상환에서 색 고르기

요청(연구 책임자, 2026-11-28): 참여자가 색상환 팔레트에서 색을 고를 수 있게.

## 확인한 사실
1. 지금 색은 이름 없는 견본 17개(무채색 5개, 유채색 12개: h=k/12, s 0.6, l 0.5) 가운데 하나를 누른다(`shared/lexicon/candidate_values.v3.json`). 값 표 근거에 "색상환이 아니라 정해진 견본 + 무채색"이라고 적혀 있다. 서버는 견본 id만 받는다. 스펙·선택 파일·Unity는 HSL 0–1 수치로 흐르고, Unity는 견본 id를 읽지 않는다.
   - 빈틈: 말한 색(예: 파랑 215°)은 어느 견본과도 맞지 않아 화면에 고른 표시가 없고, 다른 견본을 누르면 말한 색으로 돌아올 수 없다.
2. 출처 우선순위는 edited > llm_quoted > chosen > said > default. 색 항목은 처음 값과 마지막 값이 다르면 `material.color`와 `material.saturation`을 edited로 적는다.
3. 밝기는 따로 있는 단계 항목이고 색의 l과 지각상 겹친다.
4. 뼈대에는 색 고르기 방식 언급이 없다. 어긋나는 결정은 G22(값은 정해진 단계 안에서만, 자유 입력은 버린 대안). G17·G31과는 맞는다.

## 권하는 안
- 넣을 곳: 웹 조절 화면의 색 줄(헤드셋 안이 아님).
- 꼴: 색상 고리 하나(72칸, 5°) + 기존 무채색 견본 5개. 고리는 h만 정한다. s·l은 규칙: 말한 색이 유채색(s≥0.10)이면 말한 s·l, 아니면 s 0.6·l 0.5. 6k번째 칸은 기존 견본 h00–h11과 같다.
- 처음 상태: 말한 유채색이면 손잡이를 말한 h 자리에 두고 그 자리 눈금을 남긴다(서버가 말한 값을 허용 목록에 더함). 말한 무채색이면 손잡이 없음. 말하지 않았으면 손잡이 없음, 회색 견본은 속 빈 테두리(`colorSource`). llm_quoted면 그 칸과 기존 안내.
- 조작·기록: 손을 놓거나 키를 누를 때만 `adjust` 한 번. 입력 `{"hueStep":k}` 또는 견본 id. 조절 기록 색 값에 선택 속성 `hueStep`. 값 표 v4.0.0(`kind:"hue_ring"`). 선택 파일 형식은 0.5 그대로(하위 호환으로만 더함) → 헤드셋 빌드를 다시 만들 필요 없음.
- 구현: CSS `conic-gradient`, pointer events, 외부 라이브러리 없음. `role="slider"`, ←/→ 1칸, Shift 6칸, Home 처음 값, `aria-valuetext` "색 k / 72"(색 이름 없음), 손잡이 44px 이상.
- 문구: `adjust_color_ring_hint` "고리를 누르거나 끌어서 색을 바꿀 수 있어요."(draft), protocol 0.11.0.
- 분석: 요약용 규칙(s<0.10이면 무채색, 아니면 가장 가까운 k/12 칸)을 분석 스크립트에만 둔다.
- 미룰 것: 채도 축, l 축, 사전 측정용 색상환.

## 버린 대안
- 연속 원판(h+s)·HSV 삼각형: 채도·밝기 슬롯과 겹치고, 값 검증을 정해진 단계로 묶을 수 없다(G22).
- 견본 12개 유지: 요청을 채우지 못한다.
- 헤드셋 안: 두 집단 모두 손 조작이 늘고 빌드를 다시 해야 한다.

## 위험
G22를 바꾸는 일이라 연구 책임자 결정이 필요하다. 5° 차이가 헤드셋에서 보이는지, CSS hsl과 Unity 렌더 색의 차이, 미리보기 지연은 확인하지 않았다.
