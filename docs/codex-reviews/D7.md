# D7 — Codex 응답 (2026-11-26)

## A. 멈춤 거리 과제

### 1. 현재 구현

- 정면 경로에서 한 번 움직이는 **왕복이 아닌 단방향 접근·후퇴 시행**을 한다. 접근은 3.0m에서 시작해 0.2m까지, 후퇴는 0.5m에서 시작해 4.0m까지 간다.
- 속도는 설정값 `stopSpeedMps=0.25m/s`; 참여자가 트리거를 누르면 그 프레임의 거리에서 멈추고 시행이 끝난다.
- 방향은 참여자 번호에 따라 정한 뒤 교차 배치하며, 방향별 본 시행은 4회, 연습 시행은 총 2회다.
- `stopdistance.csv` 열은 `trial,practice,direction,start_distance_m,speed_mps,stop_distance_m,rt_ms,timed_out`이다. 제한 거리에 도달할 때까지 누르지 않으면 timed out으로 기록한다.
- 분석기는 접근·후퇴의 유효 거리 평균을 따로 계산한다. 매 프레임 머리·물체 자세도 다른 기록 파일에 남는다.

### 2. 새 설계안

경로는 기존 직선 정면 접근·후퇴를 유지하되 **반복 왕복**으로 바꾼다. 거리 범위는 0.3–3.5m를 제안한다. 경계에서 잠시 멈춘 뒤 방향을 바꾸고, 속도는 일정한 0.20m/s로 한다. 경계에서 반전하는 순간 급격한 움직임이 느껴지지 않도록 짧은 완화 구간을 둔다. 시작 위치는 범위 안에서 고르게 무작위화하고 첫 방향도 무작위화하되, 참여자 번호와 난수 seed를 기록해 재현 가능하게 한다. 한 시행에서 최소 한 번 멈춤을 받아도 예정된 총 시간이 끝날 때까지 계속 움직이면 반복 조정이 가능하다.

버튼은 **누르는 동안 정지, 놓으면 재개**로 구분한다. 매번 누른 순간에 거리·방향을 표본화하고, 놓는 순간부터 움직임을 다시 시작한다. 별도 확정 입력(예: 길게 누르기)을 제공해 최종 선택을 고정한다. 확정 전 입력은 전부 조정 이력으로 남긴다. 화면 안내 문구와 입력 방식은 참여자 이해도·IRB 문구 검토가 필요하다.

본 시행 시간 상한은 45초를 권한다. 확정 입력 없이 상한에 도달하면 마지막 멈춤 값을 확정값으로 간주하되 `ended_by=timeout`으로 구분한다. 한 번도 멈추지 않은 경우 거리를 만들어내지 않고 결측으로 둔다(`stop_distance_m` 공란, `no_stop=true`). 경계 통과 자체는 성공 반응으로 치지 않는다.

### 3. 기록과 주 결과

새로운 `stopdistance` 형식 버전에서 시행별로 시작 방향·시작 거리·속도·시간 상한, 멈춤 횟수, 각 멈춤의 거리·방향·시각, 경계 통과 횟수, 최종 확정 거리, 종료 사유를 기록한다. 각 멈춤은 별도 `stop_events` 행으로 기록하는 편이 CSV 한 행 안에 가변 길이 이력을 넣는 것보다 분석·검증하기 쉽다.

주 결과는 **최종 확정 거리**이며, 멈춤 횟수·초기 멈춤·조정 폭은 보조 지표로 둔다. 최종값은 원하는 거리에 맞춘다는 과제 지시와 가장 직접적으로 대응한다. 접근/후퇴 차이는 반응시간 편향을 포함할 수 있으므로 방향별 최종값과 방향 효과를 함께 보고한다. 접근·후퇴를 합친 평균 하나만 주 결과로 삼지 않는다. 별도로 정지 직전 속도와 반응시간을 기록해 운동 방향에 따른 지연을 확인한다. 왕복 설계만으로 반응시간 편향을 제거할 수는 없다.

### 4. 직접 배치와 G59-11

직접 배치 직후에 정해진 시작점에서 물체가 반복 왕복하므로, 가장 최근에 놓은 위치에 물체가 고정되어 있던 현재 설계보다 **단순한 시각적 잔상·기준점 끌림은 줄어들 가능성**이 있다. 하지만 방금 놓은 거리가 기억·주의에 남는 효과까지 제거하지는 않는다. 두 과제의 순서는 현재의 `checkBeforeStopDistance` 설정 및 본 실험 순서와 함께 고정하고, stop-distance 값은 직접 배치와 별개 결과로 보고한다. G59-11의 민감도 분석에서도 제외 여부를 사후 선택하지 않도록 사전 규칙을 유지한다.

### 5. 호환성과 문구 버전

새 동작은 `stopDistanceLoopEnabled=false` 같은 **기본 꺼짐 설정**으로 격리한다. 기존 값에서는 입력 처리, 기존 시행 수·기록 행·JSON 키 순서를 건드리지 않아 기존 기록 바이트 golden을 보존한다. 새 설정이 켜진 기록은 기존 `stopdistance.csv`와 다른 파일명 또는 명시적인 새 기록 형식 버전으로 분리해야 분석기가 옛 행을 새 스키마로 오해하지 않는다. 러너 설정·manifest·분석기도 설정이 켜진 경우에만 새 필드를 기록한다. 참여자 문구는 기존 문구 파일을 덮어쓰지 말고 새 버전 파일에 추가하며, 문구 상태 `draft`와 출처를 함께 적는다.

### 6. 참고 연구 이름

- stop-distance / interpersonal distance 측정 패러다임
- Method of Adjustment, Method of Limits
- staircase procedure

구체 서지·왕복 반복 조정의 대인 거리 적용 근거는 **확인 필요**.

## B. 눈높이 정규화

### 1. 현재 처리

XR 리그는 가능한 경우 Floor tracking origin을 요청하고, 머리 위치와 회전을 `HeadPoseProvider`에서 받아 기록한다. 리센터는 수평 위치와 방향만 조정하며 높이는 건드리지 않는다. 물체 시작 위치는 `startDistanceM`, `startHeightM`로 설정되고 멈춤 거리 물체는 `stopHeightM=1.2m`에 놓인다. 배치 공간의 바닥 표시는 바닥 y=0을 기준으로 한다. 코드는 앉기·서기를 강제하지 않는다. 따라서 현재 설정은 **참여자가 앉았는지 서 있었는지 기록·통제하지 않으며**, 체크리스트는 실제 눈높이와 `headpose.csv`의 `head_y`가 ±5cm 이내인지 확인하도록 되어 있다.

### 2. 방식 비교

| 방식 | 지각·안전 | 구현 비용 | 자료 비교 |
|---|---|---:|---|
| (a) 카메라 높이 고정 | 시야 높이는 통일되지만 Floor 기준 좌표와 실제 바닥의 불일치가 커질 수 있다. 실제 바닥 표시가 떠 있거나 관통해 보이고 멀미·방향감 저하 위험이 있다. | 중간 | 눈높이는 맞아도 실공간 대응이 달라짐 |
| (b) 세계는 유지하고 대상·경로를 눈높이 기준 배치 | 바닥은 실제 바닥과 일치한다. 시선 기준 자극은 통일할 수 있지만 바닥 표식과 물체의 높이 관계가 참여자별로 달라질 수 있다. | 중간 | 자극의 시선 상대 위치 비교에 유리 |
| (c) 기록·분석만 정규화 | 장면과 바닥 정합성은 유지한다. 지각 차이는 남지만 오프라인 비교 기준을 만들 수 있다. | 낮음 | 원자료 보존 시 여러 기준으로 재분석 가능 |
| (d) 조합 | (b)+(c)를 기본으로 하고, 카메라 위치는 건드리지 않는다. 바닥 좌표를 보존하면서 자극과 분석 기준을 눈높이에 맞춘다. | 중간 | 원좌표와 정규화 좌표를 함께 두면 가장 유연 |

### 3. 권고안

(d)를 권한다. **실험실에 앉은 자세 기준 눈높이 1.20m**를 기준으로 제안한다. 다만 실제 자세 분포와 헤드셋 추적값을 파일럿에서 확인해 확정해야 한다. 세션 시작 때 Floor origin 상태와 안정된 머리 위치를 확인하고, 참여자가 정해진 자세로 편안히 앉아 정면을 보는 시점에 3초간 머리 높이를 표집해 중앙값을 사용한다. 이 단계는 높이를 기록하는 보정이며 카메라를 위아래로 옮기지 않는다. 물체·경로의 수직 위치에는 `eyeHeightM - 1.20m` 오프셋을 적용하되 바닥 표시 y=0과 수평 거리는 유지한다. 보정값이 없거나 추적 origin이 Floor가 아니면 높이 보정 조건은 실행하지 않고 미보정 세션으로 표시한다. 임의 기본값으로 대체하지 않는다.

기록 열은 `head_height_raw_m`, `eye_height_calibrated_m`, `height_offset_m`, `tracking_origin`, `posture`(앉음/섬/미기록), `calibration_valid`로 제안한다. 분석기에는 원래 좌표와 정규화 좌표를 모두 내고, RQ2·RQ3의 주 분석이 어느 좌표를 쓰는지 사전 고정한다.

### 4. 테스트·golden 호환

높이 오프셋이 기본값에서 0이면 현재 장면·기록이 그대로 나오도록 `eyeHeightNormalizationEnabled=false`를 기본값으로 둔다. 켠 경우에만 manifest 설정과 정규화 열을 추가한다. 기존 배치 화면·물체 좌표 golden, `headpose.csv` 바이트 대조, stop-distance 기록 golden을 변경하지 않고, 새 설정 on/off 및 비-Floor 실패를 별도 테스트한다. 기록 버전은 기존 행의 의미를 바꾸지 않는 추가 열을 허용하는지 계약을 확인하고, 의미가 달라지는 정규화 데이터는 새 버전 또는 별도 파일로 분리한다.

## C. 구현 순서

1. `PlacementConfig.cs`: loop 설정과 눈높이 보정 설정·유효성 검사 추가. 두 기능 기본값은 꺼짐.
2. `PlacementSession.cs`, `StopDistanceSchedule.cs`: 반복 운동·시행 상한·확정·이력 상태를 추가하되 기존 분기 동작은 유지.
3. `PlacementRecordWriter.cs`: 새 설정에서만 새 stop event 기록과 보정 메타데이터 기록.
4. `PlacementExperimenterGui.cs`, `PlacementXrRig.cs`, `PlacementSpace.cs`: 실험자 설정, Floor-origin 상태 확인, 기준 높이 상대 배치 연결.
5. `placement_task*.json`: 새 버전 문구 키 추가. 고정 문구 변경은 `status`와 출처를 기록하고 프로토콜 버전을 올린다.
6. `chatbot/ifs_chatbot/eval/placement.py`: 기존 기록과 새 스키마를 분기 파싱하고 최종 거리·방향별 통계·멈춤 이력을 출력한다.
7. 테스트: `PlacementTests.cs`, `PlacementRunnerTests.cs`, XR rig 테스트, 분석기 합성 기록 테스트를 추가한다. 기존 golden은 그대로 두고 설정 on/off, 무멈춤, timeout, 반복 멈춤/재개, 바닥 추적 실패를 새 fixture로 검증한다.

주요 위험은 반복 입력이 참여자에게 복잡해지는 점, 확정 입력과 timeout 규칙이 측정 개념을 바꿀 수 있는 점, Floor tracking 실패 및 자세 차이로 인한 표본 손실, 눈높이 기준 배치가 바닥 지각을 왜곡할 가능성이다. 파일럿에서는 입력 이해도·편안함·정규화 적용 여부를 먼저 확인해야 한다.
