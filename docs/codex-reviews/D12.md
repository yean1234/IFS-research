## 설계안

### 1. 흐름

- **위치:** 후보 선택 화면에서 참여자가 `[맞는 게 없어요]`를 누른 뒤, 현재처럼 바로 기준 후보 0번으로 확정하지 않고 생성 설명 화면으로 이동한다. 설명 입력은 물체 생성용으로만 쓰고, 면담 응답이나 `IFSSceneSpec` 추출에는 다시 넣지 않는다.
- **고지·질문 문구 초안** (`status: draft`, 출처: D12 설계안, 2026-11-28, IRB 검토 전):

  > 다음에 적으시는 말은 물체 메시를 만드는 데 사용됩니다. 모양을 설명해 주세요. 적지 않거나 [건너뛰기]를 눌러도 괜찮습니다.

  입력 예시·선택지는 제시하지 않는다. 참여자가 입력하지 않거나 건너뛰면 기존 후보 화면으로 돌아간다.
- **횟수·후보:** 다시 말하기는 한 번, 생성 후보는 최대 한 개로 제한한다. 재시도 반복은 다른 표현을 유도하고 대기 부담을 늘릴 수 있다. 기존 절차 후보는 계속 제시한다.
- **대기·실패:** 생성 중에는 “물체 후보를 준비하고 있어요” 같은 고정 문구와 건너뛰기 동작을 둔다. 목표 PC에서도 약 27–30초가 걸리므로, 오래 걸리거나 실패하면 기존 후보 화면으로 돌아간다. 위기 판정이면 생성 없이 고정 위기 문구로 전환하고 세션을 멈춘다.
- **결과 경로:** 생성 후보를 포함한 후보 화면에서 고른 경우에만 장면에 쓴다. 생성 실패·차단·불일치로 후보가 없거나 다시 맞지 않으면 현재의 절차 후보로 진행한다. 끝내 맞는 것이 없어도 기준 후보 0번으로 기존 방식대로 진행하며, 선택 기록에 `none`을 남긴다.
- **두 집단:** 두 집단 모두 같은 화면, 고지, 입력 기회, 후보 생성 절차를 거친다. 달라지는 것은 이후 배치 구간뿐이어야 한다.

### 2. 입력 거르기

생성 프롬프트는 다시 말한 글 전체가 아니라, **규칙으로 확인된 형태 표현만** 조립한다. 원문 범위(charSpan)와 변환 결과를 모두 추적할 수 없으면 생성하지 않는다.

- 위기 판정은 생성보다 먼저 한다. 위기 문구 이후에는 생성 모델을 부르지 않는다.
- 감정어·감각어·비유만 있는 표현은 형태 프롬프트에 넣지 않는다. 형태 낱말과 함께 있어도 이 낱말들은 제외한다.
- 사람·얼굴·동물 범주가 검출되면 생성 요청을 차단한다. 출력 메시에서도 해당 형상을 관문으로 차단한다.
- 안개·불꽃처럼 메시로 표현하기 어려운 범주는 기존 G62-e처럼 차단한다. 구름·안개가 한 표현에 섞이면 임의로 구름만 골라 생성하지 말고 보수적으로 차단한다.
- 색·재질은 생성 프롬프트에서 제외한다. 이 설명으로 색·질감 슬롯도 바꾸지 않는다.
- 크기·위치는 프롬프트에서 제외하고 크기·위치 슬롯에도 반영하지 않는다. 메시 정규화와 사용자 조절 규칙만 적용한다.
- 차단됐다고 범주나 대체 표현을 알려 주면 답을 유도할 수 있다. 고정 문구는 “이 설명으로는 후보를 만들지 못했어요. 기존 후보를 보거나 건너뛸 수 있어요.” 정도로 두고, 구체적 차단 사유는 연구자 기록에만 남긴다.

### 3. 한국어→모델 입력

**제안: (a) 기존 고정 사전과 차단 규칙을 확장한다.** 번역 모델이나 한국어 문장 입력 모델은 쓰지 않는다. 다시 말한 낱말이 사전 밖이어도 곧바로 자유 번역하지 않고, 승인된 형태 낱말·형태 수식어 목록에 들어온 뒤에만 생성한다. 목록 밖 낱말은 후보 생성에 쓰지 않고 기존 후보로 돌아간다. 이 안은 사용자가 사전 밖 표현을 직접 말할 수는 있어도, 사전 밖 어휘를 모두 생성에 활용한다는 목표까지 달성하지 못한다. 그 목표를 유지하려면 번역 모델·새 어휘 규칙의 별도 검토와 평가가 필요하다.

원칙 1 예외 문구는 다음처럼 좁혀 제안한다.

> **추가 예외는 형태 메시 후보 생성에 한한다.** 참여자가 생성용으로 직접 입력한 글에서 사전·규칙이 승인한 형태 표현만 골라 고정 사전으로 변환하고, 로컬 형태 생성 모델에 전달할 수 있다. 입력 문장 전체를 LLM·번역 모델로 처리하지 않는다. 모델 리비전·가중치 digest·seed·생성 설정을 고정해 기록하며, 출력은 확인용 후보로만 저장한다. 이를 `IFSSceneSpec` 슬롯 값에 쓰지 않는다.

같은 입력 재현은 정규화·분석기·사전 버전, 생성 프롬프트, 모델 파일 digest, seed, 생성 설정을 고정하고 캐시 키에 포함한다. 동일 조건 재실행에서 출력 해시가 달라지는지는 PC에서 별도로 확인한다. 완전한 비트 단위 결정성을 보장하지 못하면 해당 자산을 세션 간 재사용하지 않고, 실제 생성 메시 해시를 기록한다.

### 4. 스펙과의 관계

다시 말한 글은 `IFSSceneSpec`의 어떤 슬롯도 바꾸지 않는다. 형태 슬롯도 예외가 아니다. 생성 결과는 기존처럼 `form-asset` 부속 자산이며, 선택 기록에서만 출처와 선택을 남긴다. 원칙 2와는 “참여자가 생성용으로 직접 말한 텍스트”라는 별도 출처를 둬 추론값과 혼합하지 않는 방식으로 맞춘다. 참여자가 입력했더라도 색·질감·크기·위치를 시스템이 추론해 채우지는 않는다.

### 5. 기록

- 입력·차단 사유·프롬프트 근거 범위·모델 출처·seed·자산 해시·제시 후보·선택·실패를 세션별 로컬 기록에 보존한다. 자유 기술 원문은 git에 넣지 않고, 암호화된 세션 저장소에서 접근을 제한한다. 분석용 내보내기에는 원문 대신 세션 식별자와 필요한 범주만 남긴다.
- 재생성 단계와 입력·대기·실패 결과를 표현하려면 selection 기록에 필드가 추가되므로 **새 스키마 판**을 낸다. 예: `selection.v0.4`; 선택 프로토콜도 고지 문구를 포함한 새 판으로 낸다. 모든 새 고정 문구는 `status: draft`와 출처를 기록하고, 정식 채택 시 프로토콜 버전을 올린다.
- G59-11의 분석 원칙은 유지한다. 참여자를 제외하지 않는다. 민감도 분석에 기존 “맞는 게 없어요” 집단을 그대로 두고, 추가로 재생성 입력·생성 후보 제시·생성 후보 선택 여부에 따른 결과를 구분해 보고한다. 이는 재생성 집단을 사후 제외하는 기준이 아니라 절차 차이를 살피는 민감도 분석이다.

### 6. 안개 사례

네 문장—「검은 안개가 있는 느낌」, 「구름 같은데 구름 보다는 덜 뺵빽하고 보이지 않는 안개같은?」, 「먹구름」, 「넓게 펼쳐진 안개가 떠오른다」—은 안개 범주 검출 시 모두 생성 차단으로 처리한다. 사용자가 다시 말한 설명에도 안개가 남아 있으면, 형태 표현이 추가로 있어도 메시 후보를 내지 않는다. 따라서 이 설계만으로는 뭉친 구름 메시 문제를 해결하지 못한다.

원하는 “넓게 퍼진 옅은 안개”에 가까운 표현은 안개 메시 생성이 아니라 **규칙 기반 파티클·볼륨 렌더링 경로(G74)**에서 풀어야 한다. 해당 경로는 메시 생성과 분리해 검토하고, 참여자가 직접 말한 넓이·농도 같은 속성만 반영해야 한다.

### 7. 위험과 시험

가장 큰 위험은 ① 사전 밖 표현이 여전히 생성되지 않아 기대를 충족하지 못하는 점, ② 재질·감정·대상을 형태로 잘못 추출하거나 사람·동물·비메시 범주를 통과시키는 점, ③ 긴 대기와 실패가 참여자의 불편·선택 편향을 만드는 점이다.

필요한 자동 시험은 입력 원문 근거 추적, 슬롯 비변경, 색·재질·크기·위치 제외, 위기 시 생성 호출 0회, 사람·얼굴·동물 및 안개·불꽃 차단, 후보 상한 1개, 실패·건너뛰기의 절차 후보 복귀, 집단 간 동일 흐름이다. 같은 입력의 프롬프트와 캐시 키가 고정되는지도 확인해야 한다.

이 PC에서는 실제 모델 파일 digest와 출력 해시, 재실행 결정성, 생성 시간·최대 VRAM, 대기 중 취소와 실패 복귀, 안개·사람·동물 관문을 실측해야 한다. 이 답변에서는 코드를 수정하거나 시험을 실행하지 않았다.

### 8. 본 실험 적용 여부

**2026-12-02 본 실험에는 적용하지 않는다.** 현재 생성 메시 기능이 본 실험 설정에서 꺼져 있다는 G67-b를 유지한다. 참여자 재진술을 추가하면 안내·대기·후보 경험이 바뀌고, G59-11 분석 및 선택 기록에도 새 변수가 생긴다. 모집 전 검토·문구 확정·기록 판 추가·보호 절차 검토와 PC 실측을 마칠 일정 여유가 없다. 우선 합성 데이터와 연구자 시험으로 검증한 뒤, 별도 연구 설계 변경으로 판단한다.
