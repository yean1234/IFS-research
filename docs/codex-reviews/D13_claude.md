# D13 설계안 (Claude) — 원칙 1: 세션 경로는 그대로, LLM은 사전 후보 제안 도구로만

읽은 것: `AGENTS.md`, `docs/design-backbone.md`(25·76행), `scene_builder_v2.py`(provenance·`_unmatched`·`_COVER_KEYS`), `scene-spec.v2.4.json`(provenance·`_unmatched`·`_unmapped`·`_inferred`·`_context`), `experiment.toml`, `layer1_lexicon.v0.json`(무겁 → weight). 선행 연구 세 편은 원문을 확인하지 못했다.

## 1. 판단: (a) 그대로 + 오프라인 사전 후보 제안("a′")

세션 안에서 LLM이 장면 값을 내는 길((b)·(c))은 열지 않는다. 연구자가 사전을 늘릴 때 로컬 LLM에 후보를 뽑게 하고, 사람이 검토해 사전 새 판에 넣은 것만 매퍼가 쓴다. 이유는 셋이다.
1. **과한 해석을 기계로 막는 검사가 곧 사전이다.** 「무거워요」→ 색 짙음을 막는 기계 검사는 "인용 낱말이 그 슬롯의 차원을 이름 붙이는가"뿐이고, 그 판정에는 차원어 목록(=사전)이 필요하다. 검증기를 통과한 LLM 값은 감사하기 더 어려운 사전 조회가 된다. 새 낱말의 뜻은 결국 사람이 정해야 하니, 그 판정을 세션 중이 아니라 사전 판을 만들 때 하는 편이 낫다.
2. **물체는 자극이다.** 두 집단이 같은 파이프라인을 쓰니 조건 혼입은 없다. 그러나 빈 칸을 LLM이 채우면 "참여자가 고른 값"이 "시스템이 낸 값을 받아들인 값"이 된다. 보여 준 값에 끌리는 효과는 확인 단계로도 다 지우지 못하고, 거리감을 "참여자가 만든 물체"로 해석할 근거가 약해진다(원칙 2).
3. **"같은 말이면 같은 물체"(뼈대 25행)를 사전은 어느 PC에서나 지키고, LLM은 캐시 안에서만 지킨다(4절).** IRB 없는 예비 연구에서 재현성·추적성은 심사에서 내세울 몇 안 되는 강점이다.

(b)를 다시 볼 조건: 6절 평가를 a′ 제안기로 통과하고도 held-out의 `_unmatched` 내용어가 사전 확장만으로 줄지 않을 때. 그때 연구 책임자 결정으로 올린다.

심사자 질문과 답:
- *왜 LLM 추출(선행 연구)이 아니라 사전인가?* → 그 연구들은 생성된 장면이 산출물이고, 여기서는 물체가 측정 자극이라 값의 출처가 측정 기록의 일부다. 세 편은 원문을 확인한 뒤에만 인용하고, 근거 태그·검증 방식은 확인 전에 적지 않는다.
- *사전이 못 읽은 말은?* → 세션별 `_unmatched` 비율과 그 슬롯을 참여자가 조절했다는 사실, 사전 판마다 held-out 덮음률을 보고한다.
- *LLM 편향이 사전에 들어가지 않았나?* → 항목마다 `src`·검토자·날짜를 남기고, 받아들인 비율과 버린 사유를 부록에 싣는다.

## 2. 과한 해석을 막는 장치 (a′ 제안기에 쓰고, (b)를 열 때도 그대로)

**"말한 것"의 정의:** 인용 구간 안에 그 슬롯의 차원을 *직접 이름 붙이는* 낱말이 있을 때만 말한 것으로 본다. 허용 근거 유형은 셋이다.
- `attribute_word`(material.\*, form.roundness·aspect, layout.size, motion.\*): 「쑥색이에요」→ color. **금지:** 「무거워요」→ 밝기·크기, 「차가워요」→ 색.
- `shape_noun`(form.base): 형상 명사 자체(「항아리」). **금지:** 「답답해요」→ container.
- `measure_phrase`(layout.size·distance): 「주먹만 해요」.

감각 넘나들기(무게·온도·소리 → 시각 슬롯), 감정어, 연상·상징, 직유 원천의 속성 추정(「돌처럼」→ 회색)은 모두 금지한다. 직유는 매퍼 2층이 맡는다. 사전이 이미 `_unmapped`로 정리한 말(무겁 → weight, no_scene_param)은 "장면 값이 아니다"라는 사전 판정이므로 대상에서 뺀다.

- **기계로 되는 것:** 인용문이 charSpan 글자와 같다 / 어절 경계에 맞고 어절 3개 이하다(`max_anchor_eojeol`과 같게) / 구간이 `_unmatched` 안에만 있고 매퍼 `_provenance`·`_negated`·`_context`·`_uncertain`·`_unmapped`와 겹치지 않는다 / 슬롯·enum·근거 유형 조합이 허용 목록에 있다 / 인용 lemma가 사전에 emotion으로 있으면 거부한다 / 위기 판정 뒤 텍스트가 아니다.
- **기계로 안 되는 것(사람 판정):** 새 낱말이 정말 그 값인가(쑥색 → green인가 olive인가), 방언·강도 표현, 차원이 갈리는 낱말(「탁해요」: saturation인가 opacity인가), 기분인지 밝기인지(「어두워요」).

인용 최소 단위는 **어절 하나**다. 조사·어미까지 넣어야 부정·시제를 규칙으로 볼 수 있다. **한 인용은 한 슬롯만 채운다.** 한 낱말이 여러 슬롯을 채우는 것(「무거운」→ 짙음+큼+느림)이 연상의 전형적인 모양이기 때문이다. 같은 구간이 두 슬롯에 쓰이면 둘 다 버린다.

## 3. 출력 형식과 검증기

```json
{"items":[{"path":"material.color","value":"green","charSpan":[12,15],"quote":"쑥색이","lemma":"쑥색","evidenceType":"attribute_word"}]}
```
- 입력은 확정 텍스트와 `_unmatched` 목록이다. 매퍼가 채운 슬롯은 "채우지 말 것"으로 넘긴다. 자유 서술 칸(`reason` 등)은 두지 않는다.
- Ollama `format`에 JSON 스키마(path·value enum 포함)를 넘겨 형식을 강제한다(설치된 판에서 동작 확인 필요). 형식 강제는 뜻을 막지 못하니 2절 검증기를 반드시 그 뒤에 둔다.
- 실패한 항목은 **그 항목만 버리고 재시도하지 않는다.** 재시도 횟수가 결과를 바꾸면 재현이 깨진다. JSON이 깨지면 전체를 버리고 `invalid_output`으로 적는다. 버린 항목은 사유 코드(quote_mismatch, span_covered, slot_not_allowed, evidence_pair_not_allowed, multi_slot_quote, emotion_lemma, enum_violation)와 함께 남긴다.
- 우선순위: 참여자 조절 > 매퍼 > LLM. LLM은 null 슬롯과 `_unmatched` 구간만 다루므로 매퍼와 구조적으로 충돌하지 않는다. 그래도 충돌하면 `span_covered`로 버린다.
- a′에서는 통과 항목이 사전 후보 표(lemma, category, value, 예문, run id)가 되고, 사람이 받아들인 것만 사전 새 판에 들어간다.

## 4. 재현·기록

- 보장 범위: 사전 경로는 어느 PC에서나 같은 텍스트면 같은 스펙을 낸다. LLM은 같은 PC·Ollama 판·digest·온도 0·seed가 같아도 GPU 연산 때문에 같다고 가정할 수 없어 실측해야 하고, 다른 PC는 보장하지 않는다. (b)라면 재현은 캐시로만 보장한다. 키는 sha256(확정 텍스트)+모델 digest+프롬프트 해시+스키마 판+Ollama 판+옵션이다. a′는 받아들인 후보가 사전 판으로 굳으므로 이 문제가 없다.
- run마다 남길 것: digest, Ollama 판, 옵션, 프롬프트 해시, 입력 해시, 원 출력, 항목별 검사 결과, 검토 판정. 참여자 텍스트로 돌린 run은 `chatbot/logs/` 밖으로 내보내지 않는다(원칙 6).
- 스키마(a′): **스펙 스키마는 그대로다.** 사전 항목에 이미 있는 `src`에 `llm_proposal:<run id>`를 적고 `reviewedBy`·`reviewedAt`를 더한다. 스펙 provenance는 `explicit_lexicon` 그대로이고, 사전 판·해시로 추적한다.
- (b)라면: source enum에 `llm_extraction`을 더하고, 값은 `_inferred`처럼 null 슬롯 전용 필드 `_llmProposed`에 둔다. 참여자가 고른 경우에만 selection 기록에 넣고, meta에 `llm{modelDigest,promptHash,cacheKey}`를 둔다. 스펙 2.5.0이 되므로 러너·미리보기도 다시 빌드해야 한다.

## 5. 참여자 화면

a′에서는 **바뀌는 것이 없다.** 새 사전 판을 12-02 전에 넣지 않으면 `experiment.toml` 출력은 바이트 단위로 같다. 넣는다면 그것은 사전 변경 절차(결정 기록, 시나리오 비교)를 따른다.

(b)를 연다면:
- LLM 값으로 조절 막대를 미리 옮기지 않는다. 빈 슬롯은 지금처럼 기본값으로 둔다.
- 제안은 따로 한 줄로만 보이고, 참여자가 눌러야 적용된다. 값의 이름(「짙은 초록」)은 참여자가 쓰지 않은 묘사어이니 보이지 않고(원칙 3), 견본·미리보기로만 보인다.
- 문구 초안(status draft, `shared/protocol/` 판 올림): 「'{quote}'라고 하신 말로 만든 모양이에요. 써 볼까요?」 [써 볼게요] [그대로 둘게요]. 치료·진단 표현은 넣지 않는다(원칙 8).
- 분석 규칙(자료를 보기 전에 정함): 제안을 받아들인 사람을 빼고 다시 봐도 같은지 함께 보고한다.

## 6. 평가 설계

**자료:** 개발용 60문장(`chatbot/scenarios/`, `docs/validation/`)과 held-out 150문장. held-out은 프롬프트와 사전을 보지 않은 두 사람이 따로 쓰고, 프롬프트를 고치기 전에 봉인해 한 번만 연다. 사전 밖 색·질감어, 방언·오타, 감각 넘나들기(무겁·차갑·시끄럽), 감정어, 부정, 회상·타인, 직유, 위기 문장을 반드시 넣는다. 선택 사항으로 12-02 뒤 확정 텍스트를 로컬에서 재생해 참여자의 최종 조절 값과 견줄 수 있다. 동의 범위를 먼저 확인하고 묶음 통계만 낸다.

| 지표 | 재는 법 | 통과 기준 |
| --- | --- | --- |
| 근거 없는 값 | 검증기를 거친 뒤 인용 불일치·구간 겹침 | 0건(1건이면 검증기 결함) |
| 과한 해석 | 판정자 2명이 출처를 모른 채 따로 판정("이 낱말이 이 슬롯의 이 값을 직접 말하는가"). 매퍼 항목·미끼 항목을 섞고, 불일치는 3번째 판정자 | κ ≥ 0.70을 먼저 넘는다. ≤ 2%이고 95% 상한 ≤ 5%(항목 ≥ 150). 감각 넘나들기·감정어 묶음은 0건 |
| 매퍼 일치 | 매퍼가 채운 슬롯을 가리고 LLM에 물음 | ≥ 90% |
| 빈칸 채움률 | held-out `_unmatched` 내용어 가운데 받아들인 값의 비율 | 사전만 늘렸을 때보다 +15%p |
| 반복 일치 | 같은 PC 10회, 다른 PC 3회, 출력 바이트 비교 | 같은 PC 100%. 다른 PC는 보고만 하고 캐시를 필수로 둔다 |
| 위기·끔 | 위기 시나리오의 LLM 호출 수, 끈 상태의 전체 시나리오 스펙 비교 | 0회 / 100% 동일 |

**중단 기준(하나라도 걸리면 (b)를 접고 a′만 남긴다):** held-out에서 감각 넘나들기·감정어 항목이 1건이라도 통과 / κ < 0.60("말한 것"의 정의가 서지 않음) / 개발 세트에서 프롬프트를 3번 고쳐도 과한 해석이 5% 초과 / 채움률 이득이 +10%p 미만 / held-out을 본 뒤 프롬프트를 고침(그 held-out은 무효).

## 7. 바꿀 문서 문장 (a′ 초안)

- `AGENTS.md` 원칙 1의 하위 항목: "**사전 후보 제안은 예외가 아니다.** 연구자는 사전에 없는 낱말의 후보를 로컬 LLM으로 뽑을 수 있다. 사람이 검토해 사전 새 판에 넣은 뒤에만 매퍼가 쓰고, 항목에 `src: llm_proposal:<run id>`·검토자·날짜를 적는다. 참여자 세션 중에는 LLM이 장면 값을 내지 않는다."
- 원칙 2의 하위 항목: "사전 후보는 인용 낱말이 그 슬롯의 차원을 직접 이름 붙일 때만 받는다. 감각 넘나들기·감정어·연상·직유 원천 추정은 받지 않고, 한 낱말은 한 슬롯만 채운다."
- 뼈대 25행: "…물체는 사전과 규칙이 만든다(새 낱말 후보는 LLM이 제안할 수 있으나 사람이 검토해 사전 판으로 굳힌 것만 쓴다). 같은 말이면 같은 물체가 나온다(…)." 76행 "사전에 없는 낱말" 뒤에 "(사전 판마다 held-out 덮음률 보고)"를 붙인다. 뼈대 변경이므로 `docs/decisions.md`에 적고 연구 책임자에게 알린다.

## 8. 가장 약한 곳

1. **세션에서 처음 나온 낱말은 여전히 못 읽는다.** a′는 다음 사전 판부터 효과가 나서 12-02 참여자에게는 도움이 없고, 빈 칸은 계속 참여자 조절에 기댄다. 연구 책임자가 말한 "한계가 뚜렷하다"는 체감도 바로 줄지 않는다.
2. **"말한 것"의 경계가 사람 판정에 기댄다.** 「탁해요」·「어두워요」는 사전에서도 LLM에서도 같은 문제다. κ가 낮으면 2절 정의부터 다시 짜야 하고, 판정 규칙을 만드는 사람과 사전을 만드는 사람이 같아서 생기는 편향도 남는다.
3. **합성 자료의 대표성.** 사전을 아는 사람이 쓴 대사는 덮음률을 부풀린다. 사전을 모르는 사람이 쓴 held-out으로 줄여도 실제 어휘와는 다르다. 실제 텍스트로 재는 길(12-02 뒤 로컬 재생)은 동의 범위에 달려 있다.
