## 판정별 검토

1. **입력: 확정 텍스트만 — 동의.** 인용과 `charSpan`, 매퍼 제외 구간을 확정 텍스트 좌표에서 검증한다면, 발화 전체를 넣는 쪽은 참여자가 확인 때 고치거나 뺀 내용을 되살릴 수 있다. 다만 확정 텍스트가 실제 LLM 입력과 검증기에 쓰인 텍스트와 항상 같은지 기록으로 보장해야 한다. `chatbot/ifs_chatbot/llm_fill.py:473-485`

2. **영어 이름: 금지 목록과 관문만 — 조건부 반박.** 허용 목록이 “목록에 없으면 생성 불가”라는 별도 사전을 만들고 출처·유지 부담을 더한다는 우려는 타당하다. 하지만 금지 목록은 **영어 이름이 인용된 한국어 형태와 같은 뜻인지** 검증하지 않는다. 재현 예: 확정 텍스트 `덩어리`, 인용 구간 `덩어리`, LLM의 영어 이름 `cage`. 단어가 소문자 명사 하나이고 금지 목록에 없다면, 인용 일치와 문법 관문을 통과해도 뜻은 달라질 수 있다. 이 위험은 금지 목록만 늘려서는 닫히지 않는다. 독립된 한영 의미 검토를 평가 관문에 넣어야 한다. 반대로 허용 목록만으로도 새 범주나 잘못된 번역을 완전히 막지는 못하므로, 허용 목록을 채택하라는 뜻은 아니다. `tools/gen3d/prompts.py:492-514`는 제안서가 참고한 기존 관문이고, 의미 일치 검증은 별도 요구다.

3. **호출 시점: [맞는 게 없어요] 뒤 — 반박.** 이 버튼은 “현재 선택지에 맞는 것이 없다”는 뜻이지, 확인 텍스트를 LLM에 보내 새 해석을 받겠다는 동의까지 분명히 담지는 않는다. 특히 후보가 나온 뒤 거절 문구만 보여 주면 사용자는 이미 발화가 모델에 전달됐다는 사실을 알기 어렵다. 호출 전에 LLM 제안 기능과 근거 텍스트 전달을 명시하고 별도 선택을 받는 편이 낫다. 이는 면담 질문을 추가하는 것과 다른 UI 선택이며, 문구 변경은 IRB 대상이다. `AGENTS.md:15`

4. **G77-d 비활성화 — 조건부 동의.** **같은 실험 조건에서 형태 슬롯만** 끄는 것은 G77과 G82가 같은 칸을 경쟁적으로 채우는 일을 막는다. 다만 G77의 다른 빈 슬롯 제안까지 끄거나, G82가 실제 호출되지 않은 세션의 경로를 뭉뚱그리면 비교 조건이 달라진다. 형태 칸 비활성화 범위, 호출 여부, 후보 채택·거절 여부를 각각 기록해야 한다. G77의 형태 값이 기존 규칙 값보다 우선하지 않는 조건도 유지해야 한다. `AGENTS.md:8`

5. **자유 입력 칸 제외 — 동의.** 새 형태 입력을 추가하면 그 입력에도 인용·부정·과거·금지 범주 검증이 필요하고, 참여자가 쓰지 않은 표현을 유도할 가능성도 생긴다. 다만 `[그 말이 아니에요]`를 누른 뒤 다시 LLM을 부르지 않는다는 점과 거절 사실을 기록하는 방식을 명확히 해야 한다. `AGENTS.md:11`

6. **평가 통과 전 실험 플래그 비활성화 — 동의.** 방향은 타당하지만 “통과 기준을 넘기 전”만으로는 재현 가능한 결정이 아니다. 아래처럼 데이터와 기준을 사전에 정하고, 층별 결과도 함께 공개해야 한다.

   - **사전 밖 형태 채움률:** 규칙 경로가 형태를 못 찾았지만 참여자가 구체적인 형태를 명시한 합성 문장 **1,000건**을 고정 평가셋으로 둔다. 채움률은 `검증을 통과하고 의미가 맞는 LLM 후보 수 / 명시 형태가 있는 전체 평가 건수`로 계산하고, **80% 이상**을 잠정 목표로 제안한다. 의미 일치는 한국어·영어 검토자 판정을 기준으로 삼는다. 이 수치는 제안값이지 기존 결정에 합의된 기준은 아니다.
   - **부정·과거 등 차단 문장:** 부정, 과거, 타인, 가정, 비유를 각각 **300건씩** 만든다. 각 층에서 출력이 검증기를 통과한 오통과는 **0건**이어야 한다. 0/300이면 95% 상한이 대략 1%다. **149건에서 0건이어도 상한이 약 2%**라는 기준이 기존 검토안에 인용되어 있으므로, 더 엄격한 목표를 원한다면 층별 표본을 늘려야 한다. `docs/decisions.md:1155`
   - **금지 범주:** 사람·몸·동물·무기·안개·불꽃 등 각 범주 **300건씩**, 오통과 **0건**을 요구한다. 범주별 건수를 합산해 한 수치로 처리하지 않는다.
   - **추가 필수 관문:** 영어 이름과 인용의 의미 불일치도 별도 평가한다. 금지 범주 오통과가 0이어도 의미가 다른 이름을 내는 오류는 남는다.

## 두 안 모두 놓친 것

- 인용문만 보여 주고 **실제로 제안한 형태 낱말을 보여 주지 않으면**, 참여자가 번역이나 해석이 틀렸는지 알아차리기 어렵다. 제안 낱말과 인용 근거를 함께 제시하거나, 그 낱말을 참여자가 이해할 수 있는 방식으로 검증해야 한다.
- `shapePromptPath: rule | llm | none`만으로는 **LLM 호출·후보 노출·후보 채택·거절**을 구별하기 어렵다. 예컨대 LLM을 불렀지만 후보가 기각된 경우와, LLM을 부르지 않은 경우가 분석에서 섞일 수 있다.
- G82는 현행 `AGENTS.md:6`의 두 예외 외에 새 예외를 추가한다. 실험 적용 전에 원칙 1, G77-d와의 관계, 프로토콜 문구의 `draft` 상태와 버전을 함께 정리해야 한다.
- 합성 오프라인 평가만으로 참여자 화면에서의 이해나 거절 경험까지 확인되지는 않는다. 실험을 켜기 전, 화면 문구와 거절 경로도 별도로 점검해야 한다.

## 꼭 고쳐야 하는 것

- 의미가 다른 영어 형태 이름을 걸러낼 검토 기준과 평가를 추가한다.
- 호출 전에 참여자가 LLM 기능과 발화 전달을 알 수 있게 하고, 동의와 IRB 문구를 정리한다.
- 평가의 데이터 수·층화·수치 기준을 미리 고정한다.
- 호출·노출·채택·거절을 구분해 기록하고, G77-d는 형태 슬롯에 한정해 비활성화한다.

## 권고

- 영어 이름과 인용 근거를 참여자가 함께 확인할 수 있게 한다.
- 오프라인 평가 통과 후에도 후보 거절률과 이해도는 별도 지표로 계속 살핀다.
