## 지적

1. **높음 — XR이 세션 중 끊겨도 데스크톱 화면 노출과 세션 진행을 막지 않습니다.**  
   `unity/Assets/IFS/Runtime/Placement/PlacementRunner.cs:299-307, 990-1007`  
   **재현 경로:** XR로 시작한 뒤 공간 고르기나 과제 도중 헤드셋을 잠재우거나 벗습니다. XR 상태는 세션이 실행 중일 때 입력 재구성에 쓰이지 않고, `Tick`은 계속 세션을 진행합니다. Link 데스크톱 보기로 돌아가면 실험자 화면이 보일 수 있습니다. 공간 고르기 단계는 입력이 끊기면 시간 제한도 없어 멈춘 채 기록됩니다.  
   **고칠 방향:** 실행 중 XR 상태 이탈을 감지해 입력을 막고 실험자 화면 노출 경로를 안내하며, 중단·재개와 기록 규칙을 명시합니다.

2. **중간 — 기본 설정에서도 기존 기록 바이트가 달라집니다.**  
   `unity/Assets/StreamingAssets/IFS/placement_task.v0.json:2`, `unity/Assets/StreamingAssets/IFS/placement_task.scaleA.v0.json:2`, `unity/Assets/IFS/Runtime/Placement/PlacementRecordWriter.cs:558-563`  
   **재현 입력:** `environmentChoice=experimenter`로 기존처럼 세션을 시작합니다. manifest에 문구 판이 기록되는데 기본 문구 파일 판이 `0.8→0.9`, scaleA가 `0.8-scaleA→0.9-scaleA`로 바뀌어 해당 필드가 달라집니다. `PlacementEnvironmentTests`의 golden은 `fixed-1` 문구를 쓰므로 실제 StreamingAssets 파일의 판 변경을 검증하지 않습니다(`unity/Assets/IFS/Tests/Editor/PlacementEnvironmentTests.cs:37, 121`).  
   **고칠 방향:** 바이트 동일성이 요구되면 기존 기본 파일 판을 유지하거나, 변경을 의도한 기록 호환성 변경으로 명시하고 실제 파일을 쓰는 golden 검증을 추가합니다.

3. **중간 — 허용된 앉은 눈높이 하한에서 안내 판 중심이 바닥 아래로 갑니다.**  
   `unity/Assets/IFS/Runtime/Placement/PlacementRunner.cs:1063-1064`, `unity/Assets/IFS/Runtime/Placement/PlacementConfig.cs:194-195`  
   **재현 입력:** 상대 눈높이 모드에서 앉은 자세 `E=0.95m`로 보정합니다. 판 중심 높이는 `0.6 + (0.95−1.6) = −0.05m`입니다. `E=1.10m`에서도 중심은 바닥 위 `0.10m`입니다. 판 하단은 중심보다 더 낮으므로 일부가 바닥에 묻힐 수 있습니다.  
   **고칠 방향:** 앉은 범위에서 판 전체가 바닥 위에 남도록 위치를 제한하거나, 눈높이 기준 판 배치 규칙을 조정합니다.

4. **낮음 — XR 초기화가 늦으면 일시 상태를 시작 거부로 고정할 수 있습니다.**  
   `unity/Assets/IFS/Runtime/Placement/PlacementRunner.cs:586-600, 752-757`  
   **재현 경로:** Play 직후 XR이 아직 활성화되기 전에 Setup 확인을 누릅니다. 그 시점의 `XrHeadActive=false`로 오류가 추가되고, XR이 뒤늦게 켜져도 시작은 남아 있는 오류 때문에 거부됩니다. 다시 Setup 검사를 해야 회복될 수 있습니다.  
   **고칠 방향:** XR 초기화 대기·재검사 경로를 두거나, 상태가 안정된 뒤 확인하도록 화면에서 분명히 안내합니다.

## 문제없다고 확인한 것

- 참여자 번호는 공백·비숫자·1 미만이면 검증 단계에서 거부되어 공간 순서 함수까지 전달되지 않습니다(`unity/Assets/IFS/Runtime/Placement/PlacementRunner.cs:545-551`). 양수 번호에 대한 순환 순서 구현은 확인했습니다.
- 공간 고르기에서 세 공간을 다 보기 전 확인은 무시되고 기록됩니다. 정상 확인은 확정 알림 뒤 intro로 이어집니다(`unity/Assets/IFS/Runtime/Placement/PlacementSession.cs:900-949`).
- 유효한 확인과 방아쇠가 같은 프레임에 들어와도 확인 처리에서 반환하므로, 그 프레임의 방아쇠가 다음 단계로 넘어가지는 않습니다.
- 잠금이 요구하는 문구 판 `0.9-scaleA`와 새 키가 맞고, 새 키에는 `draft` 상태와 출처가 있습니다(`unity/Assets/IFS/Runtime/Placement/PlacementExperimentLock.cs:25-28`, `unity/Assets/StreamingAssets/IFS/placement_task.scaleA.v0.json:71-79`).
- 실기 화면 위치·XR 초기화 지연·세션 중 XR 이탈은 코드만 검토했으며, Unity 에디터와 헤드셋에서는 확인하지 않았습니다.
