## 발견 사항

1. **높음 — 금지 범주인 재질·배경 명사가 대상 자리에 통과할 수 있음**  
   파일: `tools/gen3d/prompts.py:673, 709–717`; `shared/lexicon/shape_english_rewrite_block.v0.json:13–14`

   `english_material` 검사는 대상 명사구의 마지막 낱말을 빼고 실행합니다. 코드 주석은 `marble`, `sponge` 같은 낱말을 대상 명사로 허용합니다. 장면·배경 목록도 열거된 낱말만 막고 장소 범주 전체를 검사하지는 않습니다.

   **재현 입력:** `대리석이에요`에서 G82가 채택하지 않고, G85가 `subject.en="marble"`을 내면 재질 검사에서 머리 명사가 제외됩니다. `동굴이에요`에서 G85가 `subject.en="cave"`를 내는 경우도 `cave`는 배경 목록에 없고 WordNet 금지 뿌리에 장소가 없습니다. 두 경우 모두 통과할 수 있다는 것은 정적 코드에 따른 추론이며, 해당 모델 출력을 실제로 재현한 것은 아닙니다.

   **수정 방향:** 대상 명사구의 머리 명사에도 재질·장소·배경 범주 검사를 적용하고, 배경을 나타내는 대상어의 허용 범위를 보강하세요.

2. **중간 — 생성기 쪽 재검증이 서버 검증보다 좁음**  
   파일: `tools/gen3d/prompts.py:740–773`

   `_rewrite_head`는 인용 글자와 구간, 영어 낱말은 확인하지만 부정·과거·비유, 매퍼가 제외한 구간, 규칙 문맥에서 제외된 구간은 다시 검사하지 않습니다. 현재 정상 흐름에서는 서버의 `llm_rewrite.validate`가 채택한 항목만 전달되므로, 곧바로 LLM 원출력이 무검증으로 프롬프트에 들어가는 경로는 찾지 못했습니다. 다만 생성기가 자체 재검증에서도 같은 판정을 한다는 설명과 달리, 서버 검증이 우회되거나 입력이 어긋나면 fail-closed가 보장되지 않습니다.

   **재현 입력:** 직접 생성기 입력에 `예전에 대리석을 봤어요`와 정확히 일치하는 인용 구간, 영어 대상 `marble`을 넣으면 `_rewrite_head`에는 과거 문맥을 거부할 검사가 없습니다. 이는 서버를 거치지 않은 생성기 호출을 가정한 방어 심층 시험 사례입니다.

   **수정 방향:** 생성기에서도 문맥·매퍼 제외 검증을 재사용하거나, 서버가 검증한 항목에 대한 명시적 입력 검증 경계를 추가하세요.

3. **중간 — 원시 출력 전문이 기록되지 않을 수 있음**  
   파일: `chatbot/ifs_chatbot/llm_rewrite.py:394–406`

   `rawText`를 4,000자로 자릅니다. 따라서 더 긴 모델 응답은 기록에서 일부 사라집니다. 파싱한 `rawItem`은 보존되지만, 결정 기록이 요구한 원시 출력 전문은 항상 남는다고 볼 수 없습니다.

   **재현 입력:** 4,000자를 넘는 유효 JSON 응답을 내는 대역 LLM을 쓰면 `rawItem`은 파싱되더라도 `rawText` 끝부분은 기록되지 않습니다.

   **수정 방향:** 원시 응답을 전문으로 로컬 기록에 보존하거나, 전문을 별도 로컬 아티팩트로 남기고 세션 기록에 무결성 해시와 참조를 기록하세요.

4. **중간 — 중립 안내가 참여자의 주의를 특정 차원으로 유도함**  
   파일: `shared/protocol/selection_protocol.v0.14.json:281–285`

   새 문구 끝의 “색은 보지 말고 모양만 봐 주세요”는 색과 모양을 명시하고 어느 쪽에 주의를 둘지 지시합니다. 치료 표현은 찾지 못했지만, 작업 원칙 3의 차원어·유도 표현 제한과 충돌할 소지가 있습니다. 문구는 `draft`이고 G85 출처가 기재되어 있습니다.

   **수정 방향:** 이 지시가 필요한 이유를 설계에 남기고 검토하거나, 선택 화면을 중립적으로 안내하는 문구로 다듬으세요.

5. **낮음 — G85 전에 별도 LLM 예열 요청이 추가됨**  
   파일: `chatbot/ifs_chatbot/llm_rewrite.py:381–383`; `chatbot/ifs_chatbot/llm.py:159–170, 180–183`

   G85 본 호출 전에 Ollama에 사용자 입력 `.`을 보내는 예열 요청이 있습니다. 예열 결과는 사용하지 않고, 성공 여부와 시간은 `contextPrimed`로 기록합니다. 위기·확인 판정 검사는 이 경로보다 앞에 있어, 판정 세션에서 예열 요청이 실행되는 경로는 찾지 못했습니다. 다만 “확정 텍스트만 읽는다”는 G85 원칙을 엄격히 적용하면 본 추출 외의 모델 요청이며, 호출 기록도 본 추출과 분리되어 있지 않습니다.

   **수정 방향:** 예열을 G85 호출로 볼지 명확히 정하고, 별도 요청·실행 결과임을 기록하거나 제거하세요.

## 확인 결과

- **중복 인용 구간:** `repair_span`은 오프셋이 틀렸을 때 인용이 원문에 정확히 한 번 있을 때만 위치를 고칩니다. 두 번 이상 나오면 고치지 않아 검증에서 거부됩니다. 모델이 유효한 오프셋으로 두 발생 중 하나를 가리키면 그 발생을 씁니다. 이 동작은 fail-closed지만, 중복 발생 시험은 찾지 못했습니다.
- **경로와 덮어쓰기:** 규칙·G82가 형태를 얻으면 G85 경로는 그 값을 덮지 않습니다. G85 출력은 생성 프롬프트 입력으로 전달되며 `IFSSceneSpec` 슬롯에 기록되는 경로는 확인하지 못했습니다.
- **위기·확인 판정:** G85는 캐시 조회 전에 세션 판정을 확인합니다. 판정 뒤에는 G85 호출이나 중립 형태 생성이 없습니다. `[그 말이 아니에요]`는 거절 기록 후 기존 조절 경로로 이동하며 재호출하지 않습니다.
- **메시 재시도:** 같은 세션에서 최대 한 번 돌아가며, 각 메시 시도 결과와 누적 횟수를 기록합니다. 구현과 README의 시험 설명에서 이 제한을 확인했습니다.
- **화면·개인정보:** 참여자 화면에는 영어 프롬프트나 파일 경로를 렌더링하는 경로를 찾지 못했습니다. 근거 낱말과 고정 안내만 표시하며, 세션 ID는 API 경로에 쓰이지만 화면 문구로 출력되지는 않습니다. 이는 정적 코드 확인입니다.
- **외부 전송:** G85는 설정된 Ollama 호스트에 요청합니다. `experiment-g85.toml`은 `127.0.0.1`을 사용합니다. WordNet 코드는 로컬 자료를 읽고 `nltk.download`를 호출하지 않습니다. 실행 중 네트워크 동작 자체는 확인하지 않았습니다.
- **고정 문구:** 새 프로토콜 문구 모두 `draft` 상태와 G85 출처가 있습니다. 치료 표현은 찾지 못했습니다. 중립 안내의 사실성 문제는 사용자가 이미 제외하라고 지정한 항목이라 여기서 다시 지적하지 않았습니다.
- **기록:** 모델 digest, 프롬프트 판·해시, 온도, seed, 입력 해시, 기각 사유, 호출·노출·선택·거절, 조립 프롬프트 기록 경로를 확인했습니다. 원시 응답 길이 제한은 위 발견 사항과 같습니다.
- **G85 출력이 검증 없이 프롬프트에 직접 들어가는 정상 경로:** 찾지 못했습니다. 대상·근거 꾸밈·덧붙임은 서버 검증 후 채택되고, 생성기 재검증에도 통과해야 합니다. 다만 생성기 재검증의 문맥 검사 누락은 별도 방어 심층 문제입니다.

## 빠진 시험

기존 시험 정의와 README의 시험 결과를 읽었고 시험은 다시 실행하지 않았습니다. 다음 시험은 찾지 못했습니다.

- 잘못된 `charSpan`과 중복 인용 두 건의 조합: 거부되는 경우와 유효 오프셋으로 한 건을 지정하는 경우
- 재질 대상 명사와 목록 밖 장소·배경 대상어가 G85 검증을 통과하지 않는 경우
- 생성기 재검증이 과거·부정·매퍼 제외 근거를 독립적으로 거부하는 경우
- 4,000자 초과 원시 응답의 기록 완전성
- 참여자 모드 응답·DOM에 영어, 세션 ID, 로컬 경로가 없는지 자동 확인하는 시험

지정된 Unity 설정 파일과 `chatbot/logs/`는 열지 않았고, 파일 변경도 하지 않았습니다.
