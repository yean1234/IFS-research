## 발견 사항

- **중간 — 놓기와 확인이 같은 프레임이면 쥔 채 확인을 막는 규칙을 우회합니다.**  
  [PlacementSession.cs](</<repo>/unity/Assets/IFS/Runtime/Placement/PlacementSession.cs:831>)에서 그 프레임의 `GrabHeld == false`를 보고 먼저 `Release("button")`을 호출한 뒤, 같은 프레임의 `ConfirmDown`을 처리합니다. 따라서 재현 입력 `Held == true`, `GrabHeld == false`, `ConfirmDown == true`에서는 `ConfirmPlace()`가 `_held == false`를 보고 확인을 받아들여 조건 종료 알림을 시작합니다. 놓은 다음 별도 프레임에서 확인해야 한다는 의도라면, 그 프레임의 확인을 무시하거나 입력 순서를 조정해야 합니다.

## 문제를 찾지 못한 항목

- **확인 뒤 알림 중 조작 차단과 최종 위치:** 확인 후 `ConditionClosing` 분기에서 입력을 `StepCondition`에 넘기지 않고 상태를 `idle`로 둡니다. 종료 시 `_obj`를 최종 위치로 기록하므로 확인한 위치가 유지되는 흐름입니다([PlacementSession.cs](</<repo>/unity/Assets/IFS/Runtime/Placement/PlacementSession.cs:1699>), [PlacementSession.cs](</<repo>/unity/Assets/IFS/Runtime/Placement/PlacementSession.cs:976>)).
- **쥔 채 확인:** 별도 프레임에서 쥔 채 확인하면 `confirm_ignored`와 `reason=held`를 기록하고, 놓기나 종료를 유발하지 않습니다. 왼손·오른손은 설정된 단일 XR 컨트롤러에서 확인 입력을 읽는 구조입니다. 두 컨트롤러 입력을 함께 합치는 동작은 확인되지 않았습니다.
- **상한·알림 경계:** 확인 알림이 시작된 뒤에는 90초가 지나도 알림 종료를 기다립니다. 반면 확인 입력이 조건 타이머 상한을 넘긴 프레임에 들어오면 먼저 timeout 분기가 실행되어 그 확인은 처리되지 않습니다. 두 경계의 우선순위는 코드상 일관됩니다.
- **중단 기록:** 조건 단계에서 중단하면 `conditionCompleted: false`, `conditionEndReason: aborted`로 기록합니다. 알림 중 중단도 `aborted`로 기록하는 경로입니다.
- **보기만 조건:** `static`, `system_move`, `replay`는 확인 입력으로 종료하지 않습니다. `point_select`의 확인은 위치 선택에 쓰이지만 조건 단계는 상한까지 계속됩니다. 다만 새 G86 Editor 시험은 `replay` 모드를 직접 포함하지 않습니다.
- **잠금·문구 판:** 권고 설정은 값을 켜고, 잠금 비교와 시작 거부 검사에도 해당 값이 포함됩니다. 잠금 문구 판은 `0.11-scaleA`이며 두 문구 JSON의 `condition_place`에는 `status: draft`, 출처와 G86 결정이 있습니다. 문구에 치료·유도 표현은 보이지 않았습니다.
- **설정 해제·기록:** 설정이 꺼지면 새 `placement.json` 필드와 `condition_end` 이벤트를 추가하지 않고 기존 확인 동작을 유지하는 코드입니다. 파일 바이트 동일성까지 확인하는 시험은 실행하지 않았습니다.

## 추가 시험 공백

- 놓기와 확인의 동시 프레임 경계, 확인과 90초 상한의 같은 프레임 경계, 알림 중 상한 경과를 고정한 시험이 없습니다.
- `xrHand: left`의 실제 XR 입력 경로, 양손을 동시에 사용하는 상황, 조건 단계 중 XR 연결 끊김·복구를 다루는 G86 시험이 없습니다. 현재 러너는 XR 연결이 끊겨도 조건 타이머를 멈추지 않고, 알림 타이머도 세션 시각에 따라 진행합니다.
- view의 `replay` 모드와 실험 잠금에서 값을 껐을 때의 **시작 거부**를 직접 검증하는 G86 시험이 없습니다.

분석기는 옛 기록의 `conditionEndReason` 추정을 문서화하고, 새 필드 및 `config_mismatch:conditionEndsOnConfirm` 분기를 구현했습니다. 다만 옛 기록의 필드 누락·불완전 상태 조합은 시험 사례가 제한적이므로, 기록이 부분적으로만 남은 경우 종료 사유를 확정하기 어려울 수 있습니다.

시험은 요청대로 실행하지 않았습니다. 파일을 수정하지 않았으며, 지정하신 OpenXR 설정 파일과 `chatbot/logs/`는 열지 않았습니다.
