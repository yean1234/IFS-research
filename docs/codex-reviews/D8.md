## 제안: 생성형 형태를 **사전 생성 후보를 고르는 선택적 경로**로 추가

이 경로는 기존 결정 G7·G61-a·X40을 바꾸므로, 먼저 책임자가 이를 대체하는 새 결정을 기록해야 합니다. 형태 생성 모델이 참여자 대신 대상을 해석하는 위험은 남습니다. 따라서 **형태가 말로 명시됐을 때만 후보를 만들고, 사용자가 고르거나 고치며 확인하는 절차**를 파이프라인의 필수 조건으로 두겠습니다. IRB 승인 전에는 합성 발화와 연구팀 내부 점검에만 씁니다.

### 1. AGENTS.md 원칙 1·2 개정안

**1. 역할과 결정성.** LLM은 면담 질문 생성에만 쓰고, 형태 생성 모델은 참여자가 말한 형태를 바탕으로 메시 후보를 만드는 데만 쓴다. 장면의 형태 후보 생성·매핑, 색·질감 초깃값, 슬롯 추출은 명시된 발화와 사전·규칙으로 결정하며, 형태 생성 모델은 말하지 않은 속성을 추가하지 않는다. 같은 확정 텍스트와 같은 버전·설정·seed에는 같은 후보 결과를 요구하되, 바이트 단위 재현성을 확인하지 못한 모델은 그 한계를 기록한다.

**2. 말하지 않은 값과 사용자 선택.** 사용자가 말하지 않은 값은 미지정으로 남기며, 모델이 만든 후보는 참여자가 고르고 조절해 확인하기 전까지 참여자의 응답이나 장면 값으로 간주하지 않는다. 발화와 모델 출력이 충돌하면 발화 및 사용자의 명시적 수정이 우선하고, 후보 거부·생성 실패·선택 없음은 그대로 기록한다. 색·질감 등 사전 매핑 초깃값도 출처를 표시하고 사용자가 조절할 수 있게 한다.

### 2. 파이프라인에서 생성기가 놓일 자리

**배치 생성 + 세션 중 선택**을 권합니다. 발화에서 명시적 형태 명사를 사전으로 찾고, 메시 지원 범주에 속하는 경우에만 로컬 생성기가 합성 발화용 후보 묶음을 만듭니다. 실험 경로에서는 사전 생성된 검수 후보를 고르게 하고, 새 발화에 대응하는 묶음이 없으면 세션 중 생성은 연구팀 내부 점검에만 씁니다. 자유 생성 결과를 즉시 제시하면 지연·실패·후보 차이가 조건에 섞일 수 있습니다.

후보가 없거나 생성이 실패하면 **형태를 비워 두고**, 사용자가 기존 형태 후보를 고르거나 형태 조절을 하기 전까지는 메시를 보여 주지 않습니다. 안개·불꽃·연기처럼 메시 표현의 근거가 약한 범주는 생성 대상으로 취급하지 않습니다. 기존 프로토콜의 결정적 기본 형태를 보여 주는 경우에도 `default`로 분명히 기록하고, 형태가 없다는 사실을 시각적으로 오인시키지 않도록 사전 검증합니다. 그 표현이 불가능하면 해당 범주는 내부 평가에만 남깁니다.

### 3. 첫 모델과 다음 후보

첫 부착 모델은 **TripoSG**로 제안합니다. 주어진 조사에서 형태만 GLB로 내보내고 8GB 이상 메모리 요구로 확인되어, 16GB GPU와 기존 glTFast 로더를 이용하는 파이프라인에 맞습니다. 색·질감은 생성 모델에 맡기지 않고 기존 슬롯 조절로 처리합니다.

다만 조사 요약만으로 이 PC의 Windows 환경에서 설치·실행이 보장되지는 않습니다. **12월 2일까지 실험 파이프라인에 붙일 수 있다고 단정할 근거는 부족합니다.** 첫날에 설치, 단일 실행, GLB 로드, 동일 입력 반복 결과 확인을 통과하지 못하면 후보로만 남기고, 이미 실행 경로가 있는 **Shap-E → SDXL → TripoSR**를 비교 기준선으로 사용합니다. 이 기준선의 기존 120개 평가에서 문장 일치가 4개뿐이었다는 사실 때문에, 이를 사용자용 후보 생성에 바로 투입하는 것은 반대합니다. 두 번째 후보는 TRELLIS v1입니다. 16GB 요구가 이 PC에 맞지만 설치·Windows 호환성을 먼저 확인해야 하므로 마감 전 주 경로로 삼기 어렵습니다.

### 4. 스키마와 기록

`scene-spec.v2.3.json`을 덮어쓰지 말고 **2.4를 추가**해 생성 메시를 참조하는 선택 슬롯을 둡니다. 예를 들어 `form.meshRef`(선택한 로컬 자산 식별자), `form.meshStatus`(미지정/후보/선택/거부/실패), 생성 후보가 정한 것이 아닌 **사용자가 확정한 값**임을 provenance로 나타냅니다. 색·질감은 기존 슬롯과 사용자 조절 기록을 유지합니다. 2.0–2.3은 기존 스키마로 그대로 읽습니다.

`selection.v0.2.json`은 호환성을 위해 기존 파일을 바꾸기보다 새 버전을 추가합니다. 생성 이벤트마다 모델명과 가중치 **digest**, 코드·환경 버전, seed, 프롬프트 원문과 해시, 입력 발화의 비식별 참조/해시, 후보 ID와 자산 해시, 표시 순서, 선택·거부·재생성·실패 사유와 시각을 기록합니다. 출처는 기존 `said/chosen/edited/default`와 혼합하지 말고, “모델 후보 생성”은 **후보 자산의 생성 이력**으로 분리합니다. 사용자가 후보를 선택하면 최종 슬롯 출처는 `chosen`, 수정하면 `edited`로 남깁니다. 원문 발화는 세션 로그 규칙에 따라 git 밖에 둡니다.

### 5. 거리 결과변수를 지키는 장치

후보 생성·렌더 전에 바운딩 박스를 정해진 크기 기준으로 정규화하고, 최종 크기는 참여자가 조절한 크기 슬롯으로 결정합니다. 메시 단위, 실제 렌더 크기, 정규화 전후 크기와 조절 이력을 기록합니다. 사람·얼굴·동물 형상은 연구 범위·위험과 거리 지각 편향을 고려해 후보 생성을 막고, 통과 여부를 기록합니다. 바닥 접촉점, 바닥 그림자, 눈높이, 재질·밝기·불투명도, 초기 위치(정면 1.5m 고정), 메시 경계 상자와 실제 투영 크기도 점검·기록합니다. 분석용 공변량 후보는 크기, 형상 범주, 물체 친숙도, 얼굴·위협 단서 여부, 접촉·그림자 상태, 눈높이, 색·밝기, 후보 선택·수정 여부입니다. 주 분석에 임의로 추가하지 말고 사전 명시한 민감도 분석에 둡니다.

### 6. 프롬프트 구성

한국어 발화에서 **사전에 등재된 형태 명사만 규칙으로 추출**하고, 고정된 한영 대응표로 영어 프롬프트를 만듭니다. 문장 전체 번역이나 LLM 재서술은 금지합니다. 크기·색·감정·재질·기능 등은 명시 발화에서 별도로 추출한 항목만 넣고, 빈 항목은 프롬프트에서 생략합니다. “안개”, “불꽃” 등 제외 범주가 감지되면 생성 호출 자체를 막습니다. 프롬프트 템플릿·사전 버전·추출 근거를 기록해 같은 입력이 같은 문자열을 만들게 합니다.

범위를 **내부 합성 평가**로 한정합니다. 기준선 포함 합성 발화 30개(메시 가능 형태 20, 미지정·비메시 형태 10)를 고정하고, TripoSG 설치·실행·GLB 로드, 프롬프트 규칙, 선택/거부/실패 기록을 연결합니다. 통과 기준은 ① 30개 중 미지정·비메시 10개 생성 호출 **0건**, ② 가능한 형태 입력 20개 중 생성·로드 성공 **18개 이상**, ③ 결정적 규칙 추출·프롬프트 동일성 **20/20**, ④ 모델 반복 실행의 메시 동일성 **20/20**(실패 시 비결정성을 명시하고 이 기준 미통과), ⑤ 블라인드 연구팀 평가자 2명이 형태 일치 1–5점을 매겨 중앙값 **4 이상인 사례 16/20 이상**, ⑥ 바닥 접촉·크기 정규화 검사 통과 **20/20**입니다. 이 기준은 모델의 타당성을 입증하는 것이 아니라 후속 평가로 넘길지 결정하는 내부 게이트입니다.

참여자 연구 적용, 온라인 생성, 열린 범주, 복잡한 재질 생성, 거리 결과에 대한 인과 주장은 미룹니다.

### 8. 약한 점과 논문 서술

1. **형태 일치 평가가 연구자 판단에 좌우됩니다.** 평가자 수·합의도와 실패 사례를 함께 보고하고, 합성 평가를 참여자 타당성으로 일반화하지 않습니다.
2. **선택·수정 절차가 소유감과 응답을 바꿀 수 있습니다.** 생성 모델 효과와 확인·조절 절차 효과를 분리할 수 없다고 쓰고, 현재 연구 파이프라인에는 탐색적 구현으로 위치시킵니다.
3. **형태를 정규화해도 친숙도·실루엣·그림자 영향이 남습니다.** 이를 거리 지각의 잠재 교란으로 명시하고, A1–A7이 주 결과라는 점과 거리 측정이 RQ2 탐색 결과라는 점을 유지합니다. 논문은 생성 메시가 거리 판단을 개선한다고 주장하지 말고, 통제와 공변량 기록을 갖춘 후속 검증 필요성을 적어야 합니다.
