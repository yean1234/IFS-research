- **중간 — 설정 판 조합을 시작 시 검증하지 않습니다.**  
  `chatbot/ifs_chatbot/controller.py:200-225`, `chatbot/ifs_chatbot/web/stage.js:722-724, 855`  
  재현: `[selection] table = "candidate_values.v4.json"`와 `protocol = "selection_protocol.v0.10.json"`을 함께 설정해 시작합니다. 시작 검사는 LLM 안내 문구만 확인하고, 고리 문구의 존재나 값 표와 프로토콜 판의 조합은 확인하지 않습니다. 고리 UI는 새 문구 키를 요청하므로 프로토콜에 키가 없으면 화면 문구가 누락되거나 키 이름으로 표시될 수 있습니다. 반대 조합인 v3 표 + 0.11 문구도 거부되지 않아 선택 기록에 의도하지 않은 문구 판이 기록될 수 있습니다. **시작 시 v4와 0.11의 대응을 검증하고 불일치면 설정 오류로 중단하세요.**

  `chatbot/ifs_chatbot/web/stage.js:789-805`  
  재현: 고리의 현재 손잡이 위치를 누르고 움직이지 않은 채 놓습니다. `dragIdx === idx`이면 `send()`를 호출하지 않아 조작 횟수와 이벤트가 남지 않습니다. 같은 색 재선택을 기록하는 서버 동작 및 문서의 조작 기록 약속과 화면 입력 경로가 달라집니다. **현재 칸을 눌렀다 놓은 경우에도 한 번 전송되도록 처리하세요.**

## 문제없다고 확인한 것

- 고리 입력 검증은 허용 키만 받고, 칸·채도 단계에 정수 범위를 적용합니다. `72`, 음수, 실수, 숫자 문자열, `bool`, `null`, 배열, 알 수 없는 키는 거부되며 두 단계 키를 함께 보내는 입력은 의도된 형식으로 처리됩니다. 견본 ID와 단계 객체를 섞어 보내는 입력도 거부됩니다. 확인 위치: `chatbot/ifs_chatbot/selection.py:470-515`.
- 선택 화면 진입·완료 경로에서 `colorRing.initial`과 `final.origin`을 기록하고, 색 미조작 상태와 실제 선택 상태를 분리합니다. G77 값 제안과 위기 판정 세션의 미적용 처리도 테스트에 포함돼 있습니다. 확인 위치: `chatbot/ifs_chatbot/selection.py:517-590, 1556-1571`, `chatbot/tests/test_g79_color_ring.py:301-332`.
- 웹 코드는 외부 URL·CDN을 참조하지 않으며, 화면 문구는 프로토콜에서 가져옵니다. DOM 텍스트는 `textContent` 경로를 사용합니다. 지정한 고리 렌더링 코드에서 서버 문구를 `innerHTML`에 삽입하는 경로는 찾지 못했습니다.
- `color_bin`은 입력 범위를 확인하고, 360°를 0°로 순환시키며, 경계에서 위쪽 칸을 택하는 규칙을 구현합니다. `color_bin` 결과를 화면이나 선택 기록에 쓰는 경로도 찾지 못했습니다. 확인 위치: `chatbot/ifs_chatbot/eval/color_bins.py:20-32`.
- 새 프로토콜 문구는 `draft` 상태와 출처를 갖고, 0.10 파일은 별도 보존돼 있습니다. v3 표 경로에서는 고리 전용 기록 키와 조작 입력 키를 추가하지 않도록 분기돼 있습니다. 확인 위치: `shared/protocol/selection_protocol.v0.11.json:17-23`, `chatbot/ifs_chatbot/selection.py:1381-1383`, `chatbot/tests/test_g79_color_ring.py:275-290`.

읽기 전용으로 검토했으며 파일은 수정하지 않았고 테스트도 실행하지 않았습니다.
