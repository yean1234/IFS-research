### 1. Q1의 논리 — 문제 있음

- **근거**　①에서만 `가까운 > 먼`이 나와도 고른 값의 기억을 배제할 수 없다. ①은 자기 답에 확신이 있어 잘 기억하고, ③은 임시 답이라 잊기 쉽다. 참가자가 자기 답과 일관되게 평정해야 한다고 느껴도 같은 결과가 나온다. 반대로 ③에게 색상환을 보여 주면 그 자리에서 색 심상이 생겨, ③의 효과가 선택 기억에서 왔는지 새 심상에서 왔는지 알 수 없다. 현재 확증 검정은 ① 안의 차이만 다룬다. ①에서 유의하고 ③에서 유의하지 않아도 두 효과가 다르다는 증거는 아니다.
- **고칠 방법**　자발적 기술에서 수치 기준을 독립적으로 확보할 수 있는 사례부터 시작한다. 형상과 무관한 기억 과제로 별도의 같은 범주 값을 무작위 배정해, 두 기준이 서로 다른 변형을 가리킬 때 어느 쪽 평정이 높은지 본다. 이 통제를 시행하기 전에는 결론을 “제시 전 보고값에 가까운 형상이 더 닮았다고 평정되는가”로 한정한다.
- **근거 파일**　[RQ 제안 3.2절](<repo>/docs/rq-v2-proposal.md:52), [설계 정본의 평가 시점 정의](<repo>/docs/research-design.md:18)

### 2. 가까운·먼 규칙 — 문제 있음

- **근거**　색에는 색상·채도·명도가 있고 색상각은 순환한다. 무채색에는 의미 있는 색상 방향이 없다. 회색 기본값 `w`와 자발적으로 보고한 파랑 `p` 사이에는 보존할 공통 색 낱말이 없을 수 있다. `p`가 낱말 범위 밖이거나 `w`가 끝값이면 같은 범주 안에서 양쪽 변형을 만들 수 없다. 크기는 `w`에서 로그 눈금으로 ±0.25를 움직이면 지름이 두 배와 절반이 된다. 수치상 대칭이어도 원본과 똑같이 달라 보인다는 보장은 없다. 색도 같은 알베도 ΔE00에서 조명·투명도·배경에 따라 실제 화면 차이가 달라진다.
- **고칠 방법**　속성별로 허용 범위·축·거리 함수를 동결한다. 첫 시행은 유채색의 색상 한 축, 무채색의 명도 한 축, 크기의 렌더 지름을 기준으로 삼는다. `w`와 `p`가 같은 명시 범주에 있고, 양쪽 후보가 범주에 남으며 `d(near,p) < d(w,p) < d(far,p)`일 때만 쌍을 채택한다. 기본값·범위 밖·끝값·축 불일치는 사유를 기록하고 주 대비에서 뺀다. 두 방향의 원본 대비 차이는 실제 렌더에서 허용 오차를 정해 각각 확인한다.

### 3. Q2 — 문제 있음

- **근거**　두 손 간격은 참가자가 가로폭·높이·최대 지름 중 무엇을 보고했는지 모르면 해석하기 어렵다. 자리도 표면을 짚은 값과 중심을 짚은 값이 다르고, 팔이 닿는 경계에서 직접 짚기와 광선 깊이 조절이 바뀐다. 예를 들어 손 간격 30cm가 정확히 기록돼도 화면에서 30cm 형상이 더 작게 보이면 시각적으로 가장 잘 맞는 후보가 더 큰 쪽일 수 있다. 자로 하는 보정은 추적 오차를 점검한다. 보고와 관찰의 편향이 같다는 가정은 별도 검증이 필요하다. 데스크톱을 빼면 Quest 안에서 과제를 실행할 수 있는지는 볼 수 있지만, 몸 기준 단서가 어떤 정보를 더하는지는 비교할 수 없다. [가상 행동 과제의 크기·거리 지각 실험](https://pmc.ncbi.nlm.nih.gov/articles/PMC8367880/)
- **고칠 방법**　같은 Quest에서 몸 기준 단서를 제공하는 조건과 줄인 조건을 비교한다. 두 조건 모두 중립 표식으로 최대 가로폭과 눈 기준의 중심 깊이를 같은 방식으로 맞추게 하고, 알려진 표적으로 거리대별 편향과 반복 오차를 먼저 잰다. 질문도 ‘자리’ 전체에서 실제 조작하는 ‘깊이’로 좁힌다.
- **근거 파일**　[RQ 제안 3.3절](<repo>/docs/rq-v2-proposal.md:61), [SceneLoader의 전방 거리·높이·스케일 처리](<repo>/unity/Assets/IFS/Runtime/Loading/SceneLoader.cs:701)

### 4. Q3 — 문제 있음

- **근거**　두 교차 대비가 양수여도 두 조작이 두 지표를 모두 올릴 수 있다. 예를 들어 가까움의 효과가 닮음과 소유감에서 각각 2와 1이고, 다루기의 효과가 각각 1과 2면 두 대비는 모두 양수다. 또 고정 궤적과 30초는 직접 다룬 사람이 실제로 본 면·거리·속도를 맞추지 못한다. 같은 심상을 네 번 보면 먼저 잡아 본 형상의 친숙함이나 소유감이 뒤의 관찰 조건에도 남는다. 조작 순서만 반씩 나누면 이월이 사라지지 않는다.
- **고칠 방법**　후속 실험에서는 다루기를 참가자 간에 배정하고, 보기 조건에 능동 참가자의 시점 기준 궤적을 짝지어 재생한다. 각 심상은 한 번만 평가하고 가까움 배정은 여러 심상에 걸쳐 균형화한다. 지표 간 비교는 사전에 정한 기준 분산으로 표준화하고 두 결과의 상관을 반영한 공동모형으로 대비와 구간을 보고한다. “서로 넘지 않음”까지 주장하려면 각 교차 효과가 사전에 정한 동등성 범위 안에 들어야 한다.
- **근거 파일**　[RQ 제안 3.4절](<repo>/docs/rq-v2-proposal.md:69), [척도 차이 관련 메모](<repo>/docs/rq-v2-proposal.md:159)

### 5. 측정 — 문제 있음

- **근거**　‘닮았다’에 6점을 준 직후 ‘내 것’에도 비슷한 점수를 주면 문항 간 일관성이 구성개념의 연관처럼 보인다. Q3에서 공통 ‘내 것’ 단일 문항도 함께 받는지 불분명하다. Peck & Shu의 문항은 실물 소비재의 심리적 소유를 묻는다. 한국어 ‘내 것’은 심상의 출처, 물체 소유, 조작 통제권으로 다르게 읽힐 수 있다. 머리 자세로는 실제 다루기나 통제감을 확인할 수 없다. [Peck & Shu 원문, Study 1](https://www.anderson.ucla.edu/faculty/suzanne.shu/JCR%2520touch%2520ownership.pdf)
- **고칠 방법**　Q1에서는 닮음만 받고, 마지막에 판단 기준·가설 추측·심상 변화 여부를 짧게 묻는다. Q3에서는 중복 소유 문항을 빼고, 별도 블록에서 지표 순서를 균형화한다. 번안 문항은 인지 인터뷰로 ‘내 것’의 지시 대상과 채점 규칙을 확인한 뒤 탐색 척도로 쓴다. Q3에는 실제 잡기·회전·노출과 지각된 통제감 확인을, 헤드셋 시행에는 정본의 멀미 전후 측정과 중단 기록을 복원한다.
- **근거 파일**　[RQ 제안의 측정표](<repo>/docs/rq-v2-proposal.md:86), [설계 정본의 사후 인터뷰](<repo>/docs/research-design.md:284), [VR 측정표](<repo>/docs/research-design.md:338)

### 6. 통계 — 문제 있음

- **근거**　평정의 관측 단위는 참가자×심상×속성×변형이고, 가까움 대비의 단위는 참가자×심상×속성의 쌍이다. 독립 표본은 참가자다. 참가자당 심상이 하나면 두 무선절편을 분리할 수 없다. ①이 여러 개여도 A에서 가능한 쌍은 최대 두 개, 현재 헤드셋 안에서는 최대 세 개이며 경계 탈락으로 더 줄어든다. 쌍이 0개인 사람은 주 대비에 정보를 주지 않는다. 두 쌍을 낸 사람이 더 크게 반영되는 분석은 사람마다 같은 비중을 주는 추정과 답이 달라질 수 있다.
- **고칠 방법**　A에서는 ①의 유효 쌍별 `가까운−먼`을 계산해 참가자별 평균을 주 추정치로 삼고, 속성별 결과와 0쌍 비율·탈락 사유를 함께 보고한다. 후속 혼합모형은 속성을 고정효과로 두고, 시행 수준 모형이라면 참가자 무선절편·가까움 무선기울기와 참가자 내 쌍 무선절편의 추정 가능성을 점검한다. 모집 20명을 충분하다고 볼 근거는 없다. 최소 관심 효과, 유효 쌍 발생률, 참가자 내 상관을 바꿔 검정력을 모의하고, 내부 시행은 실행 가능성과 탈락률 파악에 쓴다.

### 7. 원칙 위반 — 문제 있음

- **근거**　**1·2** 별도 파일과 결정론적 변형은 허용되는 구조다. 다만 ③의 임시 선택을 ‘참가자 심상의 값’으로 표시하거나 기본값 `w`에 참가자의 말이라는 출처를 붙이면 미지정과 실험값이 섞인다. **3** 챗봇 면담 흐름에서 “○○이 있었나요?”와 ①②③을 제시하면 참가자가 쓰지 않은 차원어·선택지·회고 질문이 들어갈 수 있다. **7** 구현 목록은 `draft`와 버전만 명시한다. 문구별 출처가 빠져 있고, 기존 과제 문구 로더는 출처가 비어 있으면 거부한다.
- **고칠 방법**　면담 확정 뒤 버전이 있는 별도 실험 과제로 보고를 받고, ③은 미지정과 값 없음으로 저장한다. 원본 spec과 출처를 동결하고, 보고값과 실험용 덮어쓰기는 별도 기록에 둔다. 고정 문구마다 `status`·출처·버전을 남기고 기존 초안 차단을 실험 과제에도 적용한다. 면담 프로토콜을 바꾸는 경우 해당 프로토콜 버전과 검증기 예외도 기록한다.

### 8. 단계 계획과 구현 목록 — 문제 있음

- **근거**　12/2까지 데스크톱에서 한 속성의 전 과정과 내부 사례를 보이는 범위는 현실적이다. 두 속성의 범주 보정, 새 과제 UI, 가변 순서, 새 측정·분석, §5 지표까지 묶은 A에는 완료 기준과 실패 시 축소 기준이 없다. 현재 정본의 11/19–20 진행 판단과도 맞춰야 한다. 참여자 자료가 없다면 내부 시행은 작동·실패 사례를 보여 주는 데 쓸 수 있다.
- **구현 충돌**　러너는 spec을 읽으면 바로 계획을 생성한다. 보고 파일을 나중에 읽는 순서로는 쌍을 만들 수 없다. 생성기는 다섯 조건의 Williams 순서를 먼저 배정한다. 쌍 생략까지 지원하려면 유효 조건을 확정한 뒤 순서를 만들어야 한다. 기존 최종 선택을 유지하면 헤드셋 11개 중 10·11번을 현재 키 입력으로 고를 수 없다. 분석기는 순서 길이 5를 기대하고 형상 ID당 평정 하나만 남기므로, 같은 ID로 두 문항을 쓰면 덮어쓴다. [러너의 계획 생성](<repo>/unity/Assets/IFS/Runtime/Ownership/OwnershipRunner.cs:265), [생성기의 순서 배정](<repo>/unity/Assets/IFS/Runtime/Ownership/OwnershipVariantGenerator.cs:199), [러너의 숫자 입력](<repo>/unity/Assets/IFS/Runtime/Ownership/OwnershipRunner.cs:572), [분석기의 평정 읽기](<repo>/chatbot/ifs_chatbot/eval/ownership.py:346)
- **고칠 방법**　A는 크기 한 속성과 내부 재현으로 고정한다. 먼저 `세션 ID + spec 해시 + 보고 파일 버전`의 연결을 정하고, `보고 검증 → 쌍·생략 사유 생성 → 실제 조건으로 순서 배정 → 시행 ID·문항 ID로 기록 → 분석`을 한 번 관통시킨다. 정본의 진행 판단일에 보정·기록이 미완이면 시스템과 후속 프로토콜 중심으로 투고 범위를 동결한다. [설계 정본의 진행 판단과 대체 범위](<repo>/docs/research-design.md:437), [현재 manifest](<repo>/unity/Assets/IFS/Runtime/Ownership/OwnershipManifest.cs:43)
- **A+ 선행 조건**　기기 확인 뒤로 XR 플러그인을 미루면 첫 확인 자체가 막힐 수 있다. 현재 머리 자세 코드는 XR 입력을 못 읽으면 데스크톱으로 전환한다. Quest 단독 빌드에서는 `StreamingAssets`의 문구를 `File.ReadAllText`로 읽는 경로도 바꿔야 한다. XR 초기화와 단독 빌드의 에셋·입력·기록 경로를 먼저 확인하고, 실제 `xr` 자세 기록과 양안 렌더가 확인된 뒤 Q2·Q3를 진행한다. ### 9. 교수 지적 2·3에 대한 답 — 문제 있음

- **근거**　결론을 도형 공간에 한정하면 지적 3에는 답이 된다. 지적 2의 핵심인 ‘이 prefab이 심상을 얼마나 표현하는가’는 여전히 열려 있다. Lin 등의 실험은 만질 수 있는 도형과 색·정서의 연합을 다뤘다. 현재 prefab 목록의 대표성을 뒷받침하지 않는다. 출판된 IFS 부분 묘사와 이번 중립 심상도 서로 다른 표본이다. [Lin 외 CHI 연구 원문](/ 아닌 https://purehost.bath.ac.uk/ws/portalfiles/portal/226671922/Linetal2021_CHI.pdf)
- **고칠 방법**　세 지표의 입력과 해석을 먼저 고정한다. **① 덮은 비율**은 원문에서 묘사 표현을 같은 단위로 코딩하고, 실제 반영·왜곡·누락을 판정한 뒤 유형별 분모를 만든다. HSL 렌더 키 수와 `_unmapped` 표현 수만으로는 비율을 계산할 수 없다. **② 다양성**은 범주형·연속형 거리, 가중치, 결측 처리 규칙을 정하고 기본값 포함 여부별로 계산한다. 낮은 거리는 비슷한 입력이나 매핑 수렴으로도 생긴다. **③ 거리와 반응**은 실제 렌더 거리·도우미 평정·참가자 평정을 같은 자극 ID로 연결하고, 공유 원본과 참가자 내 반복을 반영한다. 지금 분석기는 원본 대비 평정 하락은 계산하지만 이 관계는 산출하지 않는다. 참여자가 없다면 ①–②는 명시된 합성 입력의 시연치, ③은 후속 연구 지표다.

### 이 제안에서 가장 먼저 고쳐야 할 것 3가지

1. **Q1의 결론을 제시 전 보고값과의 일치로 좁히고 ③ 강제 선택을 없앤다.** 심상과 선택 기억을 구별하려면 독립 기준을 둔 별도 대비가 필요하다.
2. **한 속성에서 유효한 가까운·먼 쌍의 조건을 동결한다.** 같은 낱말 범위, 양방향 렌더 차이 허용 오차, 쌍을 만들 수 없는 경우의 처리부터 정한다.
3. **12/2 투고 범위를 데스크톱 한 속성의 전 과정 검증으로 고정한다.** 내부 시행으로 보여 줄 결과와 후속 참여자 연구에서 검증할 주장을 원고에서 명시한다.
