## 1. LLM이 읽는 내용

**선택 — 확인된 참여자 발화만 전달하고, 면담자 질문과 챗봇 문구는 제외한다.** 생성은 [맞는 게 없어요]를 누른 뒤에만 시도하며, 확인된 참여자 발화 중 규칙 경로가 형태를 못 정한 경우에 한정한다.

확정 텍스트만 주면 앞선 발화에서 가리키는 말이나 정정 내용을 놓칠 수 있다. 참여자 발화 전체는 형태 단서를 찾는 데 유리하지만, 면담자 질문까지 포함한 대화 전체는 질문에 들어 있던 표현을 참여자가 말한 형태처럼 모델이 받아들일 위험이 더 크다. 참여자 발화만 주면 그 위험을 줄이면서 여러 발화에 걸친 맥락은 보존할 수 있다. 입력에는 발화별 식별자와 텍스트만 두고, 질문 내용으로 추정하지 않도록 한다.

**버린 대안 — 확정 텍스트만 또는 대화 전체.** 전자는 정정·지시어 맥락을 잃고, 후자는 면담자 표현이 생성 결과에 섞일 수 있다. 다만 발화 전체의 폭도 넓으므로 인용 검증과 문장 단위 안전 검사가 반드시 필요하다. G73은 확정 텍스트를 바탕으로 했고, G77도 확정 원문 인용을 검증하는 구조다(`docs/decisions.md:1100,1205–1206`; `chatbot/ifs_chatbot/llm_fill.py:263`).

## 2. LLM이 내는 내용

**선택 — 영어 프롬프트 전체가 아니라, 형태 낱말과 근거를 담은 구조화 결과를 낸다.** 예를 들면 `ko_shape`, 참여자 발화 인용과 발화 내 문자 위치, 짧은 `en_head`를 한 항목으로 반환하게 한다. 규칙 코드가 이 항목을 고정된 영어 프롬프트 틀에 넣는다. 모델은 색·재질·감정·크기·위치·장식·배경을 추가할 수 없다.

한국어 낱말과 인용만 반환하면 현재 영어 기반 생성 파이프라인이 그 낱말을 새 형태로 옮길 수 없다. 그러므로 사전에 없는 낱말은 LLM이 짧은 영어 형태 이름도 제안해야 한다. 이 영어 이름은 번역이 맞다는 보증이 아니므로, 참여자에게는 한국어 인용과 형태 이름을 함께 보여 확인·수정할 수 있게 한다. 프롬프트에 붙이는 나머지 문구와 제약은 규칙이 고정한다. 현재 `rules_prompt`가 슬롯에서 프롬프트를 만들고, G77의 `_llm_head`가 인용과 영어 형태를 다시 확인하는 구조를 확장할 수 있다(`tools/gen3d/prompts.py:86,517–539`).

**버린 대안 — 영어 프롬프트 전체를 모델이 작성.** 생성할 세부가 늘고 원문 근거와 프롬프트 문장 사이를 검증하기 어렵다. **한국어 낱말만 반환하는 대안**도 검토했지만, 사전에 없는 영어 대응을 정할 수 없어 현재 생성기에 바로 연결되지 않는다.

## 3. 형태를 전혀 말하지 않은 경우

**선택 — 형태를 말하지 않은 경우는 계속 생성하지 않는다.** “쑥색이고 차가워요”에는 색과 감각만 있고 형태 단서가 없으므로 생성하지 않는다. 새 예외는 **형태를 말했으나 규칙 사전에 없는 경우**에만 적용한다. 원칙 2도 “형태를 말하지 않았으면 생성하지 않는다”를 유지하되, “규칙이 형태를 매핑하지 못했더라도 참여자가 구체 형태를 말했으면 인용 근거가 확인된 생성 후보를 만들 수 있다”로 보완한다.

**버린 대안 — 형상을 말하지 않아도 LLM이 대화 전체에서 형태를 추론.** 이는 ‘말하지 않은 내용은 추론하지 않는다’는 원칙 2를 다시 약화시키고 색·감각만으로 형태를 지어낼 위험이 있다(`AGENTS.md:9`; `docs/decisions.md:761,1209`; `docs/decisions.md:1330–1331`).

## 4. 제외 범주와 부정·과거·타인·가정 발화

**선택 — 입력 사전 검사, 출력 검증, 생성 단계 관문을 모두 둔다.**

- **입력 단계:** LLM 호출 전에 참여자 발화만 추리고, 형태 단서가 없거나 위험 표지가 확인된 문장은 fail-closed로 건너뛴다. 면담자 질문과 챗봇 문구는 전달하지 않는다.
- **출력 단계:** 인용이 실제 발화의 문자 구간과 일치하는지, 그 구간이 형태 낱말인지 검사한다. 부정·과거·타인 발화·가정·비유 문장 규칙을 적용하고, 사람·얼굴·몸·동물·무기·안개·불꽃·빛 등 금지 범주를 한국어 형태 낱말과 영어 형태 이름 양쪽에서 검사한다. 영어 쪽은 기존 `english_shape_reasons` 목록을 재사용·확장할 수 있다(`tools/gen3d/prompts.py:492–514`; `shared/lexicon/shape_english_block.v0.json:21–80`).
- **그림 관문:** 금지 범주는 이미지 프롬프트 전에도 차단하고, 생성된 그림에도 기존 그림 관문을 적용한다. 통과한 그림으로 만든 메시에도 사람·동물 등 기존 관문을 다시 적용한다. 어느 한 단계에서든 판정이 불분명하면 생성 후보를 노출하지 않는다. G62는 프롬프트와 출력 양쪽에서 사람·얼굴·동물을 차단하도록 정했다(`docs/decisions.md:765`; `docs/decisions.md:1164–1168`).

“예전에는 공이었어요”처럼 과거 형태만 말한 경우는 차단한다. “예전에는 공이었는데 지금은 돌덩이예요”처럼 현재 진술이 별도로 있어도, 문장 단위 검사가 어느 구간을 현재 진술로 확실히 분리하지 못하면 건너뛴다. 이 보수적 처리의 대가는 일부 현재 형태 진술을 놓칠 수 있다는 것이다. 매퍼의 부정·과거 처리는 아직 미해결이므로, 생성 경로에서 별도 검사하고 합성 대사로 검증해야 한다(`docs/decisions.md:1266–1267,1336`).

**버린 대안 — LLM 지시문만으로 금지 범주를 처리.** 현재 코드에도 영어 낱말 차단과 재검증이 있지만, 프롬프트만으로 의미 오염이나 금지 대상을 막을 수는 없다(`tools/gen3d/prompts.py:517–530`).

## 5. 규칙 형태와 실험 비교

**선택 — 규칙 경로가 먼저다.** 규칙 사전이 형태를 정하면 현재 규칙 프롬프트를 그대로 쓴다. 규칙이 형태를 정하지 못했으나 참여자가 구체 형태를 말한 증거가 있을 때만 LLM 후보를 만들고, 규칙 결과를 덮어쓰지 않는다. 무형태·금지·불확실 판정은 LLM에 넘기지 않는다.

기존 실험 흐름과 LLM 보조 흐름은 세션별로 구분한다. 세션 기록에 설정 플래그, 조건 배정, 프롬프트 방식, 사전·검증기 판, 모델 digest를 남긴다. 도중에 방식을 바꾸면 변경 전후를 별도 분석 층으로 보고하고, “LLM 사용 여부”를 공변량으로 기록한다. 공변량 하나로 조건 차이가 사라진다고 간주하지 않는다. 가능하면 참여자 단위 조건을 고정한다. G62도 형태 생성이 측정값에 영향을 줄 수 있어 공변량 기록을 결정했고, G73/G75/G77은 각 기능을 설정 플래그로 켜도록 했다(`docs/decisions.md:765,1109,1164,1205`).

**버린 대안 — LLM이 매번 형태를 새로 판단하거나 규칙 값을 대체.** 알고리즘·측정 조건이 더 크게 바뀌고, 같은 발화에서 어느 경로가 쓰였는지 해석하기 어려워진다.

## 6. 재현성·기록과 위기·확인 판정

**선택 — 별도 설정 플래그와 버전이 있는 기록·캐시를 둔다.** 모델 digest, 프롬프트 판과 해시, 온도, seed, 입력 해시, 원시 출력, 인용 검증 결과, 기각 사유, 선택된 영어 형태 이름, 그림·메시 seed와 자산 해시, 관문 결과를 기록한다. 캐시 키에는 입력 발화 해시·발화 정규화 판·모델 digest·프롬프트 판·금지 목록 판·생성 파이프라인 판을 포함한다. 같은 입력의 재호출 대신 저장된 결과를 재사용하되, 캐시도 안전 판정 뒤에만 읽는다.

**위기·확인 판정이 한 번이라도 있었던 세션은 호출하지 않는다.** 캐시가 있더라도 마찬가지다. 이는 G77의 기존 원칙을 그대로 적용한다(`AGENTS.md:12`; `docs/decisions.md:1210`; `chatbot/ifs_chatbot/llm_fill.py:154`; `chatbot/ifs_chatbot/selection.py:301–308`). 원시 출력과 인용은 참여자 자료이므로 로컬 세션 기록에만 두고 git에 올리지 않는다(`AGENTS.md:14`; `docs/participant-protection.md:47`).

**버린 대안 — 온도 0·seed만으로 재현을 주장.** G77 실측에서는 가드 모델을 함께 올렸을 때 고정 설정에도 원시 출력이 바뀐 사례가 있었다. 기록과 캐시가 결과 추적에 필요하다(`docs/decisions.md:1263`; `docs/chatbot-design.md:356–357`).

## 7. 참여자에게 보이는 내용

**선택 — 어떤 발화에서 어떤 형태 낱말을 얻었는지 인용과 함께 보여 주고, 수정하거나 거절할 수 있게 한다.** G75처럼 그림 단계에서는 모양만 보게 하고, 모델이 만든 이미지는 메시 생성 전에 확인받는다. 참가자는 인용된 형태 낱말을 고치거나 지우고, 그 수정도 새 입력으로 같은 안전 관문을 거친다.

**새 고정 문구 초안(`draft`):**  
> “이 말에서 ‘{인용된 형태 낱말}’을 바탕으로 모양을 만들어 봤어요. 다르면 모양 낱말을 고치거나 [이 중에는 없어요]를 눌러 주세요.”

이 문구는 IRB 대상이므로 프로토콜에 `status: draft`와 결정 출처를 남기고 버전을 올린다(`AGENTS.md:13`; `docs/decisions.md:1165,1168,1207`).

**버린 대안 — 출처를 감추거나 수정할 수 없는 결과만 제시.** 참여자는 모델이 발화를 어떻게 해석했는지 알아차리고 정정할 수 있어야 한다. 기존 G77도 인용과 함께 보여 주고 고칠 수 있게 한다(`docs/decisions.md:1207`).

## 8. `AGENTS.md` 원칙 1·2 새 문안

**선택 — LLM 예외를 [맞는 게 없어요] 뒤의 제한된 형태 후보 추출로 한정한다.** 아래 문안은 그대로 붙일 수 있다.

> 1. **LLM은 정해진 유도와 제한된 형태 후보 추출에만 쓴다.** 장면 속성(IFSSceneSpec)은 사전·규칙(화이트박스)이 먼저 정한다. 같은 설정·사전·기록을 재사용하는 기존 규칙 경로는 같은 확정 텍스트에서 같은 추출 결과를 내야 한다.  
>    - **면담 질문 생성:** 기존 검증을 통과한 면담 질문 생성에만 LLM을 쓴다.  
>    - **형태 생성 프롬프트 후보(G82):** [맞는 게 없어요]를 누른 뒤, 규칙이 형태를 정하지 못했지만 참여자가 형태를 구체적으로 말한 경우에 한해, 로컬 LLM은 참여자 발화만 읽고 형태 낱말·영어 형태 이름·참여자 원문의 인용 구간을 제안할 수 있다. 면담자 질문과 챗봇 문구는 입력하지 않는다. LLM은 전체 그림 프롬프트를 만들지 않는다. 규칙이 나머지 프롬프트를 구성한다. 인용 일치, 현재 긍정 진술, 허용 형태, 사람·얼굴·동물 및 메시로 그릴 수 없는 범주 검증과 그림·메시 관문을 통과한 후보만 참여자에게 보인다. 형태를 말하지 않았거나 판정이 불확실하면 생성하지 않는다. 사용자가 확인한 경우에만 장면에 쓰며, 생성 후보의 출처와 근거를 별도 기록한다.  
>    - 모델 digest·프롬프트 판·온도·seed·입력 해시·원시 출력·기각 사유·관문 결과를 기록하고 캐시한다. 위기·확인 판정이 있었던 세션에서는 캐시 조회를 포함해 LLM을 부르지 않는다. 참여자 원문과 원시 출력은 git에 올리지 않는다.  
> 2. **사용자가 답하지 않은 내용을 시스템이 임의로 추론하지 않는다.** 말한 것이 추론한 것을 덮어쓴다. 비어 있는 슬롯은 비어 있다고 표시한다(기본값과 미지정을 섞지 않는다). 사전에 없는 형태라도 참여자가 형태를 구체적으로 말했으면, 그 말의 인용이 검증된 생성 후보를 제안할 수 있다. 형태를 전혀 말하지 않았거나 현재 형태를 확인할 수 없으면 생성하지 않는다. 생성 메시에는 말하지 않은 세부가 들어갈 수 있으므로 ‘생성’ 출처를 별도로 기록하고, 참여자가 확인한 후보만 장면에 쓴다. 모델은 색·재질·크기·위치·거리·비율을 정하지 않는다. 메시 크기는 규칙으로 맞추고 사용자가 정한 값으로만 조절한다.

**버린 대안 — G62 규칙을 전부 삭제.** 이번 변경의 목표는 사전 밖 형태를 열어 주는 것이므로 나머지 규칙·기록·확인 장치는 유지한다(`AGENTS.md:5–9`; `docs/decisions.md:760–766`).

## 9. 구현 범위와 첫 단계

**선택 — 기본 꺼짐 플래그를 둔 별도 G82 경로로 구현하고, 첫 단계는 합성 대사 오프라인 평가로 한다.** 기존 G77을 무리하게 재정의하지 않고, 새 경로의 입출력·검증·기록을 검증한 다음에만 실험 설정으로 켠다.

첫 단계는 **실험 경로에 연결하지 않고 합성 대사로 후보 추출·기각 기록을 평가하는 것**이다. 실패하거나 호출을 건너뛰면 기존 규칙 결과를 그대로 두고, [맞는 게 없어요] 뒤 G73/G75의 기존 경로로 넘어간다. G73도 차단·실패·시간 초과 시 기존 경로를 사용한다(`docs/decisions.md:1106`).

**버린 대안 — 처음부터 본 실험에 플래그를 켬.** 현재 G77 형태 출력은 드물었고, G81에서도 사전 밖 형태가 자주 후보 단계까지 가지 못했다. 먼저 합성 대사에서 안전 경로와 유용성을 확인해야 한다(`docs/decisions.md:1263,1331,1337`).

## 10. 약한 지점 3가지와 확인 방법

**선택 — 아래 세 가지를 구현 승인 전 평가 항목으로 둔다.**

1. **영어 형태 이름이 한국어 인용과 의미상 맞는지 자동 보장하기 어렵다.** 금지 목록은 위험 범주를 거를 뿐 번역의 정확성을 입증하지 않는다. **확인:** 사전 밖 합성 형태 목록을 이중 언어 검토자가 원문·한국어 후보·영어 이름·그림을 함께 판정하고, 불일치율과 기각률을 기록한다.
2. **부정·과거·타인·가정 발화는 문장 경계와 문맥에 따라 오탐·누락이 난다.** 현재 매퍼에도 관련 미해결 사례가 있다. **확인:** 최소대립 합성 문장 묶음과 여러 발화에 걸친 정정 사례를 만들고, 허용·차단 오분류를 따로 센다(`docs/decisions.md:1266–1267`).
3. **그림 후보 자체가 참여자의 심상에 영향을 줄 수 있고, 모델 출력은 매번 다를 수 있다.** 그림을 고른 세션에서 후보 노출 효과와 본 연구 조건이 섞일 수 있다. **확인:** 그림 제시 여부·제시 순서·선택·거절을 기록하고, 노출된 세션을 제외한 민감도 분석을 자료 열람 전에 정한다. 동일 입력 재실행도 교차 프로세스에서 확인한다. G75도 그림 노출의 암시와 별도 분석 필요를 기록했다(`docs/decisions.md:1168`; `docs/chatbot-design.md:346,356`).

**버린 대안 — CLIP·가드 모델이 이 문제를 해결한다고 간주.** 그림 관문은 금지 대상·그림 품질 판정의 일부를 맡지만, 인용의 의미와 영어 번역이 정확한지 또는 후보가 심상을 바꾸는지는 판정하지 않는다.

## 책임자가 정해야 하는 것

- G82를 **본 실험에 적용할지**, 적용한다면 LLM 보조 조건을 별도 조건으로 고정할지.
- 구조화 출력의 영어 형태 이름을 허용할지, 아니면 사전 밖 낱말을 다룰 제한된 번역 방식을 추가할지.
- 새 참여자 문구와 수정 UI를 IRB 절차·프로토콜 버전에 어떻게 반영할지.
- 원시 출력과 인용이 포함된 로컬 기록의 접근·보유 기간을 어떻게 정할지.
