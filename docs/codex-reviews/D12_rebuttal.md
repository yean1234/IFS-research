## 반박

- [심각도 높음] **갈래·덮어쓰기는 원칙 2가 허용하는 범위를 넘어섭니다.** 다시 적기 안내는 글을 물체 모양 생성에 쓴다고 알립니다. 그 글의 밀도·비율·투명도·발광을 장면 값으로도 쓰면, 그 용도를 알리지 않은 채 입력의 의미를 확장합니다. “참여자가 말한 값”이라는 사실만으로 조절 화면의 초기값에 옮겨도 된다는 동의가 되지는 않습니다. 재진술을 형태 생성에만 쓰는 Claude 안을 유지하거나, 장면 속성까지 쓰려면 별도 고지·동의와 프로토콜 검토를 거치고 참가자가 확인한 값만 적용하십시오. 출처도 `resaid`만으로 뭉뚱그리지 말고 값별 글자 범위와 적용 경로를 기록해야 합니다.

- [심각도 높음] **두 집단이 배치 구간만 다르다는 설계 조건과 결과변수에 영향을 줍니다.** 재진술 단계 자체는 공통이라도, 새 입력으로 안개 렌더·발광·입자 밀도·투명도를 바꾸면 물체의 대비·가시성·친숙함이 달라집니다. 이는 “보기만/직접 배치” 외의 장면 차이를 만들고 거리감·멈춤 거리에도 영향을 줄 수 있습니다. [design-backbone.md](<<repo>/docs/design-backbone.md>) 2절은 두 집단의 차이를 배치 구간으로 한정하고, G62-e는 거리 결과변수를 위해 렌더 조건을 통제합니다. 본 실험에 미루는 결정은 유지하고, 별도 시행에서도 적용 전후 렌더 변수를 기록하고 비교 가능성을 평가하십시오.

- [심각도 높음] **G72의 `layout.size` 불변만으로 거리 통제가 보장되지 않습니다.** 비율 덮어쓰기 자체는 `layout.size`(가장 긴 변)를 바꾸지 않지만, 안개 밀도·투명도나 파티클·발광은 보이는 경계와 대비를 바꿉니다. G62-e의 가장 긴 변 정규화는 이 렌더 변화까지 상쇄하지 않습니다. 각 렌더 경로의 실측 치수·가시성·조명 조건을 기록하고, 거리 측정에 미치는 영향을 사전 평가하십시오. [G72 결정](<<repo>/docs/decisions.md:1068>)도 비율은 가장 긴 변 안에서 모양만 바꾸는 것으로 정합니다.

- [심각도 높음] **“같은 매퍼를 다시 돌린다”는 것이 재진술 전용 매핑 규칙을 뜻하는지 불분명합니다.** 기존 매퍼는 문장 맥락·부정·비유·직접 진술 우선순위로 확정 텍스트를 해석합니다. 재진술은 과제가 다르므로 같은 규칙을 그대로 적용하면 “넓게 펼쳐진 안개”의 비율뿐 아니라 맥락상 제외되어야 할 표현이나 다른 슬롯까지 읽을 수 있습니다. 적용할 규칙과 읽을 슬롯을 명시적으로 제한하고, 확정 스펙 매핑과 재진술 매핑을 별도 버전·기록으로 남기십시오.

- [심각도 높음] **WordNet 거르개는 사람·동물 유사 형상을 막는 안전 관문으로 충분하지 않습니다.** 사람을 닮은 마스코트·캐릭터·인형은 물리적 사물 뜻도 가지므로 `physical_entity` 통과가 가능하고, 영어 번역어의 모든 뜻에 금지 상위어가 있는지 보는 방식은 문맥을 모른 채 오차단·누락을 함께 만듭니다. 특히 금지 범주 판정이 대역어 선택에 종속됩니다. 사전·WordNet만으로 통과시키지 말고, 승인된 물체 범위와 사람 유사 출력 차단을 별도 검증하며 통과 실패는 차단 처리하십시오.

- [심각도 중간] **대역 사전의 라이선스와 다의어 문제를 해결된 것처럼 채택했습니다.** Claude 안도 한국어기초사전의 다운로드 형식·명사 필드·CC BY-SA 조건을 확인하지 못했다고 적었습니다. 판·해시를 고정해도 사용·재배포 조건은 해결되지 않습니다. 또 대역 후보가 2개일 때 “뜻마다 후보”를 만들면 실제 문맥에 맞지 않는 영어 명사구도 노출될 수 있습니다. Codex 안의 승인 목록을 단순한 사전 확장으로 기각하지 말고, 먼저 사전의 라이선스·필드·다의어 표본을 확인하십시오. 승인 목록은 범위를 좁히는 검증 단계로 사용할 수 있습니다.

- [심각도 중간] **대기 상한과 사용자 이탈 경로가 불명확합니다.** 후보 2개를 순차 생성하면 회당 생성만 약 1분이며, 모델 적재·검증 시간이 더해집니다. 2회 재진술이면 총 대기는 약 2분이 아니라 그에 근접한 여러 분이 될 수 있습니다. “고정 문구·경과 막대만”으로는 생성기 정지, 시간 초과, 세션 종료 시 복귀가 정해지지 않습니다. 전체 최대 대기, 취소/건너뛰기, 타임아웃 뒤 기준 후보 복귀를 명시하고 서버·브라우저가 중단 상태를 일치하게 기록하십시오.

- [심각도 중간] **G59-11 민감도 분석은 노출 기준도 포함해야 합니다.** `[맞는 게 없어요]`를 누른 세션을 기존 정의대로 유지하는 것은 적절하지만, 생성 후보를 골랐는지만으로 나누면 재진술·대기·실패·차단을 경험했으나 후보를 선택하지 않은 참가자를 놓칩니다. 선택 여부와 별개로 재진술 화면 노출, 입력 제출, 생성 시도, 후보 제시를 각각 기록하고, 해당 절차를 경험한 세션을 포함한 민감도 결과를 사전 정의하십시오. [G59-11](<<repo>/docs/decisions.md:684>)의 “자료를 보기 전에 정한다”는 원칙에 맞춰야 합니다.

- [심각도 중간] **기록안에 덮어쓰기 값의 스키마·재현 정보가 빠져 있습니다.** `selection.v0.4`에 출처 이름만 더하면 기존 `finalOverrides`, `sourceDetails`, 비율 기록과의 연결이 보장되지 않습니다. 현재 스키마는 생성 메시를 스펙 슬롯과 분리하고, G72 비율은 별도 슬롯·축 기록으로 다룹니다. 각 재진술 값의 슬롯, 원문 위치, 매퍼·사전 판, 최초값과 최종값, 적용 여부, 후보/렌더 경로를 스키마에서 명시하고 검증해야 합니다. 원문은 git 밖에 두되 파일 접근·삭제·백업 절차도 [participant-protection.md](<<repo>/docs/participant-protection.md>)와 맞추십시오.

- [심각도 낮음] **두 안을 가르는 1회·1후보 대 2회·2후보 선택의 근거가 약합니다.** 다의어를 모두 후보로 낸다는 이유는 재진술 횟수를 2회로 늘리는 근거와 별개입니다. 2회·회당 2개는 대기 시간을 늘리고 후보 비교를 추가합니다. Claude 안이 제시한 상한을 그대로 채택하기보다, 실제 서버에서 최악 대기·실패율을 측정하고 사전 정의한 지연 상한에 맞춰 회차와 후보 수를 결정하십시오.
