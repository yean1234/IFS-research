너는 이 연구 저장소의 설계 자문이다. 파일을 수정하지 말고 읽기만 해라. 한국어로 답하라. 다른 설계안은 보여 주지 않는다. 네 안을 독립적으로 내라.

## 맥락
- 연구: IFS Find→Focus→Flesh out 면담 챗봇 → 확정 텍스트 → 화이트박스 규칙 매핑(SceneSpec JSON) → Unity VR 형상(Quest). 저장소 원칙은 AGENTS.md, 연구 설계는 docs/research-design.md(원본 형상 1개 + 속성 하나만 바꾼 변형본 4개에 "내 것 같다" 평정, RQ1–3).
- 연구 책임자가 렌더 결과(모의 응답을 렌더한 시트 3장, 저장소에는 없음)를 보고 낸 문제 제기:
  1. 구름 표현이 잘 되지 않는다.
  2. 결과가 도형 위주다. 선행연구들은 도형만 쓰지 않고, 사용자가 직접 만들게 하거나 쓸 수 있는 에셋을 미리 정해 둔다. 미리 정해 두지 않는다면 다양한 응답을 반영해야 하는데, 그러면 3D 생성 모델 말고는 답이 없지 않은가. 지금 도형으로 잘 돌아가도 참여자가 무엇을 말할지 모른다.
- 다른 에이전트가 낸 개선 제안(효과 순): (1) 사전에 형태 낱말 추가(구름·액체·빛·불꽃, 렌더러는 그대로), (2) 새 형태 추가(선·엉킴, 얇은 판·천, 스키마와 렌더러 변경), (3) 매퍼 오류 수정(자세가 참여자 자신의 것인지 구분, "거의 투명"이 0이 됨, 거리 0).

## 이미 알고 있는 것 (되풀이하지 말 것)
- 형태는 두 경로다: `form.type`(blob/mist/shell/fragments, 절차 모형 + IFS 셰이더의 정점 변위)과 모양 낱말(`_unmapped` category shape → Sphere/Cube/FlatCylinder/Cone, docs/shape-mapping.md). 구름·연기는 사전에서 mist로 간다.
- docs/imagery-targets.md: 내적 경험이 묘사되는 형태를 A 사람, B 동물, C 사물 은유, D 추상·감각 형태, E 심상 없음으로 나눴고, 지금 범위는 D다. C는 사물 모형 대신 속성으로 나눠 그리고, A·B는 범위 밖으로 뒀다. 형태별 빈도 자료는 없고 시험 문장은 합성 문장이다.
- docs/research-design.md 9.1절: 규칙 렌더를 택한 이유는 속성 하나만 통제해 바꿔야 하기 때문이고(생성 모델은 한 낱말을 바꿀 때 다른 속성이 함께 바뀌지 않는다고 보장하기 어렵다고 판단, 문헌 확인은 아님), 원칙 1(장면 속성은 사전·규칙만)·원칙 5(로컬 실행)도 이유다. 생성 모델과의 비교는 후속 연구로 적어 뒀다.
- 원칙 2: 참여자가 말하지 않은 내용을 시스템이 채우지 않는다. 기본값과 미지정을 섞지 않는다.
- 참여자가 VR에서 `form.type`을 바꾸는 조정 입력은 있다(SetCategory). 모양 자체를 조정하는 입력은 없다.
- 일정: 12/2 투고(약 10일), 그 전에는 참여자 없이 팀 내부 시행만 가능할 수 있다.

## 설계해 달라는 것
각 항목에 하나의 안을 정하고 이유를 2–3문장으로 적어라. 대안을 나열만 하지 말 것. 위 9.1절의 기존 입장이 틀렸다고 보면 그렇게 말하고 근거를 대라.
1. **열린 입력에 대한 표현 전략**: 참여자가 무엇을 말할지 모른다는 조건에서, 형상을 무엇으로 만들 것인가. (닫힌 절차 모형 집합 확장 / 미리 만든 에셋 목록 / 실행 중 text-to-3D·이미지 생성 / 참여자가 직접 조정·제작 / 이들의 조합 가운데 하나를 고르거나 다른 안을 내라.) RQ1–3의 속성 단일 조작, 원칙 1·2·5, Quest 단독 실행 성능을 모두 놓고 판단하라.
2. **"3D 생성 모델 말고는 답이 없다"는 주장에 대한 판정**: 맞다/틀리다/조건부로 답하고, 이 연구에서 생성 모델을 쓴다면 원칙을 깨지 않는 사용 위치가 있는지(있으면 어디, 없으면 왜).
3. **표현하지 못하는 입력의 처리**: 사전·모형에 없는 형태가 나왔을 때 참여자에게 무엇을 보여 주고 무엇을 기록할지.
4. **구름**: 지금 mist 모형으로 구름이 잘 안 보이는 원인 가설과, Quest에서 돌아가는 구체 구현 방식 하나(셰이더·메시·파티클 수준까지). unity/Assets/IFS 아래 실제 코드를 읽고 답하라.
5. **다른 에이전트 제안 (1)–(3)의 순서 판정**: 그대로/바꿈. "사전 낱말만 추가하면 렌더러를 손대지 않고 반영이 늘어난다"는 주장이 연구 책임자의 문제 제기 1과 어떻게 맞거나 어긋나는지.
6. **범위를 넓힐지 정하는 자료 기준**: 어떤 자료에서 어떤 수치가 나오면 도형·절차 모형 범위를 유지하고, 어떤 수치가 나오면 에셋·생성 쪽으로 가야 하는지. 10일 안에 참여자 없이 얻을 수 있는 자료와, 파일럿에서 얻을 자료를 나눠라.

- 마지막에 "가장 불확실한 결정" 2개와 확인 방법.
