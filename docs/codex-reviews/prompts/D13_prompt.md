# D13 — 원칙 1 변경 검토: 근거 인용을 단 LLM 추출로 매퍼의 빈칸 채우기

당신은 이 저장소의 설계자입니다. 코드를 고치지 말고 한국어로 답하세요. 다른 설계자의 답은 보지 못합니다.

## 배경
- 원칙 `AGENTS.md`(특히 1·2·4·5), 설계 뼈대 `docs/design-backbone.md`(25행: LLM은 면담 질문만, 물체는 사전·규칙, 같은 말이면 같은 물체. 76행 한계: 사전에 없는 낱말).
- 지금 추출: 확정 텍스트 → 규칙 매퍼 v2(`chatbot/ifs_chatbot/scene_builder_v2.py`, 사전 `shared/lexicon/scene_params.v2.json`) → IFSSceneSpec(`shared/schemas/scene-spec.v2.4.json`). 못 읽은 낱말은 `_unmatched`에 남고 슬롯은 빈다. 참여자는 후보 고르기·조절 화면(`chatbot/ifs_chatbot/selection.py`, `web/stage.js`)에서 값을 고친다.
- 연구 책임자의 문제 제기(2026-11-28): 사전 매핑의 한계가 너무 뚜렷하다. LLM으로 말을 JSON으로 바꾸는 구현은 선행 연구(LLMER IEEE TVCG 2025, HOG-Layout CVPR 2026, PARSE EMNLP 2025 Industry — 연구 책임자가 준 2차 요약이고 원문 미확인)가 있다. 제안: LLM이 스펙 JSON을 만들되 값마다 참여자 원문의 어느 낱말을 근거로 했는지 태그를 달게 하고, 말하지 않은 속성은 못 만들게 한다.
- 메인의 잠정 판단(반박해도 된다): 매퍼는 그대로 두고 LLM은 매퍼가 비운 슬롯·`_unmatched` 낱말만 채운다. 값마다 ① 인용 검사(원문 글자 그대로 있는가) ② 규칙 검사(인용 구간에 부정·과거·타인·비유 규칙, 허용 슬롯·enum) ③ 참여자 확인(조절 화면에 따로 표시) ④ 재현(온도 0·seed·digest·텍스트 해시 캐시). 출처는 `llm`으로 따로 적는다. 12-02 본 실험에는 쓰지 않는다. 먼저 합성 대사(`chatbot/scenarios/`, 검증 자료 `docs/validation/`)로 재고 결정한다.
- 로컬 모델만 쓴다(Ollama, 면담에 쓰는 모델은 `chatbot/config/experiment.toml`). 위기 판정 뒤에는 LLM을 부르지 않는다.

## 과제
원칙 1을 바꿀지, 바꾼다면 어떻게 바꿀지 설계안을 낸다. "바꾸지 않는다"가 답이어도 된다.

1. **판단**: 원칙 1을 (a) 그대로 (b) 빈칸 채우기로 좁게 열기 (c) LLM 추출을 주 경로로 — 어느 것이 이 연구(물체가 실험 자극이고 결과변수가 거리, 예비 연구, IRB 없음)에 맞는가. 논문에서 심사자가 물을 것과 답.
2. **과한 해석을 막는 장치**: 인용이 진짜여도 값이 추론인 경우(「무거워요」→ 색 짙음)를 무엇으로 막나. 슬롯마다 "말한 것"의 기준을 어떻게 정의하나(슬롯 정의·허용 근거 유형). 기계 검사로 되는 것과 안 되는 것을 가른다. 인용 구간 최소 단위, 한 인용이 여러 슬롯을 채우는 것을 허용할지.
3. **출력 형식과 검증기**: LLM 출력 JSON 틀(값·charSpan·인용문·근거 유형), 제약 디코딩/스키마 강제 여부, 검증 실패 때 처리(버림·재시도 횟수), 매퍼 값과 충돌할 때 우선순위.
4. **재현·기록**: "같은 말이면 같은 물체"를 어디까지 보장할 수 있나(같은 PC·다른 PC), 무엇을 기록하나, 스펙 provenance 표기와 스키마 변경 범위.
5. **참여자 화면**: LLM이 채운 값을 참여자에게 어떻게 보이고 확인받나. 암시 효과(보여 준 값에 끌림)와 문구(초안, 원칙 3·7·8).
6. **평가 설계**: 켜기 전에 잴 것 — 자료(합성 대사, held-out 구성), 지표(근거 없는 값, 과한 해석 비율의 사람 판정 절차, 매퍼와의 일치, 빈칸 채움률, 반복 실행 일치율), 통과 기준 숫자, 미리 정할 중단 기준.
7. **바꿀 문서 문장**: `AGENTS.md` 원칙 1·2와 뼈대 25행의 새 문장 초안(바꾸는 안일 때).
8. 이 안의 가장 약한 곳 3가지.

- 12-02 실험 경로(`experiment.toml`)의 출력은 바뀌지 않아야 한다(기본 끔).
- 분량 A4 세 쪽 이내. 파일 줄 번호 근거는 필요한 곳만.
