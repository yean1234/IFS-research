# D7 — 멈춤 거리 과제 다시 설계 · 눈높이 정규화 (독립 설계안)

당신은 이 저장소(IFS 심상 외부화 VR 연구, Unity + Python)의 설계 검토자입니다. 코드를 고치지 말고 **설계안만** 한국어로 내세요. 다른 검토자의 답은 볼 수 없습니다. AGENTS.md의 작업 원칙을 지킵니다.

## 배경
2026-11-26 교수님 피드백 가운데 설계가 갈릴 수 있는 두 가지입니다.

1. **멈춤 거리 과제**: 지금은 물체가 다가오고 참여자가 멈춤 버튼을 한 번 눌러 거리를 정한다. 피드백: "한 번에 정하게 하지 말 것. 시스템이 물체를 정해진 루프·경로 안에서 계속 움직이고, 참여자는 원하는 거리에 멈출 때까지 멈춤 버튼을 여러 번 누를 수 있게(forgiveness)."
2. **눈높이 정규화(RQ2·RQ3)**: "참여자 키가 달라 눈높이가 다르다. 어떤 키가 들어오든 똑같은 눈높이가 되도록 정규화."

## 먼저 읽을 것 (필요한 부분만 grep)
- `unity/Assets/IFS/` 아래 멈춤 거리(stop distance), 배치(placement), 머리 위치·높이 기록, 러너 설정 코드와 테스트
- `unity/Assets/StreamingAssets/IFS/placement_task*.json`
- `docs/research-design.md`, `docs/decisions.md`의 멈춤 거리·높이 관련 항목, `docs/headset-checklist.md`
- 분석기(`chatbot/` 또는 `tools/` 아래 eval)의 멈춤 거리·높이 열

## 답할 것
### A. 멈춤 거리 과제
1. 지금 구현을 5줄 안으로 요약(경로, 속도, 시행 수, 기록 열).
2. 새 설계안: 경로 모양(왕복? 범위 최소·최대 거리, 속도 프로필, 시작 방향·시작 거리의 무작위화 여부), 버튼 규칙(멈춤 → 다시 움직임 → 확정을 어떤 입력으로 가르는지), 확정 방법, 시간 상한, 한 번도 누르지 않았을 때 처리.
3. 무엇을 기록하고 무엇을 주 값으로 삼을지(마지막 멈춤 거리, 멈춤 횟수, 각 멈춤의 거리·방향, 통과 횟수 등)와 그 이유. 다가올 때 멈춤과 멀어질 때 멈춤의 히스테리시스(반응 시간 편향)를 어떻게 다룰지.
4. 직접 배치 조건에서 "방금 놓은 거리"에 끌리는 문제(G59-11)에 이 설계가 주는 영향.
5. 기본값에서 예전 기록과 바이트 단위로 같아야 한다는 지금까지의 관례(새 설정은 기본 꺼짐)와 어떻게 맞출지. 문구 파일 버전.
6. 선행연구에서 참고할 것(대인 거리 stop-distance, method of adjustment/limits, 계단법)이 있으면 이름만. 확인하지 못한 서지는 "확인 필요"로.

### B. 눈높이 정규화
1. 지금 코드가 눈높이·물체 높이·시작 위치를 어떻게 다루는지 요약(앉은 자세인지 선 자세인지 포함).
2. 가능한 방식을 비교: (a) 가상 카메라 높이를 모두 같은 값으로 고정(리그 오프셋) (b) 가상 세계는 그대로 두고 물체·경로·바닥 표시를 눈높이 기준으로 배치 (c) 기록·분석만 눈높이 기준 단위로 정규화 (d) 조합. 각각 지각(거리 지각·바닥 어긋남·멀미), 안전(실제 바닥), 구현 비용, RQ2·RQ3 자료의 비교 가능성.
3. 권고안 하나와 구체 값(기준 눈높이, 보정 시점, 보정 절차, 실패 시 처리), 기록할 열.
4. 권고안이 깨뜨릴 수 있는 기존 테스트·golden과 피하는 법.

### C. 구현 순서
파일 단위 작업 목록(추가·수정 파일, 새 설정 이름, 테스트)과 위험.

## 이미 알고 있는 것 (다시 지적하지 말 것)
- IRB 판정이 필요하다는 점, 표본이 작다는 점, 멈춤 거리가 물체에는 처음 쓰이는 지표라는 점.
- 자리 문항 `want_move`는 이번에 뺀다(교수님 결정). 면담 첫 질문은 '우선순위가 가장 높은 일'로 바뀐다.
- 점검 문항을 멈춤 거리 앞으로 옮기는 설정(`checkBeforeStopDistance`)은 이미 있다.
