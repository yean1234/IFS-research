## 확인해 달라는 것
지적마다 "고쳐짐 / 덜 고쳐짐 / 새 결함"으로 답하고, 덜 고쳐졌거나 새 결함이면 재현 입력과 파일:줄, 고칠 방법 한 줄을 적어라.
1. **문항 분리(CP5-1)**: '내 것' 세션이나 0.2 기록이 Q1(`nearMinusFar`) 집계에 들어갈 수 있는 경로가 남았는가. 문항이 다른 세션이 평균되는 곳이 남았는가.
2. **크기 물리 단위(CP5-2)**: Unity의 `wM/loM/hiM`(`RenderedSize`)과 웹이 기록하는 `widthM`이 같은 양을 가리키는가. 자세 스케일이 있는 spec에서 두 값의 정의가 어긋나는가. log(미터) 비교와 too_close 문턱의 부호·단위.
3. **보기 뒤 보고(CP5-3)**: `first_viewing_utc`와 보고 `createdAtUtc`의 비교가 시간대·형식·시계 차이(웹 서버와 Unity가 같은 PC가 아닐 때)에서 틀릴 수 있는가. 러너의 `requirePrereport` 경로가 보고 내용을 자극·순서·화면에 쓰는 곳이 있는가.
4. **연결 검사(CP5-4)**: 정상 절차(챗봇에서 확정 → 보고 제출 → Unity가 spec과 보고 파일을 읽음)에서 **정상 보고가 잘못 제외되는** 경로가 있는가. 특히 (가) Unity manifest의 `sessionId`(spec의 meta.sessionId, 없으면 파일 이름)와 보고의 `sessionId`가 같은 값이 되는가, (나) 챗봇이 확정 때 고정한 장면 파일 sha256과 Unity가 계산한 spec 파일 sha256이 같은 파일·같은 바이트를 가리키는가(v0·v1 대체 매핑, 줄바꿈·재직렬화), (다) 바이트 그대로 복사와 해시.
5. **수정이 만든 새 결함**: 첫 선택과 최종 선택의 처리, 무채색 띠 값(`h: null`)이 분석기·스키마·Unity 복사 경로에서 깨지는 곳, 0.1 보고와 0.2 보고를 섞어 읽을 때, 조건 수별 cb 일반화가 5조건 기존 배정을 바꾸는지.
