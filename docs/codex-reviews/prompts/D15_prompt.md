너는 이 연구 저장소의 독립 설계자다. 파일을 수정하지 말고 읽기만 해라. 한국어로 답하라. 다른 설계자의 안은 보지 못한다.

## 결정된 것 (바꾸지 못함)
연구 책임자가 2026-11-28에 작업 원칙 1을 바꾸기로 했다(G82). 지금은 [맞는 게 없어요] 뒤의 형태 생성 프롬프트를 사전·규칙만 만든다(`AGENTS.md` 1번 "LLM·번역 모델로 프롬프트를 만들지 않는다"). 그래서 사전에 없는 형태 낱말(조약돌, 판때기, "돌덩이 같은 게")은 생성이 시작되지 않는다(`docs/decisions.md` G81, `docs/validation/run-g81-shape-inputs/README.md`).
책임자가 바라는 것: 참여자가 [맞는 게 없어요]를 누르면 **챗봇과 나눈 대화 내용을 바탕으로** 로컬 LLM이 형태 생성 프롬프트를 만들어, 사전에 없는 형태도 로컬 그림·3D 모델이 새로 만들어 준다.

"원칙을 바꾸지 말자"는 답은 필요 없다. 어떻게 바꿔야 피해가 가장 적은지 설계하라.

## 설계할 것
1. **LLM이 무엇을 읽는가.** 확정 텍스트만 / 참여자 발화 전체 / 면담자 질문 포함 대화 전체. 각각의 위험과 고른 것.
2. **LLM이 무엇을 내는가.** 영어 프롬프트 전체 / 한국어 형태 낱말 + 인용 구간(영어는 규칙이나 고정 표가 붙임) / 그 밖. 참여자가 말하지 않은 세부가 섞이는 것을 어떻게 막거나 가려 적는가.
3. **형태를 전혀 말하지 않은 경우**(예: "쑥색이고 차가워요")에 생성하는가. 원칙 2 "형태를 말하지 않았으면 생성하지 않는다"를 어떻게 고쳐 쓰는가.
4. **사람·얼굴·동물, 안개·불꽃 차단**을 LLM 출력에 어떻게 다시 거는가(입력 쪽, 출력 낱말 쪽, 그림 관문 쪽). 부정·과거·타인·가정 문장("예전에는 공이었어요")은 어떻게 다루는가.
5. **규칙 사전이 형태를 잡은 경우**와의 관계. 규칙이 먼저인가, LLM이 늘 만드는가. 실험 도중 방식이 바뀌면 세션 간 비교가 어떻게 되는가(조건·공변량 기록).
6. **재현성·기록.** 모델 digest, 프롬프트 판, 온도, seed, 원시 출력, 기각 사유, 캐시. 위기·확인 판정 세션.
7. **참여자에게 보이는 것.** 무엇을 바탕으로 만들었는지 보여 주는가, 고칠 수 있는가. 새 고정 문구가 필요하면 draft 문안.
8. **`AGENTS.md` 원칙 1·2의 새 문안**(그대로 붙일 수 있게).
9. 구현 범위(바꿀 파일, 설정 플래그, 시험)와 가장 작은 첫 단계. 실패 시 무엇으로 되돌아가는가.
10. 이 설계에서 가장 약한 곳 3가지와 확인 방법.

## 이미 알고 있는 것 (되풀이하지 말 것)
- G77 LLM은 형태 낱말을 거의 채우지 못했다(실측 19건 중 13건 빈 출력, G81에서는 1건만).
- 매퍼가 부정·과거 문장에서 값을 채우는 문제는 따로 미해결로 적혀 있다.
- 생성 메시가 후보에서 빠지는 웹 버그(G81)는 따로 고친다.
- 그림 관문(CLIP)과 가드 모델(kanana-safeguard)은 이미 있다.
