# D11 — 첫 답이 무엇이든 '그 느낌'을 구체 심상으로 이끄는 면담 앞부분

당신은 이 저장소의 설계자입니다. 코드를 고치지 말고 한국어로 답하세요. `AGENTS.md`(작업 원칙)와 `docs/design-backbone.md`(설계 뼈대)를 먼저 읽습니다. 다른 설계자의 답은 보지 못합니다.

## 연구 맥락 (요약)
- 참여자는 요즘 가장 신경 쓰는 일을 떠올리고, **그 일을 떠올렸을 때 드는 느낌**을 면담으로 구체 심상(눈에 보이는 물체)으로 만든다. 물체는 사전·규칙이 만들고, 헤드셋에서 그 물체를 직접 놓거나(직접 배치) 보기만 한다. 결과변수는 그 느낌과의 거리감(문항)과 공간 거리(멈춤 거리·놓은 거리, RQ2)다. 평정 문항은 대상을 '그 느낌'으로 부른다(결정 G66, `docs/decisions.md`).
- 면담 앞부분의 고정 문구는 `shared/protocol/elicitation_protocol.v1.5.json`의 `fixedPhrases`: opening, location, focus_hold, bridge_like_what_plain(그리고 X가 있을 때 결정론 문장 「그 '{X}'은(는) 마치 무엇 같나요?」), fleshout_open. 흐름과 다리 질문 설계는 `docs/chatbot-design.md` §5-3, 결정 G58·G60·G64.
- location 답은 `parse_body_relation`으로 SceneSpec의 `bodyRelation` 슬롯이 된다(`chatbot/ifs_chatbot/extract.py:176,190`). 이 슬롯이 그 뒤(후보·Unity 시작 위치 등)에 쓰이는지 직접 확인하라.

## 연구 책임자가 직접 해 본 세션 (연구자 시험 입력, 실제 참여자 아님)
차례대로 참여자 답: 「빨리 끝내고 싶다」 → 「마음 속에」 → 「빨리 끝내고 싶다는 간절한 마음」 → 「역동적인 형체?」 → 「바람이 불면 천이 펄럭이듯이 물체가 계속 꾸물꾸물 움직이는 느낌」 → 「기본 모형은 구형인 것 같아」 → 「동그란 원?」 → 「크기는 보통 크기고 모양은 구체」 → 「색은 밝은 회색, 밝기는 무광」.

연구 책임자의 지적:
1. 첫 질문에 「빨리 끝내고 싶다」고 답하니 다음 질문이 '그것'으로 돌아오는데 문맥에 맞지 않는다. 이 사례만 고치지 말고, **참여자가 첫 질문에 어떤 종류의 답을 해도**(감정어, 바람·욕구, 생각·판단, 상황·사건, 몸 감각, 이미 심상, 평가·모름 등) 연구 주제에 맞게 심상을 구체화할 수 있게 다듬을 것.
2. 「그것이 몸 안에, 몸 표면에, 아니면 몸 주변에 있나요?」 — 마음속에 든 생각이니 다들 '몸 안'을 고르지 않을까. (실제 답은 선택지 밖의 「마음 속에」였다.)
3. 「준비가 되면 지금 알아차려지는 것을 적어 주세요」, 「지금 그것은 마치 무엇 같나요?」 — 무엇을 적어야 할지 모를 것 같다. 예시 답을 보여 주면 답의 유형을 정해 주는 문제가 생기는가.

## 할 일
각 지적을 **비판적으로** 검토한다(맞는 부분, 틀리거나 과장된 부분, 지적보다 더 근본적인 문제). 그 위에서 면담 앞부분(opening부터 fleshout 들어가기 전까지)의 고친 안을 낸다.

반드시 다룰 것:
- 첫 답의 유형별로 다음 질문이 무엇을 가리키게 되는지. '그것' 같은 지시어 대신 참여자 원문을 되돌려 부르는 방식(원칙 3: 참여자 말만 되돌림)을 쓸지, 어떤 결정론 규칙으로 무엇을 인용할지(LLM에 맡기지 않는다). 원문을 그대로 넣었을 때 어색해지는 경우(동사·문장 답 「빨리 끝내고 싶다」 등)의 처리.
- location 질문의 역할: IFS·Focusing의 Find 단계에서 온 문구다. 이 연구에서 (a) 심상 구체화에 필요한가, (b) 선택지(몸 안/표면/주변)가 예시·선택지 금지(원칙 3)와 어떻게 맞물리는가, (c) **VR에서 거리·위치를 재는 연구에서 면담 중 '몸 안/주변'을 묻는 것이 놓는 자리나 거리 답을 미리 끌어당기는가**, (d) `bodyRelation` 슬롯이 실제로 쓰이는지. 그대로/열린 질문으로/삭제 가운데 권고와 이유.
- 답 형식 안내: 내용 예시 없이 "무엇을 적으면 되는지"를 알려 주는 방법(형식 허락: 짧아도 됨, 모르면 모른다고 해도 됨, 낱말 하나도 됨 등)과, 내용 예시를 줄 때의 위험(답 유형·내용 고정, 요구 특성). 예시를 줄 거라면 어떤 조건에서(중립 연습 과제, 연구 주제와 무관한 대상 등). 근거 문헌이 있으면 저자·연도만 적고 확인 못 한 것은 "확인 못 함"이라 쓴다. 지어내지 않는다.
- 다리 질문 「지금 그것은 마치 무엇 같나요?」가 비유를 원한다는 뜻(눈에 보이는 무언가)을 참여자가 알아듣게 하는 방법. 질문 틀 6개 원칙과의 관계.
- 고정 문구는 IRB 대상 문구 규칙(원칙 7)을 따르되, 이 연구는 지도교수 결정으로 IRB 심의 없이 진행한다(G68). 새 문구는 모두 draft. 문구 수를 불필요하게 늘리지 않는다.
- 두 집단에 똑같이 적용되어 집단 차이를 만들지 않아야 한다(뼈대 2절).

## 출력
1. 세 지적 각각의 비판적 판정(맞음/부분/아님 + 이유, 각 3–6줄).
2. 고친 흐름: 단계 | 문구 원문(전문) | 결정론 규칙(무엇을 인용하나, 어떤 경우 무엇을 내나) | 바뀐 이유. 첫 답 유형 7가지 각각에 대해 실제로 나갈 문장 예를 표로.
3. location 권고(그대로/열린 질문/삭제)와 그에 따른 코드 영향(`bodyRelation`).
4. 답 형식 안내 권고와 위험.
5. 이 안의 가장 약한 곳 3가지.
