# D8 설계안 요청: 형태(메시)를 로컬 생성 모델로 만드는 경로를 실험 파이프라인에 넣기

너는 이 저장소(IFS 심상→VR 외부화 연구)의 독립 설계자다. 저장소는 읽기만 한다. 아래 결정에 대한 **너의 설계안**을 한국어로 쓴다. 다른 설계자의 안은 보지 못한다. 좋다고 맞장구치지 말고, 근거가 약한 부분은 반대하라.

## 연구 책임자의 요청 (바꿀 수 없는 것)

1. 물체의 **형태(메시)** 는 로컬 생성 모델로 만든다.
2. **색·질감** 등은 사전 매핑으로 초깃값을 정하고 사용자가 조절한다.
3. 이를 위해 AGENTS.md **원칙 1·2를 고친다**.
4. 모델을 골라 **현재 실험 파이프라인에 넣는다**.

요청 자체를 뒤집는 안(예: "생성 모델을 쓰지 말자")은 답이 아니다. 다만 범위·조건·안전장치는 네가 정한다.

## 이미 알고 있는 것 (다시 조사하지 말 것)

- 최신 RQ는 `docs/rq-v4-proposal.md`(V4)와 `docs/decisions.md` G59·G60이다. 독립변수는 직접 배치 대 보기만(참여자 간). 주 종속변수는 구별 문항 A1–A7. 놓은 거리·멈춤 거리는 탐색 RQ2의 결과변수다. 물체 시작 위치는 정면 1.5 m 고정이고 Unity는 spec의 `layout.distance`를 쓰지 않는다. 크기는 참여자 조절 7항목 중 하나다(G10).
- 형태는 지금 사전·규칙 + 절차 메시다(`form.type`, `form.base`, 슈퍼쿼드릭 윤곽; 스키마 `shared/schemas/scene-spec.v2.3.json`). 출처 4종(말함/고름/고침/기본값)은 `selection.v0.2.json`에 적는다.
- 기존 결정 G7·G61-a·X40은 "생성형 3D를 값 경로에 넣지 않는다"였고, G5는 "규칙 방식 대 생성+참여자 확인 비교"를 보류해 두었다.
- `docs/gen3d-feasibility.md`(2026-11-22): Shap-E, SDXL→TripoSR을 이 PC(Windows 11, RTX 5080 16 GB, Python 3.11, torch 2.11+cu128)에서 돌렸다. seed 고정 시 바이트 단위로 같았다. 그러나 120개 중 4개만 문장과 맞았고, 안개·선·종이·천이 실패했고, 외형 서술이 없는 답에도 형상을 지어냈다. 코드는 `tools/gen3d/`(generate.py, prompts.py 등)와 `unity/Assets/IFS/Runtime/Experimental/Gen3D/Gen3DGlbLoader.cs`(glTFast 6.21, asmdef `IFS.Gen3D`)에 있다. 모델 환경은 저장소 밖(`gen3d-venv/`, `../gen3d-models`)이다.
- 2026-11-27 조사 결과(`research_notes/심상 외부화 3D 생성 모델 검토/` 세 파일, 필요하면 읽어라):
  - VR에서는 익숙한 물체의 원래 크기가 거리 판단을 크게 좌우한다(Rzepka 2023). 외형에 따라 사람들이 두는 거리가 수십 cm 달라진다(Iachini 2014: 원기둥 약 65 cm, 사람 형상 36–45 cm). 얼굴·눈·위협 단서, 바닥 접촉·그림자, 눈높이도 영향을 준다. 색·밝기 효과는 방향이 일정하지 않다.
  - 외부화한 내적 대상까지의 거리를 결과로 잰 선행 연구는 찾지 못했다.
  - 생성형 외부화 연구는 "내 이미지와 다르다"는 불일치를 흔히 보고했다. 소유감은 고르기·다시 만들기·확인하기가 있을 때 유지된다(시스템 산출물 중 고르기만 하면 소유감 3.14, 함께 만들기 4.60, 7점 아님 원 척도 기준). AI가 만든 이미지는 거짓 기억을 약 2배 늘렸다(Pataranutaporn 2025). 생성 이미지가 정확하다고 느낄수록 불안이 더 올랐다는 예비 연구가 있다(Worry Gallery 2026).
  - 모델 후보: TripoSG(MIT, 8 GB 이상, 형태만 GLB), TRELLIS.2-4B·Pixal3D(MIT, 열린 면을 다룬다고 주장, 공식은 24 GB·Linux, Windows 3.11용 바퀴 없음, 게이트된 의존 모델), Roblox Cube 3D(텍스트→형태, OBJ, 경계 상자 조건, 라이선스 본문 미확인), TRELLIS v1(MIT, 16 GB), Direct3D-S2, SF3D/SPAR3D(게이트). Hunyuan3D는 라이선스가 한국을 제외해 쓸 수 없다. 앞단 이미지 모델 후보는 FLUX.2 klein 4B, Z-Image-Turbo, FLUX.1-schnell(모두 Apache-2.0)이다.
  - 얇은 것·천·종이·안개·불꽃은 SDF/닫힌 면 계열의 알려진 실패 유형이다. 안개·연기·불꽃을 메시로 잘 만드는 공개 모델 근거는 없다.
  - 문장↔형태 일치도는 로컬에서 CLIP/SigLIP 다중 시점 렌더, Uni3D, 공개 VLM 판정으로 잴 수 있다.
- IRB 승인이 없어 참여자 데이터를 모으지 않는다. 지금 할 수 있는 것은 합성 문장 평가와 연구팀 내부 점검이다. 학회 제출 마감은 2026-12-02다.
- AGENTS.md 원칙 3–8은 그대로다(로컬 실행, digest 기록, 위기 대응, 참여자 데이터 비공개 등).

## 답해야 할 것

1. **원칙 1·2의 새 문구**(각 3문장 이내). 무엇이 여전히 금지인지가 분명해야 한다. LLM(면담)과 형태 생성 모델을 구분하라.
2. **파이프라인에서 생성기가 놓이는 자리.** 실행 중 생성인가, 미리 만들어 둔 묶음에서 고르기인가, 둘의 조합인가. 생성이 실패하거나 발화에 형태 서술이 없을 때 무엇을 보여 주는가. 안개·불꽃처럼 메시로 안 되는 범주는 어떻게 하는가.
3. **첫 번째로 붙일 모델과 그 이유**, 두 번째 후보. 이 PC에서 12월 2일까지 실제로 돌릴 수 있는가를 기준으로.
4. **스키마·기록 변경**: scene-spec, selection.json에 무엇을 더하는가(출처 종류, seed, 모델 digest, 프롬프트, 후보 집합, 거부 기록). 기존 2.3과의 호환.
5. **거리 결과변수를 지키는 장치**: 크기 정규화, 사람·얼굴·동물 형상 처리, 바닥 접촉·그림자, 공변량으로 기록할 것.
6. **프롬프트를 어떻게 만드는가**: 한국어 발화 → 영어 프롬프트를 LLM 없이 규칙으로 만드는가. 말하지 않은 내용이 프롬프트에 들어가지 않게 하는 방법.
7. **12월 2일까지의 최소 구현 범위와 통과 기준**(숫자로). 그 뒤로 미룰 것.
8. **이 설계의 가장 약한 점 3개**와, 논문에서 그것을 어떻게 적어야 하는지.

분량은 1,200단어 이내. 파일 경로를 인용할 때는 저장소 상대 경로를 쓴다.
