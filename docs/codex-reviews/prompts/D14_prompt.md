너는 이 연구 저장소의 독립 설계자다. 파일을 수정하지 말고 읽기만 해라. 한국어로 답하라. 경로는 저장소 기준 상대 경로로만 적어라. 다른 모델도 같은 질문을 따로 받고 있다. 네 안만 써라.

## 요청 (연구 책임자)
"참여자가 색상환 팔레트에서 색을 고를 수 있게 해 달라."

## 맥락
파이프라인: 면담(챗봇) → 확정 텍스트 → 사전·규칙 매퍼가 장면 스펙 → 참여자가 웹 화면에서 물체 후보를 고르고 고침(조절 화면) → 헤드셋(Unity)에서 배치·멈춤 거리 측정.

읽을 것: `AGENTS.md`(원칙 1·2·5·6·7), `docs/design-backbone.md`(2절 "물체 고르고 고치기"와 색·조절 칸), `docs/participant-protection.md`, `docs/decisions.md`에서 색·조절·출처 결정(grep), `docs/chatbot-design.md`의 조절 화면 절. 코드: `chatbot/ifs_chatbot/selection.py`, `chatbot/ifs_chatbot/candidates.py`, `chatbot/web/`의 조절 화면, `shared/schemas/selection.v0.5.json`과 스펙 스키마의 색 표현, `shared/protocol/selection_protocol.v0.10.json`, `unity/Assets/IFS/Runtime/Placement/PlacementSelection.cs`.

## 먼저 확인할 사실 (짧게, `파일:줄` 근거)
1. 지금 참여자가 색을 고치는 방법과 고를 수 있는 값의 집합. 색이 스펙·선택 파일·Unity에서 흐르는 형식.
2. 출처 표기(말한 값 / 기본값 / 참여자가 고친 값 / llm_quoted)의 기록 방식.
3. 밝기·투명도 슬롯과 색의 관계.
4. 뼈대·결정 가운데 색상환과 어긋나는 것.

## 설계안에 담을 것
- 어디에 넣는가(웹 조절 화면인지 헤드셋 안인지)와 근거.
- 색상환의 꼴(연속 hue만 / 채도·밝기까지 / 고정 견본 팔레트). 밝기 슬롯과 겹치지 않게 하는 방법. 말한 색이 있을 때와 없을 때의 처음 상태(원칙 2: 기본값과 미지정을 섞지 않는다).
- 기록과 스키마(고른 값 형식, 처음 값, 바꾼 횟수·시간, 출처), 스키마 판, Unity 쪽 변경과 헤드셋 빌드.
- 외부 CDN·라이브러리 없이 구현(원칙 5), 색각 이상·접근성.
- 새 참여자 문구(원칙 7)와 문구 안.
- 분석 영향(색 이름 enum 집계·검증 자료, enum으로 되돌려 적는 규칙).
- 가장 작은 1단계와 미룰 것, 바뀌는 파일, 시험.
- 위험과 확신하지 못하는 점.
