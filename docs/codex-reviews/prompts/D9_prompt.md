# D9 — 감정 형용사·추상 기분 서술에서 구체 심상으로 가는 면담 구조 (독립 설계안)

당신은 이 저장소(IFS 심상 외부화 VR 연구, 로컬 LLM 면담 챗봇 + 규칙 기반 추출)의 설계 검토자입니다. 코드를 고치지 말고 **설계안만** 한국어로 내세요. 다른 검토자의 답은 볼 수 없습니다. AGENTS.md의 작업 원칙(특히 1·2·3·7·8)을 지킵니다.

## 배경
지금까지의 합성 시험은 참여자가 처음부터 "얇은 조개껍데기" 같은 사물을 말하는 경우였다. 실제 참여자는 첫 질문("…그 일을 떠올리면 지금 어떤 느낌이 드나요?", G60)에 "기대돼요", "숨막혀요", "답답해요", "불안해요" 같은 감정 형용사나 추상적인 기분 서술로 답할 가능성이 높다. 연구 책임자의 요구는 이렇다: **이런 답에서 출발해도 참여자가 스스로 구체적인 심상(형태·색·크기·질감·위치)을 말하게 되도록 면담이 구조화되어야 한다.**

## 지금 구현에 대해 확인된 사실 (다시 조사하지 않아도 됨)
- 조건 2(chatbot) 순서(`shared/protocol/elicitation_protocol.v1.4.json`): opening(고정) → location(고정: "그것이 몸 안에, 몸 표면에, 아니면 몸 주변에 있나요?") → LLM find 최대 1회 → focus_hold(고정) → LLM flesh_out 최대 5회 → 고정 차원 프로브 3개("그것에 크기나 모양이 있나요?" / "…색이나 밝기가…" / "…움직임이…") → 확정.
- 질문 틀 6개: anything_else, what_kind, where, like_what("그 '{X}'은(는) 마치 무엇 같나요?"), relationship, then_what. find 단계는 anything_else·like_what만 허용. 어느 틀을 쓸지는 LLM이 고르고 코드 규칙은 없다.
- 컨트롤러(`chatbot/ifs_chatbot/controller.py`)는 발화 종류로 갈라지지 않는다. `extract.py`의 `find_modality`(body_sensation / emotion / image_or_scene …)는 로그에만 쓴다.
- 사전(`shared/lexicon/layer1_lexicon.v0.json`)의 emotion(49개)·sensation(20개) 범주는 슬롯을 정하지 않는다. `anchors.py`에서 감정어는 순위가 낮은 인용 후보이고 "느낌·기분·감정·마음·생각"은 인용하지 않는다. '기대'는 사전에 없다.
- 오프라인 대역으로 돌려 보면: "불안해요" → "'불안'에 대해 더 있나요?" → 프로브 3개 → 슬롯이 모두 빈 채 확정(회색 기본 형상 또는 2×2 기본값 후보, G19). "기대돼요" → "그 '설레요'는 어떤 '설레요'인가요?" 같은 어색한 질문이 검증기를 통과한다. "숨막힌다"는 은유 확인 정규식(`숨이?\s*막히`)에 걸리지 않는다.
- 검증기: "그 '불안'은 마치 무엇 같나요?"와 "그 '불안'은 어디쯤 있나요?"(flesh_out)는 통과. '몸'·'모양'·'보이다'·'생김새'·'떠올리면'을 넣은 LLM 질문은 V5(leak/novel)·V7·V6에 막힌다. 고정 문구는 V1–V9를 거치지 않지만 원칙 7(status·출처 표기, 프로토콜 버전 올림)을 따라야 한다.
- 압박하지 않기 규칙: 짧은 "없어요·모르겠어요" 답이면 그 단계의 LLM 질문을 건너뛴다. 프로브는 차원마다 한 번만 묻는다.
- 가상 참여자는 없고 시나리오는 정해 둔 답 목록을 재생한다(`python -m ifs_chatbot.simulate`, `tests/test_scenarios.py`).
- 기존 조사 `reports/자기 관련 심상 유도 질문.md`: Ikemi의 다리 문장("how is the whole thing felt in you?" → "A rock, a big rock."), Clean Language의 "that's X like what?", ACT "Physicalise the Emotion"(예시·선택지가 있어 원칙 3과 충돌)을 검토했으나 구현하지 않았다.

## 답할 것
1. **진단**: 감정어·추상 서술로 시작한 면담이 형상 없이 끝나는 원인을 단계별로(첫 질문, find, flesh_out, 프로브, 인용 후보 순위) 5줄 안으로.
2. **설계안 하나**: 감정어·추상 서술 → 구체 심상으로 가는 질문 순서. 다음을 정하라.
   - 발화 종류에 따라 흐름을 가를지(규칙 기반 판정: 어떤 신호로 "아직 형상이 없다"를 판정하는지), 아니면 모든 참여자에게 같은 순서를 줄지.
   - 다리 질문을 고정 문구로 둘지, LLM 질문 틀로 둘지, 섞을지. 각 질문의 **한국어 문구 원문**과 근거 출처(Focusing, Clean Language, IFS Flesh out 지침 등), status(spec/draft).
   - 감정어 → (몸의 자리) → (감각의 질) → (형상·은유) 가운데 어떤 단계를 거치게 할지와 순서의 이유. like_what 틀을 언제 강제할지.
   - 몇 번까지 묻고 멈출지, "없어요·모르겠어요·안 보여요"에서 어떻게 물러날지(압박하지 않기와의 균형). 형상이 끝내 없을 때 기록·후속 처리.
   - 조사 문제: 감정어 뒤 조사('불안'은/이), 용언 어간('설레요'를 그대로 되묻는 문제), 사전에 없는 감정어('기대') 처리.
3. **원칙과의 충돌 점검**: 설계안의 각 질문이 원칙 2(추론 금지)·3(참여자 말만 되돌려 묻기, 예시·선택지·비유 금지)·8(치료 아님)과 부딪치는 곳, 그리고 유도 오염(면담자가 '모양'·'보이다' 같은 시각 양식을 먼저 꺼내는 것)이 연구 결과(RQ: 외부화한 형상이 "내가 떠올린 모습과 닮았다")에 주는 위험과 완화책. 검증기를 약하게 만드는 변경이 있으면 무엇을 왜 약하게 하는지.
4. **조건 1(static)과의 형평**: 정적 조건에도 같은 다리 문구를 넣어야 조건 비교가 깨지지 않는가.
5. **시험 계획**: 감정어로 시작하는 시나리오를 어떻게 만들고(가상 참여자를 로컬 LLM으로 둘지, 정해 둔 답 재생으로 둘지), 무엇을 성공 기준으로 잴지(형상 슬롯 채움 비율, 다리 질문 도달률, 검증기 위반 수, 어색한 질문 수 등). 선행 연구 응답 자료를 입력으로 쓸 때 주의할 점.
6. **구현 순서**: 파일 단위 작업 목록(프로토콜 버전, 프롬프트, 컨트롤러, 사전, 검증기, 테스트·시나리오), 기본값에서 예전 기록과 같아야 한다는 관례(새 기능 기본 꺼짐)와 맞추는 법, 위험.

## 이미 알고 있는 것 (다시 지적하지 말 것)
- IRB 판정이 필요하고 새 고정 문구는 심의 대상이라는 점.
- 표본이 작다는 점, 로컬 모델(gemma4:e4b)이 작아 질문 품질에 한계가 있다는 점.
- 감정어에서 색·모양을 사전으로 추론해 값으로 넣는 방법은 G61-a에서 기각했다(원칙 2). 다시 제안하지 말 것.
- 느낌만 말한 사람에게 사물 후보를 내밀지 않는다(chatbot-design 7.4).
