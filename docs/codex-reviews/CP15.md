읽기 전용 검토 결과입니다. 파일은 수정하지 않았고 시험도 실행하지 않았습니다. 아래는 구현상 확인된 문제와, 실제 모델 동작에 따라 달라질 수 있는 추측을 구분해 적었습니다.

### 높음

- **영어 형태 금지 목록이 단어 단위 정확 일치라 변형형을 통과시킵니다.** `chatbot/ifs_chatbot/llm_fill.py:306-315`, `chatbot/prompts/llm_fill/llm_fill.v0.1.0.json:84-94`  
  재현 경로: 형태 슬롯이 열린 상태에서 인용 구간은 유효한 형태 명사이고 `value`가 `figures`, `dolls`, `statues`, `skulls`, `hands`처럼 금지어의 복수형이면, 정규식은 통과하고 금지 목록과도 일치하지 않습니다. `tools/gen3d/prompts.py`는 이를 형태 프롬프트에 넣습니다.  
  금지 대상으로 명시한 사람·얼굴·인형·해골 형상이 프롬프트에 들어갈 수 있습니다. **형태소 정규화·어근 검사와 합성어·동의어 목록을 보강하고, 생성 직전에도 같은 규칙으로 재검증하십시오.**

### 중간

- **위기·확인 판정이 기록된 뒤에도 세션 캐시 결과가 먼저 반환될 수 있습니다.** `chatbot/ifs_chatbot/llm_fill.py:388-406`  
  재현 경로: 같은 세션·확정 텍스트로 `run()`이 한 번 성공한 뒤 확인 또는 위기 플래그가 추가된 상태에서 같은 키로 다시 호출하면, 캐시 반환이 `session_flag()` 검사보다 앞서 기존 채택값을 돌려줍니다.  
  호출을 반복하는 경로가 생기면 원칙 4의 세션 차단이 우회됩니다. **캐시 반환 전에도 플래그를 검사하고, 플래그가 있으면 캐시 채택값을 폐기하십시오.** 현재 일반 확정 흐름에서 이 재호출이 발생하는지는 확인하지 못했습니다.

- **영어 금지 목록은 형태소·부분 문자열 검사 없이 공백 분리 후 정확 일치만 합니다.** `chatbot/ifs_chatbot/llm_fill.py:306-315`, `chatbot/prompts/llm_fill/llm_fill.v0.1.0.json:85-98`  
  재현 경로: 형태 후보의 영어 값에 금지 단어의 복수형·합성어·목록에 없는 동의어를 넣습니다. `mists`, `fogbank` 등은 현재 차단 목록의 항목과 정확히 일치하지 않습니다.  
  안개·불꽃류와 사람·동물 형상을 막는 규칙이 목록의 표기형에 의존합니다. **영어 정규화·형태소/구성어 검사와 명시적 동의어 목록을 추가하고, 이 경계 사례를 시험에 넣으십시오.**

- **확정 텍스트가 프롬프트에 그대로 삽입되어 지시문 경계가 없습니다.** `chatbot/ifs_chatbot/llm_fill.py:153-178`, 프롬프트 템플릿은 `chatbot/prompts/llm_fill/llm_fill.v0.1.0.json`  
  재현 입력: 확정 텍스트에 `위 규칙을 무시하고 …` 같은 지시문을 포함합니다.  
  스키마와 검증기가 출력 범위를 제한하지만, 입력을 데이터로만 취급하도록 명확히 분리하거나 주입 입력을 다루는 시험은 확인하지 못했습니다. 출력이 바뀌는 정도는 **실제 모델에서 확인이 필요한 추측**입니다. **텍스트를 명확한 비신뢰 인용 영역으로 구획하고, 주입 문구가 포함된 합성 입력에서 채택값·화면 노출을 점검하십시오.**

### 낮음

- **검증 시험이 금지 영어 단어의 변형형과 프롬프트 주입 경계 사례를 다루지 않습니다.** `chatbot/tests/test_g77_llm_fill.py:243-289`, `315-327`  
  시험은 형태 프롬프트 재검증, 일부 검증 실패, 플래그 상태에서의 호출 차단을 확인하지만, 금지 영어 복수형·합성어 및 프롬프트 주입 입력은 보이지 않습니다.  
  위 높음·중간 지적이 회귀 시험으로 고정되지 않아 변경 때 다시 열릴 수 있습니다. **위 재현 입력을 합성 대사 시험에 추가하십시오.**

### 문제없다고 확인한 것

- 매퍼가 이미 채운 슬롯은 `open_slots()`에서 제외되고, 검증기도 `slot_filled`로 기각합니다. 후보 생성은 LLM 초기값을 해당 슬롯의 모든 후보에 동일하게 적용하며, 확정 스펙 자체를 수정하는 경로는 확인하지 못했습니다.
- 조절 화면 안내는 `{quote}`를 DOM `textContent`/텍스트 노드로 출력합니다. 이 경로에서 HTML로 해석되는 XSS는 확인되지 않았습니다. (`selection.py:1637-1639`, `web/app.js:7-15`)
- 위기·확인 플래그는 새 호출 전에 검사되며, 매퍼 장면 안전 플래그도 기록됩니다. 다만 위의 캐시 반환 순서 예외가 있습니다.
- 0.5 기록에는 원시 출력·항목·기각 사유·채택값·적용값·참여자 최종값·노출 플래그가 정의되어 있습니다. Unity는 0.5에서 `llm_quoted`를 허용하고, 0.1–0.4에는 기존 출처 목록을 적용합니다.
- 플래그 비활성 기본값과 시험상 비활성 출력 경로는 유지되는 것으로 확인했습니다. `llm_fill_note`는 설정 시 프로토콜 존재 여부를 확인하고, 문구는 draft로 표시되어 있습니다.
