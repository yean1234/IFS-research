### 새로 찾은 문제

- **높음 — 유니코드 닮은꼴 문자로 금지어 우회**  
  [prompts.py:500-509](<repo>/tools/gen3d/prompts.py:500), [shape_english_block.v0.json:14](<repo>/shared/lexicon/shape_english_block.v0.json:14)  
  재현: `skսll` (가운데 문자는 키릴 문자 U+ս), `fоg` (가운데 문자는 키릴 문자 о). 형식 검사는 실패하지만 토큰에서 비ASCII 문자를 제거한 뒤 금지 목록 대조를 하므로 `english_banned`/`non_meshable` 사유가 붙지 않습니다. 생성 경로는 형식 사유도 거부해 통과하지는 않지만, 금지 범주 판정이 누락됩니다.  
  고칠 방향: 형식 위반이면 형태 값을 무조건 거부하고, ASCII 외 문자가 섞인 값의 금지어 검사는 정규화·혼합 문자 정책을 명시해 별도 시험으로 고정합니다.

- **중간 — 구분 표시 후보를 참여자 텍스트만으로 고름**  
  [llm_fill.py:210-213](<repo>/chatbot/ifs_chatbot/llm_fill.py:210)  
  재현: `norm="일반 문장"`인 세션의 `_unmatched`에 `<<<참여자 자료 0 시작>>>`가 들어 있으면, 실제 감싸는 원문에는 그 표시가 없으므로 0번이 선택됩니다. 그 표시는 감싸기 바깥의 미분류 자료에 나타납니다.  
  고칠 방향: 템플릿에 렌더링되는 모든 값(슬롯 안내·구분 밖 텍스트 포함)과 충돌하는지 검사하거나, 각 자료를 구조화된 별도 경계로 전달합니다.

- **중간 — 번호 선택이 10,000개에서 실패**  
  [llm_fill.py:184-189](<repo>/chatbot/ifs_chatbot/llm_fill.py:184)  
  재현: 자료 문자열에 `<<<참여자 자료 0 시작>>>`부터 `<<<참여자 자료 9999 시작>>>`까지 모두 포함하면 `ValueError`가 납니다. `run()`은 입력 구성 전에 예외를 반환·기록하는 경로가 보이지 않아 면담 확정 후 처리 실패로 이어질 수 있습니다. 추측: 상한을 넘는 합성 입력이면 발생하고, 일반 참여자 입력에서 현실적인지는 확인하지 않았습니다.  
  고칠 방향: 시도 상한을 제거하거나 충돌 실패를 예외 밖의 기록된 안전한 건너뜀으로 처리합니다.

- **중간 — ‘skipped’ 기록이 캐시의 선행 성공 기록을 덮어씀**  
  [llm_fill.py:410-417](<repo>/chatbot/ifs_chatbot/llm_fill.py:410)  
  재현: 성공 응답을 캐시에 둔 뒤 위기 플래그를 추가하고 같은 키로 다시 실행하면, `done("skipped")`가 해당 키의 캐시 항목을 교체합니다. 이후 분석에서는 원래 성공 호출·원시 응답·채택값이 캐시에서 사라집니다. 테스트도 캐시 길이만 확인합니다.  
  고칠 방향: 플래그에 따른 건너뜀 기록은 별도 실행 기록으로 남기고 기존 결과 캐시를 덮지 않도록 합니다.

- **중간 — 영어 금지 검사 중 숫자·유니코드를 토큰에서 삭제**  
  [prompts.py:500-509](<repo>/tools/gen3d/prompts.py:500)  
  재현: `skull2`, `skullé`, `sküll`은 정규식 형식 위반이지만 토큰화 후 각각 `skull`, `skull`, `skll`이 되어 일부는 금지 사유가 붙습니다. 반대로 `f0g`는 `fg`가 되어 `fog` 검사를 빠져나갑니다. 생성 직전 형식 검사가 최종 차단하더라도 서버 검증 결과의 사유가 일관되지 않습니다.  
  고칠 방향: 허용 문자 외 문자를 제거해 검사하지 말고, 그 자체로 형식 오류·기각을 확정합니다.

- **중간 — 불규칙 복수와 소유격 변형이 시험에 없음**  
  [prompts.py:457-479](<repo>/tools/gen3d/prompts.py:457), [test_g77_llm_fill.py:420-440](<repo>/chatbot/tests/test_g77_llm_fill.py:420)  
  재현: `children`, `wolves`, `knives`는 차단되지만, 목록에 없는 불규칙 복수 `men`은 `man`으로 연결돼도 `man`은 exact 목록에 있어 현재는 차단됩니다. 반면 `wolf’s`(곡선 아포스트로피)는 토큰 정리 후 `wolfs`처럼 처리되어 어간 규칙에서 `wolf`를 찾지 못합니다. 테스트에는 소유격 사례가 없습니다.  
  고칠 방향: 소유격 `'s`/`’s`를 별도 규칙으로 처리하고, 요구된 불규칙형·소유격을 검증기와 생성기 공통 시험에 추가합니다.

- **낮음 — 플래그 없는 정상 세션의 선행 캐시 시험은 있으나 변경된 분기 자체는 간접 검증**  
  [test_g77_llm_fill.py:364-367](<repo>/chatbot/tests/test_g77_llm_fill.py:364)  
  재현: 정상 세션에서 두 번째 호출이 `cached=True`이고 모델 호출 수가 1임을 확인합니다. 캐시 키에 목록 해시를 추가해도 플래그가 꺼진 경우 이 동작은 유지됩니다. 다만 목록 해시가 실제 키를 바꾸는 시험은 없습니다.  
  고칠 방향: 목록 해시가 바뀌면 새 키가 되고, 동일 목록·정상 세션은 기존 캐시를 재사용한다는 두 조건을 직접 고정합니다.

시험은 실제로 여러 수정을 확인하지만, 위에 든 유니코드·혼합 숫자·가운데 낱말·소유격과 10,000개 경계는 직접 확인하지 않습니다. `test_data_fence_picks_marker_absent_from_text`는 번호 선택의 기본 사례만 확인하며, 한계를 넘는 입력은 시험하지 않습니다.
