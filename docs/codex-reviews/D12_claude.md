# D12 독립 설계안 (Claude 하위 에이전트): [맞는 게 없어요] 뒤 '다시 적은 글'로 형태 메시 생성

작성 2026-11-28. 프롬프트 `docs/codex-reviews/prompts/D12_prompt.md`. Codex 안은 보지 않았다. 코드는 고치지 않았다.
뼈대 칸: 2절 "말이 물체가 되는 길"(형태 메시 예외), 5절 "안내문이 답을 미리 정한다", 6절 분석 규칙 ①. 원칙 1·2·3·4·6·7이 걸린다.

## 0. 한 줄 요약
다시 적은 글은 **형태 프롬프트에만** 쓰고 스펙 슬롯은 바꾸지 않는다. 사전 밖 낱말은 번역 모델이 아니라 **공개 한·영 대역 사전 + WordNet 범주 거르개(둘 다 판·sha256 고정)**로 옮긴다. 최대 2회, 회당 후보 2개. 본 실험(12-02)에는 넣지 않는다.

## 1. 흐름
설정 `[gen3d] resay = false`(기본). `v4-gen3d.toml` 계열에서만 켠다. 문구는 `selection_protocol` 0.8.0(새 판, 모두 `status: draft`).

| 단계 | 화면 | 내용 |
|---|---|---|
| R0 | 후보 화면 | 지금과 같음. [맞는 게 없어요]를 누르면 R1로(꺼져 있으면 지금처럼 기준 후보 0번으로 조절) |
| R1 | 다시 적기 | 아래 문구 + 글칸 + [이 글로 만들어 주세요] / [그냥 넘어갈게요](→ 지금 경로) |
| R2 | 거르기(즉시) | 위기 판정 → 규칙 프롬프트. 막히면 기다리지 않고 R4-막힘으로 |
| R3 | 기다림 | 고정 문구 + 진행 막대(경과 시간만). 중간 SDXL 이미지는 보이지 않는다(말하지 않은 색·부속물이 보임) |
| R4 | 새 후보 | 이번 회차 생성 후보(최대 2) 위에, 앞서 본 후보 줄(접힘, 고를 수 있음) 아래, [맞는 게 없어요] |
| 끝 | | 고르면 그 후보로 조절. 2회 뒤에도 안 맞거나 둘 다 막히면 **지금과 같은 경로(기준 후보 0번으로 조절)** |

고정 문구 초안(draft, 자작):
- `resay_intro`: 「떠올리신 그것의 모양을 한 번 더 적어 주세요. 적어 주신 글은 화면의 물체 모양을 새로 만드는 데 쓰이고, 기록으로 남아요. 모양을 나타내는 말만 쓰이고, 색이나 크기는 다음 화면에서 직접 고칠 수 있어요.」
- `resay_notice_generated`: 「새로 만든 모양에는 적지 않은 부분이 들어갈 수 있어요. 맞는 것이 있을 때만 골라 주세요.」(R4 위)
- `resay_submit` 「이 글로 만들어 주세요」, `resay_skip` 「그냥 넘어갈게요」
- `resay_wait`: 「모양을 만들고 있어요. 1–2분쯤 걸려요.」
- `resay_blocked`: 「이번에는 적어 주신 글로 모양을 만들지 못했어요.」 + (1회차면) 「한 번 더 적어 보시거나 넘어가실 수 있어요.」 — **이유는 말하지 않는다**(「사람 모양」「안개」 같은 범주어를 시스템이 꺼내지 않게. 이유는 연구자 화면·기록에만)
- 예시·선택지·묘사어는 넣지 않는다(원칙 3의 정신, G70-d). '모양'은 과제어이고 기존 probe_shape에도 있다.

횟수·후보 수: **다시 적기 최대 2회, 회당 생성 후보 최대 2개**(seed = 기준 + 회차×10 + k, 고정 순서). 근거: 후보당 27–30초 + 모델 적재 → 회당 약 1.5–2분, 2회면 세션이 최대 4분쯤 늘어난다. 세 번째부터는 같은 실패가 되풀이될 가능성이 크고(seed만 다름) 참여자 피로가 크다.
두 집단: 이 단계는 헤드셋 전 데스크톱 단계라 두 집단 모두 같은 규칙으로 자동 진행한다(실험자 재량 없음). 조건 배정은 이 화면에 보이지 않게 둔다. 최종 형태 출처(절차/생성/다시 적은 생성)와 다시 적기 횟수·대기 시간을 집단별로 보고한다(무작위라도 20명에서는 치우칠 수 있다).

실행 구조: 챗봇 서버(torch 없음)는 생성 모델을 부르지 않는다는 G62-b를 유지한다. 대신 저장소 밖 venv의 **생성기 상주 프로세스**(`tools/gen3d` localhost 전용, 외부 전송 없음)에 작업을 넘긴다. 순서: 위기 판정 → Ollama 두 모델(gemma4:e4b, kanana-safeguard) `keep_alive: 0`으로 내림 → 생성기 호출(시간 제한 240초) → 사이드카 검증(지금 `form_assets.py` 규칙) → 후보. 선택 단계 뒤에는 LLM이 필요 없으므로 내려도 면담에 영향이 없다. 호출 전에 세션 상태를 디스크에 쓴다(생성기가 죽어도 세션은 지금 경로로 이어짐).

| 다시 적은 글 속 | 처리 | 참여자에게 |

프롬프트 길이: 중심 명사 1 + 비유·명사꾸밈 최대 1 + 꾸밈말 최대 2. 넘치면 처음 나온 순서로 자른다(SDXL이 덧붙이는 것을 줄임).

## 3. 한국어 → 모델 입력: (d) 고정 대역 사전 확장을 고른다
| 안 | 판단 |
|---|---|
| (a) 지금 사전만 | 연구 책임자가 지적한 한계 그대로 |
| (b) NLLB 등 번역 모델 | 탐욕 디코딩·CPU fp32면 결정적일 가능성이 높다. 그러나 문맥 없는 낱말 번역의 뜻 고르기가 블랙박스이고, 원칙 1의 "번역 모델로 프롬프트를 만들지 않는다"를 지워야 한다. 원칙의 약화 폭이 가장 크다 |
| (c) 한국어 직접 이미지 모델(Qwen-Image 양자화) | 약 20B를 16 GB에 올리려면 양자화, 결정성·품질 미확인, TripoSG와 VRAM 경쟁, 인코더가 감정어·색을 해석(G62-f 충돌). 12-02 전 불가 |
| **(d) 공개 한·영 대역 사전 + WordNet 범주 거르개** | 채택. 사전·규칙만으로 결정적이고, 낱말마다 어느 사전 항목에서 왔는지 감사할 수 있다 |

(d)의 규칙:
1. 손으로 만든 `shape_prompt_en` 사전이 먼저 이긴다(지금 동작 불변).
2. 형태 자리(중심 명사·비유 원천·명사 꾸밈)의 명사인데 사전에 없으면, **국립국어원 한국어기초사전 한·영 대역어**(내려받기 판·sha256 고정, 저장소 밖 또는 파생 표만 저장소 안)를 찾는다. ⚠ 라이선스(CC BY-SA 2.0 KR로 알고 있음)·내려받기 형식·대역어 필드는 확인 필요. 대안은 Wiktionary 추출본(kaikki).
3. 대역어는 3낱말 이하 영어 명사구만 받는다(괄호·설명 문장은 버림). 뜻이 여럿이면: 거르개를 통과한 서로 다른 대역어가 1개면 쓰고, 2개면 **뜻마다 후보 1개**(기존 '구름' 해석 갈림 축과 같은 선례), 3개 이상이면 그 낱말을 쓰지 않는다(`ambiguous_sense`).
4. WordNet(NLTK 판 고정)으로 그 영어 명사의 **모든** 명사 뜻의 상위어를 보고, 2절 차단 범주가 하나라도 있으면 차단, `physical_entity` 아래 뜻이 하나도 없으면 버린다(보수적: 오차단 쪽으로 기운다).
5. 토큰마다 `source: lexicon | bilingual_dict`, 사전 항목 id, WordNet synset을 사이드카에 남긴다. charSpan 감사(fail closed)는 그대로.

결정성: Kiwi 판 + 두 사전 sha256 + WordNet 판 + 규칙 판이 같으면 같은 글 → 같은 프롬프트 바이트(모델 없음). 프롬프트 → GLB는 지금처럼 seed·리비전 고정(같은·다른 프로세스 34/34 확인됨), 캐시 키에 대역 사전 sha256을 더한다. 세션이 달라도 같은 다시 적은 글이면 같은 자산.

원칙 1 예외 문구 제안(AGENTS.md, 지금 문단 전체를 바꿈):
> **예외는 형태(메시) 후보 하나뿐이다(G62, 2026-11-27; D12).** 로컬 형태 생성 모델은 규칙이 만든 프롬프트만 받아 메시 후보를 만든다. 프롬프트의 입력은 확정 텍스트, 또는 [맞는 게 없어요] 뒤 참여자가 '물체의 모양을 만드는 데 쓰인다'는 안내를 받고 직접 다시 적은 글뿐이다. 프롬프트의 낱말은 고정 사전(손으로 만든 형태 사전, 그리고 판과 sha256을 기록한 공개 대역 사전에서 규칙으로 찾은 명사)에서만 오고, 모든 낱말은 입력 글의 글자 위치로 거슬러 가야 한다. 모델 리비전·가중치 해시·seed를 고정해 기록하고, 그 출력이나 다시 적은 글로 스펙의 슬롯 값(색·질감·크기·위치 포함)을 채우지 않는다. LLM·번역 모델로 프롬프트를 만들지 않는다.

원칙 2 예외에 한 문장 추가: 「다시 적은 글로 만든 후보는 '다시 적은 생성' 출처로 따로 적고, 다시 적은 글은 형태 후보 말고 다른 곳에 쓰지 않는다.」

## 4. 스펙과의 관계
- **다시 적은 글은 IFSSceneSpec 슬롯을 하나도 바꾸지 않는다.** 확정 텍스트·`meta.sourceTextHash`·spec sha256 불변. 매퍼를 다시 돌리지 않는다.
- 원칙 2 "말한 것이 추론한 것을 덮어쓴다"와의 관계: 다시 적은 글은 '형태 후보를 만들어 달라'는 과제에 대한 답이라, 그 안의 색·크기를 스펙 값으로 읽는 것은 시스템이 용도를 넓혀 해석하는 것이다. 참여자는 R1 문구대로 조절 화면에서 직접 바꾸며, 그 값은 `edited`(참여자가 직접 정함)로 남아 어떤 추론값보다 앞선다. 곧 "말한 것 > 추론"은 조절 단계의 `edited`로 지켜진다.
- 매퍼를 다시 돌리면 후보 집합·후보 id·G72 비율·헤드셋 스펙 판이 세션 중간에 바뀌고, 두 집단 공통 경로가 복잡해진다. 생성 메시는 지금처럼 `form.asset`일 뿐 `form.type` 값이 아니다(G62-c).

## 5. 기록
- **selection.v0.4 필요.** 0.3에 더하는 것: 출처 값 `generated_resaid_chosen`(form.type), 후보 `sources.form.type = generated_resaid`, `generation.resay = {setting, protocolVersion, rounds:[{round, textSha256, textFile, chars, safety{keyword, model, result}, prompt{status, blockReason, blockDetail, tokens(source·사전 항목·synset·charSpan)}, candidates[{candidateId, assetId, seed, sense}], rejected, waitMs, outcome}], outcome: chosen_round_n | skipped | exhausted | blocked | crisis | generator_failed}`. 꺼져 있으면 0.3 그대로(바이트 동일).
- form-asset 사이드카 `v0.1`: `inputKind: confirmed | resaid`, `bilingualDict{name, version, sha256}`, `wordnet{version}`. 조회 키는 확정 텍스트가 아니라 (세션, 회차)로 묶어 `form_assets.py`의 확정 텍스트 조회와 섞이지 않게 한다.
- **원문 위치**: `logs/selection/<sessionId>/resay.json`(git 밖, 세션 기록과 같은 디스크·삭제 절차). selection.json에는 sha256·글자 수·charSpan만. 생성기 쪽 캐시(`gen3d-out`)에는 원문을 두지 않고 영어 프롬프트만(사전 낱말이라 식별 위험 낮음, 그래도 삭제 요청 시 함께 지운다). 노션·git·합성 시나리오에는 원문을 옮기지 않는다(원칙 6).
- **분석 구분**(자료 보기 전 고정): (i) R0에서 [맞는 게 없어요]를 한 번이라도 누른 세션은 **나중에 다시 적은 후보를 골랐어도** G59-11 ①의 "맞는 게 없어요 세션"으로 센다(사후에 정의를 바꿀 여지를 없앰). (ii) 새 민감도 ⑤: 최종 형태 출처가 `generated_resaid_chosen`인 세션을 뺀 결과. (iii) G13 두 문항은 출처(절차/생성/다시 적은 생성)별로 기술만 한다 — 다시 적은 세션의 G13은 "만드는 데 쓰인다"는 안내 뒤에 고른 것이라 비교 가능한 값이 아니다.

| 검은 안개가 있는 느낌 | '안개' 중심 명사, 다른 형태 명사 없음 → `nonMeshable` 차단, 생성기 호출 0 |
| 구름 같은데 … 보이지 않는 안개같은? | '구름' 비유 원천·'안개' → 차단 |
| 먹구름 | scene_params에서 `form.type=mist` → 차단(사전 밖 경로였어도 WordNet `cloud` → 차단) |
| 넓게 펼쳐진 안개가 떠오른다 | '안개' → 차단 |

곧 **네 문장 모두 아무것도 생성하지 않고**, 2회를 써도 같은 결과라 참여자에게는 기다림 없는 `resay_blocked` 두 번이 된다. 원하는 모양(넓게 퍼진 옅은 안개)에 가까워지지 않는다. 메시 생성으로는 원리상 가까워질 수 없다(볼류메트릭 로컬 모델 없음, 이미 알고 있음).
이 사례의 경로는 **규칙 쪽 안개 렌더**다: ① G72 비율(「넓게 펼쳐진」 → 너비·깊이 1, 높이 작게)이 mist에 이미 비균일 배율로 걸린다 — test03이 G72 이후 코드로 어떻게 보이는지 먼저 다시 본다. ② 「덜 빽빽하고」「옅은」「흐릿한」 같은 밀도어를 mist의 밀도(입자 수·opacity) 슬롯으로 옮기는 사전 항목을 별도 결정으로 더한다(말한 것만). ③ 조절 화면에 안개일 때 투명도·밝기·너비/높이/깊이가 보이는지 확인. ④ 덧붙임: 스펙 form.type이 mist면 R1 화면 문구를 바꾸지 않되(모두 같은 흐름), 연구자 화면에 "안개 형태는 생성 대상이 아님"을 보인다.

## 7. 위험과 시험
가장 큰 위험 3개:
1. **세션 안 생성의 운영 위험**: Ollama 상주 모델을 내리지 못하거나 시스템 메모리가 모자라 생성기·서버가 죽으면(G62 평가 중 실제로 시스템 메모리 부족으로 멈춤) 참여자가 화면 앞에서 수 분을 기다리다 세션이 깨진다. IRB 없는 실험에서 부담·불편이 늘어나는 쪽이다.
2. **요구 특성·측정 오염**: "물체를 만드는 데 쓰인다"는 두 번째 유도는 물체 중심 묘사를 끌어내고, 고른 생성 메시가 말하지 않은 세부(SDXL 덧붙임)를 담은 채 G13·A1–A7 사전 점수 직전에 놓인다. 참여자가 '그나마 나은 것'을 고르면 대표성 점수가 부풀 수 있다.
3. **거르개 구멍과 기대 미달**: 대역 사전의 뜻 오류(예: 다의어), WordNet에 없는 신조어·외래어, 사람 유사 사물(마스코트·캐릭터)의 통과. 반대로 보수적 차단 때문에 연구 책임자가 원한 "사전 밖 낱말" 이득이 작을 수 있고, 흐린 대상(안개)은 처음부터 이득이 없다.

꼭 필요한 자동 시험(모델 없이 모의 생성기로):
- 설정 끔 → selection 기록이 지금과 바이트 동일(S4 시나리오 포함).
- 위기 키워드 글 → 가드 모델 0회·생성기 0회·고정 문구. 가드 모델 위기 → 생성기 0회.
- 차단 범주 합성 문장 묶음(사람·동물·안개·불꽃·감정어만·형태 없음, 사전 밖 명사 포함) → 생성기 0회.
- 프롬프트 내용 토큰 전부 charSpan이 다시 적은 글과 일치, source ∈ {lexicon, bilingual_dict}, 감정·색·크기·위치 낱말 0개.
- 같은 글을 두 프로세스에서 → 프롬프트·사이드카 키 동일. 대역 사전 sha256이 다르면 키가 다름.
- 스펙·확정 텍스트 sha256이 다시 적기 전후 같음, finalOverrides는 참여자 조절만 반영.
- 회차 상한 2, [그냥 넘어갈게요], 생성기 시간 초과·죽음 → 기준 후보 0번 조절 경로와 `outcome` 기록.
- Ollama 내림 호출이 생성기 호출보다 먼저(호출 순서 모의 확인).
- selection.v0.4·form-asset v0.1 스키마 검증, selection.json에 원문 없음, `resay.json`은 log_dir 안.

이 PC에서 사람이 잴 것:
- 실제 서버 + Ollama 상주 상태에서 회당 대기 시간(첫 회 냉적재, 둘째 회), 최대 VRAM, **시스템 메모리 최대치**.
- 세션 경로로 만든 자산의 다른 프로세스 결정성(GLB sha256).
- 대역 사전 적용 범위: 지금 사전에 없는 합성 사물 명사 50개쯤에서 옮겨진 비율, 뜻 오류, 차단 오탐을 연구팀이 판정.
- 연구자 본인이 R1–R4를 끝까지 해 보고 기다림·문구가 견딜 만한지(참여자 아님).

## 8. 본 실험(12-02) 적용: 넣지 않는다
- G67-b가 다시 켤 조건으로 둔 "세션 연결과 평가"가 아직 없다. 이 기능은 그 세션 연결을 새로 만드는 일이고, 남은 4일 안에 구현·Codex 검토·이 PC 실측·연구자 시험을 마칠 수 없다.
- 참여자에게 닿는 새 고정 문구 5–6개와 기다림·실패 경로가 생긴다. IRB 없이 진행하는 실험(G68)에서 시험되지 않은 참여자 경로를 넣는 것은 participant-protection의 취지와 맞지 않는다.
- 모집 중간에 켜면 앞뒤 참여자의 흐름이 달라지고, G59-11 ①의 대상 정의가 자료 수집 중에 바뀐다.
- 대역 사전 라이선스·범위가 미확인이고, 안개 같은 대표 사례에는 이득이 없다.
- 본 실험에서는 지금처럼 [맞는 게 없어요] → 기준 후보 0번 조절을 유지하고, 그 빈도·G13 점수를 기록해 이 기능의 필요를 재는 근거로 쓴다. 기능은 본 실험 뒤 별도 시행에서 `v4-gen3d` 계열로 시험한다.

## 확인하지 못한 것
한국어기초사전 한·영 대역어의 내려받기 형식·라이선스 문구·명사 범위, NLTK WordNet 판의 차단 범주 적중률, 생성기 상주 프로세스의 시스템 메모리 사용량, test03 문장이 G72 이후 코드에서 어떻게 그려지는지.
