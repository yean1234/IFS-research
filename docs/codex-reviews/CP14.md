## 지적

### 중간 — 다른 세션의 그림을 URL로 조회할 수 있음

- **파일:줄:** [server.py](<repo>/chatbot/ifs_chatbot/server.py:156), [server.py](<repo>/chatbot/ifs_chatbot/server.py:291), [selection.py](<repo>/chatbot/ifs_chatbot/selection.py:802)
- **재현 경로:** 세션 A가 그림 고르기 화면일 때 `/api/sessions`에서 A의 ID를 확인하고, 그 ID와 화면에 나온 그림 URL로 PNG를 요청합니다. 그림을 고른 뒤에도 `image_png()`는 `stage == "picking"`인지 확인하지 않아 같은 URL이 계속 유효합니다.
- **문제:** 그림 URL이 세션 ID와 회차·자리 번호만으로 열립니다. 세션 ID 목록도 API로 조회할 수 있어, 같은 서버에 접근 가능한 사용자가 다른 세션의 생성 그림을 볼 수 있습니다.
- **고칠 방향:** 그림 요청에 세션 소유자 확인을 추가하고, 현재 해당 세션이 `picking` 단계일 때만 응답하도록 제한하세요.

### 낮음 — 잘못된 파일 경로가 기록에 남을 수 있음

- **파일:줄:** [none_gen.py](<repo>/chatbot/ifs_chatbot/none_gen.py:686), [selection.py](<repo>/chatbot/ifs_chatbot/selection.py:717)
- **재현 입력 또는 경로:** 생성기가 `image-pick.json`에 `images[].file`로 절대 경로나 `../` 경로를 기록합니다. `_image_result()`가 경로를 무효로 표시해 그림은 숨기지만, 원래 문자열은 결과 객체에 남고 `selection.json`의 이미지 기록에도 복사됩니다.
- **문제:** 생성기 산출물이 잘못되거나 바뀌면 로컬 절대 경로가 참여자 기록에 들어갈 수 있습니다. 파일 경로 검증이 표시 차단에는 쓰이지만 기록값 제거에는 적용되지 않습니다.
- **고칠 방향:** 경로 검증에 실패한 파일은 기록할 때도 경로를 저장하지 말고, 무효 사유만 남기세요.

## 문제없다고 확인한 것

- G75 플래그가 꺼진 경로는 `imagePick` 기록과 이미지 생성 인자를 추가하지 않도록 분기되어 있습니다. 다만 바이트 단위 불변 시험은 실행하지 않았습니다.
- 이미지 생성 실패·관문 미통과·파일 누락·해시 불일치는 표시를 막고 기존 none 경로로 이어집니다.
- 메시 생성 결과는 이미지 선택만으로 장면에 적용되지 않고, 생성 후보를 참여자가 선택해야 적용됩니다. Unity는 0.4를 0.3과 같은 러너 필드 규칙으로 읽습니다.
- 키워드 위기는 생성 중에도 모델 없이 고정 문구 경로로 처리됩니다.
