## 0. 한 줄

컴퓨터가 대신 꺼낸 심상을 두고 사람은 **무엇으로 "닮았다"고 하고, 무엇으로 "내 것"이라고 하는가.**
예측: 닮음은 물체의 값이 머릿속 값에 가까운지에 따라 움직이고, 내 것 같은 느낌은 손으로 다뤄 보았는지에 따라 더 크게 움직입니다.

## 1. 질문 세 개

| | 직관 문장 | 어디서 | 지위 |
|---|---|---|---|
| Q1 | 말만 맞으면 닮은 것인가, 내가 보고한 머릿속 값에 가까워야 닮은 것인가. | 데스크톱 3D, 헤드셋 | A 단계에서는 실행 가능성 확인, B 단계에서 확증 |
| Q2 | 그 값에는 **크기와 깊이(나와의 거리)**도 들어 있는가. 그리고 같은 물체를 헤드셋 안의 '창'으로 볼 때보다 '내 앞 공간'에 놓고 볼 때 그 어긋남을 더 알아차리는가. | 헤드셋만 | B 단계 |
| Q3 | 손으로 다뤄 보면 닮음보다 내 것 같은 느낌이 더 크게 움직이는가. | 헤드셋만 | B 단계 |

발표의 RQ2(어느 속성이 바뀌면 더 떨어지는가)는 "말과 어긋난 변형본 4개"로 그대로 두되 조작 확인과 탐색 결과로만 씁니다. 발표의 RQ3(정하지 않은 속성)은 3.2의 보조 분석이 됩니다.

## 2. 연구자 생각 네 가지에 대한 판단

**생각 1. 색을 떠올리지 않고 형태만 떠올린 사람이 있을 수 있다. RQ1을 색 인지 연구로 바꾸면?**
- 지적은 맞습니다. 색이 머릿속에 없던 사람에게 가까운 파랑과 먼 파랑은 구분할 이유가 없으므로, 차이가 안 나와도 "말에 기댄다"는 뜻이 아닙니다.
- 색 인지 연구로 좁히는 것은 권하지 않습니다. 색 기억과 색 범주 연구는 이미 두껍고, "말인가 머릿속 값인가"라는 일반 주장을 잃습니다.
- 대신 비교를 **속성마다 따로** 하고, 참여자가 그 속성이 머릿속에 있었다고 답한 경우에만 가까운·먼을 가립니다(3.2). 색이 없던 사람은 색 비교에서 빠지고 크기에서 검사받습니다. 쓸 수 있는 쌍이 하나도 없는 사람의 비율도 결과로 보고합니다.
- 형태 자체의 가까운·먼 비교는 이번에는 못 합니다. 절차 모형(blob)의 울퉁불퉁함과 길쭉함은 연속값이라 C 단계에서 가능합니다.

**생각 2. "가까운 값은 닮음을, 직접 조작은 소유감을 올린다"를 구체화.** 3.4에 설계했습니다. 물체의 값을 바꾸지 않는 조작이어야 하고, 속성을 고치는 편집은 물체가 바뀌어 닮음도 오르므로 쓰지 않습니다. 검토 결과 "서로 넘지 않는다"는 주장은 20명 규모로는 할 수 없어 "상대적으로 더 움직인다"까지만 주장합니다.

**생각 3. 부분의 생김새 자료로 어휘를 제한하면 도형보다 근거가 있다.**
- 방향은 맞지만 **지금은 그런 자료가 없습니다.** IFS 부분의 생김새를 범주로 코딩해 빈도를 낸 연구는 찾지 못했습니다(PubMed 검색 포함).
- 간접 근거는 엇갈립니다. IFS 지침은 "보이나요? 안 보이면 어떻게 경험되나요? 얼마나 가까이 있나요?"를 묻고(Anderson의 6F 설명), 통증 심상 연구에서 심상이 있다고 답한 사람은 36%였습니다(Gosden 외 2014). 감정 그리기에서는 얼굴 표정이 42–49%, 추상이 16–29%였습니다(Weng 외 2024). Mood Worlds 참여자는 사람을 사물로 대신 나타냈습니다.
- 그래서 5절처럼 자료를 직접 만듭니다. 사람 모습으로 묘사되는 부분이 많으면 도형으로는 덮을 수 없다는 점이 가장 큰 위험입니다.

**생각 4. Quest 3로 측정 가능한가, 그리고 질문이 직관적이지 않다.**
- 측정은 조건부로 가능합니다(4절).
- 질문은 Q2의 두 문장으로 정리했습니다. 비교 조건은 데스크톱 모니터가 아니라 **같은 헤드셋 안의 '창'**입니다. 기기가 같아 화면 차이가 섞이지 않습니다.

## 3. 설계

### 3.1 공통 장치: 같은 말, 다른 값

- 속성마다 축 하나를 정합니다. 유채색은 색상, 무채색은 명도, 크기는 `layout.size`(로그 척도).
- 화면에 그려지는 원본 값 w에서 **양쪽으로 같은 만큼** 옮긴 두 변형(lo, hi)을 만듭니다. 이 자극은 참여자 보고와 무관하게 정해집니다. 실험자도 어느 쪽이 가까운 쪽인지 모릅니다.
- 어느 쪽이 "가까운" 변형인지는 분석 때 참여자가 보기 전에 보고한 값 p로 정합니다.
- 쌍을 쓰는 조건(하나라도 어기면 사유를 기록하고 주 대비에서 뺌):
  - 두 변형이 모두 범위 안에 있고 말한 낱말의 범위를 넘지 않는다.
  - 두 변형의 원본 대비 차이가 허용 오차 안에서 같다(색은 렌더 알베도 ΔE00 기준).
  - w가 말에서 온 값이다(기본값이면 "같은 말"이 없으므로 보조 분석으로만).
  - p가 w에서 충분히 떨어져 있고, d(가까운, p) < d(w, p) < d(먼, p)가 성립한다.
- 잠정값: 크기 ±0.10(지름 약 1.32배), 색 ΔE00 12, 색상 이동 상한 20°, 대칭 허용 오차 ΔE 3. 색 낱말의 폭이 사전에 없어 상한은 근거 없는 잠정값이며, 도우미의 이름 붙이기로 확인합니다.

### 3.2 Q1: 보고한 값에 가까운 쪽을 더 닮았다고 하는가

- **보기 전 보고 과제**(면담 확정 뒤, 면담 프로토콜과 분리된 고정 문구 과제): 속성마다 한 번 "떠올린 모습에 ○○이 있었나요?" ① 처음부터 있었다 ② 물어봐서 그때 정했다 ③ 지금도 정해진 것이 없다. 색과 크기에서 ①②인 경우에만 값을 한 번 고릅니다. **③은 값을 받지 않습니다.**
- 주 추정치: ①인 유효 쌍의 (가까운 − 먼) '닮았다' 차이를 참여자별로 평균한 값. 속성별 결과, 쌍이 0개인 참여자 비율, 제외 사유를 함께 보고합니다.
- 보조: ②인 쌍(방향만), 원본 대비 두 변형 평균의 하락을 ①②③별로(정하지 않은 속성은 옮겨도 덜 떨어지는가).
- **결론의 범위**: 양수가 나오면 "보기 전에 보고한 값에 가까운 형상을 더 닮았다고 평정한다"까지입니다. 머릿속 그림 때문인지 방금 고른 값을 기억해서인지는 이 설계로 가르지 못합니다. B 단계에서 통제 하나를 더합니다(8절).
- 고른 값과 ①②③ 답은 장면 JSON에 넣지 않고 세션 폴더의 별도 파일에 기록합니다(원칙 1·2).
- 형상마다 '닮았다' 한 문항만 받습니다. 끝에 판단 기준, 실험 목적 추측, 보는 동안 떠올린 모습이 바뀌었는지를 묻습니다.

### 3.3 Q2: 크기와 깊이 (헤드셋, B 단계)

- 보고 방식: 형상을 보기 전에, 떠올린 깊이에 중립 표시를 한 번 놓고, 그 자리에 놓인 중립 괄호의 폭을 두 손 간격으로 한 번 맞춥니다. "가장 넓은 폭"과 "가운데"를 보고하도록 고정합니다. 보고도 관찰도 같은 화면의 시각 판단이 되게 하기 위함입니다.
- 사전 확인: 알려진 크기·거리의 표적으로 거리대별 치우침과 반복 오차를 먼저 잽니다.
- 조작하는 축은 크기와 깊이 둘입니다. 높이는 기록만 합니다.
- 비교: 같은 변형들을 **내 앞 공간에 놓인 조건**과 **헤드셋 안의 창으로 보는 조건**에서 봅니다. 예측은 크기·깊이 쌍의 (가까운 − 먼) 차이가 공간 조건에서 더 크고, 색 쌍의 차이는 두 조건에서 같다는 것입니다.

### 3.4 Q3: 다루기와 가까움 (헤드셋, B 단계)

- 다루기는 **참여자 간** 조건입니다. 다루는 사람은 30초 동안 잡고 돌려 보고 가까이 가져왔다가 놓습니다(놓으면 제자리로). 보는 사람은 짝지어진 다루는 사람의 시점 기준 궤적을 그대로 봅니다.
- 가까움은 참여자 내 조건입니다(가까운 변형과 먼 변형, 순서 균형).
- 측정: '닮았다' 1문항과 소유감 문항을 따로 떨어진 블록에서 받고 블록 순서를 균형화합니다. 조작 확인으로 실제 잡기·회전 기록과 "내가 움직였다" 문항을 둡니다.
- 분석: 두 지표를 사전에 정한 기준 분산으로 표준화하고 상관을 반영한 공동모형으로 교차 대비를 봅니다.

| 결과 | 뜻 |
|---|---|
| 가까움은 닮음을, 다루기는 소유감을 상대적으로 더 움직임 | 닮음과 내 것은 서로 다른 손잡이에 더 민감하다 |
| 다루기가 닮음도 비슷하게 올림 | '닮았다' 문항이 물체의 값만 재지 않는다. 선행 연구의 전체 일치 문항 해석에도 걸리는 결과 |
| 가까움이 소유감도 비슷하게 올림 | 닮음이 내 것 느낌으로 가는 길 중 하나다 |

"서로 전혀 넘지 않는다"는 주장은 교차 효과가 사전에 정한 동등성 범위 안에 들어야 하므로 표본을 따로 산정합니다.

### 3.5 측정

| 지표 | 문항 | 언제 |
|---|---|---|
| 닮음(주) | "떠올린 모습과 닮았다" 1–7 | 모든 형상 |
| 소유감 | Peck & Shu(2009) 3문항을 옮긴 초안, 1–7. 인지 인터뷰로 '내 것'이 무엇을 가리키는지 확인한 뒤 탐색 척도로 | Q3 (B 단계) |
| 달라 보임, 이름 붙이기 | 도우미 5–8명 | 사전 1회 |
| 머리 자세 | 위치·방향 | 관찰 중. Quest 3에는 시선 추적이 없음 |
| 멀미 전후(VRSQ), 중단 기록 | 설계 정본 그대로 | 헤드셋 시행 |

- '내 것처럼 느껴진다'를 형상마다 '닮았다' 바로 뒤에 묻지 않습니다. 앞 문항 점수를 따라가는 경향이 두 느낌의 관련처럼 보이기 때문입니다(발표안에서 바뀐 점). 러너 설정으로 문항을 바꿔 별도 블록에서 받을 수는 있습니다.
- 친밀감(IOS)은 넣지 않습니다. IFS에서 외현화의 목적이 부분과 거리를 두는 것이라 높을수록 좋은 지표가 아닙니다.

### 3.6 한 사람이 보는 형상 수 (A 단계)

원본 1 + 말과 어긋난 변형 최대 4 + 유효한 쌍(색 2, 크기 2) = 최대 9개, 형상당 30초. 유효하지 않은 쌍은 보여 주지 않으므로 사람마다 5–9개입니다. 제시 순서는 실제 조건 수에 맞춘 Williams 설계로 정합니다.

## 4. Quest 3로 측정 가능한가

| 필요한 것 | 판정 | 조건 |
|---|---|---|
| 실제 크기·거리로 그리기 | 가능 | 물체는 0.5 m 밖에 둠(Meta 권장. 스키마 최소값 0.3 m는 쓰지 않음). 거리는 실제의 약 70%로 지각된다는 Quest 2 결과가 있어(Kelly 외 2022) 절대값은 주장하지 않음 |
| 손 간격으로 폭 맞추기 | 가능 | 컨트롤러 절대 오차 약 1 cm(Quest 2, Carnevale 외 2022). Quest 3 컨트롤러 검증 논문은 찾지 못함. 세션마다 자로 10·30·60 cm 확인. 맨손 추적은 오차 1.7 cm라 쓰지 않음(Godden 외 2025) |
| 깊이 표시 놓기 | 가능 | 앉은 자세 고정, 시작할 때 눈높이 기록 |
| 변형과 평정 | 가능 | 이동폭은 근거 자료가 없어 내부 시행으로 정함 |
| 잡기·돌리기 | 가능 | 새로 구현해야 함 |
| 머리 자세 기록 | 가능 | 구현돼 있으나 기기에서 확인한 적 없음 |
| 시선 추적 | 불가 | Quest 3에 없음. 머리 방향 대리 지표만 |
| "몸 안"에 있는 심상 | 불가 | 몸 앞에 두는 것으로 대신하고 한계로 적음 |

손 간격(몸 감각)과 관찰(시각)은 서로 다른 양식이라 헤드셋의 거리·크기 압축이 저절로 상쇄되지 않습니다. 3.3에서 보고를 같은 화면의 표시 맞추기로 바꾼 이유입니다.

구현 쪽 위험이 측정 쪽보다 큽니다.
- macOS에서는 Quest Link를 쓸 수 없습니다. Windows PC가 없으면 헤드셋 단독 빌드만 가능합니다.
- 프로젝트에 XR 플러그인이 없고(X27) 컨트롤러 입력 코드도 없습니다. 머리 자세 코드는 XR 입력을 못 읽으면 조용히 데스크톱 모의 조작으로 넘어갑니다.
- 단독 빌드에서는 문구 파일을 `File.ReadAllText`로 읽는 경로가 동작하지 않습니다.
- 형상 셰이더 3종은 surface shader이고, Built-in 파이프라인이 Quest에서 문제없이 도는지는 기기에서만 확인됩니다.
- 그래서 **기기 확인 작업을 따로 먼저** 합니다: XR 초기화, 양안 렌더, 문구·기록 경로, 실제 `xr` 머리 자세 기록. 이것이 통과하기 전에는 Q2·Q3 구현을 시작하지 않습니다. 이 작업은 Unity 에디터와 기기가 있는 곳에서만 할 수 있습니다.

## 5. 도형 어휘의 근거 (교수 지적 2·3, 생각 3)

- 지적 3에 대한 답: 이번 실험에서 도형은 **속성을 하나씩 통제할 수 있는 자극 공간**입니다. 결과는 이 공간 안에서만 주장합니다.
- 지적 2("이 prefab이 심상을 얼마나 표현하는가")는 **이번 제안으로는 답하지 못합니다.** 문헌(Lin 외 CHI '21, Jonauskaite 외 2020, Pinilla 외 2021)은 기본 시각 속성이 정서 의미를 싣는다는 근거이지, 지금 prefab 목록이 대표적이라는 근거가 아닙니다.
- 답을 만드는 지표 세 가지와 필요한 것:
  1. **덮은 비율**: 원문에서 묘사 표현을 같은 단위로 코딩하고 반영·왜곡·누락을 판정해 유형별 분모를 만듭니다. 설계 정본의 반영률 정의를 씁니다.
  2. **다양성**: 참여자 간 장면 JSON 거리. 범주형·연속형 거리, 가중치, 결측 처리, 기본값 포함 여부를 먼저 정합니다. 거리가 작은 것은 입력이 비슷해서일 수도 있습니다.
  3. **거리와 반응**: 렌더 거리, 도우미 평정, 참여자 평정을 같은 자극 ID로 잇습니다.
- 참여자 자료가 없으면 1–2는 합성 입력으로 계산한 시연값이고 3은 후속 지표입니다.
- 어휘를 자료로 제한하는 일은 별도 형성 연구입니다: 출판된 부분 묘사 150–300개를 유형(사람-나이, 사람-역할, 동물, 사물, 자연물·물질, 추상 형태, 몸 감각만, 시각 정보 없음)과 속성 차원(색, 크기, 몸 위치·거리, 움직임, 질감, 온도, 무게, 나이, 자세)으로 코딩합니다. 출판 사례는 생생한 사례 쪽으로 치우쳐 있다는 한계를 적습니다.
- 주의: 이번 실험 과제는 중립 심상이고, 출판된 부분 묘사와는 다른 표본입니다.

## 7. 파이프라인 변경 (A 단계)

1. 변형 생성기: 양쪽 변형(`color_lo`, `color_hi`, `size_lo`, `size_hi`), 쌍 유효성과 제외 사유, manifest `shiftPairs`.
2. 제시 순서: 실제 조건 수를 먼저 정한 뒤 n조건 Williams 설계.
3. 러너와 기록: 가변 길이 순서, 문항 ID(`item`), '닮았다' 문구 초안.
4. 보기 전 보고 과제: 기록 형식(`shared/schemas/prereport.v0.json`), 고정 문구(`shared/protocol/prereport_task.v0.json`, status draft·출처), 웹 화면. 기록은 세션 ID와 spec 해시로 형상 기록과 잇습니다.
5. 분석기: 가까운·먼 가리기, 참여자별 평균, 제외 사유, ①②③별 하락.

Q2·Q3용 구현(XR 초기화, 컨트롤러 입력, 잡기, 창 조건)은 기기 확인 뒤로 미룹니다.

### 7.1 구현 상태 (2026-11-18)

1–5는 구현했고 Codex 검토 두 번(`CP5`, `CP6`)의 지적을 반영했습니다. 버전: 생성기 `ownership-variants/0.3`, 기록 `ifs-ownership/0.3`, 보고 형식 `ifs-prereport/0.2`, 보고 과제 문구 0.3(모두 draft), 분석 요약 `ownership-summary/0.5`.

- 확인한 것: dotnet compile-check 빌드 오류 0, C# 테스트 190 통과, 관련 Python 테스트 100 통과(브라우저 자동 조작 포함). 전체 pytest는 파일별로 나눠 494 통과·14 건너뜀.
- **확인하지 못한 것: Unity 에디터와 Quest 3에서는 한 번도 돌리지 않았습니다.** 실제 화면에서 양쪽 변형이 구분되는지, 형상 9개의 배치, 러너가 보고 파일을 복사하는 동작은 Unity에서 직접 봐야 합니다.

내부 시행 한 건의 순서:
1. 챗봇에서 면담하고 텍스트를 확정합니다.
2. 같은 화면의 링크로 보기 전 보고 과제를 합니다(`/prereport?session=<id>`). 기록은 `logs/<sessionId>/prereport.json`.
3. Unity 러너에서 장면 파일과 보고 파일을 고르고 `requirePrereport`를 켠 채 시작합니다. 러너가 보고 파일을 기록 폴더로 복사합니다(이것이 '보기 전'의 증거).
4. 형상마다 '닮았다'를 말로 답하고 실험자가 입력합니다.
5. `python -m ifs_chatbot.eval.ownership --records <기록 루트> --out <저장소 밖 폴더>`로 `shift_pairs.csv`와 가까운 − 먼 요약을 냅니다.

구현하면서 알게 된 것:
- 잠정 이동폭에서는 일부 색에서 쌍이 만들어지지 않습니다. 예: 어두운 파랑(HSL 0.6/0.5/0.4)은 색상 상한 20° 안에서 ΔE00 12에 닿지 못합니다. 내부 시행에서 이동폭을 정할 때 쌍이 빠지는 비율을 함께 봐야 합니다.
- 사전의 수치 크기 변환과 Unity가 그리는 크기의 눈금이 다릅니다("9 cm"라고 말해도 약 20 cm로 그려짐). 크기 비교는 그려진 폭과 보고한 폭을 미터로 견주므로 Q1 분석에는 영향이 없지만, 매핑 문제로 따로 고쳐야 합니다.
- 참여자마다 조건 수가 5–9개로 달라 제시 순서의 완전 균형은 사전에 보장되지 않습니다. 분석기가 조건 집합별 균형을 보고합니다.
- 사후 질문 세 가지(판단 기준, 목적 추측, 심상 변화)는 아직 구현하지 않았습니다.

## 8. 남는 위험

- **보고값 기억**: Q1에서 가까운 쪽이 높아도 머릿속 그림 때문인지 고른 값의 기억 때문인지 가르지 못합니다. B 단계 후보 통제는 둘입니다. (가) 형상과 무관한 같은 범주 값 하나를 외우게 하고 두 기준이 서로 다른 변형을 가리킬 때 어느 쪽 평정이 높은지 보기(Codex 안). (나) 자극이 보고와 무관하므로 보고를 평정 뒤에 받는 집단을 두기(메인 안). 둘 다 완전하지 않아 B 설계 때 정합니다.
- 색 낱말의 범위가 사전에 없습니다. 이동 상한은 잠정값입니다.
- ①②③은 면담 뒤의 회고 보고입니다.
- 20명이 충분하다는 근거는 없습니다. 쌍이 0개인 참여자는 주 추정치에 정보를 주지 않습니다.
- 소유감 문항은 실물 소비재용 문항을 옮긴 것이라 '내 것'이 심상의 출처, 물체 소유, 조작 통제 중 무엇으로 읽히는지 확인이 필요합니다.
