# 내부 시행 안내 — 연구팀 시스템 점검 (1–6단계, 원하면 7–8단계)

작성 2026-11-23, 브랜치 `claude/prototype-v4-build`. 근거는 `docs/prompts/prototype-v4-build.md` D10, `docs/decisions.md` X79·X80·G7–G28, `docs/no-irb-direction.md` 4절입니다. 통과 기준은 정하지 않았습니다(⚠ 사람이 정할 것).

## 0. 먼저 읽을 것 — 이 시행은 무엇이고 무엇이 아닌가

- **IRB 승인 없이 하는 연구팀 내부의 시스템 점검입니다.** 사람을 모집하는 실험이 아닙니다(X79). 팀원이 흐름이 끝까지 도는지, 어디서 막히는지를 확인합니다.
- **중립 심상(사물·풍경)만 넣습니다.** 마음에 걸리는 개인적인 내용을 넣지 않습니다(X80). 면담 첫 문구는 "지금 가지고 있는 걱정거리 가운데 가장 풀기 쉬운 것 하나를 떠올려 주세요"(1.3.0)이고 사전 측정 지시문도 "지금 마음에 걸려 있는 그것"을 가리키지만, 이 시행에서는 그 문구를 따르지 말고 6절의 예시 같은 중립 심상으로 답합니다.
- **응답을 사람에 대한 자료로 쓰지 않습니다.** 평균, 전후 변화, 조건 차이를 계산하지 않습니다. 사전 측정의 주 척도 문항(A1–A7)은 화면에 뜨는지만 보고 [답하지 않기]를 고릅니다. 두 평정 문항(모습 일치·대표성)은 점검표에 **시스템 점검용으로만** 적습니다.
- **세션 기록은 git에 올리지 않습니다.** `chatbot/logs/`는 git 밖입니다. 채운 점검표도 저장소 밖에 둡니다. 세션 ID는 가명(예: `TRIAL-01`)을 쓰고 실명을 넣지 않습니다.
- 저자의 시스템 사용을 논문에 싣는 것이 소속 기관과 학회 규정상 확인 대상인지는 **연구자가 확인합니다.** 확인 전에는 "연구팀이 동작을 확인했다" 이상으로 쓰지 않습니다.

## 1. 준비물과 한 번만 할 일

| 무엇 | 내용 |
| --- | --- |
| PC | Windows, GPU(미리보기 플레이어가 Direct3D 11로 그림). 헤드셋 단계를 하려면 Quest 3 + Quest Link |
| Python 환경 | 저장소 루트에서 `cd chatbot; python -m venv .venv; .venv\Scripts\python -m pip install -r requirements.txt` |
| 설정 프로필 | `chatbot/config/v4.toml`(고치지 않고 그대로 씀). 매퍼 v2, 후보·조절·사전 측정 단계 켬, 미리보기 `webgl`(안 되면 `image` → 글 요약) |
| Ollama | **조건 1(정적)에 `--backend offline`이면 LLM이 필요 없습니다.** 안전 가드 모델(Kanana)은 Ollama가 켜져 있고 모델이 있으면 쓰고, 없으면 경고만 남기고 키워드 사전만으로 검사합니다(`v4.toml`의 `guard.required = false`). 가드 모델을 일부러 끄려면 `--no-guard-model` |
| WebGL 미리보기 빌드 | 저장소 **밖** `../webgl-build/preview/`(`index.html` + `Build/`, 약 47.6 MB). 설정 `[preview] webgl_dir`. 서버가 같은 출처 `/preview/webgl/`로 내보냅니다. Unity Hub에 Web Build Support 모듈이 있어야 빌드할 수 있습니다 |
| 미리보기 플레이어(예비) | 저장소 **밖** `../webgl-build/preview-win/IFSPreview.exe`. 설정 `[preview] image_player`. WebGL 빌드 폴더가 없거나 브라우저가 WebGL2를 못 쓰거나 Unity가 뜨지 않으면 그 세션은 이 플레이어의 정지 그림(`image`)으로 내려가고, 이것도 없거나 실패하면 글 요약(`none`)으로 내려갑니다. 내려간 사실과 이유는 화면 경고 줄·`selection.json`의 `preview`·세션 로그에 남습니다 |
| 브라우저 | Chrome(또는 Edge) 최신, 하드웨어 GPU. WebGL2가 되어야 합니다. GPU가 없으면 Chrome이 소프트웨어 렌더로 띄울 수 있지만 윤곽선이 하드웨어 렌더와 다릅니다(`docs/validation/webgl/README.md` 10.4) |

미리보기 빌드(처음 한 번, 그리고 Unity 렌더 코드가 바뀔 때마다). WebGL로 빌드 대상을 바꾸면 전체 재임포트가 일어나므로 **저장소의 `unity/`가 아니라 저장소 밖 복사본에서** 빌드합니다. WebGL과 예비 플레이어를 같은 복사본에서 차례로 빌드해 같은 소스를 쓰게 합니다.

```powershell
# 저장소 루트에서. 다른 Unity 프로세스(에디터 포함)가 그 복사본을 열고 있지 않아야 함
$U = "C:\Program Files\Unity\Hub\Editor\6000.0.85f2\Editor\Unity.exe"; $W = "..\webgl-build"
robocopy unity "$W\proj" /MIR /XD Library Temp Logs obj UserSettings      # 종료 코드 0–7이면 정상(8 이상 = 실패). 복사본의 Library는 다시 씀
& $U -batchmode -buildTarget WebGL -projectPath "$W\proj" -executeMethod IFS.SceneSpec.EditorTools.PreviewBuild.BuildWebGLPreview -outDir "$W\preview" -reportPath "$W\preview-build-report.json" -logFile <로그 파일>
& $U -batchmode -projectPath "$W\proj" -executeMethod IFS.SceneSpec.EditorTools.PreviewBuild.BuildWindowsPreview -outDir "$W\preview-win" -logFile <로그 파일>
# 결과: 두 보고서의 "result": "Succeeded". 빌드 산출물은 git에 넣지 않음
```

- 2026-11-23(G12 연결) 이 PC에서 위 순서로 빌드했습니다. WebGL 73.5초(Library 재사용), Windows 플레이어 4.9초, 둘 다 오류 0. 저장소의 파일은 바뀌지 않았습니다. 예전처럼 저장소의 `unity/`에서 Windows 플레이어만 빌드하면 `OpenXRPackageSettings.asset`이 줄바꿈만 바뀔 수 있으니 `git checkout -- <그 파일>`로 되돌립니다.
- 빌드하지 않으면: WebGL 빌드 폴더가 없으니 모든 세션이 처음부터 `image`(정지 그림)로 갑니다. 이때 조절의 움직임 줄은 꺼집니다(G22, 아래 7절).

## 2. 실행 (1–6단계)

```powershell
cd chatbot
.venv\Scripts\python.exe -m ifs_chatbot.server --config v4 --backend offline --condition static
```

1. 서버 창에 `웹 데모: http://127.0.0.1:8000`, 오프라인 대역 경고, `[selection] … 문구 28개가 초안(status draft)` 경고가 나오면 준비된 것입니다. 서버는 127.0.0.1에만 열립니다.
2. 브라우저에서 **http://127.0.0.1:8000** 을 엽니다. 맨 위 "조건 1 · 정적 프롬프트"가 골라져 있는지 보고, 가명 ID(예: `TRIAL-01`)를 적고 [세션 만들기] → [시작].
3. **면담(1단계).** 고정 질문에 6절의 중립 심상으로 답합니다. 모르면 "없어요" 또는 [넘어가기].
4. **확정(2단계).** [고칠게요]를 눌러 확정 텍스트를 6절의 예시 문장 그대로 바꾸고 [고친 내용으로 확정]. 예시 문장 그대로 확정하면 6절의 기대 흐름과 비교할 수 있습니다. 확정 뒤 [다음 단계로].
5. **후보 선택(4단계).** 후보(최대 4개)와 [맞는 것이 없다]가 나옵니다. 하나를 [이것으로 고르기] 하거나 [맞는 것이 없다]. 서로 구별되는 후보가 하나뿐이면(빈 자리가 없거나, 움직임만 비어 정지 미리보기에서 차이가 없음) 이 화면 없이 바로 조절 화면이 나옵니다(G34, 기록 `selection.skipped = true`).
6. **조절(5단계).** 색·형태·밝기·투명도·크기·질감·움직임(색이 맨 앞, G31)을 고치고 [다 고쳤어요]. 고칠 것이 없으면 그대로 누릅니다. 위치·거리 항목은 없습니다. 색을 바꿨는지는 `colorChanged`로 기록됩니다.
7. **사전 측정(6단계).** 지시문과 9문항. A1–A7은 [답하지 않기], 두 평정 문항(모습 일치·대표성)은 1–7로 답하고 점검표에 옮겨 적습니다. [제출].
8. 오른쪽 "연구자 화면"(맨 위 체크)에서 세션 상태, 후보 규칙·축, 선택, 조절 횟수를 볼 수 있습니다. "확정·추출" 탭에서 spec을 봅니다. 화면은 처음에 **연구자 보기**로 열립니다(G44). 참여자가 보는 화면만 보려면 체크를 풀거나 주소 끝에 `?view=participant`(세션을 다시 열 때는 `?sid=<세션ID>&view=participant`)를 붙입니다. 참여자 보기에는 연구자 패널·배지·체크가 없으니 **Ctrl+Alt+R** 또는 주소의 `view=researcher`로 돌아옵니다. 머리글의 "n / N"은 참여자가 거치는 단계(면담·확정·후보·조절·사전 측정) 가운데 지금 위치입니다.
   - **넷째 제외 범주 알림(G50, 초안).** 확정 텍스트에 죽음·자해·외상 범주 낱말(예: 피·올가미·해골)이 나오면 연구자 화면 맨 위(탭과 상관없이)에 빨간 테두리의 [안전 표시]가 뜹니다(범주·낱말·몇 번째 문장·글자 위치·형태를 막았는지). 같은 내용이 "진행·안전" 탭 알림에 `scene_safety_flag`로도 남습니다. 참여자 보기에는 나오지 않습니다. 이때 형태 후보는 나오지 않고 기본 덩어리에 말한 속성만 입힙니다(조절의 형태 항목은 그대로 쓸 수 있고, 그 사실이 기록에 남음). 진행은 막지 않으므로 **VR(7–8단계)로 이어 갈지는 실험자가 정합니다.** 이 동작과 문구는 초안이고 교수님·IRB 확인 전입니다(`docs/morning-todo.md`).
9. 끝나면 서버 창에서 **Ctrl+C**로 멈춥니다. 이때 상주 미리보기 플레이어도 함께 닫힙니다. 서버 창을 강제로 닫거나 프로세스를 죽이면 `IFSPreview.exe`가 남을 수 있으니 작업 관리자에서 끝냅니다(2026-11-23 확인).

2026-11-23 이 명령 그대로 서버를 띄우고, 합성 확정 텍스트 3개로 HTTP API를 끝까지 몰아 확인했습니다. 세 세션 모두 후보 4개, 미리보기 `image`(후보 PNG 응답 200, 플레이어 시작 0.5초, 한 장 11–12 ms), 선택(후보 1개·"맞는 것이 없다" 1개·후보 1개 + 형태 조절), 조절, 사전 측정 제출까지 갔습니다. 브라우저 화면 자체는 이번에 손으로 눌러 보지 않았고, 같은 화면의 헤드리스 캡처가 `docs/validation/selection-flow/screens/`에 있습니다.

2026-11-23(G12 연결) WebGL 미리보기로 같은 화면을 헤드리스 Chrome에서 버튼을 눌러 끝까지 확인했습니다(합성 시나리오 S1–S9 + 조절 일곱 항목의 모든 값). 후보 그림은 [다음 단계로]를 누른 뒤 처음 페이지에서 약 2.3초(Unity 시작 0.7초 + 미리 그리기 1.5초), 같은 브라우저로 다시 열면 약 0.4초에 나왔고, 조절은 누를 때마다 약 26 ms에 화면이 바뀌었습니다. 상세는 `docs/validation/webgl/README.md` 11절.

## 3. 끝난 뒤 파일이 생기는 곳 (모두 `chatbot/logs/` 아래, git 밖)

| 파일 | 내용 |
| --- | --- |
| `chatbot/logs/<세션ID>.json` | 세션 로그(`elicit-log/0.1`). 확정 텍스트, 턴, `selection:*` 사건 요약, 미리보기 대체 알림 |
| `chatbot/logs/scenes/<세션ID>.json` | 원본 spec(매퍼 v2). 후보·조절 단계에서 바뀌지 않음. 헤드셋 러너가 읽는 파일 |
| `chatbot/logs/scenes/<세션ID>.v0.json` · `.v1.json` · `.v2.json` | 같은 확정 텍스트의 비교용 출력 |
| `chatbot/logs/selection/<세션ID>/candidates.json` | 후보 생성기 출력(축, 후보 전체, 표시 순서) |
| `chatbot/logs/selection/<세션ID>/selection.json` | 선택 기록(`ifs-selection/0.2`): 보여 준 후보와 순서, 고른 후보 또는 `none` 또는 선택 건너뜀(`skipped`), 조절 이력, 색을 바꿨는지(`colorChanged`), `finalOverrides`, 슬롯별 출처(said/chosen/edited/default, 모형 없는 모양어를 말한 형태 자리는 said_unrendered_chosen/said_unrendered_default), 거리 하한 기록(`distanceFloor`: 말한 값·그려진 값) |
| `chatbot/logs/selection/<세션ID>/premeasure.json` | 사전 측정 응답(1–7 또는 null) |
| `chatbot/logs/preview-queue/` | 미리보기 플레이어 요청 폴더와 `player.log` |

- 서버가 떠 있는 동안 `http://127.0.0.1:8000/api/sessions/<세션ID>/final`로 원본 spec과 selection.json을 한 번에 볼 수 있습니다(조절을 마친 뒤).
- [응답 폐기]를 누르면 세션 로그와 이 세션의 selection 폴더가 지워집니다.
- 점검이 끝나면 이 파일들은 지우거나 저장소 밖으로 옮깁니다.

## 4. 헤드셋 단계까지 이어 가기 (7–8단계, 선택)

`unity/README.md`의 「헤드셋 연결 (Quest 3 + Quest Link, OpenXR)」을 따르고, 점검은 `docs/headset-checklist.md`에 적습니다. 사람이 헤드셋을 쓰고 확인한 적은 아직 없습니다.

1. Unity 에디터에서 `Assets/IFS/Scenes/PlacementExperiment.unity`를 열고 Play.
2. 실험자 화면 Setup:
   - **spec**: `<세션ID>.json`. 에디터에서 spec 목록 폴더의 기본값은 `<unity 폴더>/../chatbot/logs/scenes`라 이름만 적으면 됩니다.
   - **선택 파일 selection.json**: `../selection/<세션ID>/selection.json`(spec 목록 폴더 기준 상대 경로. 절대 경로도 됨).
   - 조건·통제 방식, 참여자 입력(auto), 주 사용 손. 참여자 번호는 내부 점검용 번호를 씁니다.
3. [확인]에서 선택 파일 요약(고른 후보 또는 "맞는 것이 없다", 덮어쓰기)을 보고 [시작]. 선택 파일에 넷째 제외 범주 표시(`safetyFlags`)가 있으면 실험자 화면의 경고 자리(단계 바로 아래, 오류·경고 뒤)에 [안전 표시] 줄이 뜹니다. 러너는 시작을 막지 않으니 진행할지는 실험자가 정합니다(초안). 이 줄은 PC 모니터의 실험자 화면에만 보이고 헤드셋에는 나오지 않습니다.

- spec 파일을 다른 곳으로 옮기거나 줄바꿈을 바꿔 저장하면 `specSha256`이 달라져 러너가 시작을 거부합니다. 파일을 고치지 말고 그대로 씁니다.
- 시작 자리는 spec의 거리·높이가 아니라 실험 설정(정면 1.5 m, 높이 1.2 m)입니다. spec에 거리·높이가 있으면 확인 화면에 경고가 나오고 기록에 `layoutIgnored`가 남습니다(의도한 동작).
- 헤드셋 안 평정도 시스템 점검용으로만 적고 자료로 모으지 않습니다.
- 헤드셋 없이 러너가 선택 파일을 읽는지만 보려면 자동 시행 배치(`unity/README.md` 「배치 실험 러너 ▸ 실행」, `-specPath`·`-selectionPath`)를 씁니다. 이번에 채팅 세션의 파일로 돌려 보지는 않았고, 합성 선택 파일로 돌린 결과가 `docs/validation/runner-selection/`에 있습니다.

## 7. 알려진 한계

- 후보를 보는 것 자체가 떠올린 심상을 바꿀 수 있습니다(`docs/chatbot-design.md` 7절). 이 점검은 그 크기를 재지 않습니다.
- 형태는 덩어리·안개·껍질·조각 네 가지와 기본 형상 다섯 가지(담는 것·선·얇은 판·불꽃·물방울, D6)입니다. 기본 형상은 형상을 이름 붙이는 명사를 말했을 때만 그려지고, 후보에서는 내밀지 않으며, 조절 "형태" 항목의 5–9번째(이름 없이 견본 그림으로 보임 — 글 요약 모드는 번호: 1–4 덩어리·안개·껍질·조각, 5–9 담는 것·선·판·불꽃·물방울)에서 고를 수 있습니다. 회색 불꽃·얇은 판의 옆모습·가는 선은 덜 읽힐 수 있습니다(`docs/validation/base-forms/README.md`). 동물·식물·사람·구멍·웅덩이 모양은 없습니다(사람·무기 등은 그리지 않기로 함).
- 밝기는 후보에서 빠졌지만(G34), 어두운 색에서는 조절의 밝기 차이가 화면에서 거의 구별되지 않을 수 있습니다. 조절 항목이 화면에 반영되는지 검사하는 테스트(G22)는 아직 없습니다. 후보 쪽 구별 규칙은 코드로 확인한 두 경우(최종 값이 같음, 정지 미리보기의 움직임)만 빼므로, 작은 안개의 질감 차이처럼 거의 같아 보이는 후보가 남을 수 있습니다(합성 시나리오 S1, `docs/validation/selection-flow/README.md`).
- 미리보기는 WebGL(브라우저 안 Unity, OpenGL ES 3.0/ANGLE)로 그립니다. 헤드셋(Direct3D 11)과 같은 코드·셰이더지만 그래픽 API가 달라, 같은 spec을 Windows 플레이어로 그린 것과 평균 색 ΔE00 평균 약 0.1, 가는 윤곽선에서 최대 1.4 차이가 납니다(`docs/validation/webgl/README.md` 11절). 시야각(60°)이 헤드셋(약 96°)과 달라 형상이 더 크게 보입니다.
- WebGL이 안 되어 `image`(정지 그림)로 내려가면 움직임은 보이지 않으므로 그 항목을 끕니다(G22). 이 경우 그 세션의 움직임은 후보·말한 값·기본값 그대로 남고, `selection.json`의 `adjustUnavailable.motion`에 꺼졌다는 기록이 남습니다.
- 안개는 퍼진 안개가 아니라 작은 구름 덩이로 그려집니다. 헤드셋 안에서 구름 안으로 카메라가 들어가면 시야가 가려집니다.
- 사전 측정 지시문("말씀하신 대로 나타낸")과 면담 첫 문구는 자기와 관련된 내용을 전제로 쓰였고, 모두 초안입니다.
- 헤드셋 러너는 선택 기록의 출처 값과 해시 기준을 검사하고(G26·G27), `ifs-selection/0.1`·`0.2`를 모두 읽습니다. 매퍼 v2가 거리를 하한으로 올려도 헤드셋의 시작 자리는 실험 설정이라 말한 거리와 무관합니다(G33).
- 오프라인 대역 백엔드와 조건 1만 점검합니다. 조건 2(LLM 면담)는 Ollama와 면담 모델이 필요하고 이 안내의 범위 밖입니다.
