## 3. 이 저장소에서 덧붙인 것과 이유

로컬 모델(gemma4:e4b)로 시나리오를 돌리며 실제로 나온 문제에 대응한 것입니다.

1. **인용 후보(`anchors.py`)** — e4b는 참여자 문장을 통째로 인용했다(“그 '젖은 종이처럼 축 처진 덩어리 같아요'는 마치 무엇 같나요?”). 컨트롤러가 원문에서 낱말·짧은 명사구('덩어리', '축 처진 덩어리', '조여요')를 잘라 프롬프트에 넣는다. 후보는 모두 원문의 부분 문자열이라 새 말을 주지 않는다. 사전 표제어 순위로 묘사어를 앞에, 신체 부위·비유 원천 명사를 뒤에 둔다.
2. **V3 확장** — 3어절을 넘는 인용과 여러 어절 문장 통째 인용을 막는다. '조여요'처럼 한 어절 용언은 허용한다.
3. **V5 엄격 모드** — 사전에 없는 새 내용어도 막는다. 질문 틀의 말(관계, 사이, 마치, 대하, 있 …)만 허용한다. 따옴표 구간은 지우지 않고 자리표시자(QQ)로 바꿔 분석한다. 지우면 '그 은 마치…'에서 '은'이 명사(銀)로 분석돼 정상 질문이 막혔다.
4. **V7 확장** — 질문 틀의 '은(는)'·'{X}'를 그대로 쓴 출력을 막는다(e4b에서 실제로 나옴).
5. **V8 차등 판정** — Kanana Safeguard는 참여자 문장 "젖은 종이처럼 축 처진 덩어리 같아요"만으로도 S2(괴롭힘)를 냈다. 대화 판정을 면담자 탓으로 돌리면 무해한 질문이 모두 막힌다. 그래서 (a) 질문만 따로 분류해 위험하면 실패, (b) 대화 판정이 참여자 말만의 판정과 같은 범주면 통과, 다르면 실패로 했다.
6. **V9 깊이 제한(L5)** — 기억·외상 서사 발화의 말을 인용 후보에서 빼고, 그런 말을 인용한 질문을 막는다. 그 턴에 질문이 다 막히면 일반 대체 문구("방금 말씀하신 것에 대해 더 있나요?")가 기억을 더 묻게 되므로 `depth_present` 고정 문구로 바꾼다.
7. **신호 없는 hold** — 규칙 11은 risk_signal과 hold를 같이 쓴다. e4b가 위험 신호 없이 hold를 내 확인 문구가 잘못 뜬 일이 있어, 신호 없는 hold는 잘못된 출력으로 보고 다시 만든다. 위험 신호가 있으면 move와 상관없이 확인 문구로 간다(L2).
8. **가드 판정 표** — 키워드 위기층 → 위기 대응(중지). 가드 S6, controversial, 키워드 모호층·은유층 → 확인 문구(S6·모호층은 연구자 알림). 그 밖의 가드 범주(S1 등) → 기록만. 같은 표현에 [계속]을 고른 뒤에는 다시 묻지 않는다(위기층은 예외 없음).
9. **Kanana를 Ollama에서 쓰는 법** — GGUF의 채팅 템플릿이 Ollama에서 깨져 메시지가 빠진다. raw 모드로 원래 템플릿을 조립하고, `<SAFE>`가 종료 토큰으로 처리돼 빈 응답(eval_count=1)으로 오는 것을 SAFE로 읽는다.
10. **압박하지 않기** — 직전 답이 '없어요·모르겠어요·넘어갈게요'면 그 단계의 LLM 질문을 건너뛴다. [넘어가기] 버튼도 같다. 위치를 모르면 `bodyRelation.status = unspecified`.
11. **철회** — 끝난 세션에서 [응답 폐기]를 누르면 로그 파일을 지운다(2D 평가 설문의 '응답을 제출하지 않고 폐기'). 위기 세션은 안전 기록이라 제외.

## 5-1. 확인 질문 루프 (개선 매핑 v1, 선택 기능 · 기본 꺼짐)

확정 직후 개선 매핑(v1)이 값으로 옮기지 못한 속성성 표현과 퍼지 일치 후보(값으로 쓰지 않은 것)를 참여자에게 다시 묻는 기능입니다. 설정은 `config/*.toml`의 `[mapping] clarify_loop`(기본 `false`), `clarify_max = 2`입니다. 확증 비교(H1)에서는 끕니다(`docs/research-design.md` 3.2).

| 항목 | 내용 |
| --- | --- |
| 질문 | 질문 틀 `what_kind` 하나만. `protocol.realize("what_kind", X)`로 만든 고정 문장 "그 'X'은(는) 어떤 'X'인가요?"이고 LLM을 부르지 않는다 |
| X | 확정 텍스트에 글자 그대로 있는 참여자 말. 사전에 없는 형용사·의태어(`_unmatched`의 XR·MAG·VA), 장면 파라미터가 없는 질감·모양어(`_unmapped`), 퍼지 일치 후보(`_needsConfirmation`, 값으로는 쓰지 않음). X 끝의 조사·어미는 Kiwi 품사로 뗀다('설명하기가' → '설명'). 회상 문장 속 말은 묻지 않는다 |
| 검사 | 나가기 전에 검증기 V1–V7·V9를 그대로 돌린다(V3 인용 원문, V4 단일 질문, V5 어휘 누출·새 내용어, V7 틀 표지). 걸리면 그 X는 묻지 않는다 |
| 답 | 확정 텍스트 뒤에 줄을 바꿔 덧붙이고 같은 텍스트로 v0·v1을 다시 만든다. [넘어가기]·'모르겠어요'·확인 필요(soft) 답은 덧붙이지 않는다 |
| 위기·그만 | 기존 흐름 그대로. 위기는 LLM 없이 고정 문구, [그만]은 이미 확정한 텍스트로 장면만 남기고 멈춘다 |
| 기록 | 세션 로그 `clarify`(대상, 질문, 검사 결과, 답, 덧붙인 줄, 최종 텍스트), 질문 턴 `source = clarify:what_kind` |

**검증기를 약하게 한 점(원칙 3에 따라 이유를 남김).** 확인 질문에는 V8(출력 가드 모델)을 걸지 않습니다(`Runtime.clarify_validator`, `guard=None`). 이유: 질문 문장이 고정 틀 + 참여자 말 인용뿐이라 새 내용을 만들 수 없고, 가드 모델을 부르면 LLM 호출이 생겨 이 기능의 결정론("같은 확정 텍스트 → 같은 질문")이 깨집니다. 대신 V3(참여자 말 그대로)·V5·V7·V9는 그대로 겁니다. 참여자 답은 기존처럼 입력 가드(키워드 + 가드 모델)를 거칩니다.

## 5-2. 회상 확인(recall_check)의 X (심상 유지 판정, 선택 기능 · 기본 꺼짐)

`[drift] recall_check`를 켜면 Flesh out 뒤 확정 요약 전에 고정 문구 "'{X}' — 지금 떠오르는 것도 그 '{X}'인가요?"를 한 번 냅니다(`docs/drift-design.md` 5절, 문구는 `elicitation_protocol.v1.1.json`의 draft).

문구가 draft이므로 `[drift] allow_draft_phrases = true`(기본 false, default·pilot 모두 false)를 함께 적어야 켜집니다. 적지 않으면 `recall_check`·`self_report`를 켜도 끄고 런타임 경고를 남깁니다(원칙 7, Codex CP2 #12). `true`는 IRB·팀 검토 전 개발·시연용입니다.

| 항목 | 내용 |
| --- | --- |
| X | 첫 단계에서 참여자가 **그것에 이름을 붙인 자리**('X 같은 게'·'X예요')에 쓴 형상 명사 원문, 가장 먼저 말한 것. 3어절 이하 |
| 쓰지 않는 말 | 주어 자리('덩어리가 있어요'), 직유 수식('구름 같은 덩어리'의 구름), 재질('유리로 돼 있어요'의 유리). 이런 말만 있으면 묻지 않음(`recallCheck.asked = false`) |
| 안전 | X에 위기 키워드·깊이 표지가 있으면 묻지 않음 |
| LLM | 부르지 않음(규칙만) |

**바꾼 이유(검토 T2-F08, 원칙 3).** 이전에는 이름 자리가 없으면 주어 자리 명사도 X로 썼고, 직유 수식어를 이름으로 읽었습니다. 그래서 참여자가 '가슴에 구름 같은 덩어리가 있어요'라고 했을 때 "'구름' — 지금 떠오르는 것도 그 '구름'인가요?"가 나갔습니다. 참여자는 그것을 '구름'이라고 부르지 않았으므로, 참여자가 쓰지 않은 이름을 시스템이 붙인 셈입니다. 지금은 참여자가 이름을 붙인 자리의 말만 인용합니다. 검증기를 약하게 한 변경이 아니라 X 고르기를 좁힌 변경입니다.

**검증기를 거치지 않는 점(기록).** 이 문구는 질문 틀 6개 밖의 고정 문구이고 X는 참여자 원문이라, 검증기 V1–V9를 거치지 않습니다(이전과 같음). 확인 질문 루프처럼 V3·V5·V9 경로를 거치게 하는 방법도 있습니다. 이번에는 분류표 범위(X 고르기)만 고쳤고, 질문 틀 밖 문구에 검증기를 어떻게 걸지는 정하지도 시험하지도 않았습니다. 문구 판단(요구 특성 포함, 검토 T2-F14)은 팀·IRB 결정으로 남깁니다.
