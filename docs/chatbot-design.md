## 3. 이 저장소에서 덧붙인 것과 이유

로컬 모델(gemma4:e4b)로 시나리오를 돌리며 실제로 나온 문제에 대응한 것입니다.

1. **인용 후보(`anchors.py`)** — e4b는 참여자 문장을 통째로 인용했다(“그 '젖은 종이처럼 축 처진 덩어리 같아요'는 마치 무엇 같나요?”). 컨트롤러가 원문에서 낱말·짧은 명사구('덩어리', '축 처진 덩어리', '조여요')를 잘라 프롬프트에 넣는다. 후보는 모두 원문의 부분 문자열이라 새 말을 주지 않는다. 사전 표제어 순위로 묘사어를 앞에, 신체 부위·비유 원천 명사를 뒤에 둔다.
2. **V3 확장** — 3어절을 넘는 인용과 여러 어절 문장 통째 인용을 막는다. '조여요'처럼 한 어절 용언은 허용한다.
3. **V5 엄격 모드** — 사전에 없는 새 내용어도 막는다. 질문 틀의 말(관계, 사이, 마치, 대하, 있 …)만 허용한다. 따옴표 구간은 지우지 않고 자리표시자(QQ)로 바꿔 분석한다. 지우면 '그 은 마치…'에서 '은'이 명사(銀)로 분석돼 정상 질문이 막혔다.
4. **V7 확장** — 질문 틀의 '은(는)'·'{X}'를 그대로 쓴 출력을 막는다(e4b에서 실제로 나옴).
5. **V8 차등 판정** — Kanana Safeguard는 참여자 문장 "젖은 종이처럼 축 처진 덩어리 같아요"만으로도 S2(괴롭힘)를 냈다. 대화 판정을 면담자 탓으로 돌리면 무해한 질문이 모두 막힌다. 그래서 (a) 질문만 따로 분류해 위험하면 실패, (b) 대화 판정이 참여자 말만의 판정과 같은 범주면 통과, 다르면 실패로 했다.
6. **V9 깊이 제한(L5)** — 기억·외상 서사 발화의 말을 인용 후보에서 빼고, 그런 말을 인용한 질문을 막는다. 그 턴에 질문이 다 막히면 일반 대체 문구("방금 말씀하신 것에 대해 더 있나요?")가 기억을 더 묻게 되므로 `depth_present` 고정 문구로 바꾼다.
7. **신호 없는 hold** — 규칙 11은 risk_signal과 hold를 같이 쓴다. e4b가 위험 신호 없이 hold를 내 확인 문구가 잘못 뜬 일이 있어, 신호 없는 hold는 잘못된 출력으로 보고 다시 만든다. 위험 신호가 있으면 move와 상관없이 확인 문구로 간다(L2).
8. **가드 판정 표** — 키워드 위기층 → 위기 대응(중지). 가드 S6, controversial, 키워드 모호층·은유층 → 확인 문구(S6·모호층은 연구자 알림). 그 밖의 가드 범주(S1 등) → 기록만. 같은 표현에 [계속]을 고른 뒤에는 다시 묻지 않는다(위기층은 예외 없음).
9. **Kanana를 Ollama에서 쓰는 법** — GGUF의 채팅 템플릿이 Ollama에서 깨져 메시지가 빠진다. raw 모드로 원래 템플릿을 조립하고, `<SAFE>`가 종료 토큰으로 처리돼 빈 응답(eval_count=1)으로 오는 것을 SAFE로 읽는다.
10. **압박하지 않기** — 직전 답이 '없어요·모르겠어요·넘어갈게요'면 그 단계의 LLM 질문을 건너뛴다. [넘어가기] 버튼도 같다. 위치를 모르면 `bodyRelation.status = unspecified`.
11. **철회** — 끝난 세션에서 [응답 폐기]를 누르면 로그 파일을 지운다(2D 평가 설문의 '응답을 제출하지 않고 폐기'). 위기 세션은 안전 기록이라 제외.

## 5-1. 확인 질문 루프 (개선 매핑 v1, 선택 기능 · 기본 꺼짐)

확정 직후 개선 매핑(v1)이 값으로 옮기지 못한 속성성 표현과 퍼지 일치 후보(값으로 쓰지 않은 것)를 참여자에게 다시 묻는 기능입니다. 설정은 `config/*.toml`의 `[mapping] clarify_loop`(기본 `false`), `clarify_max = 2`입니다. 확증 비교(H1)에서는 끕니다(`docs/research-design.md` 3.2).

| 항목 | 내용 |
| --- | --- |
| 질문 | 질문 틀 `what_kind` 하나만. `protocol.realize("what_kind", X)`로 만든 고정 문장 "그 'X'은(는) 어떤 'X'인가요?"이고 LLM을 부르지 않는다 |
| X | 확정 텍스트에 글자 그대로 있는 참여자 말. 사전에 없는 형용사·의태어(`_unmatched`의 XR·MAG·VA), 장면 파라미터가 없는 질감·모양어(`_unmapped`), 퍼지 일치 후보(`_needsConfirmation`, 값으로는 쓰지 않음). X 끝의 조사·어미는 Kiwi 품사로 뗀다('설명하기가' → '설명'). 회상 문장 속 말은 묻지 않는다 |
| 검사 | 나가기 전에 검증기 V1–V7·V9를 그대로 돌린다(V3 인용 원문, V4 단일 질문, V5 어휘 누출·새 내용어, V7 틀 표지). 걸리면 그 X는 묻지 않는다 |
| 답 | 확정 텍스트 뒤에 줄을 바꿔 덧붙이고 같은 텍스트로 v0·v1을 다시 만든다. [넘어가기]·'모르겠어요'·확인 필요(soft) 답은 덧붙이지 않는다 |
| 위기·그만 | 기존 흐름 그대로. 위기는 LLM 없이 고정 문구, [그만]은 이미 확정한 텍스트로 장면만 남기고 멈춘다 |
| 기록 | 세션 로그 `clarify`(대상, 질문, 검사 결과, 답, 덧붙인 줄, 최종 텍스트), 질문 턴 `source = clarify:what_kind` |

**검증기를 약하게 한 점(원칙 3에 따라 이유를 남김).** 확인 질문에는 V8(출력 가드 모델)을 걸지 않습니다(`Runtime.clarify_validator`, `guard=None`). 이유: 질문 문장이 고정 틀 + 참여자 말 인용뿐이라 새 내용을 만들 수 없고, 가드 모델을 부르면 LLM 호출이 생겨 이 기능의 결정론("같은 확정 텍스트 → 같은 질문")이 깨집니다. 대신 V3(참여자 말 그대로)·V5·V7·V9는 그대로 겁니다. 참여자 답은 기존처럼 입력 가드(키워드 + 가드 모델)를 거칩니다.

## 5-2. 회상 확인(recall_check)의 X (심상 유지 판정, 선택 기능 · 기본 꺼짐)

`[drift] recall_check`를 켜면 Flesh out 뒤 확정 요약 전에 고정 문구 "'{X}' — 지금 떠오르는 것도 그 '{X}'인가요?"를 한 번 냅니다(`docs/drift-design.md` 5절, 문구는 `elicitation_protocol.v1.1.json`의 draft).

문구가 draft이므로 `[drift] allow_draft_phrases = true`(기본 false, default·pilot 모두 false)를 함께 적어야 켜집니다. 적지 않으면 `recall_check`·`self_report`를 켜도 끄고 런타임 경고를 남깁니다(원칙 7, Codex CP2 #12). `true`는 IRB·팀 검토 전 개발·시연용입니다.

| 항목 | 내용 |
| --- | --- |
| X | 첫 단계에서 참여자가 **그것에 이름을 붙인 자리**('X 같은 게'·'X예요')에 쓴 형상 명사 원문, 가장 먼저 말한 것. 3어절 이하 |
| 쓰지 않는 말 | 주어 자리('덩어리가 있어요'), 직유 수식('구름 같은 덩어리'의 구름), 재질('유리로 돼 있어요'의 유리). 이런 말만 있으면 묻지 않음(`recallCheck.asked = false`) |
| 안전 | X에 위기 키워드·깊이 표지가 있으면 묻지 않음 |
| LLM | 부르지 않음(규칙만) |

**바꾼 이유(검토 T2-F08, 원칙 3).** 이전에는 이름 자리가 없으면 주어 자리 명사도 X로 썼고, 직유 수식어를 이름으로 읽었습니다. 그래서 참여자가 '가슴에 구름 같은 덩어리가 있어요'라고 했을 때 "'구름' — 지금 떠오르는 것도 그 '구름'인가요?"가 나갔습니다. 참여자는 그것을 '구름'이라고 부르지 않았으므로, 참여자가 쓰지 않은 이름을 시스템이 붙인 셈입니다. 지금은 참여자가 이름을 붙인 자리의 말만 인용합니다. 검증기를 약하게 한 변경이 아니라 X 고르기를 좁힌 변경입니다.

**검증기를 거치지 않는 점(기록).** 이 문구는 질문 틀 6개 밖의 고정 문구이고 X는 참여자 원문이라, 검증기 V1–V9를 거치지 않습니다(이전과 같음). 확인 질문 루프처럼 V3·V5·V9 경로를 거치게 하는 방법도 있습니다. 이번에는 분류표 범위(X 고르기)만 고쳤고, 질문 틀 밖 문구에 검증기를 어떻게 걸지는 정하지도 시험하지도 않았습니다. 문구 판단(요구 특성 포함, 검토 T2-F14)은 팀·IRB 결정으로 남깁니다.

## 5-3. 감정어 → 심상 다리 질문 (D9, 프로토콜 1.5 · 기본 꺼짐)

참여자가 첫 답을 '불안해요'·'기대돼요'처럼 감정어나 추상적인 기분으로 했을 때, 형상 없이 면담이 끝나지 않게 다리 질문을 한 번 냅니다. 사양은 `docs/codex-reviews/prompts/D9_rebuttal_prompt.md` 「메인의 판정」 표, 세부는 `docs/codex-reviews/D9_claude.md`입니다. 결정 기록은 `docs/decisions.md`에 메인이 남깁니다.

**두 단계의 역할(반박 처리 표 2).** focus_hold는 **주의 유지** 단계입니다. 「거기에 주의를 두고 잠시 머물러 보세요. 준비가 되면 지금 알아차려지는 것을 적어 주세요.」는 주의를 두라는 요청이고, 감각의 질을 묻지 않습니다. bridge는 형상 신호가 없을 때 한 번만 내는 Clean Language 형식의 **은유 질문**(질문 틀 like_what)입니다. 그래서 지금 흐름에는 감각의 질을 묻는 단계가 따로 없습니다. 몸 감각 질문(G64-b)을 넣을지는 연구 책임자에게 열린 문제로 남깁니다.

**성공 기준(반박 처리 표 1).** 은유 질문 한 번은 구체 심상을 보장하지 않습니다. 답으로 장면('시험 전날 같아요')·사람·추상·거절이 올 수 있습니다. 그래서 이 설계의 성공 기준은 "구체 심상이 나왔는가"가 아니라 **"다리 뒤 참여자가 스스로 형상 표현을 낸 비율"**입니다. 분모는 다리를 물은 세션(`capture.bridge.asked = true`), 분자는 그 가운데 다리 답이나 그 뒤 답에서 처음 형상 신호가 나온 세션(`capture.firstElicitedBy.kind`가 bridge·llm·probe이고 그 턴이 다리 뒤)입니다. 형상 신호는 규칙 판정이라 아래 오분류가 섞이므로, 원문을 사람이 다시 코딩한 값과 함께 냅니다. 다리 답은 원문 그대로 기록하고, 추상·장면·사람·거절이어도 더 묻지 않습니다(응답 유형 자동 분류는 넣지 않음, 반박 5 보류).

**켜는 곳.** `config/bridge.toml`에서만 켭니다. 이 설정은 프로토콜 `elicitation_protocol.v1.5.json`, 프롬프트 v1.1.0, 사전 오버레이 `layer1_interview.v0.json`, 안전 사전 `safety_ko.v0.2.json`, `[interview] anchor_doe_root`, `[validator] predicate_as_noun`을 씁니다. 기존 설정(default·pilot·v4·mac8gb)은 v1.4 프로토콜과 v1.0.0 프롬프트, v0 사전을 그대로 쓰고, 그 설정의 흐름과 기록 키는 바뀌지 않습니다(`tests/test_d9_bridge.py`).

**검증기를 약하게 한 점(원칙 3에 따라 이유를 남김).** 다리 문장(X가 있는 것)에는 검증기 V1–V7·V9를 걸고, 하나라도 걸리면 X 없는 고정 문장으로 바꿉니다(대체 사유 `fallbackReason = x_sentence_failed_validation`, 걸린 사유는 `capture.bridge.checks`).

- **V8(출력 가드 모델)을 걸지 않는 이유는 다리 문장이 질문 틀과 참여자 원문 인용만으로 된 문장(X 없는 문장은 틀만)이라서입니다.** 새 내용이 들어갈 자리가 없고, 가드 모델을 부르면 LLM 호출이 생겨 결정론("같은 답 → 같은 다리 문장")이 깨집니다. 안전 판정을 면제한다는 뜻이 아닙니다. 참여자 답은 지금처럼 입력 가드(키워드 + 가드 모델)를 거치고, 위기 판정 뒤에는 고정 문구만 나갑니다(`Runtime.clarify_validator`, `guard=None`, 확인 질문 루프 5-1과 같음).
- **X 없는 고정 문장 `bridge_like_what_plain`은 고정 문구 전용 검증 경로를 거칩니다**(반박 7, `Validator.check(..., require_quote=False)`). V1·V2·V4·V5·V6·V7·V9는 그대로 걸고, **인용 요구(V1 `anchor_required`와 V3 전부)만 뺍니다.** 참여자 말을 인용하지 않게 만든 문장이라 인용 요구를 걸면 늘 막히기 때문입니다. V3가 지키는 것(인용이 참여자 원문 그대로인가)은 인용이 없는 문장에서는 지킬 대상이 없습니다. 결과는 `capture.bridge.plainChecks`(적용·제외 목록, 통과 여부, 사유)에, 대체 사유는 `fallbackReason`(no_x · x_sentence_failed_validation)에 남깁니다. 고정 문장마저 걸리면 내지 않고 다리를 건너뜁니다(`skipped = plain_phrase_failed_validation`, 알림 `bridge_plain_blocked`). 검증기를 거치지 않은 문장은 내보내지 않습니다. 이 경로는 bridge 설정의 다리 단계에서만 쓰고, 다른 경로의 기본값(`require_quote=True`)은 바뀌지 않습니다.

**검증기를 강하게 한 점.** 다리 질문을 낸 세션에서는 그 뒤 LLM의 허용 틀에서 like_what을 뺍니다(CP11, 다리 1회를 LLM이 되풀이하지 않게). 프롬프트 맥락의 허용 목록과 V2 `template_not_allowed`가 같은 목록을 쓰므로 like_what을 내면 재생성·대체 경로로 갑니다(`capture.bridge.blockedTemplateAfter`). 다리를 건너뛴 세션은 그대로입니다. V7에 `predicate_as_noun`을 더했습니다(`[validator] predicate_as_noun`, bridge.toml만 켬). what_kind·where·like_what 틀의 X가 종결어미(EF)로 끝나는 활용형이면 막습니다. "그 '설레요'는 어떤 '설레요'인가요?" 같은 어색한 질문이 이전에는 통과했습니다. anything_else("'설레요'에 대해 더 있나요?")는 그대로 허용합니다. find 틀 제한도 허용 범위를 줄이는 쪽입니다.

**부수 수정(모두 bridge.toml에서만).** (1) 인용 후보 '-되' 어근 규칙: 분석기가 '기대되/VV'처럼 한 덩어리로 내면 '기대'를 어근 후보로 쓴다. 어근이 한 글자면('안되'·'잘되') 쓰지 않는다. 지금 Kiwi는 '기대/NNG + 되/XSV'로 나누므로 대부분 명사 경로로 잡힌다. (2) 감정어 사전에 '기대'(alt '기대되')를 오버레이로 더했다. emotion 범주는 슬롯을 정하지 않으므로 값 추론은 생기지 않는다. (3) 안전 사전 0.2.0: 은유 정규식을 `숨이?\s*막(히|힌|힐|혀|혔)`로 넓혀 '숨막혀요'·'숨이 막힌'도 확인 문구로 보낸다. noMore에 '안 보여요·안 떠올라요'를 더했다. 이 패턴은 발화 전체 일치만 본다(어미 '-요·-네요·-ㅂ니다'까지). '안 보이는데 차가운 느낌이에요'처럼 뒤에 묘사가 이어지면 noMore가 아니어서 그 묘사는 participant_texts·확정 초안에 남는다(원칙 2). (4) 프롬프트 v1.1.0: stage_find·stage_flesh_out 두 블록만 고쳤다(`chatbot/prompts/v1.1.0/README.md`).

**남은 위험(숨기지 않고 적음).** 형상 신호 판정은 사전 범위에 묶입니다. '머리가 하얘져요'(color)·'구름 위에 있는 것 같아요'(object)는 신호가 있다고 보아 다리를 건너뛰고, 사전 밖 명사로만 답하면 다리를 묻습니다(1회뿐). 아래는 **알려진 오분류**로 시험에 지금 판정 그대로 고정했습니다(`tests/test_d9_bridge.py`의 `KNOWN_MISCLASSIFIED`·`CODEX_15`). 문맥 규칙은 더 넣지 않았습니다(반박 4b, 시험 안 된 규칙이 늘어남). 잘못 건너뛰는 쪽이 잘못 묻는 쪽보다 해롭다는 점을 알고 둡니다.

| 밝은 성격이에요 | 신호 있음(brightness '밝') | 성격 묘사 |
| 시험 전날 같아요 | 신호 있음(비유 '전날 같') | 장면·상황 비유 |

'가슴이 조이고 불안해요'는 표면 일치 규칙으로 신호 없음이 되어 다리를 묻고 X '불안'을 고르지만, 참여자 원문 쪽 분석이 '불/안'으로 나뉘어 X 문장이 V5(`leak:불안`)에 걸리고 X 없는 고정 문장으로 바뀝니다(검증기는 약하게 하지 않았습니다). 다리 질문이 만든 형상은 함께 만든 것에 가까우므로, RQ 닮음 분석은 `firstElicitedBy`로 나눠 봅니다(아래 분석 메모). 새 고정 문구와 프롬프트는 draft이며 IRB·팀 검토 전입니다.

**분석 메모(반박 6).** 다리 노출 사례는 분석에서 따로 층화합니다. 층: (가) 다리를 묻지 않음(형상 신호가 먼저 있었음), (나) 다리를 물었고 형상이 다리 답이나 그 뒤에서 처음 나옴(`firstElicitedBy.kind` = bridge, 또는 다리 뒤의 llm·probe), (다) 다리를 물었으나 확정까지 형상 신호 없음(`imageless = true`). (나)의 형상은 시스템 질문이 끌어낸 것이므로 "떠올린 모습과 닮았다" 평정을 (가)와 합치지 않고 나눠 보고합니다. 조건 1·2 비교에서는 두 조건 모두 같은 다리 질문에 노출되므로, 조건 차이에 다리 노출이 섞이지 않습니다. 분석 계획 쪽 기록은 `docs/research-design.md` 6.1절 7번 항목입니다.

**검증기를 약하게 한 점(원칙 3에 따라 이유를 남김).** 다리 문장(X 있는 문장과 '그 느낌' 문장 둘 다)의 검증에서 V5(leak·novel)가 틀 말 **'눈·보이·무언가·느낌'**을 문제 삼지 않게 했습니다(`imageBridge.validation.v5Allow`, `Validator.check(..., extra_allow=…)`). 이 말들은 참여자가 쓰지 않았어도 G70-c가 정한 고정 문장의 일부라 빼지 않으면 다리 문장이 늘 V5에 걸립니다('느낌'은 1층 사전 dimension 항목이라 leak, '눈'·'보이'는 novel). 이 연구의 과제가 그 느낌을 눈에 보이는 물체로 만드는 것이고 두 집단에 같게 나가므로 과제 요구로 보았습니다(G70-c). 범위는 다리 문장 하나입니다. LLM 질문 경로(`Runtime.validator`)와 다른 고정 문장 경로에는 이 허용어가 없어서, LLM이 같은 문장을 내면 지금처럼 막힙니다(`test_v5_allow_is_what_lets_bridge_sentence_pass`). 남는 위험: 모든 참여자를 시각 쪽으로 기울이고 대표성 평정의 요구 특성이 늘 수 있습니다(G70 남는 위험과 같음). referent를 넣은 프로브·fleshout_open·depth_present는 1.5처럼 V 검사를 거치지 않는 사전 등록 고정 문구입니다. 넣는 X는 형상 신호 일반명사이면서 참여자 원문의 부분 문자열이고, 기억 서사 답의 말·깊이 표지어·인용 금지어를 빼는 규칙으로만 고릅니다.

**검증기를 강하게 한 점.** 결함 1·2의 V2 두 갈래(허용 목록, `image_x`), 대체 문구 반복 억제, find LLM을 묻는 조건, 다리 X 일반명사 제한은 모두 내보내는 질문을 줄이는 쪽입니다.

**시험.** `tests/test_g70.py`(43개)와 시나리오 4개(`chatbot/scenarios/g70_*.json`, experiment 설정에서만 돈다). 그중 `g70_researcher_fog`·`g70_researcher_finish`는 **연구 책임자의 시험 입력**(연구자 본인이 시험 삼아 적은 문장, `researcherTestInput: true`)이고 참여자 자료가 아닙니다. 확인하는 것: location 질문 없음, 같은 틀 연속 없음, like_what 1회 이하, 이미 말한 모양을 다시 묻지 않음, '그것'이 나가지 않음. like_what만 계속 내도록 꾸민 모의 LLM과 what_kind만 내는 모의 LLM으로 규칙 1·2가 막는지도 봅니다. `simulate.check_expect`에 기대 키 `textsExclude`·`maxTemplateCount`·`noConsecutiveTemplate`·`probesExclude`·`bodyRelationStatus`·`findLlmAsked`를 더했습니다(없으면 예전 그대로).

**남은 위험(숨기지 않고 적음).**
- 프로브 판정이 매퍼에 묶입니다. 매퍼가 상황 낱말에서 슬롯을 채우면(「마감이 다가와요」 → `motion.type`) 그 차원을 묻지 않습니다. 반대로 매퍼가 못 읽는 말(「보통 크기」)은 다시 묻습니다. "물은 것과 그릴 수 있는 것이 같은 출처"를 고른 대가입니다. `motion.speed`만 있으면(「빨리 끝내고 싶다」의 '빨리') 움직임을 말한 것으로 보지 않습니다.
- referent는 1층 사전 form·object 항목과 비유 표지 앞 명사에 묶입니다. '동그란 원'·'구형'처럼 사전 밖 명사나 형용사로만 형상을 말하면 '그 느낌'이 나갑니다. 사전의 사물어가 장소로 쓰이면(예: '벽 앞에') 그 말을 X로 고를 수 있습니다.
- find LLM 조건은 감정·감각 사전 범위에 묶입니다(예: '간절'은 사전 밖이라 「간절해요」만 답하면 find LLM을 건너뜀).
- G70-c 일반명사 제한은 다리 X에만 겁니다. LLM은 지금처럼 어근('간절')을 X로 쓸 수 있습니다(실제 gemma4:e4b 시험에서 「그 '간절'은 어떤 '간절'인가요?」).
- like_what을 다리에서 쓰면 그 세션의 LLM은 like_what을 쓸 수 없습니다. 형상 신호로 시작한 세션은 형상 X 금지 때문에 like_what이 거의 나가지 않습니다. 1.5와 1.6을 비교한 자료는 없습니다.

### 7.1 면담 밖이라는 것

- **이 단계들은 면담이 아닙니다.** 면담은 확정([이대로 맞아요])에서 끝나고, 확정 텍스트와 그로부터 만든 spec은 그 뒤 바뀌지 않습니다. 후보·조절의 결과는 원본 spec을 고치지 않고 덮어쓰기 목록과 선택 기록(`selection.json`)에 따로 남습니다(G14·G15). 그래서 "참여자가 말한 것"(spec의 `_provenance`)과 "시스템이 보여 주고 참여자가 고른 것"이 기록에서 섞이지 않습니다.
- **LLM을 부르지 않습니다.** 후보는 규칙과 버전을 붙인 값 표가 만듭니다(G8). 같은 확정 텍스트는 세션 ID와 상관없이 같은 spec과 같은 후보(후보 id·덮어쓰기)를 냅니다. 표시 순서는 세션 ID로 순환하므로 같은 spec과 같은 세션 ID에서만 같고, 이때 출력은 바이트까지 같습니다(G28. `chatbot/tests/test_candidates.py::test_g28a_…`·`test_g28b_…`·`test_output_sha256_is_pinned`, `test_no_randomness_or_time_in_module`).
- **면담 검증기 V1–V9를 쓰지 않습니다.** 이 단계의 글은 참여자 말을 인용하지 않는 고정 문구뿐이라 검증기가 검사할 생성 문장이 없습니다. 근거 테스트: `chatbot/tests/test_selection_flow.py::test_no_llm_or_validator_calls_in_stages`(LLM 백엔드 `generate`, 검증기 `check`, 확인 질문 검증기 `check`를 부르면 실패하게 바꾼 뒤 후보 → 선택 → 조절 → 끝내기 → 사전 측정을 돌려 호출 0, 면담 턴 수 그대로). 검증기를 약하게 한 변경은 없습니다.
- **위기 대응은 그대로입니다.** 이 단계에는 자유 입력 칸이 없습니다(조절 값은 표 안에서만, 표 밖 값은 422). 후보 단계는 확정까지 마친 세션(`endedBy = completed`)에서만 열리므로, 면담 중 위기 판정이나 [그만]으로 멈춘 세션에서는 열리지 않습니다(`controller.py` `Session.selection`, API는 409).

### 7.2 유도 위험

**후보를 보는 것이 원래 심상을 끌어갈 수 있습니다.** 참여자가 떠올린 것은 말로만 전달됐고, 말하지 않은 자리(형태, 크기, 투명도 …)는 비어 있습니다. 그 자리에 시스템이 만든 모양을 화면으로 보여 주면, 참여자는 원래 떠올린 것과 비교해 고르기보다 보이는 것 가운데 하나를 받아들이거나, 본 것에 맞춰 떠올린 것을 고쳐 기억할 수 있습니다. 이 단계 뒤에 받는 모습 일치·대표성 평정도 "원래 심상"이 아니라 "후보를 본 뒤의 심상"에 대한 평정일 수 있습니다.

### 7.3 그래도 넣는 이유

- **형상이 자기 것으로 받아들여지지 않으면 구별감 측정이 의미를 잃습니다**(지시문 1절, G2). 구별은 "내 경험인데 나와는 다르다"는 판단입니다. 화면의 형상이 내 것으로 느껴지지 않으면 "나와 다르다"는 당연해지고, 잰 값은 구별이 아니라 낯섦이 됩니다.
- **고정 도구와 생성 도구 모두 불일치를 보고했습니다.** 고정 도구 SelVReflect에서는 20명 중 8명이 표현 방법을 몰라 했고, 생성 도구(Refugio, MentalImager, Memory Printer)도 심상과 결과의 불일치를 한계로 적었습니다(`reports/IFS part 심상 범주 조사.md`). 규칙 렌더도 말하지 않은 자리를 기본값으로 채웁니다. 후보 단계가 없으면 그 기본값이 참여자 모르게 들어갑니다.
- **후보 단계는 그 기본값 자리를 참여자가 보고 고르게 바꾼 것입니다**(G9의 이유). 2×2의 0번 후보는 언제나 "후보 단계가 없었다면 그려졌을 형상"(덮어쓰기 없음)이라, 새로 보태는 것은 그 옆의 대안들입니다(G16).

### 7.5 남는 위험 (숨기지 않고 적음)

- **원칙 3과의 긴장.** 원칙 3은 면담자가 참여자가 쓰지 않은 묘사어·차원어·비유·예시·선택지를 내보내지 않게 합니다. 후보 단계는 면담 밖이지만, 시스템이 참여자가 쓰지 않은 형태와 값을 **화면으로** 내밉니다. 후보 넷은 사실상 그림으로 된 선택지입니다. 위 장치는 그 폭을 줄일 뿐 없애지 않습니다. 조절 패널의 항목 이름(형태·색·밝기·투명도·크기·질감·움직임)도 차원어입니다.
- **어느 빈 자리를 보여 줄지는 시스템이 고릅니다.** 2×2의 두 차원은 고정 우선순위(형태 > 크기 > 투명도 > 질감 > 움직임, G16·G34)가 정하고, 나머지 빈 자리는 기본값으로 남습니다(출처 "기본값"으로 기록).
- **모형이 없는 모양어를 말한 사람에게 말한 모양과 다른 형태를 내밉니다(G32).** '길쭉한 게 있어요'라고 말한 사람에게 덩어리·안개 후보를 보여 줍니다. 이전 규칙(G29)은 이 자리를 말한 자리로 두어 내밀지 않았습니다. 연구 책임자가 "그려지는 것과 맞게 고르게 한다"를 택했고, 대신 출처를 `said_unrendered_*`로 따로 적어 분석에서 떼어 볼 수 있게 했습니다. 사전의 모양어 범주에는 '가장자리'·'경계'·'구멍' 같은 부분·구조 낱말도 있어서, 이런 낱말만 말한 경우에도 형태 후보가 열립니다(낱말을 가리지 않음 — 기록의 `saidWords`로 구분).
- **후보가 화면에서 구별되지 않을 수 있습니다(일부만 막음).** 구별 규칙(G34)은 코드로 확인한 두 경우(최종 값이 같음, 정지 미리보기의 움직임)만 뺍니다. 안개·조각 형상에서 질감 0.5와 0.1이 구별되는지, 어두운 색에서 투명도·질감 차이가 보이는지는 그림으로 재지 않아 규칙에 넣지 않았습니다(값 표 `distinctness.unverified`). 밝기는 후보에서 빠져 S5에서 본 "어두운 색의 밝기 후보" 문제는 후보 쪽에서는 없어졌습니다. 조절 쪽 반영 검사(G22, `adjustItems.availability`)는 여전히 없습니다. image 미리보기는 움직임을 멈추고 그리므로 조절 화면에서 움직임을 바꿔도 그림이 바뀌지 않습니다. 2026-11-23 WebGL 연결 뒤에는 WebGL 조절 화면에서 움직임이 재생되고, image로 내려간 세션에서는 움직임 줄을 끕니다(7.7절). 다른 항목은 헤드리스 확인에서 값마다 화면이 바뀌었지만, 기본 형상 물방울의 질감 0.7 → 0.9처럼 최대 채널 차 7/255밖에 안 되는 조합이 있었습니다(`docs/validation/webgl/README.md` 11절).
- **평정의 대상이 흔들립니다.** 대표성·모습 일치는 후보를 보고 고친 뒤에 받습니다. 높게 나와도 원래 떠올린 것과 같다는 뜻이 아닙니다. 예전 사전 측정 지시문의 "조금 전에 보신 물체는 그것을 말씀하신 대로 나타낸 거예요"는 바로 뒤 대표성 문항을 앞질러 정하고 [맞는 게 없어요] 세션에서는 사실이 아니어서, G59(0.5.0)에서 "조금 전에 보신 물체는 면담에서 말씀하신 것을 바탕으로 만든 거예요."로 고쳤습니다. 지시 대상도 "지금 마음에 걸려 있는 그것"에서 "면담에서 떠올리신 그것"으로 바꿔 면담 첫 질문(G58)과 맞췄습니다(초안, IRB 검토 전). G60(elicitation 1.4.0)에서 첫 질문을 "요즘 가장 신경 쓰고 있는 일 가운데 우선순위가 가장 높은 일 하나를 떠올려 주세요. 자세한 내용은 말하지 않아도 괜찮아요. 그 일을 떠올리면 지금 어떤 느낌이 드나요?"로 다시 바꿨고, "면담에서 떠올리신 그것"은 그대로 맞습니다. G65·G66(2026-11-27, selection 0.6.0)에서는 지시문의 '이것'·'그것'을 없애고 대상을 나눠 부릅니다. 강도 점검 W1은 "그 일"(면담 처음에 떠올린 일), A1–A7과 대표성은 "그 느낌"(그 일을 떠올렸을 때 든 느낌), G13 문항의 물체는 "이 물체"입니다(초안, IRB 검토 전).
- **사람에게 확인하지 않았습니다.** 이 단계가 심상을 실제로 얼마나 끌어가는지는 합성 시나리오로 알 수 없습니다. 연구팀 내부 시스템 점검(`docs/internal-trial-guide.md`)은 동작 확인이지 이 위험의 측정이 아닙니다(X80).

### 7.6 새 문구와 표시 방식

- 화면 문구 27개(형상 안내, 후보 안내, 버튼, [맞는 것이 없다], 조절 안내, 항목 이름 일곱, 사전 측정 지시문·척도·문항 9개·"답하지 않기", 끝 안내)가 모두 `status: draft`이고 문구마다 `source`가 있습니다(`shared/protocol/selection_protocol.v0.json`, protocolVersion 0.2.0). 0.2.0에서 후보 1개 화면의 문구 두 개(`single_candidate_intro`·`proceed_single_button`)를 뺐습니다(G34로 그 화면이 없어짐, 0.1.0 원문은 커밋 `1051d48`). 남은 문구의 글은 바꾸지 않았습니다. 0.3.0(G12 연결)에서 문구 하나(`adjust_item_unavailable`, 7.7절)를 더해 28개가 됐습니다. 0.4.0(G57)에서 글을 다듬었고, 0.5.0(G59, 2026-11-25)에서 사전 측정 지시문 두 곳을 고치고 강도 점검 문항 `W1_intensity` "지금 그것을 떠올리면 마음이 많이 쓰인다"를 첫 문항으로 더해 사전 측정 문항이 10개, 문구가 29개가 됐습니다(W1은 표본 특성 기술용이고 주 지표가 아닙니다). 두 평정 문항은 지시문 G13의 문장을 글자 그대로 쓰고, A1–A7은 `docs/rq-v4-questionnaire-draft.md`와 글자 그대로 같습니다(`test_protocol_texts_match_sources_verbatim`). 치료·내담자·진단 표현은 없습니다(`test_protocol_has_no_therapy_terms`).
- 형상 안내 문구는 지시문 6절의 초안 "당신이 말한 것을 바탕으로 만든, 그것을 대신하는 형상입니다"입니다(⚠ 사람이 정할 것).
- 초안임을 알리는 방식은 러너의 기존 방식(X35)과 같습니다. 화면마다 맨 위에 "초안 문구 사용 중 — 이 화면의 문구 28개가 status draft(IRB·연구팀 검토 전)입니다" 줄, 서버 시작 로그와 `/api/health`·연구자 화면의 런타임 경고, 세션 로그의 `selection:candidates` 사건과 `selection.json`·`premeasure.json`의 `protocol.draftCount`·`draftKeys`. `[selection] require_spec_phrases = true`로 두면 초안 문구가 있을 때 후보 단계를 시작하지 않습니다(`test_require_spec_phrases_refuses_start`).
- G59: `[selection] participant_draft_banner = false`로 두면 맨 위 경고 줄을 참여자 보기에서 숨기고 연구자 보기에서만 보입니다. 기록의 `draftCount`·`draftKeys`와 서버 경고는 그대로입니다. 기본값은 `true`(지금과 같음)이고, 숨길지는 사람이 정합니다 ⚠.
- 문구를 확정하면 `status`를 바꾸고 출처를 적은 뒤 프로토콜 버전을 올립니다(AGENTS.md 7).

### 7.7 미리보기 방식과 움직임 (G12 WebGL 연결, 2026-11-23)

- 새 흐름의 미리보기는 WebGL(같은 Unity 코드를 브라우저에서 돌림)입니다. 안 되면 그 세션만 정지 그림(image, G25 경로) → 글 요약(none)으로 내려가고, 실제로 쓴 방식과 내려간 이유를 `selection.json`의 `preview`와 세션 로그에 남깁니다. 브라우저의 WebGL 렌더러 문자열(GPU 이름)과 Unity 그래픽 장치 문자열도 적습니다. 장치 정보라 참여자를 가리키지 않고, 사용자 에이전트 같은 다른 브라우저 정보는 적지 않습니다.
- 후보 칸은 방식과 상관없이 **정지 그림**입니다(구별 규칙 `still_preview_motion`의 전제). 조절 화면에서는 WebGL이면 움직임이 재생됩니다.
- **정지 그림(image)으로 내려간 세션에서는 움직임 조절을 끕니다**(G22 "반영되지 않는 조합은 그 항목을 끈다"). 바꿔도 화면이 같아 참여자가 효과를 볼 수 없는 값을 고르게 되기 때문입니다. 그 줄에 새 초안 문구 `adjust_item_unavailable` "이 화면에서는 바꿔도 보이지 않아 꺼 두었습니다."를 붙입니다. 항목 이름이나 값 이름을 다시 쓰지 않아 묘사어를 더 내지 않습니다. 서버도 그 세션의 움직임 조절을 받지 않고, 끈 사실을 `adjustUnavailable`로 기록합니다. 그 세션의 움직임 출처는 고르거나 말한 값·기본값 그대로 남으므로, 분석에서 `adjustUnavailable.motion`이 있는 세션은 "움직임을 고칠 기회가 없었음"으로 따로 봐야 합니다.
- 남는 위험: 같은 참여자라도 브라우저·PC에 따라 미리보기 방식이 달라질 수 있고(움직임 조절 가능 여부가 달라짐), WebGL 화면은 헤드셋(Direct3D 11)과 그래픽 API가 달라 색이 약간 다릅니다(평균 색 ΔE00 평균 약 0.1, `docs/validation/webgl/README.md` 11절).

### 7.8 안전 제외와 형태 조절 기록 (CP10 G37–G39, 2026-11-23)

- **안전 제외가 합성어·수식·직유로 새지 않게 했습니다(G37).** 이전에는 '해골 그릇', '아이 장난감 상자'가 그릇·상자로, '뱀 같은 끈'·'괴물 같은 불꽃'이 선·불꽃으로 그려졌습니다. 지금은 넓힌 명사 연속 안의 제외 형태소 하나, 또는 제외 낱말이 직유 원천인 문장이면 기본 형상을 그리지 않고 기록만 합니다(`docs/scene-spec-mapping.md` 7.5절). 그리지 않은 말은 모양어로도 세지 않아, 막힌 '끈'이 형태 후보(G32)를 여는 일도 없습니다. 면담자 문구·검증기(V1–V9)는 바뀌지 않았습니다(원칙 3).
- **대가.** 안전 쪽으로 넓게 잡아 '아이 장난감 상자', '꼬마전구', '칼 같은 건 아니고 끈이에요'처럼 사람·무기를 그리지 않는 말도 그리지 않습니다. 참여자가 말한 형상이 화면에 나오지 않는 경우가 늘어난 것이므로, 내부 시행에서 이런 문장이 나오는지 봐야 합니다(⚠ `docs/morning-todo.md`).
- **낱말 뜻에서 온 세부를 말한 것과 가릅니다(G38).** '그릇'만 말해도 입구가 넓은 그릇으로 그리는 것은 그 낱말을 말한 것의 일부로 보지만(원칙 2와의 경계), 근거를 `lexicon_implied`로 따로 적어 분석에서 참여자가 직접 말한 세부(엉킨·가는)와 섞이지 않게 했습니다.
- **형태 조절 한 번이 정한 세 슬롯을 함께 남깁니다(G39).** 형태 항목은 9값 중 하나를 고르는 조작이고, 그 조작이 `form.type`·`form.base`·`form.baseVariant`를 함께 정합니다. 말한 그릇을 선으로 바꾸면 그릇의 변형값은 쓰이지 않고(렌더러와 같은 규칙) 기록에 '고침, 값 없음'으로 남으며, 되돌리면 다시 '말함'입니다.
- **제외 판정은 G45–G51로 바뀌었습니다(매퍼 v2 builder 2.4.0).** 위 첫 두 항목(G37의 넓은 제외)은 이것으로 대체됩니다. 이제는 명사구의 중심 명사가 제외 범주(person·threat·weapon·death_self_harm_trauma)이거나 동물(에셋 없음, no_asset)일 때만 그리지 않고, 형태 후보와 [맞는 것이 없다]로 넘어갑니다(형태 축 reason `said_unrendered`, 그 낱말은 `saidWords[].unrenderedBy`에 남음). 제외 낱말이 꾸미는 말이나 빗댄 낱말로만 나오면 중심 명사를 그립니다('뱀 같은 끈' → 끈, '아이 장난감 상자' → 상자). 넷째 범주(죽음·자해·외상)만 더 엄격해서, 텍스트 어디에 나와도 형태 후보를 내지 않습니다. 색 비교('피처럼 붉은 덩어리')는 예외입니다. 넷째 범주가 나오면 세션 기록(`sceneSpec.safetyFlags`, 이벤트 `scene:safety_flag`, 연구자 알림 `scene_safety_flag`)과 `selection.json`의 `safetyFlags`에 남고, 연구자 보기와 Unity 실험자 화면에 알림이 뜹니다(참여자 보기에는 나오지 않음). VR로 진행할지는 연구자가 정합니다(초안, ⚠ 교수님·IRB 확인). 문형 표는 `docs/validation/mapper-v2/head-noun-patterns.md`에 있습니다. 면담자 문구·검증기(V1–V9)·위기 사전은 바뀌지 않았습니다.

### 7.9 화면 표현과 유도 (G44 화면 개선, 2026-11-23)

화면의 배치·크기·대비·초점·반응만 바꿨습니다. 고정 문구 글자, 문항 순서, 평정 방식, 단계 순서, 후보 표시 순서(G20), 기록 형식은 그대로이고 새 참여자용 문구는 없습니다. 상세와 전후 캡처는 `docs/validation/ui/README.md`, 정한 세부는 `docs/decisions.md` 「G44 구현 세부」.

- **값 이름을 화면에 내지 않는 원칙(7.4 "값에 이름을 붙이지 않음")은 그대로입니다.** 형태 버튼의 번호(1–9)를 **Unity가 그린 견본 그림**으로 바꿨습니다. 지금 세션의 다른 속성(색·밝기·투명도·크기·질감)은 그대로 두고 형태만 바꾼 정지 그림이라, 시스템이 이름을 붙이지 않고도 버튼이 무엇을 바꾸는지 보입니다. 글 요약(none) 모드에서는 그림이 없어 번호를 그대로 씁니다.
- **견본 그림도 시스템이 내미는 그림입니다(7.5의 긴장이 조금 커짐).** 전에는 형태 아홉 값을 보려면 하나씩 눌러야 했고 누른 것이 모두 기록됐습니다. 지금은 아홉 형태가 처음부터 작게 보입니다. 보여 준 견본은 따로 기록하지 않습니다(같은 세션·같은 상태에서 언제나 같은 그림이라 덮어쓰기 목록으로 다시 만들 수 있음).
- **움직임은 번호를 두고, 버튼에 머물면 본 미리보기에서 그 움직임을 재생합니다(WebGL만).** 정지 그림으로는 움직임이 구별되지 않고, 화살표·물결 같은 기호는 방향·성질을 시스템이 해석해 내미는 것이라 쓰지 않았습니다. 머물러 본 움직임은 조절 기록에 남지 않습니다(누른 것만 기록) — ⚠ 사람이 정할 것(`docs/morning-todo.md`). 끄려면 `web/stage.js`의 `MOTION_PREVIEW_ON_DWELL`.
- **화면 낭독기 이름도 새 묘사어를 만들지 않습니다.** 색 견본은 "색 1"–"색 17", 형태·움직임은 "형태 n"·"움직임 n"(항목 이름은 프로토콜의 기존 글). 색 이름을 붙이지 않았습니다.
- **[맞는 것이 없다]를 후보 버튼과 같은 모양·크기로 했습니다.** 전에는 점선 작은 버튼이라 후보를 고르는 쪽으로 기울 수 있었습니다(7.4 "맞는 것이 없다"의 취지를 화면에서도 지킴).
- **참여자 보기**에서는 연구자 패널, 머리글의 "데모"·영문 부제·조건·모델 배지, 문구 출처 꼬리표, 미리보기 대체 사유를 숨깁니다. 초안 문구 안내 띠(X35)는 두 보기 모두에 남깁니다(G59부터 `[selection] participant_draft_banner = false`로 참여자 보기에서만 숨길 수 있음, 기본은 보임 — 7.6절). 기본은 지금처럼 연구자 보기입니다.

### 7.10 사후 면담 기록 화면 (G59, 2026-11-25)

RQ3("자리와 그 뜻")를 받으려고 연구자가 여는 기록 화면을 더했습니다. 새 흐름(`[selection] enabled`)에서만 열리고(`/?view=postinterview&session=<세션 ID>`), 기본 설정의 화면·API·기록은 그대로입니다. 실험자 대본은 `docs/post-interview-guide.md`, 문항은 `shared/protocol/post_interview.v0.json`(0.1.0, 모두 draft, IRB 검토 전)입니다.

- **면담이 아닙니다.** 모든 평정이 끝나고 헤드셋을 벗은 뒤 실험자가 정해진 문장을 읽고 참여자 말을 받아 적습니다. LLM과 면담 검증기를 부르지 않고(`test_postinterview_never_calls_llm`), 세션 로그에 사건을 더하지 않습니다. 기록은 같은 세션 폴더의 `postinterview.json`(`ifs-postinterview/0.1`, git 밖)입니다.
- **원칙 3을 사람에게 옮긴 규칙.** 실험자는 "왜"·예시·선택지·과거를 묻지 않고, 참여자가 먼저 쓰지 않은 낱말(거리·멀리·가까이·치우다·피하다·편하다·안전)을 쓰지 않습니다. 자유 응답 문항(PI1–PI5)에는 이 낱말이 없습니다(`test_free_part_uses_no_words_the_rules_forbid_and_no_why_or_therapy_terms`). 되묻기 PI3의 `{X}`는 앞서 받아 적은 참여자 말에 글자 그대로 있는 3어절 이하 낱말만 서버가 받습니다.
- **평정 묶음은 뒤에.** 자리 근거 평정(PI6, "가까이"·"편한" 같은 낱말이 있음)은 자유 응답을 저장하거나 건너뛴 뒤에만 화면에 나오고 서버도 그 전에는 받지 않습니다. PI4(그때/지금)는 사후 재구성 민감도 점검, PI7은 평정 문항이 말하는 대상의 점검(G66 뒤로는 "그 느낌"을 무엇으로 읽었는지), PI8은 요구 특성 점검입니다.
- **남는 위험.** 받아 적기는 실험자를 거치므로 줄이거나 바꿔 적을 수 있습니다(녹음 여부 ⚠ 사람이 정할 것). PI2는 조건(place·point_select / view)에 따라 문장이 달라 응답을 조건끼리 그대로 비교하기 어렵습니다.
- 분석기(`eval/placement.py --selection-dir`)는 사전 측정·사후 면담 파일이 있으면 `pre_*`·`pi_*` 열을 더하고, 자유 글은 글자 수·건너뜀만 표에 넣습니다. 파일이 없으면 출력은 바이트까지 그대로입니다(`test_analyzer_without_files_is_byte_identical`).

### 7.11 [맞는 게 없어요] 뒤 형태 생성과 참고 그림 고르기 (G73·G75, 2026-11-28, experiment 설정만)

후보 화면에서 처음 [맞는 게 없어요]를 누르면 그때까지의 말(확정 텍스트)로 로컬 모델이 형태를 하나 더 만들어 후보 맨 앞에 보여 줍니다(G73, `chatbot/ifs_chatbot/none_gen.py`). 프롬프트는 규칙만 만들고(한→영 고정 사전, 말한 형태 낱말만, 낱말마다 원문 위치), 참여자가 그 후보를 골라야만 장면에 씁니다(AGENTS.md 원칙 1·2의 G62 예외). 운영 절차는 `docs/run-experiment.md` 6절입니다.

G75(`[gen3d] on_none_image_pick = true`, `experiment.toml`만)는 그 사이에 **3D 모델이 참고할 그림을 참여자가 먼저 고르는** 화면을 넣습니다(선행 Refugio, Mora 외 2026의 흐름).

- **흐름.** 같은 규칙 프롬프트에 무채색 화풍 고정 문구(`tools/gen3d/prompts.image_pick_prompt`, builder `gen3d-shape-prompt/0.4.0+imagepick+mapper-v2`, 화풍 `g75-image-style/0.1.0`)를 붙여 SDXL 그림 3장(seed = 기준 + 3r, + 1, + 2 — r은 회차) → 그림마다 출력 관문(CLIP 사람·얼굴·동물, 기존 라벨·문턱 0.5) → 통과한 그림만 seed 순서로 나란히 보임 → 고른 그림으로만 TripoSG(형태 seed = 그 그림의 seed) → 후보 맨 앞. 그 뒤는 G73과 같습니다.
- **화풍을 무채색으로 고정한 이유.** 최종 물체는 형태만 쓰고 색·재질은 말한 값(매핑)과 조절 값으로 칠합니다. 참여자가 그림의 색을 보고 고르면 고른 이유와 장면이 어긋납니다. 그래서 그림은 흰 배경 회색 점토 조형 하나로 그리고, 안내 문구가 "색은 나중에 말씀하신 대로 칠하니, 모양만 봐 주세요"라고 알립니다. 고정 문구는 심상 속성이 아니라 시스템 문구이고(`slot: template`), 내용 토큰은 바뀌지 않습니다. 이 함수를 거치지 않는 G62 기본 후보·G73 경로의 프롬프트는 그대로입니다.
- **원칙 3과의 관계.** 그림 3장은 시스템이 내미는 선택지입니다. 후보 넷과 같은 긴장(7.5절)이 있고 더 큽니다: 모델이 말하지 않은 세부(구멍·개수·비율)를 그림에 넣습니다. 그래서 고르기 화면에 노출된 세션을 `generation.imagePickExposed`로 가르고, 회차마다 보여 준 그림의 seed·sha256·관문 결과·보인 순서·고른 자리를 남깁니다(`afterNone.imagePick`). 화면은 그림에 이름·설명을 붙이지 않고 번호만 씁니다. 문구 4개(그림 대기·고르기 안내·[이 중에는 없어요]·[넘어갈게요])는 `selection_protocol.v0.9.json`(0.9.0)에 draft로 있습니다.
- **다시 고르기.** [이 중에는 없어요]나 만든 후보에 다시 [맞는 게 없어요]면 새 seed 3개로 다음 회차(`on_none_image_rounds`, 기본 2), 그다음은 기존 none 경로(0번 후보로 조절)입니다. 모든 회차를 거절하면 `afterNone.status = declined`. 이 플래그가 켜져 있으면 G73의 '같은 프롬프트 seed + 1로 다시 만들기'(`on_none_max_regenerations`)는 쓰지 않습니다. [넘어갈게요]는 기다리지 않고 넘어가기와 같은 경로입니다.
- **모델과 면담의 상호 배제(CP13)는 그대로입니다.** 그림 단계와 형태 단계가 각각 하나의 생성 작업입니다: 면담·가드 모델을 내림 → 생성기 → 다시 올림. 작업 중에는 새 면담을 409로 막고 키워드 위기 문장은 통과시킵니다. 참여자가 그림을 고르는 동안에는 모델이 다시 올라가 있어 다른 세션의 면담·위기 판정이 가드 모델 없이 돌지 않습니다. 대기 한도는 단계마다(`on_none_image_timeout_s`·`on_none_mesh_timeout_s`, 각 180초, 모델 내리기 포함)이고 고르는 시간은 넣지 않습니다. 고르는 사이에 다른 세션이 면담을 시작하면 형태 단계는 만들지 않습니다(`interview_active`, 기존 경로).
- **기록 형식.** 플래그를 켠 세션은 처음 none을 누르는 순간 `ifs-selection/0.4`(`shared/schemas/selection.v0.4.json`, 0.3에 선택 필드만 더함: 단계 `picking`, `afterNone.imagePick`, `generation.imagePickExposed`, 값 `declined`)로 씁니다. 헤드셋 러너는 0.4를 0.3과 같은 규칙으로 읽습니다(읽는 필드가 같음). 플래그를 끄면 G73의 0.3 기록 그대로입니다.
- **남는 위험.** 그림 관문은 그림 한 장을 CLIP에 넣는 것이라 메시 렌더 6시점 관문보다 약하고, 형태를 만든 뒤 메시 관문(사람·동물·여러 물체)을 한 번 더 거칩니다. 그림과 만든 메시가 같은 모양이라는 보장은 없습니다(TripoSG가 그림을 다시 해석함). 색을 말하지 않은 참여자에게는 안내의 '말씀하신 대로 칠하니'가 맞지 않습니다(기본 색). 사람에게 확인하지 않았습니다.
