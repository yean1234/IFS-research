# 규칙 매핑 불일치 점검 (2026-11-17)

후보1 실험(`docs/research-design.md`)에서 원본 형상은 참여자 말을 규칙 매퍼(v1)가 옮긴 결과입니다. 매퍼가 말을 잘못 읽으면 원본부터 "내 것 같지 않은" 형상이 됩니다. 이 문서는 매퍼가 어떤 말을 어떻게 틀리는지 합성 문장으로 점검한 기록입니다. **이번에는 매퍼를 고치지 않았습니다**(`docs/decisions.md` X29, 9절).

- 대상: `chatbot/ifs_chatbot/scene_builder_v1.py`(`scene-spec-builder-v1/1.2.0`), 사전 `layer1-attribute-lexicon@1.0.0`, `scene-params@1.0.0`(`shared/lexicon/scene_params.v1.json`), 분석기 Kiwi. 커밋 1e0a093 시점 코드이며 매퍼·사전은 바꾸지 않았습니다.
- 이전 held-out 평가(`docs/validation/e2e/`, `docs/mapping-failures.md`)와는 다른 점검입니다. 그쪽은 정답 라벨과 채점기로 잰 비율이고, 이쪽은 실패 유형을 찾으려고 일부러 어려운 문장을 넣은 사례 점검입니다.

## 1. 방법

- **합성 문장 85개.** 기본 색·복합 색·부정·두 부분 색·색 비유·형태 비유·정도 부사·비교·부분 한정·위치·움직임·배경 대상·모순·사전 밖 낱말·부분 문자열 함정 등 유형별로 AI 에이전트가 썼습니다. 참여자 자료가 아닙니다(원칙 6).
- **held-out을 쓰지 않았습니다.** `chatbot/tests/fixtures/imagery_corpus/heldout.json`은 열지 않았습니다.
- **코드 무수정.** 문장마다 `SceneSpecBuilderV1.build()`를 한 번 호출하고 값·근거(`_provenance`)·보존 필드를 뽑았습니다. 실행 스크립트와 출력은 저장소 밖 임시 폴더에 있습니다. 85개 모두 매핑 `v1`로 처리됐고(폴백 없음), 원칙 검사(`check_principles`) 위반은 0건이었습니다.
- **판정.** 출력마다 아래 다섯 유형 중 하나를 붙였습니다. 판정도 AI 에이전트가 했고 사람 판정이 아닙니다. 경계 사례는 경계라고 표시했습니다(3·4절).

| 유형 | 뜻 |
| --- | --- |
| 일치 | 말한 속성이 맞는 슬롯에 맞는 값으로 들어감. 부정·배경 대상·부분 색처럼 값을 만들지 않아야 하는 경우는 값 없이 알맞은 보존 필드에 남음 |

**이 점검의 한계.** 문장은 실패를 찾으려고 고른 것이라 **비율은 실제 참여자 텍스트의 오류율이 아닙니다.** 57/85를 정확도로 쓰지 않습니다. 문장 작성과 판정이 모두 AI 에이전트이고, 한 문장짜리 입력이라 면담 전체 텍스트(여러 턴, 정정)의 동작은 보지 않았습니다.

## 5. "초록색 안개"의 실제 출력과 기본값 구분

입력 「초록색 안개가 있어요.」(C01)와 「초록색 안개」(U05)는 같은 값을 냅니다.

| 슬롯 | 값 | 근거 |
| --- | --- | --- |
| `form.type` | mist | '안개' — `formLexicon.안개>form.type:mist`(explicit_lexicon) |
| `material.color` | HSL(0.333, 0.45, 0.4) | '초록색' — `colorTerm.초록색>material.color:hsl`(phrase_rule) |
| 그 밖의 슬롯 전부 | null | — |
| `_unmatched` | '있어요' | (C01만) |

Unity는 null 슬롯을 기본값으로 채우고 어느 키를 채웠는지 `DefaultsUsed`에 남깁니다(`SceneParams.cs:65-75`, 기본값 `SceneParams.cs:12-28`). 이 문장에서는 다음 10개 키가 기본값입니다: `form.posture`(없음), `material.brightness` 0.5, `material.roughness` 0.5, `material.opacity` 1, `material.erosion` 0, `layout.size` 0.5, `layout.distance` 0.33, `layout.verticalOffset` 0.75, `motion.type` still, `motion.speed` 0.5. 색 h·s·l과 형태는 말한 값입니다. mist 프리셋 자체가 매우 옅게 보인다는 점은 따로 알려진 문제입니다(`docs/morning-todo.md`).

**말한 값과 기본값을 가르는 방식.**

1. spec 단계: 말한 것만 값이 되고, 값마다 `_provenance`에 원문 근거(trigger, charSpan, rule)가 붙습니다. 말하지 않은 슬롯은 null입니다. 기본값을 spec에 쓰지 않습니다(원칙 2).
2. `_inferred`(감정어·신체 부위에서 나온 3층 제안)는 값이 아니라 따로 둡니다. 후보1 러너는 이것을 쓰지 않고, 쓴 흔적(`InferredUsed`)이 있으면 실행을 거부합니다.
3. Unity 단계: null → 기본값, 키는 `DefaultsUsed`에 기록합니다.
4. 후보1 변형: 변형이 바꾼 키의 출처 슬롯에 `_provenance`가 있으면 stated, 없으면 default입니다(`docs/decisions.md` X24, `docs/research-design.md` 3.2절).
5. 구별하지 못하는 것: '모르겠어요'(`_uncertain`)와 말하지 않음은 둘 다 null → 기본값입니다. 규칙이 **잘못 만든 값**도 `_provenance`가 있으므로 "말한 값"입니다.

규칙을 따져 보면 C01 원본의 후보1 변형은 이렇게 됩니다(생성기로 실행한 결과가 아니라 `docs/decisions.md` X20–X24 규칙에서 따진 예상): 형태 mist → blob(remove, stated), 색은 유채색이라 색상 회전(stated), 크기는 기본값 0.5에서 cb 방향(default), 움직임은 기본값 정지 → floating(add, default).

## 6. 후보1 실험에 미치는 영향

- **원본 평정의 바닥이 낮아집니다.** 원본이 말과 다르면 참여자는 원본부터 "내 것 같지 않다"고 할 수 있습니다. 그러면 변형의 하락이 작게 나오거나 음수가 됩니다. 연구 설계는 원본 평정 4 미만 세션을 따로 보고합니다(`docs/research-design.md` 6.1절).
- **왜곡된 값도 stated로 분류됩니다.** 예: C06에서 참여자는 초록을 말했지만 값은 회색입니다. 색 변형은 이 회색(무채색, s 0.05 < 0.10)을 기준으로 **명도 규칙**을 고르고, 출처는 stated가 됩니다. 참여자가 마음에 둔 초록과는 다른 축을 바꾸는 셈입니다. B19(감정이 커요 → 크기)에서는 형상 크기를 말하지 않았는데 크기 변형이 stated로 분류됩니다. RQ2 해석이 흐려집니다.
- **부분 한정이 전체로 번지면 저가시성이 생깁니다.** A06·A14처럼 투명도 0.1이 전체에 들어가면 원본 유효 opacity가 0.15 미만이라 러너가 `lowVisibility` 경고를 냅니다. 다섯 형상이 모두 잘 안 보이게 됩니다.
- **형태 변형의 기준이 바뀝니다.** A05에서 '끝만 뾰족'이 전체 원뿔이 되면 형태 변형은 원뿔 → 구(remove)가 됩니다. 참여자가 말한 "끝이 뾰족한 형상"과는 둘 다 다릅니다.
- **부분 명사가 모양어로 잡힙니다.** A06·C15의 '가장자리'는 `_unmapped`에 shape(값 edge)로 들어갑니다. edge는 모양 모형 표에 없으므로 모양 상태가 `unmapped_shape`가 되고, 설계 규칙대로라면 형태 변형에 `saidNotRendered`가 붙습니다. 참여자는 모양이 아니라 가장자리의 색·투명도를 말했으므로 이 플래그는 과하게 붙은 것입니다. 생성기 결과로 확인하지는 않았습니다.
- **대응(이번 범위).**
  1. **실험자 확인 화면.** 시행 전에 속성별 "말한 값 / 기본값 / 반영 못 한 것"과 변형의 from → to를 보여 줍니다(X29). 실험자는 spec을 고치지 않고, 말과 다른 값이 보이면 기록 양식에 "왜곡 의심"을 표시합니다.
  2. **반영 비율을 분석 변수로.** 세션마다 값이 있는 렌더 슬롯과 반영 못 한 속성어의 비율을 기록하고 공변량·민감도 분석에 씁니다(`docs/research-design.md` 4.5절). 반영 비율은 왜곡을 잡지 못하므로 실험자 표시와 함께 봅니다.
  3. 누락-기록 없음(C16–C18 등)은 확인 화면에서도 속성어로 드러나지 않습니다. 실험자는 `_unmatched` 원문을 함께 봐야 합니다.
