# 사후 면담 실험자 대본 (RQ3 "자리와 그 뜻", 초안)

> 결정 G59(2026-11-25), G60(2026-11-26 교수님 피드백: PI1 문장, 되받기 한 줄, 문항마다 알고 싶은 것, 헤드셋 `want_move` 뺌), G66(2026-11-27: 평정 문항의 대상 호칭이 '그 느낌'으로 바뀌어 PI7 질문·선택지를 바꿈). 문항 파일은 `shared/protocol/post_interview.v0.json`(protocolVersion 0.3.0)입니다. 문항·규칙·화면 문구는 모두 `status: draft`이고 IRB 검토 전입니다. 이 문서는 그 파일을 사람이 읽기 쉽게 풀어 쓴 것이고, 문구가 다르면 파일이 기준입니다.
>
> 이 연구는 치료가 아니라 자기성찰 보조입니다. 사후 면담도 참여자가 물체를 어디에 두었고 그 자리가 어떤 자리였는지를 듣는 데서 멈춥니다. 참여자가 면담에서 떠올린 일의 내용이나 과거를 묻지 않습니다.

## 1. 언제 하는지

RQ3 도구는 세 층입니다(G59-1). 사후 면담은 B·C층과 해석용 점검(D)을 맡습니다.

| 층 | 어디서 | 문항 |
| --- | --- | --- |
| A | 헤드셋 안, 점검 단계 | 1문항 `place_fit` "방금 이것이 있던 자리는 나에게 알맞게 느껴졌다"(두 조건 공통). G59(헤드셋 문구 파일 0.5)에서는 `want_move`까지 2문항이었으나 G60에서 뺐습니다. 멈춤 거리 과제에 여러 번 고칠 수 있는 기능을 넣기 때문입니다(교수님 결정, 헤드셋 문구 파일 0.6) |
| B | 헤드셋을 벗은 뒤, 구두 | PI1–PI5 자유 응답 |
| C | 사후 면담 맨 끝 | PI6 영향 평정 6항목(직접 배치만) |
| D | 사후 면담 맨 끝 | PI7 '그 느낌'을 무엇으로 읽었나, PI8 연구 목적 짐작 |


- **모든 평정이 끝나고, 참여자가 헤드셋을 벗은 뒤에** 합니다. 헤드셋 안 평정(사후·점검 문항)과 멈춤 거리 과제가 다 끝난 다음입니다. 사후 면담의 낱말이 평정에 섞이지 않게 하려는 것입니다.
- 장소는 데스크톱 화면 앞입니다. 실험자가 연구자 화면을 열고, 몇 문항은 참여자에게 화면을 넘겨 직접 적거나 고르게 합니다.
- 화면 여는 법: 새 흐름 서버(`--config v4`)에서 주소 `http://127.0.0.1:8000/?view=postinterview&session=<세션 ID>`를 엽니다. 세션 ID는 면담·후보 단계의 세션 ID와 같습니다. 기록은 같은 세션 폴더(`chatbot/logs/selection/<세션 ID>/postinterview.json`, git 밖)에 저장됩니다. 기본 설정(`default.toml`)에서는 이 화면이 열리지 않습니다.
- 화면에서 먼저 **조건**을 고릅니다. 조건에 맞는 문항만 나옵니다.

| 조건 | 뜻 |
| --- | --- |
| `place` | 참여자가 물체를 직접 놓은 조건 |
| `view` | 보기만 한 조건(static·replay·system_move) |
| `point_select` | 보기만 조건에서 바닥을 가리켜 자리를 고른 조건 |

## 2. 실험자 규칙

1. **"왜"를 묻지 않습니다.** "왜 거기 두셨어요?" 대신 정해진 문장("어떻게 알았나요?")만 씁니다. "왜"는 그럴듯한 이유를 나중에 지어내게 만들기 쉽습니다(사후 합리화, Nisbett & Wilson 1977).
2. **예시나 선택지를 주지 않습니다.** "예를 들면 편한 자리라든지…" 같은 말을 붙이지 않습니다. PI4·PI7의 정해진 선택지만 예외입니다.
3. **과거나 기억을 묻지 않습니다.** "예전에도 그런 적이 있나요?" 같은 질문을 하지 않습니다.
4. **참여자가 먼저 쓰지 않은 낱말을 쓰지 않습니다.** 특히 거리, 멀리, 가까이, 치우다, 피하다, 편하다, 안전. 참여자가 이 낱말을 먼저 썼다면 그 말을 그대로 되돌릴 수는 있습니다(PI3).
5. **참여자 말을 그대로 받아 적습니다.** 고치거나 줄이거나 다른 말로 바꾸지 않습니다.
6. **모든 평정이 끝나고 헤드셋을 벗은 뒤에 합니다.**

정해진 문장 밖의 말은 "네", "천천히 말씀하셔도 돼요" 정도로 줄입니다. 참여자가 힘들어하거나 그만하고 싶어 하면 바로 멈추고, 기록에는 남은 문항을 건너뜀으로 둡니다.

## 3. 문항 순서와 조건별 문구

문항은 두 부분입니다. **앞 부분(PI1–PI5)을 저장하거나 건너뛴 뒤에만 뒤 부분(PI6–PI8)이 화면에 나옵니다.** 평정 묶음 PI6에는 "가까이", "편한" 같은 낱말이 들어 있어서, 먼저 보이면 자유 응답이 그 낱말 쪽으로 끌려가기 때문입니다.

| 순서 | id | 조건 | 방식 | 문장 |
| --- | --- | --- | --- | --- |
| 1 | `PI1_place_recall` | 모두 | 구두, 실험자가 받아 적음 | 방금 물체가 있던 자리를 떠올려 주세요. 그 자리는 나에게 어떤 자리였는지, 떠오르는 대로 말해 주세요. |
| 2 | `PI2_how_known` | place · point_select | 구두 | 그 자리에 놓던 순간으로 돌아가 볼게요. 그때 '여기다' 하는 것을 어떻게 알았나요? |
| 2 | `PI2_view_noticed` | view | 구두 | 물체를 바라보던 때로 돌아가 볼게요. 그때 무엇을 알아차렸는지 떠오르는 대로 말해 주세요. |
| 3 | `PI3_more` | 모두 | 구두, 최대 2회 | 말씀하신 '{X}'에 대해 더 있나요? |
| 4 | `PI4_timing` | 모두 | 참여자가 고름: 그때 / 지금 / 둘 다 / 잘 모르겠어요 | 방금 말씀하신 것은 그때 알아차린 것인가요, 지금 돌아보며 떠오른 것인가요? |
| 5 | `PI5_one_line` | 모두 | 참여자가 직접 적음, 넘어갈 수 있음 | 방금 말씀하신 것 가운데 가장 중요한 것을 한 줄로 적어 주세요. 적고 싶지 않으면 넘어가도 돼요. |
| 6 | `PI6_basis` | place · point_select | 참여자가 고름, 1–7, 항목마다 넘어갈 수 있음 | 자리를 정할 때 아래 점들이 얼마나 영향을 주었나요? (1 전혀 영향을 주지 않았다 – 7 매우 많이 영향을 주었다) |
| 7 | `PI7_referent` | 모두 | 참여자가 고름: 그 일을 떠올렸을 때 든 느낌 / 처음에 떠올린 일 / 눈앞에 있던 물체 / 여러 가지가 섞였어요 / 잘 모르겠어요 (G66, 0.3.0. 0.2.0까지는 "'이것'을 … 눈앞의 물체 / 마음속 그것 / 둘 다 / 잘 모르겠어요") | 문항에 나온 '그 느낌'을 무엇으로 읽으셨나요? |
| 8 | `PI8_purpose` | 모두 | 참여자가 직접 적음, 넘어갈 수 있음 | 이 연구가 무엇을 알아보려 한다고 생각하셨나요? |

PI6 항목: `B1_visibility` 잘 보이는 자리인지 · `B2_reach` 손으로 옮기기 편한 자리인지 · `B3_floor_marks` 바닥의 고리나 표시 · `B4_apart` 이것과 떨어져 있고 싶은 마음 · `B5_near` 이것을 가까이 두고 싶은 마음 · `B6_no_thought` 특별히 생각하지 않고 놓았다.

**PI1 되받기(G60).** 참여자가 문항의 뜻을 되물으면 아래 한 줄만 말합니다. 예시나 다른 설명을 덧붙이지 않습니다(규칙 2·4). 파일의 `PI1_place_recall.clarify`와 같은 글입니다.

> 정답은 없어요. 그 자리에 대해 떠오르는 것이면 무엇이든 괜찮아요.

**PI3 되묻기.** `{X}`에는 참여자가 PI1·PI2(또는 앞 회차 PI3)에서 실제로 한 낱말이나 짧은 구(3어절 이하)만 넣습니다. 실험자가 고른 낱말이나 요약을 넣지 않습니다. 화면은 X가 앞서 받아 적은 글에 글자 그대로 없으면 빨간 글로 알리고, 서버는 저장을 거부합니다. 되물을 낱말이 없으면 PI3은 하지 않습니다(기록에는 건너뜀 한 줄).

## 4. 문항마다 알고 싶은 것

연구자용입니다. 참여자에게 읽어 주지 않습니다. 파일의 각 문항 `purpose`와 `rq3Layers`에 같은 내용이 있고, 기록 화면 설정(`/api/postinterview/config`)에는 보내지 않습니다. 아래 표의 B1–B5·C·D1·D2는 층 안의 순서 이름입니다. PI6 항목 id의 `B1_`–`B6_` 접두와는 관계가 없습니다.

| 문항 | 알고 싶은 것 | 답을 어디에 쓰나 |
| --- | --- | --- |
| A1 `place_fit`(헤드셋) | 자리 자체에 대한 평가를 두 집단이 같은 눈금으로 남깁니다. 보기만 집단은 자리를 정한 적이 없어 '놓은 자리' 기록이 없으므로, A1이 두 집단을 견줄 수 있는 유일한 RQ3 숫자입니다 | 조건 비교(스스로 정한 자리가 더 알맞게 느껴지는가) |
| B1 `PI1_place_recall` | 자리의 **성격**(무엇)을 참여자 자신의 낱말로 받습니다. 연구자가 범주를 내놓기 전에, 참여자가 어떤 기준(내 몸 / 물체의 모습 / 공간 / 마음속 그것 / 과제 편의)으로 그 자리를 규정하는지 봅니다. 거리·방향·높이 숫자가 같은 두 사람이 서로 다른 뜻으로 놓았는지를 가르는 자료이고, RQ3의 "그 자리를 어떻게 말하나"에 직접 답합니다 | 정리 틀의 '무엇을 기준으로 말했나' 코딩 |
| B2 `PI2_how_known` | 자리를 정하던 **순간**에 무엇을 단서로 삼았는지(과정)를 받습니다. 까닭(왜)이 아니라 그때 알아차린 것입니다 | '어떤 방향이었나' 코딩, B1과 어긋나는지 확인 |
| B2′ `PI2_view_noticed` | 보기만 집단의 대응 질문입니다. 자리를 정하지 않았으므로 바라보는 동안 알아차린 것을 받습니다 | 두 집단의 말을 같은 틀로 정리 |
| B3 `PI3_more` | 참여자가 쓴 낱말의 뜻을 연구자가 짐작하지 않도록 그 낱말만 되돌려 넓힙니다 | B1·B2 코딩의 근거 보강 |
| B4 `PI4_timing` | 그때 안 것인지 지금 돌아보며 떠오른 것인지 표시합니다 | 사후 합리화 민감도 분석(G59-11 ③) |
| B5 `PI5_one_line` | 받아 적기에서 잃는 것을 참여자가 직접 고른 한 줄로 보완합니다 | 인용 후보, 코딩 대조 |
| C `PI6_basis` | 연구자가 **미리 정한 여섯 요인**이 자리 정하기에 각각 얼마나 작용했는지를 같은 눈금으로 받습니다. 뜻이 있는 배치(떨어져 있고 싶음·가까이 두고 싶음)와 과제 가공물(잘 보임·손이 편함·바닥 표시·생각 없이 놓음)을 가릅니다. 참여자가 B1에서 스스로 말하지 않은 요인도 잡힙니다 | 참여자 사이 비교, B1 코딩의 확인 |
| D1 `PI7_referent` | 문항의 '그 느낌'을 뜻한 대로(그 일을 떠올렸을 때 든 느낌) 읽었는지, 처음 떠올린 일이나 눈앞의 물체로 읽었는지 봅니다 | 민감도 분석(G59-11 ④, G66-f): '그 느낌'을 눈앞의 물체나 처음 떠올린 일로만 읽은 사람(값 `object`·`event`)을 빼고 다시 봅니다. 값 대응: `object`·`unsure`는 0.2.0과 같고, 예전 값 `inner`(마음속 그것)는 `feeling`·`event`에 걸쳐 가를 수 없으며 `both`(둘 다)는 `mixed`에 가깝습니다 |
| D2 `PI8_purpose` | 연구 목적을 눈치챘는지 봅니다 | 민감도 분석(G59-11 ②) |

### B1과 C는 무엇이 다른가

| | B1 | C |
| --- | --- | --- |
| 형식 | 열린 말 | 닫힌 7점 평정 |
| 낱말의 주인 | 참여자 | 연구자(보기 여섯 개) |
| 묻는 것 | 그 자리가 어떤 자리였나(자리의 성격, 결과) | 자리를 정할 때 무엇이 얼마나 작용했나(결정 요인) |
| 누가 답하나 | 두 집단 모두 | 직접 배치만 |
| 쓰임 | 범주를 찾습니다(질적 코딩) | 요인의 크기를 견줍니다, B1 코딩을 확인합니다 |
| 순서 | 먼저 | 맨 끝(보기 낱말이 B1의 말을 끌고 가지 않게) |

두 문항을 함께 읽는 법:

- B1에서 "편한 자리"라고 말하고 C에서 '손이 편함'이 높으면 둘이 서로 맞는 것입니다(과제 가공물). B1에서 말하지 않았는데 C에서 '바닥 표시'가 높으면 말로는 드러나지 않은 요인입니다.
- 둘이 어긋나면 어긋난 그대로 보고합니다.

## 5. 받아 적는 법

- 참여자가 한 말을 들리는 대로 적습니다. 맞춤법만 맞추고 낱말·어순·말투는 그대로 둡니다. "음", "그러니까" 같은 군말은 빼도 되지만, 빼기로 했으면 모든 참여자에게 똑같이 뺍니다.
- 실험자가 덧붙인 말("네", "천천히요")은 적지 않습니다. 정해진 문장 밖의 말을 했다면 그 사실을 따로 메모해 둡니다(기록 화면에는 칸이 없으니 실험 노트에).
- 참여자가 대답하지 않거나 "모르겠어요"라고만 하면, 앞의 경우는 [말하지 않음(건너뜀)], 뒤의 경우는 "모르겠어요"를 그대로 적습니다.
- 실명, 연락처, 다른 사람 이름처럼 사람을 알아볼 수 있는 말이 나오면 받아 적을 때 `[이름]`처럼 가립니다.
- 저장한 뒤에는 고칠 수 없습니다(화면이 덮어쓰지 않습니다). 저장 단추를 누르기 전에 한 번 읽어 봅니다.
- 녹음 여부는 정해지지 않았습니다(⚠ 아래 8절).

| A3 공간 구조(고리·경계) | 바닥 고리, 표시, 공간 끝 같은 구조를 말함 | "두 번째 고리 위였어요" |
| A4 마음속 그것 | 물체가 나타내는 마음속 그것(면담에서 떠올린 일) 자체를 말함 | "그 일이 거기 있는 느낌이었어요" |
| A5 과제·조작 편의 | 놓기 쉬움, 잘 보임, 손이 닿음 같은 과제 사정을 말함 | "잡기 쉬운 데였어요" |
| A6 모름 | 기준을 말하지 못함 | "그냥 거기였어요" |

**B. 관계 방향** — 참여자가 **분명히 말했을 때만** 붙입니다. 코더가 짐작해서 붙이지 않습니다.

| 코드 | 뜻 |
| --- | --- |
| B1 더 보려 함 | 더 잘 보거나 더 알고 싶어 한다고 말함 |
| B2 떼어 두려 함 | 떨어뜨려 두거나 덜 보고 싶다고 말함 |
| B3 곁에 둠 | 곁에 두고 싶다고 말함 |
| B4 중립 | 방향 없이 자리만 말함 |

**C. 시점** — PI4 값(그때 / 지금 / 둘 다 / 잘 모르겠어요)을 그대로 씁니다.

## 7. 분석

- **두 코더가 따로 코딩합니다.** 코더는 조건(place·view·point_select)과 놓은 거리를 모르는 채로 코딩합니다. 기록에서 조건 이름과 거리 숫자를 지운 응답 목록을 만들어 넘깁니다.
- **일치도를 보고합니다.** 코드마다 Cohen κ(또는 일치율)를 내고, 어긋난 것은 두 코더가 의논해 하나로 정합니다. 의논 전 값과 뒤 값을 함께 적습니다.
- **나란히 놓는 표.** 세션마다 놓은 거리(분석기 `final_distance_m`), 헤드셋 안 평정 "더 알고 싶다"·"주의를 거두고 싶다", 사전 측정 열(`pre_*`), A·B·C 코드를 한 줄에 놓습니다. 분석기는 `python -m ifs_chatbot.eval.placement --records <배치 기록> --out <폴더> --selection-dir chatbot/logs/selection`으로 사전 측정·사후 면담 열을 붙입니다. 자유 글은 표에 넣지 않고 글자 수(`pi_*_chars`)와 건너뜀(`pi_*_skipped`)만 들어갑니다. 코드는 코더 표에서 세션 ID로 붙입니다.
- **민감도 점검.** PI4가 "지금"인 응답(돌아보며 떠오른 것)을 뺀 표를 하나 더 만들어 결론이 달라지는지 봅니다.
- PI6 평정은 자유 응답 뒤에 받은 보조 자료입니다. 자유 응답 코딩과 따로 기술하고, 둘이 어긋나면 어긋난 그대로 적습니다.
- PI7은 평정 문항의 "그 느낌"을 무엇으로 읽었는지 보는 조작 점검이고, PI8은 연구 목적을 짐작했는지 보는 요구 특성 점검입니다. 둘 다 결과를 해석할 때 함께 적습니다.
- 통계는 기술과 효과크기까지만 합니다(예비 연구 규모). 놓은 거리를 심리적 거리의 측정이라고 부르지 않습니다(X48).

## 8. 사람이 정할 것 ⚠

- **녹음 여부.** 녹음하면 받아 적기를 나중에 확인할 수 있지만 동의서와 자료 보관 계획이 바뀝니다. 지금 화면은 받아 적은 글만 저장합니다.
- **문항 채택.** PI1–PI8과 PI6의 여섯 항목을 모두 쓸지, 조건별 PI2 두 문장을 이대로 둘지. 모두 이 연구의 초안이고 선행 척도가 아닙니다.
- **코딩 틀.** A·B·C 코드의 이름과 경계, 한 응답에 여러 코드를 허용할지.
