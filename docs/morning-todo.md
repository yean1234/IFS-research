### 구현하면서 새로 생긴 것
- [ ] **색상을 후보에서 뺐습니다(G17).** 색을 말하지 않았으면 모든 후보가 중립 회색이고, 색은 조절에서만 바뀝니다. 유도를 줄이려는 선택이고, 밝기는 후보로 벌립니다. 색 후보를 둘지 정해 주세요.
- [ ] **어두운 색에서 밝기 후보가 화면에서 구별되지 않습니다.** 거의 검은 색(l 0.06)에서 밝기 후보 넷이 거의 같아 보였습니다(합성 시나리오 S5). 규칙은 "같은 넷"을 피했지만 렌더에서는 같아 보입니다. 이런 조합을 후보·조절에서 끌지(`adjustItems.availability`), 밝기 값을 바꿀지 정해야 합니다.
- [ ] **mist 후보가 옅습니다.** D7 전 플레이어에서는 배경과 거의 구분되지 않았고(S1·S4), 다시 빌드한 플레이어에서는 덩어리 구름으로 보입니다. 다만 회색·기본 크기·기본 거리에서는 바닥보다 조금 어두운 뭉치 정도이고(`docs/validation/cloud/README.md`), 투명도 후보 0.4와 겹치면 더 옅어집니다.
- [ ] **사전 측정 지시문이 고르고 고친 형상과 맞지 않을 수 있습니다.** "조금 전 본 물체는 그것을 말씀하신 대로 나타낸 것입니다"는 후보를 고르고 고친 형상, [맞는 것이 없다]를 고른 경우에 맞지 않습니다(draft 문구).
- [ ] **거리 하한 때문에 말한 30 cm가 약 57 cm로 그려집니다.** 매퍼 v2의 거리 하한 0.1(dev D20 '얼굴 앞 30센티쯤'). 원래 값은 `_measurements`에 남습니다. 하한을 둘지, 값을 바꿀지 정해 주세요. RQ V4 배치 러너는 시작 자리를 spec이 아니라 실험 설정으로 쓰므로 이 값이 헤드셋 안 거리를 정하지는 않습니다. spec의 거리를 그대로 쓰는 경로(예시 씬, 소유감 러너)에는 영향이 있습니다.
- [ ] **소유감 러너의 lowVisibility 계산값이 실제 화면보다 낮게 잡힙니다.** D7 뒤 mist는 덩어리 속 알파가 opacity 가까이 차지만, C# 유효 불투명도는 여전히 opacity × 0.5입니다. 그래서 lowVisibility 경고가 보수적으로 나오고, 합성 ΔE00 기록과 형태 변형 mist → blob의 불투명도 변화 기록이 실제보다 큽니다. 맞추려면 숫자와 소유감 러너 테스트를 함께 고쳐야 합니다(⚠ 메인 판정 필요).
- [ ] **구름 안에 카메라가 들어가면 시야가 가려집니다.** D7 뒤 덩어리 속은 opacity만큼 앞을 가립니다. 직접 배치에서 구름을 자기 쪽으로 끌어오면(잡기 최소 거리 0.3 m) 시야가 막힐 수 있습니다. 헤드셋에서 확인하고 대책(최소 거리, 가까울 때 옅게)을 정해 주세요.
- [ ] **환경 바닥 밝기 조정 제안(시험하지 않음).** 형상 뒤 배경이 대개 바닥이라 중간 회색 안개의 대비가 작습니다. 바닥 알베도 0.46 → 0.38 같은 조정을 제안했지만, 모든 형상의 화면과 후보1 러너의 색 측정에 영향이 있어 바꾸지 않았습니다.
- [ ] **에셋 계획 승인(결정 11개).** `docs/asset-plan.md` 6절. 승인 전에는 D6(기본 형상 경로)을 시작하지 않습니다.
- [ ] **WebGL 모듈 설치.** Unity Hub ▸ Installs ▸ 6000.0.85f2 ▸ ⚙ ▸ Add modules ▸ **Web Build Support** ▸ Install, UAC 창에서 "예". 자동 실행에서는 UAC를 누를 사람이 없어 두 번 실패했습니다. 설치 뒤 `docs/validation/webgl/README.md` 8절로 다시 판정합니다.
- [ ] **기본 매퍼를 v2로 바꿀지.** 지금 v2는 새 흐름 설정(`chatbot/config/v4.toml`)에서만 쓰고, 기본 설정은 v1입니다(G24). 바꾸면 영향받는 곳은 `docs/validation/mapper-v2/README.md` 6절.
- [ ] **held-out 재평가에 새 문장이 필요합니다.** v2는 dev와 목업만 보고 고쳤고 held-out은 열지 않았습니다. v2를 주 매핑으로 보고하려면 규칙을 보지 않은 사람이 새 평가 문장을 써야 합니다(X13).
- [ ] **모형이 없는 모양어도 형태 후보를 막습니다.** 후보 생성기는 모양어(`_unmapped` category shape)가 있으면 형태를 말한 것으로 봅니다. '실'처럼 모형이 없는 모양어도 같아서, 공으로 그려지는데 형태 후보도 나오지 않습니다(`docs/shape-mapping.md` 새 절). 모형이 있는 모양어에만 이 규칙을 걸지 정해 주세요.
- [ ] **말한 움직임이 조절 값 목록에 없을 수 있습니다.** 조절의 움직임 값은 여섯 가지(still·floating·swaying·trembling·pounding·sinking)입니다. '흩어져'(scattering)처럼 말한 값이 목록 밖이면, 조절에서 움직임을 한 번 바꾼 뒤 말한 값으로 되돌릴 수 없는지 확인이 필요합니다(화면에서 확인하지 않음).
- [ ] **헤드셋 러너의 사전 문항과 데스크톱 사전 측정이 겹칠 수 있습니다.** 사전 측정을 데스크톱으로 옮겼으므로(G11), 러너의 헤드셋 안 사전 문항(기존 "내 것 같다" `own` 등)을 `disabledItems`로 끌지 정해 주세요.
