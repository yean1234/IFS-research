# 아침에 할 일 (사람이 해야 하거나, 되돌리기 어려워 남겨 둔 것)

야간 작업 중 실행하지 못했거나 사람이 결정해야 하는 것을 모았습니다. 확인한 항목은 체크하거나 지우면 됩니다.

## 프로토타입 구현 — 사람이 정할 것 (2026-11-23, 브랜치 `claude/prototype-v4-build`)

지시문 `docs/prompts/prototype-v4-build.md` 6절은 아래 앞의 일곱 가지를 정하지 말고 임시값으로 진행하라고 했습니다. 그 뒤 항목은 구현하면서 새로 생긴 것입니다. 진행 상황은 `docs/HANDOFF.md` 맨 위 절, 결정은 `docs/decisions.md` G7–G28에 있습니다.

### 지시문 6절의 일곱 가지 (임시값으로 진행 중)
- [ ] **후보 개수.** 임시값 4. 구현에서는 4가 상한이 됐습니다(G19). 빈 자리가 둘 이상이면 2×2로 4개, 빈 차원이 하나뿐이면 그 차원의 값 수(질감은 3개), 빈 자리가 없으면 1개입니다. G34(2026-11-23) 뒤로는 서로 구별되지 않는 후보를 빼므로 2–3개가 될 수 있고, 하나만 남으면 선택 단계를 건너뜁니다.
- [ ] **대표성 문항의 하한 기준.** 임시값: 정하지 않고 값만 기록. 기준값은 자료를 보기 전에 정해야 합니다(G2·G13).
- [ ] **사람 형상을 목록에 넣을지.** 임시값: 첫 묶음에 넣지 않음(에셋 계획 6절 결정 4).
- [ ] **구별감 척도**(SCFQ 번안 / K-TMS / 1문항). 임시값: V4 제안서 추천(SCFQ 번안, 안 되면 K-TMS). 지금 데스크톱 사전 측정 화면에는 `docs/rq-v4-questionnaire-draft.md`의 주 척도안 A 7문항(초안)이 들어가 있습니다.
- [ ] **통제 조건의 종류.** 임시값: 정지 관찰(러너 기본 `static`). 네 방식 모두 설정값으로 있습니다.
- [ ] **내부 시행 통과 기준.** 임시값: 정하지 않음. 점검표는 `docs/internal-trial-guide.md` 5절.
- [ ] **형상을 소개하는 안내 문구.** 초안 "당신이 말한 것을 바탕으로 만든, 그것을 대신하는 형상입니다"(`status: draft`).

### G44 화면 개선 — 사람이 정할 것 (2026-11-23)
상세 `docs/validation/ui/README.md`, 정한 세부 `docs/decisions.md` 「G44 구현 세부」.

- [ ] **형태 견본 그림 아홉 장이 처음부터 보이는 것.** 전에는 눌러 봐야 보였고 누른 것은 모두 기록됐습니다. 견본은 기록하지 않습니다(같은 상태면 같은 그림이라 다시 만들 수 있음). 시스템이 그림으로 내미는 선택지가 늘어난 셈이라(챗봇 설계 7.5·7.9) 받아들일지.
- [ ] **기본 보기를 연구자 보기로 둔 것.** 내부 시행 안내에 맞췄습니다. 참여자가 따로 화면을 보는 시행이 생기면 참여자 보기(`?view=participant`)를 기본으로 바꿀지.
- [ ] **Unity 참여자 판에 입력 방법 안내가 없습니다.** 넣으려면 참여자용 새 문구(IRB 대상)가 필요해 만들지 않았습니다.
- [ ] **Unity에서 Esc가 확인 없이 바로 중단합니다.** 화면 단추는 확인을 거치게 했지만 Esc는 러너 입력 판정이라 그대로입니다. 막을지.
- [ ] **Unity 판이 흰색(#FFFFFF)으로 그려집니다**(재질 #E6E6E8 + 방출). 헤드셋에서 눈부시면 방출을 낮출지(`docs/headset-checklist.md` 3.10). 긴 지시문 판을 내려 마지막 줄이 약 0.1 m 높이까지 내려간 것도 헤드셋에서 볼 것.
- [ ] **소유감 러너의 `ParticipantTextDisplay`에도 같은 선형 색 버그가 있을 가능성.** 이번 범위 밖이라 고치지 않았습니다.
- [ ] **헤드셋·창 있는 브라우저·실제 화면 낭독기·어두운 테마에서 한 번 보기.** 이번에는 헤드리스 Chrome과 에디터 캡처만 봤습니다.

### D6 기본 형상 — 사람이 정할 것 (2026-11-23)
- [ ] **맨 낱말 '불'과 '눈물'을 기본 형상으로 보낼지.** 지금은 넣지 않았습니다('불이 난 것처럼 화끈거려요', '눈물이 나요'처럼 몸 반응·관용 표현과 같은 꼴이라 주어 규칙으로 가를 수 없음). 넣으면 '불' → flame, '눈물' → drop. 내부 시행에서 이 낱말이 형상으로 나오는지 보고 정해 주세요(`shared/lexicon/base_shapes.v1.json` notIncluded).
- [ ] **회색 불꽃이 불꽃으로 읽히지 않습니다.** 색을 말하면(빨강·파랑) 촛불 불꽃으로 읽히지만, 말하지 않은 중립 회색은 비틀린 물방울처럼도 보입니다(에셋 계획 결정 6의 대가). 지금처럼 둘지, 윤곽을 더 바꿀지(갈래를 더 깊게 등).
