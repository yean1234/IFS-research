## 0. 요약

면담 단계마다 참여자가 쓴 말만으로 장면 속성 스냅샷을 만들고, 첫 스냅샷과 확정 시점 상태를 비교합니다. 둘 다 말한 속성만 비교합니다. 그래서 덧붙임과 생략은 표류가 아닙니다. 형상 명사(정체)가 바뀌면 바로 표류입니다. 그 밖에는 속성 묶음의 모순 비율 `DI`가 0.2 이상이면 표류입니다. 판정에 LLM과 임베딩을 쓰지 않습니다. 같은 턴 텍스트는 언제나 같은 판정을 냅니다.

정답 라벨 18개에서 정확도 1.000(혼동행렬 TP 9 · FP 0 · TN 9 · FN 0), 덧붙임만 있는 사례 오탐 0, 두 번 실행한 출력은 바이트 동일했습니다. **이 결과는 잠정 통과입니다.** 이 라벨 집합은 임계값을 거의 구속하지 못합니다(8.3절). 설계자는 라벨 파일을 읽은 뒤 규칙을 썼고, 정확도는 라벨 사례에 나온 사전 낱말에 일부 기댑니다(8.4절: 날개·보풀·돌멩이·뭉치를 빼면 낮아짐). 새 독립 라벨로 다시 재야 합니다.

## 1. 정의

| 기호 | 정의 |
| --- | --- |
| 턴 스냅샷 `T_t` | 참여자 턴 `t` 하나의 텍스트만으로 만든 속성 값(SceneSpec 슬롯)과 형상 명사 |
| 단계 스냅샷 `S_k` | 단계 `k`(Find, Focus, Flesh out, 확인 질문)의 턴 스냅샷을 시간 순으로 합친 것. 슬롯마다 **나중 턴의 값이 앞 턴을 덮습니다** |
| 첫 단계 | 값이나 형상 명사가 하나라도 있는 가장 이른 단계 |
| 첫 스냅샷 `S_first` | 첫 단계의 턴들에서 슬롯마다 참여자가 **처음 말한 값**. 형상 명사도 처음 이름 붙인 턴의 것(이름 자리가 없으면 처음 주어 자리 턴). 값마다 그 값을 말한 턴을 기록합니다 |
| 확정 시점 상태 `S_final` | 첫 단계보다 뒤 단계의 모든 턴을 `S_k`와 같은 방식으로 합친 것. 슬롯마다 참여자가 **마지막으로 말한 값** |
| 1차 쌍 | `(S_first, S_final)`. 세션 판정은 이 쌍으로 정합니다 |
| 보조 쌍 | 인접 단계 쌍 `(S_k, S_k+1)`. 최댓값 `maxAdjacentDI`를 함께 기록합니다(판정에는 안 씀) |
| 비교 가능 묶음 `C` | 두 스냅샷에 모두 값이 있는 슬롯을 하나 이상 가진 속성 묶음(2.4절) |
| 모순 | 묶음 안의 슬롯 하나라도 3절 규칙으로 모순이면 그 묶음은 모순 |
| 덧붙임 · 생략 | 한쪽만 값이 있음. 비교하지 않습니다. **표류가 아닙니다** |

```
DI = Σ_{g∈C} w_g · [g 모순] / Σ_{g∈C} w_g          (C가 비면 DI = null)
판정 = drift      if 정체 모순 or DI ≥ θ
     = undecidable if C가 비고 형상 명사도 비교 못 함
     = no_drift   otherwise
```

`undecidable`은 모순 근거가 없다는 뜻이라 정확도 계산에서는 no_drift로 셉니다. 분석에서는 따로 셉니다(research-design 4.5).

`S_final`을 확정 텍스트 전체로 만들지 않는 이유는 4.5절과 같습니다. 매핑 규칙은 같은 층에서 먼저 말한 값을 고르고 나중 값을 `_alternatives(later_mention)`로 보냅니다. 전체 텍스트로 만들면 바뀐 값이 나타나지 않습니다. 그래서 "마지막으로 말한 값"을 턴 단위로 모읍니다. 첫 단계의 턴은 `S_final`에 넣지 않습니다. 넣으면 다시 말하지 않은 값이 자기 자신과 비교되어 분모만 키웁니다.

`S_first`를 "첫 단계를 합친 값(나중 턴이 덮음)"이 아니라 "처음 말한 값"으로 둔 이유(검토 T2-F01): 정적 조건의 Find는 opening과 location 두 턴입니다. 합치면 opening의 '파란 공'이 location의 '빨간 공'에 덮여, Find 안에서 바뀐 심상이 첫 심상이 되어 버립니다. 라벨 규칙도 "처음 떠올린 심상"과 비교합니다. 첫 단계 안에서만 바뀌고 뒤 단계에서 다시 말하지 않은 값은 여전히 비교되지 않습니다(9절 한계).

## 2. 스냅샷 만드는 법

### 2.1 슬롯 값

- 턴 텍스트 하나를 개선 매핑 v1(`scene_builder_v1.SceneSpecBuilderV1.build`)에 넣습니다. v1이 없거나 예외를 내면 그 턴만 v0(`scene_builder.py`)로 만들고 `builder: "v0"`, `builderError`를 남깁니다.
- 퍼지 일치(자모 편집거리) 후보는 비교에 쓰지 않고 `unconfirmed`에 남깁니다. 매핑 스스로 "확인 필요"라고 표시한 값은 참여자가 말한 값으로 확정되지 않았기 때문입니다(원칙 2). 매핑 v1.1부터 퍼지 후보는 슬롯 값이 아니라 `_alternatives`(reason `needs_confirmation`)에만 있으므로 거기서 읽습니다. 근거가 모두 `needsConfirmation`인 슬롯 값도 같은 방식으로 뺍니다(v1.0 출력 호환). 실제 예: '가끔' → 가슴(chest), '물웅덩이' → 엉덩이(lower_back).
- `layout.size`는 값의 출처 척도를 함께 남깁니다(`scale`): 매핑 규칙이 `logScale(…)`이면 `word`(크기 낱말), `…m`(측정·비교 m)이면 `measure`. 3절 크기 출처 규칙에 씁니다.
- 수치는 소수 셋째 자리로 반올림해 기록합니다.

### 2.2 형상 명사(정체)

`form.type`은 네 값(blob·mist·shell·fragments)뿐이라 '덩어리 → 새', '공 → 막대'를 구별하지 못합니다. 그래서 참여자가 그것을 부른 명사를 따로 뽑습니다. Kiwi 형태소와 사전 표만 씁니다.

| 단계 | 규칙 |
| --- | --- |
| 빼는 문장 | 회상 문장: `-던`(ETM) 또는 '장면'이 있는 문장. 떠올린 상황이지 형상이 아닙니다 |
| 빼는 절 | '처음·원래·아까·예전'이 있는 절(예전 값) |
| 명사 묶음 | 이어진 일반·고유명사(합성어). 색 이름·차원어·신체어 등은 떼어 내고, **오른쪽 머리**를 정체로 봅니다('털실 뭉치' → 뭉치). 'X 모양으로'의 '모양'은 건너뜁니다 |
| 덩이 머리 | 머리가 덩어리·뭉치·조각·방울·송이 같은 **덩이 명사**(`MASS_HEADS`)이면 앞 명사를 재료(`massOf`)로 함께 남깁니다('털실 뭉치' → 털실의 뭉치). 한 낱말('솜뭉치'·'돌덩어리')은 두 음절 이상 덩이 명사로 끝날 때만 떼어 봅니다 |
| 이름 자리 | (a) 'X 같은 게'·'X 같은 거요'처럼 'X 같은' 뒤 첫 명사가 의존명사(것·거)나 일반어(느낌·하나 …)일 때 (b) 'X예요·X이요' (c) 'X로 바뀌었어요·X가 됐어요' (d) 문장 끝 'X.' |
| 주어 자리 | 'X가·X는·X도' |
| 빼는 자리 | 부정('X가 아니라', 'X 말고'), 성질 비유('X처럼'), **직유 수식**('X 같은' 뒤 첫 명사가 내용 명사: '구름 같은 덩어리'의 구름. 정체는 뒤의 덩어리), **재질**('X로 돼 있어요'처럼 'X로 + 되- + -어 있-', 'X로 된', 'X로 만들어졌어요·이루어졌어요'), 크기 비교('X만 해요', 'X 정도'), 장소('X에'), 목적어('X를'). 'X로 됐어요·X로 바뀌었어요'(뒤에 '있-'이 없음)는 그대로 변화 자리입니다 |
| 빼는 말 | 신체 부위어(1층 사전 v0·v1), 관계어·부분어·배경어·차원 주제어(`scene_params.v1.json`), 부분 명사(날개·부리·보풀·가장자리 …), 차원·단위어(색·모양·크기·지름 …), 때(지금·처음 …), 일반어(것·곳·쪽 …), 색 이름(하늘색·잿빛·연노랑 …) |
| 성질 명사 | 빛·소리·냄새·기운 등은 이름 자리에서만 정체입니다. '빛이 깜빡여요'의 빛은 그것이 내는 성질일 수 있기 때문입니다 |

단계 정체(`S_k`·`S_final`)는 **이름 자리 명사가 있는 마지막 턴**의 명사입니다. 그런 턴이 없을 때만 주어 자리 명사가 있는 마지막 턴을 씁니다. `S_first`의 정체는 같은 우선순위로 **처음** 턴의 것입니다. Flesh out 답에는 '가장자리가 흐려요', '물결이 퍼져요'처럼 부분이 주어인 문장이 많습니다. 이런 주어가 이미 이름 붙인 정체를 덮지 않게 하려는 것입니다.

확인 질문 루프(`clarify`)의 답에서는 형상 명사를 뽑지 않습니다(`identityDropped`에 `clarify_answer`로 남김, 슬롯 값은 씀). 그 답은 시스템이 고른 낱말 X에 대한 "그 X는 어떤 X인가요?"의 답이라, '젤리 같은 거요'의 젤리는 심상 전체가 아니라 X를 설명한 말일 수 있기 때문입니다(검토 T2-F06).

같은 정체 판정:

| 규칙 | 예 |
| --- | --- |
| 동의어·지소어 묶음의 대표어가 같음 | 돌멩이 = 돌, 뭉치 = 덩어리, 원판 = 원반, 막대기 = 막대 |
| 한쪽이 다른 쪽의 오른쪽 머리(합성어). **짧은 쪽이 두 음절 이상일 때만** | 물방울 ⊃ 방울, 공기방울 ⊃ 방울. 한 음절 겹침은 같은 정체가 아님: 불꽃 ⊅ 꽃, 참새 ⊅ 새(9절 한계) |
| 덩이 머리: 둘 다 'X 덩이'면 재료 X가 같아야 함, 한쪽만이면 다른 쪽이 재료나 머리와 같으면 됨 | 솜 = 솜뭉치, 덩어리 = 돌덩어리, 털실 뭉치 = 털실 덩어리, 구름 덩어리 ≠ 돌 덩어리 |
| 두 집합에 같은 정체가 하나라도 있음 | {새, 부리} 와 {새} |

형태소 분석이 합성어를 나눈 경우(농구 + 공)는 머리 명사가 이미 '공'이라 오른쪽 머리 규칙을 쓰지 않습니다.

두 스냅샷 모두 형상 명사가 있을 때만 비교합니다. 겹치는 정체가 없으면 **정체 모순**이고, DI와 상관없이 drift입니다. 형상 명사를 비교할 수 있으면 정체 묶음의 판정은 `form.type`보다 형상 명사를 따릅니다(같은 '돌'도 v1은 '돌멩이'만 blob으로 읽습니다).

### 2.3 단계와 턴

- 단계는 세션 로그 턴의 `stage`(find·focus·flesh_out)를 그대로 씁니다. 정적 조건이면 opening·location = Find, focus_hold = Focus, fleshout_open·프로브 = Flesh out입니다.
- 확인 질문 루프의 답 중 확정 텍스트에 덧붙은 것은 `clarify` 단계로 넣습니다(슬롯 값만 쓰고 형상 명사는 쓰지 않음, 2.2절).
- 넘어가기·'없어요'류(`noMore`)와 버튼(`control:*`)은 넣지 않습니다. 확정 텍스트에 들어가지 않는 답이기 때문입니다.
- 확정 단계에서 참여자가 텍스트를 고쳤으면 `confirmationEdited: true`를 기록하고 연구자 요약(`summary.confirmationEdited`)에도 보입니다. 판정은 턴으로만 합니다(9절 한계).
- 한 턴에 서로 같은 정체가 아닌 형상 명사가 둘 이상 있으면 `multipleObjects.flag = true`와 그 턴·명사를 남기고 요약(`summary.multipleObjects`)에도 보입니다. 판정은 바꾸지 않습니다. 슬롯 값이 대상에 묶이지 않아 서로 다른 대상의 값이 비교됐을 수 있다는 표시입니다(검토 T2-F05, 9절 한계).

### 2.4 속성 묶음과 가중치

| 묶음 | 슬롯 | 가중 `w_g` | 근거 |
| --- | --- | --- | --- |
| 정체 identity | 형상 명사, `form.type` | 1 | 라벨 규칙의 핵심 속성(형상 정체) |
| 색 color | `material.color`·`brightness`·`saturation` | 1 | 핵심 속성(색) |
| 크기 size | `layout.size` | 1 | 핵심 속성(크기) |
| 위치 position | `body.part`·`body.layer`·`layout.verticalOffset`·`layout.distance` | 1 | 핵심 속성(위치) |
| 자세 shape | `form.posture` | 0.5 | 같은 것의 자세는 바뀔 수 있음 |
| 표면 surface | `material.roughness`·`opacity`·`erosion` | 0.5 | 같은 것을 더 자세히 볼 때 자주 다듬어짐 |
| 움직임 motion | `motion.type`(Unity 9묶음 기준)·`motion.speed` | **0** | 움직임은 그것의 상태이지 정체가 아님. 모순은 기록만 |

슬롯이 아니라 묶음으로 세는 이유: 위치 하나가 바뀌면 부위·층·높이·거리 슬롯이 한꺼번에 바뀝니다. 슬롯 단위로 세면 한 번의 변화가 여러 번 세어지고, DI가 매핑이 채운 슬롯 수에 따라 달라집니다. 핵심 묶음 넷과 보조 묶음 둘은 독립 라벨 작성자의 라벨 규칙("형상 정체, 색, 크기, 위치 중 하나가 뚜렷이 다른 값이 되었거나, 여러 속성이 조금씩 바뀌어 …")을 그대로 따른 것입니다. 이 규칙은 표류라는 개념의 정의로 썼고, 사례별 라벨에 맞춘 것이 아닙니다.

## 3. 슬롯 비교 규칙과 임계값

| 슬롯 | 모순 조건 | 수치 | 근거 |
| --- | --- | --- | --- |
| 0–1 수치(크기·밝기·채도·거칠기·투명도·침식·거리·높이·속도) | `|Δ| > τ_hard` 또는 (중립점 0.5의 서로 반대쪽 그리고 `|Δ| > τ_soft`) | `τ_soft = 0.25`, `τ_hard = 0.5` | 아래 3.1 |
| `layout.size` 크기 출처가 다름 | 크기 출처(크기 낱말 `word` ↔ 측정·비교 `measure`)가 서로 다르면 중립점 규칙을 쓰지 않고 τ_hard만 봅니다 | | 두 척도는 중립점의 뜻이 달라 '큰'(0.621) ↔ '주먹만'(0.333)이 중립점을 넘는 것은 모순이 아님(3.1, 검토 T2-F04) |

### 3.1 수치 슬롯

v1 크기 척도(로그 척도, 0.5 = ×1)에서 말로 한 크기는 `작은 0.316 · 조그만 0.25 · 아주 작은 0.224 · 큰 0.621 · 커다란 0.646 · 아주 큰 0.681`입니다. 반대 극 사이 간격(작은 ↔ 큰)은 0.31, 같은 극 안의 정도 차이는 0.1 이하입니다. 그래서 중립점을 넘는 차이가 `τ_soft = 0.25`를 넘으면 모순입니다.

측정·비교로 정한 크기는 말로 한 크기와 기준이 다릅니다(엄지손톱만 0.0, 탁구공 0.113, 주먹 0.333, 손바닥 0.475, 농구공 0.544). 크기 낱말 척도의 0.5는 "보통"이고, 측정 척도의 0.5는 20 cm입니다. '작은'(0.316) 뒤에 '엄지손톱만 해요'(0.0)라고 해도, '큰'(0.621) 뒤에 '주먹만 해요'(0.333)라고 해도 같은 것을 다듬은 것일 수 있습니다. 그래서 크기 출처가 서로 다르면 쪽과 상관없이 `τ_hard = 0.5`(측정 척도로 약 ×8, 크기 낱말 척도로 ×4)를 넘을 때만 모순으로 봅니다. 크기 출처 규칙의 대가: '작은'(0.316) → '수박만'(0.597)처럼 사람이 바뀌었다고 볼 만한 차이도 0.281이라 모순이 아닙니다(9.3절 S14).

밝기도 같은 꼴입니다(어두운 0.15 · 희미한 0.25 · 은은한 0.5 · 밝은 0.8 · 눈부신 1.0). '조금 밝은'(0.68) ↔ '은은하게 밝은'(0.5)은 같은 쪽 0.18 차이라 모순이 아닙니다.

### 3.2 색

v1 색 이름의 색상각은 빨강 0° · 주황 28° · 노랑 52° · 연두 90° · 초록 120° · 청록 175° · 하늘 200° · 파랑 215° · 남색 230° · 보라 275° · 분홍 340°입니다. 이웃한 이름 사이는 25–45°입니다. `τ_hue = 60°`면 이웃 이름으로 바꿔 말한 것(연노랑 → 주황빛 24°, 하늘색 → 남색 30°)은 다듬기이고, 이름 둘 이상 떨어진 것(파랑 → 빨강 145°, 노랑 → 보라 137°)은 모순입니다.

v1의 '연한/짙은' 수식은 l을 약 ±0.2 옮깁니다(연한 파랑 0.70, 짙은 파랑 0.30). 같은 색 이름의 연한형과 짙은형 차이(0.4)는 다듬기로 보고, 그보다 큰 차이(연한 하늘색 0.85 ↔ 거의 검은 남색 0.15)만 모순으로 봅니다. 그래서 `τ_l = 0.45`입니다.

### 3.3 θ

`θ = 0.2 = 1 / 5`. 5는 비교 가능 가중의 최댓값(핵심 묶음 4 × 1 + 보조 묶음 2 × 0.5)입니다. 핵심 묶음 하나가 뚜렷이 모순이면, 나머지 묶음이 모두 같아도 drift가 됩니다(라벨 규칙의 "하나가 뚜렷이 다른 값"). 보조 묶음 하나(0.5)만 모순이면 비교 가능 가중이 2.5 이하일 때만 drift입니다. 보조 묶음 둘이 모순이면 언제나 drift입니다.

## 4. acknowledged

첫 단계 밖의 턴에서 정규식 `바뀌었|바뀌어|바뀐|달라졌|달라져|달라진|이제는|이젠|다시\s*보니`이 나오면 `acknowledged.flag = true`와 표지(턴 번호·단계·일치 문자열)를 남깁니다. 판정은 바꾸지 않습니다. '지금은'은 넣지 않았습니다. 같은 것의 지금 상태를 말할 때도 쓰기 때문입니다.

'바뀌-·달라지-' 표지는 **같은 절**(Kiwi 절 경계: 연결 어미 '-고·-는데·-지만' 등, 쉼표, 문장 끝)에서 뒤에 부정(없다·않다·안·못·아니다)이 오면 표지로 세지 않고 `acknowledged.negatedMarkers`에 따로 남깁니다('바뀐 건 없어요', '달라진 게 없어요', 검토 T2-F10). 부정이 다음 절에 있으면('바뀌었는데 지금은 안 움직여요') 표지로 셉니다. '이제는·이젠·다시 보니'에는 이 확인을 하지 않습니다('이제는 안 움직여요'의 부정은 바뀌었다는 말을 뒤집지 않음).

## 5. 회상 확인과 자기보고 (고정 문구, LLM 없음)

두 문구 모두 `elicitation_protocol.v1.1.json`에 `status: "draft"`로 있습니다. IRB 제출 전 연구팀 검토가 필요합니다(원칙 7). v1.0.0 파일은 그대로 두었습니다. v1.1.0은 v1.0.0의 단계 순서·문구·질문 틀을 바꾸지 않고 두 문구와 `driftChecks` 절만 더했습니다(테스트가 확인).

| 문구 id | 문구 | 답 | 시점 | 설정 |
| --- | --- | --- | --- | --- |
| `recall_check` | `'{X}' — 지금 떠오르는 것도 그 '{X}'인가요?` | [네, 같아요] [조금 달라졌어요] [많이 달라졌어요] [넘어가기] | Flesh out 프로브 뒤, 확정 요약 전 | `[drift] recall_check` (기본 false) |
| `self_report_drift` | `지금 확정한 것은 이 면담을 시작할 때 처음 적어 주신 그것과 같은 것인가요? 가장 가까운 숫자를 골라 주세요.` | 1(전혀 다른 것) … 7(같은 것), [넘어가기] | [이대로 맞아요] 뒤 장면 파일을 만든 직후, 끝맺음 문구 전 | `[drift] self_report` (기본 false) |

- `{X}`는 첫 단계에서 참여자가 **그것에 이름을 붙인 자리**('X 같은 게'·'X예요', `RECALL_POSITIONS`)에 쓴 형상 명사 원문 중 가장 먼저 말한 것입니다(3어절 이하). 주어 자리('X가 있어요'), 직유 수식('구름 같은 덩어리'의 구름), 재질('유리로 돼 있어요'의 유리)은 쓰지 않습니다. 참여자가 그것을 '구름'·'유리'라고 부르지 않았는데 "그 '구름'인가요?"라고 물으면 참여자가 쓰지 않은 이름을 주게 되기 때문입니다(원칙 3, 검토 T2-F08). 그런 이름이 없으면 묻지 않습니다(`recallCheck.asked = false`와 이유). X에 위기 키워드나 깊이 표지가 있으면 묻지 않습니다. 이 문구는 질문 틀 6개 밖의 고정 문구라 검증기 V1–V9를 거치지 않습니다(`docs/chatbot-design.md` 5-2).
- 두 문구 모두 현재 시제이고 왜·과거 경험·기억을 묻지 않습니다(원칙 3). '처음 적어 주신'과 '그 X'는 **이 면담 안에서 참여자가 적은 심상**을 가리킵니다. 자전적 기억이나 과거 사건을 묻는 질문이 아닙니다. 값·예시·선택지로 심상 내용을 제안하지 않습니다(선택지는 같음/다름 정도뿐).
- 답은 버튼으로만 받습니다. 확정 텍스트와 장면에 들어가지 않습니다.
- 기본값을 끈 이유: 회상 확인은 확정 전에 참여자가 첫 심상을 다시 보게 합니다. 그러면 확정 텍스트가 바뀔 수 있고, 조건 간 비교를 교란합니다(research-design 3.2의 확인 질문 루프와 같은 논리). 자기보고는 확정 뒤라 매핑 비교를 건드리지 않지만, 문구가 draft라 IRB 검토 전에는 끕니다.
- 켜려면 `interview.protocol = "elicitation_protocol.v1.1.json"`도 함께 바꿔야 합니다. 문구가 없는 프로토콜에서 켜면 런타임 경고를 남기고 끕니다.
- 자기보고 이분 기준: `value ≤ 3` → `selfReportDrift = true`(research-design 4.5, 사전 등록 항목). 기준값은 `PARAMS.selfReportDriftMax`.

## 7. 실행

```powershell
cd chatbot
.venv\Scripts\python.exe -m pytest -q -m "not live" tests\test_drift.py tests\test_drift_review.py -s
```

`--cases`는 `eval/corpus_run.py`의 `make_runtime`·`drive_item`으로 실제 컨트롤러 정적 조건을 재생합니다(안전 검사, 이미 나온 차원의 프로브 건너뛰기, 확정까지 모두 실제 코드). 판정은 세션 로그 `drift.assessment`에서 읽습니다. 라벨이 없는 코퍼스도 돌릴 수 있습니다(판정 분포만 보고).

no_drift가 모두 DI 0이고 drift의 최소 DI가 0.333이라, 여유는 θ 쪽으로 0.13입니다. 인접 단계 쌍만 보면 DR12·DR18은 DI 0입니다(바뀐 값이 Focus에 다시 나오지 않음). 1차 쌍을 (첫 스냅샷, 확정 시점 상태)로 둔 이유입니다.

`drift/1.1.0`(검토 T2 반영) 뒤에도 18개 항목의 판정·DI·모순 묶음·acknowledged는 1.0.0과 모두 같습니다(결과 JSON에서 판정 버전 문자열만 다름). 개선 매핑 v1.1(작업 3 수정)로 바뀐 뒤 1.0.0 판정기로 먼저 다시 잰 값도 같았습니다(sha256 `93687ebd…` 그대로).

**잠정 통과.** AC-2 기준 4–6은 수치로 충족합니다. 그러나 (1) 설계자가 라벨을 읽은 뒤 규칙을 썼고, (2) 수치가 거의 구속되지 않으며(8.3), (3) 정확도가 라벨 사례에 나온 사전 낱말에 일부 기댑니다(8.4). 새 독립 라벨로 다시 재기 전까지는 잠정 결과로 보고합니다.

### 8.2 라벨 없는 dev 코퍼스 30개 (참고)

`imagery_corpus/dev.json`은 한 심상을 단계마다 자세히 말하는 대사입니다(표류를 의도하지 않음). drift 판정 0/30, undecidable 21/30입니다(`drift/1.1.0`에서 다시 잼, 1.0.0과 같음). undecidable이 많은 것은 대부분 속성을 한 번씩만 말하기 때문입니다(덧붙임). 보류 코퍼스(held-out)는 열지 않았습니다.

### 8.3 임계값 민감도 (한 수치만 바꿔 다시 실행, 조정에 쓰지 않음)

`drift/1.1.0` 코드로 다시 쟀습니다(2026-11-16). 한 수치만 아래 격자로 바꾸고 나머지는 그대로 두었습니다. 격자: `τ_hue` 10°–180°(10° 간격), `τ_l` 0.05–0.95, `τ_soft` 0–0.6, `τ_hard` 0.1–1.0(모두 0.05 간격), `θ` 0.05·0.1·…·0.3·0.32·0.333·0.334·0.34·0.4·0.5·0.6. 범위의 끝은 이 격자 해상도까지만 맞습니다.

| --- | --- | --- |
| `τ_hue`(60°) | 10°–130° | 140°: 0.944(DR15 놓침), 150°–180°: 0.889(DR11·DR15 놓침) |

**사전 의존(검토 T2-F07, `drift/1.1.0`에서 다시 잼).** 라벨 사례에 나온 사전 낱말을 하나씩 빼고 18개를 다시 돌린 결과입니다.

### 9.1 자기보고와의 관계

규칙 판정은 **말로 나온 속성의 일관성**을 봅니다. 자기보고는 참여자가 느낀 **같음**을 봅니다. 둘은 다른 것을 잴 수 있습니다. 참여자는 색이 바뀌어도 "같은 것"이라고 할 수 있고, 말한 속성이 다 같아도 "다른 것"이라고 할 수 있습니다. 그래서 규칙 판정을 정답으로 두지 않고, 자기보고를 기준으로 규칙 판정이 얼마나 맞는지 봅니다(탐색, RQ4).

### 9.2 AUC 분석 계획 (탐색)

| 항목 | 내용 |
| --- | --- |
| 기준 | 자기보고 ≤ 3 = 표류(사전 등록), 넘어가기는 결측 |
| 예측값 | 1차 쌍 `DI`(연속). 정체 모순이면 1.0으로 둡니다(판정 규칙과 같은 방향) |
| 지표 | ROC AUC(95% 부트스트랩 CI, 참여자 단위 재표집), 이분 판정의 민감도·특이도, `DI`와 자기보고(1–7)의 Spearman 순위상관 |
| 따로 셈 | undecidable(`DI = null`) 비율, acknowledged와 자기보고의 일치, 회상 확인 답과 자기보고의 일치(회상 확인을 켠 세션만) |
| 주의 | 표류 사례가 적으면 AUC 구간이 넓습니다. 표류 기저율을 함께 보고합니다. 수치(τ·θ)는 이 분석 전에 고정하고, 바꾸면 버전을 올립니다 |

### 9.3 검토 T2 합성 대화 회귀와 알려진 한계

2단계 독립 검토자(T2)가 라벨 18개 밖에서 만든 합성 대화 41개를 `chatbot/tests/fixtures/drift/review_t2_regression.json`에 옮겨 두었습니다(S01–S22·T01–T14는 판정기에 바로, W1–W5는 정적 조건 컨트롤러 재생). `expected`는 검토자의 기대이고, 검토자가 '?'로 둔 3개(S08·S11·S13)는 기대가 없습니다. **규칙을 고친 뒤 이 대화로 확인했으므로 독립 평가가 아닙니다.** AC-2 집계(8.1)와 따로 셉니다(`tests/test_drift_review.py`).

| 집계 | 고치기 전(`drift/1.0.0`, 매핑 v1.1) | 고친 뒤(`drift/1.1.0`) |
| --- | --- | --- |
| 기대가 있는 38개 중 기대와 같음 | 20 | 33 |
