## 0. 요약

면담 단계마다 참여자가 쓴 말만으로 장면 속성 스냅샷을 만들고, 첫 스냅샷과 확정 시점 상태를 비교합니다. 둘 다 말한 속성만 비교합니다. 그래서 덧붙임과 생략은 표류가 아닙니다. 형상 명사(정체)가 바뀌면 바로 표류입니다. 그 밖에는 속성 묶음의 모순 비율 `DI`가 0.2 이상이면 표류입니다. 판정에 LLM과 임베딩을 쓰지 않습니다. 같은 턴 텍스트는 언제나 같은 판정을 냅니다.

정답 라벨 18개에서 정확도 1.000(혼동행렬 TP 9 · FP 0 · TN 9 · FN 0), 덧붙임만 있는 사례 오탐 0, 두 번 실행한 출력은 바이트 동일했습니다. 다만 이 라벨 집합은 임계값을 거의 구속하지 못합니다(8.3절). 설계자는 라벨 파일을 읽은 뒤 규칙을 썼습니다(8.4절). 새 독립 라벨로 다시 재야 합니다.

## 1. 정의

| 기호 | 정의 |
| --- | --- |
| 턴 스냅샷 `T_t` | 참여자 턴 `t` 하나의 텍스트만으로 만든 속성 값(SceneSpec 슬롯)과 형상 명사 |
| 단계 스냅샷 `S_k` | 단계 `k`(Find, Focus, Flesh out, 확인 질문)의 턴 스냅샷을 시간 순으로 합친 것. 슬롯마다 **나중 턴의 값이 앞 턴을 덮습니다** |
| 첫 스냅샷 `S_first` | 값이나 형상 명사가 하나라도 있는 가장 이른 단계의 `S_k` |
| 확정 시점 상태 `S_final` | `S_first`보다 뒤 단계의 모든 턴을 같은 방식으로 합친 것. 슬롯마다 참여자가 **마지막으로 말한 값** |
| 1차 쌍 | `(S_first, S_final)`. 세션 판정은 이 쌍으로 정합니다 |
| 보조 쌍 | 인접 단계 쌍 `(S_k, S_k+1)`. 최댓값 `maxAdjacentDI`를 함께 기록합니다(판정에는 안 씀) |
| 비교 가능 묶음 `C` | 두 스냅샷에 모두 값이 있는 슬롯을 하나 이상 가진 속성 묶음(2.4절) |
| 모순 | 묶음 안의 슬롯 하나라도 3절 규칙으로 모순이면 그 묶음은 모순 |
| 덧붙임 · 생략 | 한쪽만 값이 있음. 비교하지 않습니다. **표류가 아닙니다** |

```
DI = Σ_{g∈C} w_g · [g 모순] / Σ_{g∈C} w_g          (C가 비면 DI = null)
판정 = drift      if 정체 모순 or DI ≥ θ
     = undecidable if C가 비고 형상 명사도 비교 못 함
     = no_drift   otherwise
```

`undecidable`은 모순 근거가 없다는 뜻이라 정확도 계산에서는 no_drift로 셉니다. 분석에서는 따로 셉니다(research-design 4.5).

`S_final`을 확정 텍스트 전체로 만들지 않는 이유는 4.5절과 같습니다. 매핑 규칙은 같은 층에서 먼저 말한 값을 고르고 나중 값을 `_alternatives(later_mention)`로 보냅니다. 전체 텍스트로 만들면 바뀐 값이 나타나지 않습니다. 그래서 "마지막으로 말한 값"을 턴 단위로 모읍니다. `S_first` 단계의 턴은 `S_final`에 넣지 않습니다. 넣으면 다시 말하지 않은 값이 자기 자신과 비교되어 분모만 키웁니다.

## 2. 스냅샷 만드는 법

### 2.1 슬롯 값

- 턴 텍스트 하나를 개선 매핑 v1(`scene_builder_v1.SceneSpecBuilderV1.build`)에 넣습니다. v1이 없거나 예외를 내면 그 턴만 v0(`scene_builder.py`)로 만들고 `builder: "v0"`, `builderError`를 남깁니다.
- 값의 근거가 모두 `needsConfirmation`(자모 편집거리 퍼지 일치)이면 비교에 쓰지 않고 `unconfirmed`에 남깁니다. 매핑 스스로 "확인 필요"라고 표시한 값은 참여자가 말한 값으로 확정되지 않았기 때문입니다(원칙 2). 실제 예: '가끔' → 가슴(chest), '물웅덩이' → 엉덩이(lower_back).
- 수치는 소수 셋째 자리로 반올림해 기록합니다.

### 2.2 형상 명사(정체)

`form.type`은 네 값(blob·mist·shell·fragments)뿐이라 '덩어리 → 새', '공 → 막대'를 구별하지 못합니다. 그래서 참여자가 그것을 부른 명사를 따로 뽑습니다. Kiwi 형태소와 사전 표만 씁니다.

| 단계 | 규칙 |
| --- | --- |
| 빼는 문장 | 회상 문장: `-던`(ETM) 또는 '장면'이 있는 문장. 떠올린 상황이지 형상이 아닙니다 |
| 빼는 절 | '처음·원래·아까·예전'이 있는 절(예전 값) |
| 명사 묶음 | 이어진 일반·고유명사(합성어). 색 이름·차원어·신체어 등은 떼어 내고, **오른쪽 머리**를 정체로 봅니다('털실 뭉치' → 뭉치). 'X 모양으로'의 '모양'은 건너뜁니다 |
| 이름 자리 | (a) 'X 같은 게' (b) 'X예요·X이요' (c) 'X로 바뀌었어요·X가 됐어요' (d) 문장 끝 'X.' |
| 주어 자리 | 'X가·X는·X도' |
| 빼는 자리 | 부정('X가 아니라', 'X 말고'), 성질 비유('X처럼'), 크기 비교('X만 해요', 'X 정도'), 장소('X에'), 목적어('X를') |
| 빼는 말 | 신체 부위어(1층 사전 v0·v1), 관계어·부분어·배경어·차원 주제어(`scene_params.v1.json`), 부분 명사(날개·부리·보풀·가장자리 …), 차원·단위어(색·모양·크기·지름 …), 때(지금·처음 …), 일반어(것·곳·쪽 …), 색 이름(하늘색·잿빛·연노랑 …) |
| 성질 명사 | 빛·소리·냄새·기운 등은 이름 자리에서만 정체입니다. '빛이 깜빡여요'의 빛은 그것이 내는 성질일 수 있기 때문입니다 |

단계 정체는 **이름 자리 명사가 있는 마지막 턴**의 명사입니다. 그런 턴이 없을 때만 주어 자리 명사가 있는 마지막 턴을 씁니다. Flesh out 답에는 '가장자리가 흐려요', '물결이 퍼져요'처럼 부분이 주어인 문장이 많습니다. 이런 주어가 이미 이름 붙인 정체를 덮지 않게 하려는 것입니다.

같은 정체 판정:

| 규칙 | 예 |
| --- | --- |
| 동의어·지소어 묶음의 대표어가 같음 | 돌멩이 = 돌, 뭉치 = 덩어리, 원판 = 원반, 막대기 = 막대 |
| 한쪽이 다른 쪽의 오른쪽 머리(합성어·하위어) | 물방울 ⊃ 방울, 참새 ⊃ 새, 농구공 ⊃ 공 |
| 두 집합에 같은 정체가 하나라도 있음 | {새, 부리} 와 {새} |

두 스냅샷 모두 형상 명사가 있을 때만 비교합니다. 겹치는 정체가 없으면 **정체 모순**이고, DI와 상관없이 drift입니다. 형상 명사를 비교할 수 있으면 정체 묶음의 판정은 `form.type`보다 형상 명사를 따릅니다(같은 '돌'도 v1은 '돌멩이'만 blob으로 읽습니다).

### 2.3 단계와 턴

- 단계는 세션 로그 턴의 `stage`(find·focus·flesh_out)를 그대로 씁니다. 정적 조건이면 opening·location = Find, focus_hold = Focus, fleshout_open·프로브 = Flesh out입니다.
- 확인 질문 루프의 답 중 확정 텍스트에 덧붙은 것은 `clarify` 단계로 넣습니다.
- 넘어가기·'없어요'류(`noMore`)와 버튼(`control:*`)은 넣지 않습니다. 확정 텍스트에 들어가지 않는 답이기 때문입니다.
- 확정 단계에서 참여자가 텍스트를 고쳤으면 `confirmationEdited: true`만 기록합니다(9절 한계).

### 2.4 속성 묶음과 가중치

| 묶음 | 슬롯 | 가중 `w_g` | 근거 |
| --- | --- | --- | --- |
| 정체 identity | 형상 명사, `form.type` | 1 | 라벨 규칙의 핵심 속성(형상 정체) |
| 색 color | `material.color`·`brightness`·`saturation` | 1 | 핵심 속성(색) |
| 크기 size | `layout.size` | 1 | 핵심 속성(크기) |
| 위치 position | `body.part`·`body.layer`·`layout.verticalOffset`·`layout.distance` | 1 | 핵심 속성(위치) |
| 자세 shape | `form.posture` | 0.5 | 같은 것의 자세는 바뀔 수 있음 |
| 표면 surface | `material.roughness`·`opacity`·`erosion` | 0.5 | 같은 것을 더 자세히 볼 때 자주 다듬어짐 |
| 움직임 motion | `motion.type`(Unity 9묶음 기준)·`motion.speed` | **0** | 움직임은 그것의 상태이지 정체가 아님. 모순은 기록만 |

슬롯이 아니라 묶음으로 세는 이유: 위치 하나가 바뀌면 부위·층·높이·거리 슬롯이 한꺼번에 바뀝니다. 슬롯 단위로 세면 한 번의 변화가 여러 번 세어지고, DI가 매핑이 채운 슬롯 수에 따라 달라집니다. 핵심 묶음 넷과 보조 묶음 둘은 독립 라벨 작성자의 라벨 규칙("형상 정체, 색, 크기, 위치 중 하나가 뚜렷이 다른 값이 되었거나, 여러 속성이 조금씩 바뀌어 …")을 그대로 따른 것입니다. 이 규칙은 표류라는 개념의 정의로 썼고, 사례별 라벨에 맞춘 것이 아닙니다.

## 3. 슬롯 비교 규칙과 임계값

| 슬롯 | 모순 조건 | 수치 | 근거 |
| --- | --- | --- | --- |
| 0–1 수치(크기·밝기·채도·거칠기·투명도·침식·거리·높이·속도) | `|Δ| > τ_hard` 또는 (중립점 0.5의 서로 반대쪽 그리고 `|Δ| > τ_soft`) | `τ_soft = 0.25`, `τ_hard = 0.5` | 아래 3.1 |
| `material.color` 둘 다 유채색 | 원형 색상 거리 `> τ_hue` 또는 `|Δl| > τ_l` | `τ_hue = 60°`, `τ_l = 0.45` | 아래 3.2 |
| `material.color` 한쪽이라도 무채색 | `|Δl| > τ_l` 또는 `|Δs| > τ_s` | `τ_s = 0.4` | 색상각은 무채색에서 뜻이 없음(4.5절) |
| 유채색 기준 | `s ≥ 0.15` 그리고 `0.08 < l < 0.92` | | 회색(s 0.05)·흰색(l 0.95)·검정(l 0.08)을 무채색으로 |
| `body.part` | 같지도 않고 포함 관계도 아님 | 포함: lower_belly⊂belly, heart⊂chest, forehead⊂face⊂head, throat·nape⊂throat_neck, lower_back⊂back, hand⊂arm, foot⊂leg. body·whole_body·skin은 모든 부위와 같음 | 같은 부위를 더 좁게 말한 것은 다듬기 |
| `body.layer` | 위층(inner·surface·around)이 다름 | surface_above⊂surface, around_*⊂around | |
| `form.type`·`form.posture` | 값이 다름 | | 범주형 |
| `motion.type` | Unity 움직임 묶음(`SpecMotion.cs`)이 다름 | | 가중 0 |
| 위치 묶음 예외 | 첫 스냅샷 이후 턴에 **자리를 옮기는 움직임**(moving·drifting·rising·sinking·settling·approaching)이 있으면 위치 모순을 `explained_by_motion`으로 바꿈 | floating(떠 있다)·rotating은 제외 | 참여자가 그것이 움직여 옮겼다고 말함 |

### 3.1 수치 슬롯

v1 크기 척도(로그 척도, 0.5 = ×1)에서 말로 한 크기는 `작은 0.316 · 조그만 0.25 · 아주 작은 0.224 · 큰 0.621 · 커다란 0.646 · 아주 큰 0.681`입니다. 반대 극 사이 간격(작은 ↔ 큰)은 0.31, 같은 극 안의 정도 차이는 0.1 이하입니다. 그래서 중립점을 넘는 차이가 `τ_soft = 0.25`를 넘으면 모순입니다.

측정·비교로 정한 크기는 말로 한 크기와 기준이 다릅니다(엄지손톱만 0.0, 탁구공 0.113, 주먹 0.333, 손바닥 0.475, 농구공 0.544). '작은'(0.316) 뒤에 '엄지손톱만 해요'(0.0)라고 해도 같은 것을 다듬은 것입니다. 같은 쪽 안에서는 `τ_hard = 0.5`(크기로 ×4)를 넘을 때만 모순으로 봅니다.

밝기도 같은 꼴입니다(어두운 0.15 · 희미한 0.25 · 은은한 0.5 · 밝은 0.8 · 눈부신 1.0). '조금 밝은'(0.68) ↔ '은은하게 밝은'(0.5)은 같은 쪽 0.18 차이라 모순이 아닙니다.

### 3.2 색

v1 색 이름의 색상각은 빨강 0° · 주황 28° · 노랑 52° · 연두 90° · 초록 120° · 청록 175° · 하늘 200° · 파랑 215° · 남색 230° · 보라 275° · 분홍 340°입니다. 이웃한 이름 사이는 25–45°입니다. `τ_hue = 60°`면 이웃 이름으로 바꿔 말한 것(연노랑 → 주황빛 24°, 하늘색 → 남색 30°)은 다듬기이고, 이름 둘 이상 떨어진 것(파랑 → 빨강 145°, 노랑 → 보라 137°)은 모순입니다.

v1의 '연한/짙은' 수식은 l을 약 ±0.2 옮깁니다(연한 파랑 0.70, 짙은 파랑 0.30). 같은 색 이름의 연한형과 짙은형 차이(0.4)는 다듬기로 보고, 그보다 큰 차이(연한 하늘색 0.85 ↔ 거의 검은 남색 0.15)만 모순으로 봅니다. 그래서 `τ_l = 0.45`입니다.

### 3.3 θ

`θ = 0.2 = 1 / 5`. 5는 비교 가능 가중의 최댓값(핵심 묶음 4 × 1 + 보조 묶음 2 × 0.5)입니다. 핵심 묶음 하나가 뚜렷이 모순이면, 나머지 묶음이 모두 같아도 drift가 됩니다(라벨 규칙의 "하나가 뚜렷이 다른 값"). 보조 묶음 하나(0.5)만 모순이면 비교 가능 가중이 2.5 이하일 때만 drift입니다. 보조 묶음 둘이 모순이면 언제나 drift입니다.

## 4. acknowledged

`S_first` 단계 밖의 턴에서 정규식 `바뀌었|바뀌어|바뀐|달라졌|달라져|달라진|이제는|이젠|다시\s*보니`이 나오면 `acknowledged.flag = true`와 표지(턴 번호·단계·일치 문자열)를 남깁니다. 판정은 바꾸지 않습니다. '지금은'은 넣지 않았습니다. 같은 것의 지금 상태를 말할 때도 쓰기 때문입니다.

## 5. 회상 확인과 자기보고 (고정 문구, LLM 없음)

두 문구 모두 `elicitation_protocol.v1.1.json`에 `status: "draft"`로 있습니다. IRB 제출 전 연구팀 검토가 필요합니다(원칙 7). v1.0.0 파일은 그대로 두었습니다. v1.1.0은 v1.0.0의 단계 순서·문구·질문 틀을 바꾸지 않고 두 문구와 `driftChecks` 절만 더했습니다(테스트가 확인).

| 문구 id | 문구 | 답 | 시점 | 설정 |
| --- | --- | --- | --- | --- |
| `recall_check` | `'{X}' — 지금 떠오르는 것도 그 '{X}'인가요?` | [네, 같아요] [조금 달라졌어요] [많이 달라졌어요] [넘어가기] | Flesh out 프로브 뒤, 확정 요약 전 | `[drift] recall_check` (기본 false) |
| `self_report_drift` | `지금 확정한 것은 이 면담을 시작할 때 처음 적어 주신 그것과 같은 것인가요? 가장 가까운 숫자를 골라 주세요.` | 1(전혀 다른 것) … 7(같은 것), [넘어가기] | [이대로 맞아요] 뒤 장면 파일을 만든 직후, 끝맺음 문구 전 | `[drift] self_report` (기본 false) |

- `{X}`는 첫 스냅샷 단계에서 참여자가 쓴 형상 명사 원문입니다(이름 자리 우선, 3어절 이하). 시스템이 고르거나 바꾼 말이 아닙니다. 형상 명사가 없으면 묻지 않습니다. X에 위기 키워드나 깊이 표지가 있으면 묻지 않습니다.
- 두 문구 모두 현재 시제이고 왜·과거 경험·기억을 묻지 않습니다(원칙 3). '처음 적어 주신'과 '그 X'는 **이 면담 안에서 참여자가 적은 심상**을 가리킵니다. 자전적 기억이나 과거 사건을 묻는 질문이 아닙니다. 값·예시·선택지로 심상 내용을 제안하지 않습니다(선택지는 같음/다름 정도뿐).
- 답은 버튼으로만 받습니다. 확정 텍스트와 장면에 들어가지 않습니다.
- 기본값을 끈 이유: 회상 확인은 확정 전에 참여자가 첫 심상을 다시 보게 합니다. 그러면 확정 텍스트가 바뀔 수 있고, 조건 간 비교를 교란합니다(research-design 3.2의 확인 질문 루프와 같은 논리). 자기보고는 확정 뒤라 매핑 비교를 건드리지 않지만, 문구가 draft라 IRB 검토 전에는 끕니다.
- 켜려면 `interview.protocol = "elicitation_protocol.v1.1.json"`도 함께 바꿔야 합니다. 문구가 없는 프로토콜에서 켜면 런타임 경고를 남기고 끕니다.
- 자기보고 이분 기준: `value ≤ 3` → `selfReportDrift = true`(research-design 4.5, 사전 등록 항목). 기준값은 `PARAMS.selfReportDriftMax`.

### 9.1 자기보고와의 관계

규칙 판정은 **말로 나온 속성의 일관성**을 봅니다. 자기보고는 참여자가 느낀 **같음**을 봅니다. 둘은 다른 것을 잴 수 있습니다. 참여자는 색이 바뀌어도 "같은 것"이라고 할 수 있고, 말한 속성이 다 같아도 "다른 것"이라고 할 수 있습니다. 그래서 규칙 판정을 정답으로 두지 않고, 자기보고를 기준으로 규칙 판정이 얼마나 맞는지 봅니다(탐색, RQ4).

### 9.2 AUC 분석 계획 (탐색)

| 항목 | 내용 |
| --- | --- |
| 기준 | 자기보고 ≤ 3 = 표류(사전 등록), 넘어가기는 결측 |
| 예측값 | 1차 쌍 `DI`(연속). 정체 모순이면 1.0으로 둡니다(판정 규칙과 같은 방향) |
| 지표 | ROC AUC(95% 부트스트랩 CI, 참여자 단위 재표집), 이분 판정의 민감도·특이도, `DI`와 자기보고(1–7)의 Spearman 순위상관 |
| 따로 셈 | undecidable(`DI = null`) 비율, acknowledged와 자기보고의 일치, 회상 확인 답과 자기보고의 일치(회상 확인을 켠 세션만) |
| 주의 | 표류 사례가 적으면 AUC 구간이 넓습니다. 표류 기저율을 함께 보고합니다. 수치(τ·θ)는 이 분석 전에 고정하고, 바꾸면 버전을 올립니다 |
